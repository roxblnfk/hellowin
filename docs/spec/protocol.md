## Подключение

1. Браузер открывает WebSocket к Centrifugo: URL из `data-centrifugo-url`. Centrifugo опубликован на своём порту
   (RoadRunner не реверс-прокси), поэтому сервер отдаёт полный URL: `CENTRIFUGO_WS_URL` вида `:<порт>/путь` (по
   умолчанию `:8000/connection/websocket`) он достраивает схемой и хостом, по которым открыта страница, —
   `ws://localhost:8000/connection/websocket` для `http://localhost:8080/`, `wss://…` для https
   (`App\Application\Web\ServiceUrl`). Полный `ws(s)://` URL из env отдаётся как есть, путь — тоже, его фронт
   достраивает до `ws(s)://<host>`.
2. Centrifugo вызывает connect proxy → `ConnectService`. Сервер сам подписывает клиента на канал `hellowin`
   (server-side subscription): клиент **не** вызывает `subscribe`, а слушает `centrifuge.on('publication', …)`.
3. Клиентам запрещено публиковать в канал и подписываться на другие каналы.
4. В `data` подключения браузер передаёт `{playerSecret}` — секрет из `localStorage`
   (`new Centrifuge(url, {data: {playerSecret}})`). Сервер отвечает `user: publicId`; без секрета подключение анонимное.
   Подробности — [`players.md`](players.md).
5. Модератор дополнительно передаёт `moderatorSecret` (`{playerSecret, moderatorSecret}`) — секрет из `localStorage`,
   куда страница кладёт его из `?moderator=<секрет>` (и убирает параметр из адреса). Совпал с
   `HELLOWIN_MODERATOR_SECRET` — подключение получает роль модератора (backend хранит её в meta/info подключения);
   не совпал или в env пусто — обычное подключение, без ошибки. Роль сообщает `me` (`moderator: true`).

## RPC

Вызов: `centrifuge.rpc(method, data)`. Ответ: `{ok: true, …}` или `{ok: false, error: <code>}`.

Лимит: каждый вызов, кроме вызовов модератора, сначала берёт токен из ведра своего игрока (у подключения без игрока —
из ведра подключения) для группы метода: у `click`, `shoot` и `move` свои вёдра, остальные методы делят `other`.
Пустое ведро — `{ok: false, error: 'rate limited'}`, метод не вызывается; ведро пополняется само, повторять можно
сразу, но лишние вызовы снова получат отказ. Вкладки одного игрока делят его вёдра. Пороги — `HELLOWIN_RPC_RATE_*`
([`engine.md`](engine.md), «Лимиты запросов»): быстрый честный темп кликов в них укладывается. Клиент пишет отказ в
`console.warn`, как прочие ошибки RPC.

### Модератор

**Реализовано**. RPC пульта — только подключению модератора, остальным —
`forbidden` (проверяется до разбора данных). Каждый — с ответом `{ok:true, …}`; повтор с теми же данными безопасен
(идемпотентен по текущему состоянию): событие уходит только при изменении.

| Метод | Данные | Ответ, эффект |
|---|---|---|
| `scene.next` | `{scene, force?}` — сцена, которую видит модератор | `{ok:true, scene}` — сцена, которую модератор увидит: `scene+1` (переход поставлен в очередь, событие `scene` придёт следом) или текущая, если `scene` уже не текущая (без перехода). Без `force: true` — только из готовой сцены, иначе `not ready`; из финала — `final scene`; `scene` не целое ≥ 0 — `invalid scene`. На шаге финала 7 (рассвет; **реализовано** на backend) — новый цикл вечера: делает то же, что `reset` (событие `reset` с `again: true`, затем реплика `bar-again`), ответ `{ok:true, scene: 0, round}` — сцена 0 и новый раунд; повтор с той же (финальной) `scene` после цикла — `{ok:true, scene, round}` текущие, без повтора (сравнение раунда под локами, как у `reset`): ответ на `scene`, равную номеру финальной сцены, всегда несёт `round`. | `finale.step` | `{step, force?}` — шаг, на который перейти (текущий + 1); шаг 1 — только из готовой финальной сцены (круг замкнут), иначе `not ready`; с `force: true` — без проверки | `{ok:true, step}` — текущий шаг после вызова; событие `finale` и реплика `finale-{step}`; шаг не следующий (в т. ч. повтор и шаг > 5) — ответ с текущим без изменений; вне финальной сцены — `not final`; `step` не целое — `invalid step`. Шагов 0…7 (**реализовано** на backend); шаг 6 без выполненных целей проклятого мира и шаг 7 при живом боссе (или без него) — `not ready`, с `force: true` — без проверки (шаг 7 с `force` валит FrankenPHP без `boss-down`). **Реализовано** на backend (кости): шаг 2 — только после 6-6-6 (`ready` шага 1), иначе `not ready`; с `force` — можно, режим костей выключается (`dice {on: false}`) |
| `cursed.target` | `{goal, delta}` — `goal`: `drinks` или `zombies`, `delta` — целое, обычно ±5 (**реализовано** на backend) | `{ok:true, target}` — действующая цель (не ниже 1); событие `cursed` (при неизменной цели — без события); цель ≤ счётчика при выполненной второй — проклятый мир сразу готов (`ready`). Проверки по порядку: другой `goal` — `invalid goal`; `delta` не целое — `invalid delta`; не шаг 5 — `not cursed`. Добавка, которая опустила бы цель ниже 1, останавливается на цели 1 для игроков на поле сейчас |
| `boss.hp` | `{delta}` — целое, обычно ±10 (**реализовано** на backend) | `{ok:true, hp, max}` — `hp` и `max` сдвигаются на `delta`, `hp` не ниже 1, `max` не ниже `hp`; событие `boss` (при неизменном здоровье — без события). Проверки по порядку: `delta` не целое — `invalid delta`; нет босса или он повержен — `not now` |
| `dice.owl` | `{}` (**реализовано** на backend) | `{ok:true, attempt, dice}` — сова бросает кости, попытка совы n = 1…3 (в сюжете): 1-я и 2-я — HMAC от `{round}:owl:{n}`, тройка 6-6-6 пропускается — берутся следующие три кости того же потока; 3-я — 6-6-6 и победа, как у игрока (`winner {owl: true, attempt: 3}`, реплика `dice-owl-win`). Событие `roll {owl: true, attempt, dice, at}`. Режим выключен или не шаг 1 — `not now` |
| `meep` | `{flyer?}` — id бегуна на горизонте (летун `roadrunner`), по которому кликнул модератор (**реализовано** на backend) | `{ok:true}` — RoadRunner говорит «Мип-мип!»: событие `meep {flyer?, at}` всем, состояния нет. С `flyer` — над этим бегуном, без — над RoadRunner сцены (финал с шага 3, бар после рассвета). Видимость сервер не проверяет: улетевший бегун — всё равно `ok`, фронтенд пропустит; `flyer` не id (`A-Za-z0-9_-`, до 64 символов) — как без него. Без лимита (модератор), игроку — `forbidden` |
| `owl.say` | `{line, params?}` или `{text}` | `{ok:true}`, событие `owl`; `line` — id из каталога ([`scenario.md`](scenario.md), «Модератор и сова»; сервер проверяет формат slug `a-z 0-9 -` до 32 символов, не список), иначе `invalid line`; `params` — объект (не список), иначе `invalid params`; `text` — 1–200 символов после обрезки, иначе `invalid text`; если пришли и `text`, и `line` — говорится `text` |
| `flyer.special` | `{kind}` — `witch`, `roadrunner` | `{ok:true, flyer}` — id запущенного летуна этого вида (событие `flyer`), даже на паузе; другой вид — `unknown kind` |
| `zombies` | `{on}` — `true` / `false` | `{ok:true, on}`, событие `zombies` (при включении — и реплика `zombies`); зомби запускаются только в проклятом мире (`finale` = 5); `on` не bool — `invalid on` |
| `pause` | `{on}` — `true` / `false` | `{ok:true, on}`, событие `pause`; на паузе летуны и зомби не запускаются, уже запущенные долетают; `on` не bool — `invalid on` |
| `reset` | как выше | сброс ритуала |
| `thresholds` | `{k}` — множитель порогов, число от 0,1 до 10 | `{ok:true, k, thresholds: {pumpkin, bonfire, circle}}` — действующие пороги; событие `thresholds` (при неизменном `k` — без события); `k` вне диапазона или не число (строка, bool, нет поля) — `invalid k`. `k` — JSON-число: `2.0` приходит как `2` |

Коды ошибок: `unknown method`, `unknown element`, `locked` (клик по костру, пока тыквы сцены не готовы или когда костёр уже на своей последней стадии сцены; по кругу — вне финальной сцены, после шага финала 0 или когда круг замкнут: клик не
считается и не рассылается),
`busy` (не удалось взять лок), `internal error`; для `register` —
`invalid name`, `invalid look` и `anonymous` (подключение без секрета); для `move` — `anonymous`, `invalid point` (`x`/`y` не числа),
`no character` (проверяются в этом порядке); для бара — `not bar`, `has beer`, `no beer`, `not clinked` (таблица выше);
для пульта — `forbidden` и коды из таблицы выше. `bar.take`, `clink.auto` и `drink` делят ведро `other`. Для рапиры
(**реализовано** на backend) — `not cursed`, `not now`, `zombified`, `has rapier`, `no rapier`, `invalid text`, `invalid goal`;
`beer`, `word` и `cure` — в ведре `other`, `strike` — в ведре `click`.
Для костей (**реализовано** на backend) — `bad attempt` (ответ несёт ещё `last`), `not now`, `busy`, `zombified`; `roll` — в ведре `other`.

`Player` — `{id, name, look, clicks, finished, flyers, points, drinks}`: `id` — публичный id, `name` и `look` — `null` до
`register`; `look` — `{body, cloak, face, eyes, hat}` ([`players.md`](players.md), «Персонаж»); `drinks` — выпитые в
баре и проклятом мире кружки (ранжирование таблицы лидеров не меняет); `damage` (**реализовано** на backend) — урон по FrankenPHP
(удары `strike`), ранжирования тоже не меняет; `rolls` (**реализовано** на backend) — брошенные кости (новые броски `roll`), ранжирования не меняет.

`Walker` — фигурка на поле: `{id, name, look, item, walk: <Walk>, clink?, zombie?}` (`zombie: true` — **реализовано** на backend:
игрок не угадал слово, фигурку водит сервер, см. «Рапира»; без поля — обычная фигурка); `clink` — цель (`{walker: {id}}` или
`{pumpkin: {id}}`), пока фигурка идёт чокаться по клику, — до события `clink` или отмены. Ожидающий `bar.take` в
`Walker` не виден: путь к стойке — обычный `move`. `item` в баре — свой у каждой
фигурки: `beer` или `null`; в остальных сценах — предмет сцены и шага финала, как раньше. `Walk` — `{path: [{x,y}, …], startedAt, arrivesAt}`:
ломаная от текущей точки до цели (первая точка — откуда, последняя — куда), серверное время в мс. Фигурка идёт по
ломаной с постоянной скоростью; стоящая — `path` из одной точки. Где фигурка сейчас, клиент считает сам по `now`
(«Время летунов» — те же часы).

```json
{"ok":true,"player":{"id":"3f9c0a7d12b4e856","name":"Jack","look":null,"clicks":42,"finished":3,"flyers":0,"points":0}}
```

## События канала `hellowin`

Каждое событие несёт `type` и `round`. Событие с `round`, отличным от текущего у клиента, означает пропущенный сброс:
клиент запрашивает `state`.

| `type` | Поля | Когда |
|---|---|---|
| `click` | `element`, `emoji`, `clicks`, `threshold`, `stage`, `player?` | каждый принятый клик |
| `pumpkin` | `element`, `stage`, `player?` | элемент — тыква, костёр (`element: "bonfire"`) или магический круг (`element: "circle"`) — перешёл в новую стадию (ровно одно событие на переход) |
| `scene` | `scene`, `stageMax`, `bonfireStageMax` (последняя стадия костра в новой сцене), `circleStageMax` (последняя стадия магического круга в новой сцене: `HELLOWIN_CIRCLE_STAGES` в финальной, 0 до неё), `item` (предмет фигурок в новой сцене), `walkers?` — при выходе из бара (0 → 1): все фигурки (`[<Walker>]`), переставленные в зону прогулки дня — стоят (`path` из одной точки), с предметом дня | сцена сменилась (ровно одно событие на смену) |
| `reset` | `item` (предмет фигурок в сцене 0; с баром — `null`), `walkers?`, `bar?` — с баром: фигурки, переставленные на пол бара, стоят, с пустыми руками; `bar` — состояние стойки после сброса (`{mugs: max, max, pouring: null}`); `again?` — `true`, если это новый цикл вечера (`scene.next` на рассвете), а не сброс пульта (у сброса пульта поля нет). Фигурки и при сбросе, и при новом цикле — сразу в полосе `spawn` пола бара (x — где стояла, приведённый на пол), не через дверь | сброс; новый `round` в самом событии |
| `flyer` | `flyer`, `kind`, `depth`, `bush?`, `from:{x,y}`, `via?:{x,y}`, `stops?:[{x,y,sit}]` (муха: точки посадки и сколько сидит, мс), `to:{x,y}`, `wobble?:{amp,waves}`, `duration`, `points`, `launchedAt`, `expiresAt` | запущен летун. Бродячий зомби шагов 5–6 (**реализовано** на backend) — `{flyer, kind: zombie, depth, from, points, launchedAt, wander: true}`, без `to`, `duration`, `expiresAt` (см. «Бродячие зомби») |
| `shot` | `flyer`, `points`, `player?` | летун сбит, ровно одно событие на летуна |
| `walker` | `walker: <Walker>` | игрок вышел на поле (подключился с `look` — в пределах секунды, или прошёл экран входа) или сменил вид / имя. Новая фигурка в баре (**реализовано** на backend) входит в дверь — `walk {path: [door, {x: door.x, y: door.y + door_in}], startedAt: now, arrivesAt}` (`walk.bar.door`, `walk.bar.door_in`); смена вида стоящей фигурки — без двери; в остальных сценах — как раньше |
| `move` | `player: {id}`, `walk: <Walk>`, `clink?` — цель, если фигурка идёт чокаться по клику (`{walker: {id}}` или `{pumpkin: {id}}`), `stop?` — действие, которое остановило ход (`shoot`, `click`, `strike`, `drink`, `dice`; **в работе** на backend, см. «Действие останавливает ход») | фигурка пошла; `move` без `clink` отменяет её недошедшее чоканье |
| `clink` | `player: {id}` — подошедший, `walker?: {id}` или `pumpkin?: {id}` — цель, `toast` — целое ≥ 0 (индекс тоста: клиент берёт `toast % TOASTS.length`), `at` — серверное время встречи, мс | чоканье по клику (**реализовано**): публикуется в момент встречи (тикер, с точностью до ~200 мс), если цель на месте, — ровно одно на клик; не случилось — события нет, `clink` пропадает у фигурки в следующем снимке; анимация ~3 с от `at`; пришедшее с опозданием (фон, переподключение) старше 3 с клиент не играет. В баре — так же, только с `walker`; засчитывает чоканье кружкам обоих. `roadrunner?: true` вместо `walker` (**реализовано** на backend) — чоканье с RoadRunner за стойкой (тост — из барного каталога, ответ тоста — над RoadRunner); засчитывает кружке подошедшего |
| `pour` | `since`, `until` — серверное время в мс: начало розлива и когда сова поставит налитую кружку; `rumor?` — целое ≥ 0: сова приговаривает (клиент берёт `rumor % RUMORS.length`), сервер добавляет его с вероятностью `HELLOWIN_BAR_RUMOR_CHANCE` | сова начала наливать кружку (бар): фронтенд играет розлив от `since` до `until`, фаза пены у всех одна |
| `mugs` | `mugs` — сколько кружек на стойке, `max` — до скольких сова наливает сейчас (см. `bar` снимка) | сова поставила налитую кружку (бар) |
| `take` | `player: {id}`, `ok` — `true` / `false`, `mugs` (при `ok: true`) — сколько кружек осталось | `bar.take` дошёл до стойки: `ok: true` — у игрока пиво (`item: beer`), кружка ушла со стойки; `ok: false` — кружки не было, руки пустые. Ровно одно событие на дошедшую попытку; отменённая события не даёт. С `pumpkin: {id}` вместо `mugs` (**реализовано** на backend) — пиво из тыквы (`beer`, шаг 5), всегда `ok: true`, и `until` (**реализовано** на backend): когда кружка в руке (прибытие + `HELLOWIN_BEER_HANDOVER_MS`), до него фронтенд играет передачу |
| `drink` | `player: {id}` | игрок выпил пиво: анимация глотка ~1,2 с, затем `item` фигурки — `null` |
| `drinks` | `drunk`, `target` | выпито за раунд и цель бара: после каждого `drink` и смены цели; шкала в HUD |
| `leave` | `player: {id}` | у игрока нет подключений дольше `HELLOWIN_WALK_LEAVE_AFTER` мс — фигурка уходит |
| `ready` | `scene` | все тыквы сцены дошли до `stageMax`, а костёр — до своей последней стадии сцены (если она выше той, на которой он был) — сцена ждёт модератора (ровно одно событие на сцену); следом реплики совы `last-pumpkin` (если последней была тыква) или `bonfire-done` (если костёр), `circle-done` (если замкнут магический круг — в финальной сцене на шаге 0 готовность даёт он) — только если добил игрок — и `scene-ready`. Если сцене нужен костёр, последняя тыква события `ready` не даёт: вместо него реплики `last-pumpkin` и `bonfire-open`. В баре (сцена 0) — один раз за раунд, когда выпито `drunk ≥ target` (после `drink` или понижения цели) или модератор дал отмашку (`bar.ready`); следом реплика `bar-intro`, без `scene-ready`. В финальной сцене на шаге 5 (**реализовано** на backend) — ещё раз, когда выполнены обе цели проклятого мира (`ready` снят на входе в шаг 5); следом реплика `cursed-ready`, без `scene-ready`. **Реализовано** на backend (кости): на шаге 1 — первое 6-6-6 (`ready` снят на входе в шаг 1); следом реплика `dice-win` или `dice-owl-win`, без `scene-ready` |
| `finale` | `step`, `item` — предмет в руке всех фигурок с этого шага (до шага 5 — предмет финальной сцены, с шага 5 — `beer`; `null` — пустые руки; клиент меняет его всем фигуркам, как по `scene`), `reveal?` (на шаге 2 следом — `move` каждой фигурке к краю поля: от центра грядки наружу, путь тем же роутером, что у RPC `move`) | шаг финала; на шаге 4 и дальше — `reveal` (см. «Снимок»). Шаг 0 приходит вместе с `scene` при входе в финальную сцену. На шаге 6 (**реализовано** на backend) поля `item` нет (не `null`: клиент предметы фигурок не трогает) — предмет у каждого свой (пиво, пустые руки, рапира); на шаге 7 `item: rapier` у всех и `zombie` снят со всех фигурок |
| `owl` | `line?`, `params?`, `text?` | реплика совы: каталожная (`line`, `params` — только если есть подстановки, например `{player: {id, name}}`) или свободный текст модератора (`text`, показывать как текст, не HTML). Авто-реплики: `scene-ready`, `last-pumpkin`, `bonfire-open`, `bonfire-done`, `circle-done`, `scene-{N}` (после события `scene`; с баром — `scene-1` … `scene-4`, `scene-1` — выход из бара), `finale-{N}` (после `finale`, кроме шага 0 — на нём `scene-{N}` финальной сцены), `witch-down`, `zombies`, `bar-empty` (`take` с `ok: false`, не чаще раза в 20 с), `bar-intro` (бар готов), `bar-again` (после `reset` с `again: true`); **реализовано** на backend — `cursed-ready` (готовность шага 5), `finale-6`, `finale-7` (по общему правилу `finale-{N}`) и `boss-down` (`params.player` — нанёсший последний удар, перед `finale-7`); **реализовано** на backend — `dice-win` (`params: {player, attempt}`, первое 6-6-6) и `dice-owl-win` (третий бросок совы) |
| `pause` | `on` | модератор включил или снял паузу нечисти |
| `zombies` | `on` | модератор включил или выключил зомби |
| `thresholds` | `k`, `thresholds: {pumpkin, bonfire, circle}` | модератор сменил множитель порогов: клиент обновляет `threshold` элементов и `data-ready`; следующие `click` несут новый порог |
| `leaderboard` | `top: [<Player>]` — лучшие первыми, `online` — игроков с персонажами на поле (как в снимке) | раз в `HELLOWIN_LEADERBOARD_INTERVAL` мс, даже без изменений |
| `cursed` | `drunk`, `slain`, `drinksTarget`, `zombiesTarget` | **реализовано** на backend: счётчики и цели проклятого мира изменились — после `drink` и сбитого зомби на шагах 5–6, смены добавки и числа игроков; шкалы в HUD. Первое — с `finale {step: 5}` |
| `word` | `player: {id, name}`, `ok` | **реализовано** на backend: игрок молвил слово; `ok: true` — у фигурки `item: rapier`, `ok: false` — `zombie: true` (ходы — обычные `move` от сервера). Слово в событии не приходит |
| `cure` | `player: {id, name}` — расколдованный, `by: {id, name}` — кто | **реализовано** на backend: зомби-игрок расколдован (`zombie` снят, предмет прежний); ровно одно событие на превращение |
| `boss` | `hp`, `max` | **реализовано** на backend: FrankenPHP проснулся (первая рапира, очки) или модератор сменил здоровье (`boss.hp`) |
| `strike` | `player: {id, name}`, `hp` — здоровье после удара | **реализовано** на backend: удар рапирой по FrankenPHP — золотая цепная молния от фигурки; ровно одно событие на принятый `strike` |
| `dice` | `on`, `winner?` — `{player: {id, name}, attempt}` или `{owl: true, attempt: 3}` | **реализовано** на backend: режим костей включён (вход в шаг 1, когда силуэт поднимается) или выключен (первое 6-6-6 — с `winner`, следом `ready {scene}` и реплика `dice-win` / `dice-owl-win`; `force` шага 2 — без `winner`) |
| `roll` | `player?: {id, name}` или `owl: true`, `attempt`, `dice: [a, b, c]`, `at` — серверное время броска, мс | **реализовано** на backend: новый бросок костей — ровно одно событие на попытку; повтор той же попытки события не даёт |
| `meep` | `flyer?` — id бегуна на горизонте, `at` — серверное время, мс | **реализовано** на backend: модератор кликнул по RoadRunner (RPC `meep`) — пузырь «Мип-мип!» над этим бегуном или, без `flyer`, над RoadRunner сцены; кого не видно — ничего |
| `dawn` | `board: [{player: {id, name}, shots}]` — все стрелки по порядку, `shots` — сбитые за вечер (не больше `HELLOWIN_DAWN_BOARD`) | **реализовано** на backend (счёт за вечер — тоже): только на шаге 7 — при входе в него и на каждое засчитанное попадание сразу после `shot`, без склейки; см. «Топ рассвета» |
| `gone` | `flyers: [id, …]` | **реализовано** на backend: бродячие зомби убраны без попадания — на входе в шаг 7, при сбросе и `again`; клиент убирает их (тают или проваливаются) |

`player` — `{id, name}` игрока, совершившего действие (`name` может быть `null`); у анонимных действий поля нет.
`emoji` сервер выбирает из набора emoji элемента — фронтенд
может использовать его или игнорировать.

Особые летуны (**реализовано**): `roadrunner` — бежит по горизонту (`depth` 0, `from`/`to` на линии горизонта
`horizon` из `app/config/hellowin.php`; `duration` — как у ближней глубины, без `via` и `bush`), `points` 0, выстрел по нему всегда `hit:false`, без реплик
совы; `witch` — редкий, очки `HELLOWIN_FLYER_RARE_POINTS`; `zombie` — наземная цель проклятого мира: путь по
лужайке (зона `walk`) от края грядки наружу, `depth` 1, `via` нет, очки `HELLOWIN_ZOMBIE_POINTS`, частота
`HELLOWIN_ZOMBIE_INTERVAL`. `firefly` (**реализовано**, проклятый мир, набор `HELLOWIN_FLYER_KINDS_CURSED`) —
летун: мелкий, путь как у обычных (край или куст, `via` по шансу дуги), `depth` 1 или 2 (`bush` — только куст этих
глубин), `wobble` как у мышей, но вялый (`amp` 2–5, `waves` 1,5–3), `duration` — по глубине, очки —
`HELLOWIN_FLYER_FIREFLY_POINTS` на любой глубине.
`fly` (**реализовано** в движке, летун бара — сцена 0 из `HELLOWIN_FLYER_KINDS`) — муха:
быстро нарезает круги по залу, потом **садится** на поверхность (стол, стойку, кружку) на короткое время — тогда в неё
легко попасть; взлетает, кружит и садится снова. Синусоиды (`wobble`) у мухи нет. Путь задаёт сервер: `stops:
[{x, y, sit}]` — точки посадки в процентах экрана (на столешницах и стойке из `walk.bar`, по кружкам — на стойке, и на местах посадки `walk.bar.perches`) и
сколько муха сидит, мс (`HELLOWIN_FLYER_FLY_SIT`, по умолчанию 900–1600); `from` — откуда влетает, `to` — куда
улетает (внутри `walk.bar.area` или за край зала). Между точками муха летит петлями: 1–2 быстрых круга радиусом 3–6 % —
форму петель фронт строит детерминированно от id летуна, так что у всех одинаково; на каждый перелёт —
`HELLOWIN_FLYER_FLY_LEG` мс (по умолчанию 900). `duration` = сумма перелётов и посадок; `depth` 1, очки —
`HELLOWIN_FLYER_FLY_POINTS` (1), сбивается обычным `shoot` в любой момент (первый под локом), сервер принимает выстрел
до `expiresAt` + 500 мс, как у всех; пауза останавливает. Посадок 2–3 (`HELLOWIN_FLYER_FLY_STOPS`), две подряд — на
разных поверхностях; «за край зала» — на 3 % за левой или правой стороной `walk.bar.area`. `via`, `perch` и `wobble` у
мухи не приходят.
`worm` (**реализовано**, обычный летун сцены 4 из `HELLOWIN_FLYER_KINDS`) — наземная
цель: путь по лужайке (зона `walk`) из точки в точку внутри зоны — выползает из земли и уходит в землю, без краёв
экрана; обе точки вне эллипса грядки, и прямая между ними грядку не пересекает; извилистость — `wobble` (малый:
`amp` 0,8–2, `waves` 3–6); `depth` 1, `via` и `bush` нет, длительность и очки — как у летунов глубины 1. Червяк не зависит
от проклятого мира и переключателя `zombies` — обычный запуск тикера, пауза его останавливает, как всех летунов.

Летун: `flyer` — id вида `f-` + 8 hex, его же клиент шлёт в `shoot`; `depth` — от 0 (дальний) до N−1, где N — длина
`HELLOWIN_FLYER_DURATION` (по умолчанию 3); `duration` — мс от `from` до `to`, отсчёт — от `launchedAt` (см. «Время летунов»); `kind` —
случайный из набора текущей сцены `HELLOWIN_FLYER_KINDS` (по умолчанию: бар (0) — `fly`; 1 — `duck`, `chicken`; 2 — никого; 3 — `bat`; финал — `worm`), в проклятом мире (шаг финала 5) — из `HELLOWIN_FLYER_KINDS_CURSED` (по умолчанию `worm`, `bat`, `firefly`), или редкий летун сцены (по умолчанию только `roadrunner` в сцене 1; `witch` — с пульта). Сервер принимает выстрел до `expiresAt` + 500 мс. Летун без попадания исчезает сам:
отдельного события «улетел» нет. Промах мимо летуна на сервер не шлётся.

`startedAt` — серверное время запуска RoadRunner в мс (аптайм для финала: шаг 3 в HUD, шаг 4 в
разоблачении); клиент считает аптайм по часам с тем же смещением, что у летунов. Перезапуск воркеров его не сбрасывает,
перезапуск RoadRunner (контейнера `app`) — сбрасывает: это аптайм сервера, а не стека с Valkey ([`engine.md`](engine.md), «Аптайм»).

`ready` — сцена готова и ждёт модератора; `finale` — `null` вне финальной сцены, в ней `{step, reveal?}`;
`k` — множитель порогов (`threshold` в снимке и у элементов — уже умноженный), `online` — сколько
игроков с персонажами сейчас на поле (`walkers`; для пульта, ещё приходит в событии `leaderboard`); `paused`, `zombies` — переключатели пульта. `reveal` — числа вечера с начала раунда для экрана
разоблачения: `{clicks, jobs, burned, shot, drinks, lastPumpkin: {id, name} | null}` — принятые клики, выполненные задачи
перехода (переходы тыкв, костра и круга + переходы сцен), сгоревшие клики (сверх порога и после готовности тыквы;
клики `locked` по костру и кругу не принимаются и сюда не входят), сбитые летуны (и зомби), выпитые в баре кружки за
раунд (`drinks`; раунд начинается в баре, так что это кружки вечера), кто добил последний элемент
последней готовой сцены — тыкву, в сцене с костром — костёр, в финальной — круг (если элемент добит анонимно, остаётся
игрок прежней готовой сцены; `null`, если такого нет — добивали анонимно или сцены переключали `force`, не дождавшись;
имя поля осталось `lastPumpkin`). Как считаются — [`engine.md`](engine.md), «Сюжет». Рапира (**реализовано** на backend):
`drinks` — одно число вечера: кружки бара плюс кружки проклятого мира; новые поля `slain` — зомби-воркеры, сбитые с шага 5
(`cursed.slain`), и `damage` — весь урон по FrankenPHP (принятые `strike`); до шага 5 оба 0. Свежие числа приносят снимок
и следующие события `finale` (6, 7). Кости (**реализовано** на backend): `rolls` — броски костей за раунд (новые `roll` игроков, без бросков совы и повторов); как всё `reveal` — в событиях `finale` с шага 4 и в снимке (`hellowin:dice`, `rolls`).

Сброс (`reset`) возвращает и сюжет: `ready` — `false`, `finale` — `null`, `zombies` — `false`; `paused` и `k`
сохраняются — они про зал, а не про сюжет. Клиент применяет это сам по событию `reset`, без RPC. С баром
сброс ведёт в бар: `ready` — `false` (бар ждёт своей цели или отмашки), `bar` и `walkers` — из события `reset`; цель бара
(`target`), как `k`, сохраняется, `drunk` начинается с 0.

`cursed` и `boss` (**реализовано** на backend, см. «Рапира»): `cursed` — `{drunk, slain, drinksTarget, zombiesTarget}` на шагах
финала 5+, иначе `null`; `boss` — `{hp, max}` с шага 6 после пробуждения FrankenPHP (на шаге 7 — `hp: 0`; если он так и
не проснулся — `null`), иначе `null`. Сброс
обнуляет оба (`null`).

`dawn` (**реализовано** на backend, см. «Топ рассвета») — `{board}` на шаге финала 7, иначе `null`.

`flyers` (**реализовано** на backend, см. «Бродячие зомби») — живые бродячие зомби: список событий `flyer` с `wander: true` (без
`type` и `round`); на шагах 5–6, иначе `[]`. Обычные летуны в снимок не входят, как раньше.

`dice` (**реализовано** на backend, см. «Кости») — `{on, winner?}` на шаге финала 1 и дальше: `on` — режим костей включён, `winner` —
`{player: {id, name}, attempt}` или `{owl: true, attempt: 3}` после первого 6-6-6 (или нет поля, если шаг 2 взят `force`);
вне финальной сцены и на шаге 0 — `null`. Свою последнюю попытку клиент в снимке не получает: начинает с 1 и
выравнивается по `last` из ответа `bad attempt`. Сброс — `null`.

`bar` — стойка бара: `{mugs, max, pouring: {since, until, rumor?} | null, drunk, target}` (`drunk` — выпито за раунд, `target` — цель бара; `rumor` — см. событие `pour`) — сколько налитых кружек стоит (0…
`max` — число фигурок на поле, не меньше 1 и не больше `HELLOWIN_BAR_MUGS`; `max` приходит в снимке, в событии `mugs` и в `reset.bar`; игроки ушли — налитые кружки остаются, и `mugs` бывает больше `max`, пока их не разберут) и до какого серверного момента сова наливает следующую (`null` — не наливает: полно или сцена не
бар). Поле есть в снимке всегда; вне бара — `{mugs: 0, max, pouring: null, drunk, target}`: счёт и цель видны и после бара.
`roadrunner` (**реализовано** на backend) — `true`, пока за стойкой стоит RoadRunner (после «Снова в бар» — `reset` с `again: true`; снимает обычный сброс модератора, при котором `reset.bar.roadrunner` — `false`); приходит в снимке и в `reset.bar`. Место — `walk.bar.roadrunner {x, y}` (`y` — задний край стойки, как у совы), конфиг в разметке, не в снимке. Тосты RoadRunner фронтенд выбирает сам по серверному времени, сервер их не шлёт.

`bush` — id куста, из которого взлетает летун (тогда `from` — его точка, а `depth` летуна — `depth` куста, см.
[`scenario.md`](scenario.md), «Летуны»; `depth` в `bushes` снимка — **реализовано**); `wobble` (только у `kind: bat`, `worm` и `firefly`, у остальных поля нет) — кривая поверх базовой траектории: смещение поперёк пути
`amp · sin(2π · waves · t)` (`amp` — проценты экрана, `t` — доля полёта 0…1; `waves` — дробное число полных колебаний
за полёт); без поля — без колебаний; петли — `waves` с большой `amp` или отдельное поле, если понадобится (согласовать).
Диапазоны — [`engine.md`](engine.md), «Летуны». `via` — контрольная точка дуги
(квадратичная кривая), без неё полёт прямой. `x`/`y` — проценты экрана (на узких экранах фронтенд растягивает раскладку тыкв по x от центра — `spreadX`
в `public/js/layout.js`; и у тыкв, и в траекториях летунов: `from`/`to` могут выходить за 0–100 — летун влетает из-за края); `size` — `s` / `m` / `l` (у тыкв); `reachable` — тыква досягаема с лужайки для чоканья (у края грядки, **реализовано**; считает сервер из раскладки: тыква не дальше `walk.reach` процентов экрана от зоны прогулки; у каждой тыквы — `true` или `false`, у костра и круга поля нет); у магического круга (`type: circle`, id `circle`, без `size`) — как у костра:
свои `threshold` (`HELLOWIN_CIRCLE_CLICKS_PER_STAGE`) и `stageMax` (`HELLOWIN_CIRCLE_STAGES` в финальной сцене, 0 до неё),
кликабелен в финальной сцене на шаге 0, пока `stage` ниже `stageMax` (новую сцена приносит в `scene.circleStageMax`),
готовность финальной сцены — круг на `stageMax`, шаг финала 1 без готовности —
только `force`; у костра (`type: bonfire`, id `bonfire`, без `size`) — свои `threshold`
(`HELLOWIN_BONFIRE_CLICKS_PER_STAGE`) и `stageMax` (последняя стадия костра в текущей сцене, из
`HELLOWIN_BONFIRE_STAGE_MAX`; новую сцена приносит в `scene.bonfireStageMax`), кликабелен, когда все тыквы на
`stageMax` сцены, а `stage` костра ниже его `stageMax` — клиент вычисляет это сам по снимку и событиям `pumpkin`;
`threshold` в событии `click` по костру — тоже его порог; `sceneStages` — номер финальной сцены (длина списка
`HELLOWIN_SCENE_STAGE_MAX`); `stageMax` — последняя стадия тыквы в текущей сцене, в финальной — та же, что в сцене
перед ней (см. [`scenario.md`](scenario.md)). `clicks` — клики с момента перехода тыквы в текущую стадию. `walkers` — фигурки игроков на поле
(`Walker`, см. «RPC»). Страница
`GET /` отдаёт снимок в шаблон `home` (переменные — см. [`frontend.md`](frontend.md)) вместе с `centrifugoUrl`.

### Время летунов

`launchedAt` и `expiresAt` в событии `flyer` — серверное Unix-время в мс; `now` в снимке — серверное время его сборки.
Клиент считает смещение часов `offset = now − Date.now()` (по снимку страницы или RPC `state`) и **не рисует летуна**,
если `Date.now() + offset >= expiresAt`; уже нарисованного убирает к `expiresAt`. Так свёрнутая вкладка, получившая
пачку отложенных публикаций при разворачивании, не выпускает птиц, которых уже нельзя сбить (сервер принимает
выстрел не позже `expiresAt` + 500 мс). Если смещение неизвестно — считать его 0.

  {y1, y2}` — полоса появления (новых фигурок, если нет `door`, и фигурок, переставленных сбросом); `clink_reach` — до скольких процентов экрана между фигурками сервер
  признаёт `clink.auto`; `door {x, y}` (**реализовано**) — порог входной двери на линии задней стены и пола (левый угол
  зала), `roadrunner {x, y}` — место RoadRunner за стойкой (`y` — задний край стойки, как у совы; пример — `{x: 74, y: 46}`), и `door_in` — на сколько процентов экрана вниз (+y) новая фигурка входит от порога (по умолчанию 6); `perches` (**реализовано**) — места посадки мух: список `{x1, x2, y, name}` — полоса x от `x1` до `x2` на высоте `y` (точка, если `x1 == x2`), `y` — верх поверхности, на которой муха стоит: `beam` (балка), `lintel` (притолока двери), `mantel` (полка камина), `shelf-top` и `shelf` (полки над стойкой), `shield-1` … `shield-N` (кромки щитов), `barrels` (крышки бочек); каждая — своя поверхность для правила «две посадки подряд — на разных». Отдаётся клиенту в разметке (см. [`frontend.md`](frontend.md)), снимок её не несёт: это
  конфиг, а не состояние. В баре `move`, `clink` и `bar.take` строят путь по зоне бара: цель приводится на пол вне
  препятствий, путь обходит препятствия.
- **Розлив.** Пока сцена — бар, кружек меньше `max` (число фигурок на поле, 1…`HELLOWIN_BAR_MUGS`) и никто не наливается, сервер начинает розлив:
  `pouring = {since: now, until: now + HELLOWIN_BAR_POUR_MS}`, событие `pour {since, until}`. Когда `until` наступил — `mugs + 1`,
  `pouring = null`, событие `mugs {mugs}`, и если места ещё есть — сразу следующий `pour`. Ведёт тикер (раз в 200 мс),
  точность — до тика. Клиент рисует розлив по фазе между `since` и `until` (узнавший посреди — с той же фазы, что у всех), а кружку на
  стойке ставит по событию `mugs`; `pouring` с прошедшим `until` в снимке — кружка вот-вот встанет, розлив не рисуется.
- **Взять.** `bar.take` → ответ с `walk` и событие `move` всем → по прибытии (тикер, как у чоканья по клику) событие
  `take`: `ok: true` несёт оставшиеся `mugs` (отдельного `mugs` при взятии нет), у фигурки `item: beer`; `ok: false` —
  следом реплика `owl` `bar-empty` (не чаще раза в 20 с). Если стойка была полной, следом пойдёт `pour`.
- **Чокнуться.** По клику — `clink {walker}` как в проклятом мире (`move` с `clink`, затем `clink`), засчитывает обоим.
  Автоматически — браузер каждого участника сам шлёт `clink.auto {walker: партнёр}` в момент удара, засчитывается только
  ему; событий нет. Засчитанное чоканье — флаг кружки в записи фигурки на сервере; `take` начинает новую кружку без
  флага.
- **Выпить.** `drink` → `{ok:true}` и событие `drink {player}` всем; `not clinked` — ответ только вызвавшему, подсказку
  «Сначала чокнись, потом пей!» показывает его клиент, ничего не рассылается.
  `busy` — чоканье этой кружкой ещё играет (до `clinkedUntil`) или глоток предыдущей ещё идёт
  (`HELLOWIN_DRINK_MS`); тоже только вызвавшему, клиент молчит. Повторный `clink`/`clink.auto` той же кружкой — `{ok:true}`
  без изменений.
- **Выход на грядку.** `scene.next` из бара: событие `scene {scene: 1, item: pistol, walkers}` — кружки на стойке и в
  руках сгорают (`bar` → `{mugs: 0, pouring: null}`), недошедшие `bar.take` и чоканья отменяются без событий; клиент
  заменяет фигурки списком `walkers` без ходьбы (другая локация), следом — реплика `scene-1`.
- **Сброс** ведёт в бар: событие `reset` несёт `walkers` на полу бара с пустыми руками и `bar` с полной стойкой.

Решения backend (были открытыми вопросами спеки):

1. Перестановка фигурок при смене локации — полный список `walkers` в событиях `scene` (0 → 1) и `reset`, а не `move`
   нулевой длины на каждую. Новая точка — ближайшая точка новой зоны к прежней позиции (координаты бара и лужайки —
   проценты одного экрана); лок лужайки занят — событие уходит без `walkers`.
2. Ключи `walk.bar.{area, obstacles, counter, spawn, clink_reach}` и формы препятствий — как предложено. Обход — граф
   видимости по точкам вокруг каждого препятствия, кратчайший путь ([`engine.md`](engine.md), «Фигурки на поле»).
   Стойка в конфиге заходит за верх и правый край пола: за стойкой нет полоски пола, куда можно было бы встать.
3. `pour` и `pouring` несут `since` и `until` (и `rumor`, если сова приговаривает).
4. Ошибка `clink` вне проклятого мира и бара — `not cursed`; в баре без пива — `no beer` (после `not cursed`).
5. `barLayout` — массив `walk.bar` в шаблоне `home` (`HomeController`); без `walk.bar` в конфиге — `null`.
6. `drinks` — в записи игрока ([`players.md`](players.md)); выпитые за раунд — ключ `hellowin:drinks`
   (`{round, count}`), из него `drunk` и `reveal.drinks` ([`engine.md`](engine.md), «Бар»).
7. Бар — сцена 0, только если первый элемент `HELLOWIN_SCENE_STAGE_MAX` равен 0; без него сцена 0 — день, бара нет
   (старый формат списка продолжает работать).

## Рапира

**Реализовано** на backend. Правила — [`scenario.md`](scenario.md), «Рапира»; здесь — порядок сообщений. Шаги финала 5–7: цель
проклятого мира, сова с рапирой и босс, рассвет.

- **Шаг 5.** `finale {step: 5, item: beer}`, следом `cursed {drunk: 0, slain: 0, drinksTarget, zombiesTarget}` и
  `zombies {on: true}` (флаг пульта; сами зомби — бродячие, см. «Бродячие зомби»: следом сразу `HELLOWIN_ZOMBIE_MIN` событий `flyer` с `wander`, переключатель на шагах 5–6 не действует). Цели — `HELLOWIN_CURSED_PER_PLAYER` × n + добавка модератора (n — фигурки
  на поле, минимум 1), не ниже 1; n меняется — новое `cursed`. Добавка живёт до сброса.
  - **Пиво из тыквы.** `beer {pumpkin}` → ответ с `walk` и `move` всем → по прибытии (тикер, как у `bar.take`)
    `take {player, pumpkin, ok: true}`, у фигурки `item: beer`. `take` несёт `until` — прибытие +
    `HELLOWIN_BEER_HANDOVER_MS`; пиво в руке (и `drink`) — с `until`, до него фронтенд играет передачу.
  - **Чокнуться и выпить** — как в баре: `clink {walker}` и `clink {pumpkin}` засчитывают чоканье кружке (с тыквой —
    подошедшему), автоматическое — браузеры участников шлют `clink.auto` (на шаге 5+ тоже, не только в баре); `drink` →
    `drink {player}`, `drinks + 1` игроку, `drunk + 1` проклятого мира и событие `cursed`. Ошибки `drink`, `clink.auto`
    вне бара и проклятого мира — `not bar` (имя кода прежнее). Пить без чоканья можно, только если игрок на поле один.
  - **Зомби.** Каждый `shot` по `kind: zombie` на шаге 5+ — `slain + 1` и событие `cursed`. Вид смерти сервер не шлёт:
    фронтенд выбирает его по id летуна (см. [`frontend.md`](frontend.md), «Рапира»).
  - **Готово** — `drunk ≥ drinksTarget` и `slain ≥ zombiesTarget` (после `drink`, `shot` или понижения цели): `ready`
    финальной сцены — `true`, событие `ready {scene: <финальная>}` (один раз за раунд), следом реплика `cursed-ready`.
    Сам шаг не меняется: шаг 6 — `finale.step {step: 6}` модератора; без готовности — `not ready`, с `force` — можно.
    На входе в шаг 5 (`finale {step: 5}`) `ready` финальной сцены снова `false`.
- **Шаг 6.** `finale {step: 6}` без `item`, реплика `finale-6` (три части — каталог фронтенда). `beer` → `not cursed`,
  `clink {pumpkin}` → `no target`; `clink {walker}` и `drink` с пивом в руке — как на шаге 5.
  - **Слово.** `word {text}` → `{ok:true, correct}` вызвавшему и событие `word {player, ok}` всем. Нормализация на
    сервере: нижний регистр, кириллица → латиница, только `a-z`; верно, если начинается с `rapir`, или
    `levenshtein(норма, 'rapira') ≤ 1` (решение backend: при 2 проходили «пира», «рапа», «рапорт»), или `metaphone(норма) == metaphone('rapira')`. Список форм и проверка — только в
    backend: фронтенд не содержит ни ответа, ни правил и не проверяет ввод сам (кроме пустой строки). `ok: true` → у
    фигурки `item: rapier`; `ok: false` → `zombie: true`.
  - **Зомби-игрок.** Его фигурку водит сервер: тикер раз в 2–4 с даёт ей обычный ход по лужайке — событие `move`, как
    любой ход, — так все видят одно и то же. Его RPC `move`, `clink`, `clink.auto`, `beer`, `drink`, `strike`, `word`,
    `cure` → `zombified`. Ушёл с поля и вернулся — остаётся зомби.
  - **Расколдовать.** `cure {walker}` — первый под локом фигурки: `zombie` снят, событие `cure {player, by}`; опоздавшие
    получают `{ok:true, cured:false}`. Расколдованный стоит, где стоял, и снова может молвить слово.
  - **Босс.** Первое `word` с `ok: true` будит FrankenPHP: `boss = {hp: max, max}`, `max = round((HELLOWIN_BOSS_HP_BASE +
    HELLOWIN_BOSS_HP_PER_PLAYER × n) × k)`, событие `boss {hp, max}` (по `boss` фронтенд надевает очки и включает фразы
    босса). `max` округляется вверх. `strike {}` → `strike {player, hp}`; на `hp = 0` — `owl boss-down {player}` и переход на шаг 7 (ключ
    `{round}:finale:7`); удары после нуля — `not now`.
- **Шаг 7.** `finale {step: 7, item: rapier}`, реплика `finale-7`: все фигурки — `zombie` снят, в руке рапира; новые
  фигурки появляются с рапирой. Зомби не запускаются, бродячие убираются событием `gone`; летуны — из `HELLOWIN_FLYER_KINDS_DAWN` с паузой
  `HELLOWIN_FLYER_INTERVAL_DAWN`, `shoot` как всегда.
- **Сброс** — как обычно, в бар: `cursed` и `boss` — `null`, `zombie` и рапиры уходят вместе с перестановкой фигурок.
- **Снова в бар.** На шаге 7 `scene.next {scene}` модератора — то же, что `reset`: событие `reset {again: true, item, walkers,
  bar}` (фигурки сразу на полу бара, `bar.roadrunner: true` — за стойкой RoadRunner), следом `owl bar-again`; ответ
  `{ok:true, round}`. Обычный сброс пульта — `bar.roadrunner: false`.

Примеры:

```json
{"type":"cursed","round":1,"drunk":7,"slain":3,"drinksTarget":20,"zombiesTarget":20}
{"type":"take","round":1,"player":{"id":"3f9c0a7d12b4e856"},"pumpkin":{"id":"pumpkin-7"},"ok":true}
{"type":"word","round":1,"player":{"id":"3f9c0a7d12b4e856","name":"Jack"},"ok":false}
{"type":"cure","round":1,"player":{"id":"3f9c0a7d12b4e856","name":"Jack"},"by":{"id":"8a01b2c3d4e5f607","name":"Ann"}}
{"type":"boss","round":1,"hp":90,"max":90}
{"type":"strike","round":1,"player":{"id":"8a01b2c3d4e5f607","name":"Ann"},"hp":89}
{"type":"finale","round":1,"step":7,"item":"rapier"}
```

Решения backend (были открытыми вопросами спеки):

1. **Чоканье в проклятом мире — как в баре:** `clink` и `clink.auto` на шагах 5–6 требуют пиво у себя (`no beer`) и у
   фигурки-цели (`no target` — без пива или зомби); по прибытии пиво должно быть у обоих. `clink {pumpkin}` — только на
   шаге 5 (иначе `no target`), засчитывается подошедшему. На рассвете (шаг 7) чоканья нет — `not cursed`. Порог
   `clink.auto` вне бара — тот же `walk.bar.clink_reach`.
2. **Предмет с шага 5** — свой у каждой фигурки, как в баре: вошедшие в шаг 5 получают пиво, пришедшие позже — пустые
   руки (пиво — из тыквы). Рапира не переживает уход с поля (вернувшийся молвит слово снова); зомби переживает: ушедший
   зомби записывается в `hellowin:zombies` раунда и возвращается зомби.
3. **Счётчики** `drunk` и `slain` считают на шагах 5 и 6 (событие `cursed` — на обоих), готовность — только на шаге 5.
   На входе в шаг 5 переключатель зомби включается сам: событие `zombies {on: true}` без реплики `zombies`. На шаге 7
   зомби не запускаются, переключатель не трогается.
4. **Зомби-игрок** бредёт каждые 2–4 с к случайной точке лужайки в 6–12 % от себя (путь — роутер `move`).
5. **Шаг 7 от последнего удара** — задача `TransitionFinale` в очереди переходов с ключом `{round}:finale:7` (метрики
   `kind="finale"`); `boss-down` уходит сразу с `strike`, `finale {step: 7}` и `finale-7` — когда задача выполнится.
6. **Сброс без бара** снимает с фигурок заклятие зомби (с баром это делает перестановка в бар).

## Кости

**Реализовано** на backend. Правила — [`scenario.md`](scenario.md), «Кости 6-6-6»; здесь — порядок сообщений. Режим — состояние
`dice` внутри шага финала 1.

- **Вход в шаг 1.** `finale {step: 1}` (`ready` финальной сцены снят), реплика `finale-1` (вторая часть объявляет кости) и
  `dice {on: true}`.
- **Бросок.** `roll {attempt}` → ответ `{ok:true, attempt, dice}` вызвавшему и событие `roll {player, attempt, dice, at}`
  всем. Кости — HMAC-SHA256(`HELLOWIN_DICE_SECRET`, `"{round}:{player}:{attempt}"`) → три числа 1–6 (выборка с отбрасыванием
  по байтам); секрет — env, по умолчанию выводится из `ENCRYPTER_KEY` с собственной солью, а без него первый бросок
  создаёт случайный и хранит в Valkey ([`engine.md`](engine.md), «Кости»). Результат вычисляется, а не хранится
  ради повтора: тот же ключ — тот же бросок. Сервер помнит последнюю попытку игрока в раунде (`hellowin:dice` →
  `{round, players: {id: {attempt, at}}, winner, owl, rolls}`); ключ идемпотентности — `{round}:roll:{player}:{attempt}`. Попытка = последняя — повтор с
  тем же результатом, без события и счёта; = последняя + 1 — новый бросок; иначе `bad attempt` с `last` — клиент берёт
  `last + 1` и бросает заново. Пауза между новыми бросками игрока — `HELLOWIN_DICE_COOLDOWN_MS` (`busy`), повтор ей не
  подчиняется.
- **6-6-6.** Первое — под локом костей: `dice.on = false`, `winner`, события `dice {on: false, winner}`, `ready {scene}`,
  реплика `dice-win {player, attempt}`. Следующие `roll` — `not now`.
- **Сова бросает.** `dice.owl {}` (пульт) → `roll {owl: true, attempt, dice, at}`; 3-я попытка — 6-6-6 и та же победа
  (`winner {owl: true, attempt: 3}`, реплика `dice-owl-win`). «Дайте я попробую!» перед каждым броском совы показывает
  фронтенд по событию.
- **Шаг 2** — `finale.step {step: 2}` модератора: без `ready` — `not ready`, с `force` — режим выключается
  (`dice {on: false}` без `winner`).
- **Сброс** — `dice` → `null`, попытки и победитель забываются.

```json
{"type":"dice","round":1,"on":true}
{"type":"roll","round":1,"player":{"id":"3f9c0a7d12b4e856","name":"Jack"},"attempt":4,"dice":[6,2,6],"at":1760900002000}
{"type":"roll","round":1,"owl":true,"attempt":2,"dice":[3,6,6],"at":1760900009000}
{"type":"dice","round":1,"on":false,"winner":{"player":{"id":"3f9c0a7d12b4e856","name":"Jack"},"attempt":7}}
```

## Топ рассвета

Форма событий и снимка — **реализовано** на backend; счёт за весь вечер (бриф №19 «Топ летунов глобальный») — **реализовано**
на backend. Правила — [`scenario.md`](scenario.md), «Рапира», «Топ-10 рассвета». Таблица шага 7 по сбитым летунам за вечер.

- **Счёт.** `shots` — сбитые игроком летуны за весь вечер, то есть `flyers` из записи игрока: доска ведётся на каждое
  засчитанное попадание **в любой сцене** и переживает сброс и `reset` с `again`. В доску пишется не `+1`, а абсолютное
  `flyers`, которое вернуло попадание (`max(старое, новое)`), поэтому порядок прихода и повторы не дают двойного счёта.
  Порядок — `shots` по убыванию, при равенстве — `at` (когда набран текущий счёт) по возрастанию, затем `id`. Анонимные
  попадания не считаются.
- **Событие** — только на шаге финала 7: первое — сразу при входе в шаг 7, с накопленным счётом; дальше на каждое
  засчитанное попадание сразу после `shot`, без склейки. `dawn {board}` — **весь** упорядоченный список
  `[{player: {id, name}, shots}]` (не больше `HELLOWIN_DAWN_BOARD`). Своё место клиент находит в списке сам (индекс + 1) —
  личных полей в ответе `shoot` и в `me` нет; игрок за пределами `HELLOWIN_DAWN_BOARD` своей строки не увидит.
- **Снимок** (и `state`) — `dawn {board}` на шаге 7, иначе `null` (счёт при этом копится).

```json
{"type":"dawn","round":1,"board":[{"player":{"id":"8a01b2c3d4e5f607","name":"Ann"},"shots":12},{"player":{"id":"3f9c0a7d12b4e856","name":"Jack"},"shots":9}]}
```

## Бродячие зомби

**Реализовано** на backend (решение пользователя). Правила — [`scenario.md`](scenario.md), «Рапира», «Зомби-воркеров
больше». На шагах финала 5–6 зомби не уходят, а бродят, пока их не убьют.

- **Появление.** Событие `flyer {flyer, kind: 'zombie', depth, from, points, launchedAt, wander: true}` — без `to`,
  `duration`, `expiresAt`; `from` — точка, где он встаёт (на лужайке или грядке, внутри зоны `walk`). Дальше его ведёт
  фронтенд, детерминированно от id и серверного времени; позиций сервер не знает и не проверяет. В индексе летунов он
  хранится без `expiresAt`, чистильщик тикера его не трогает; живые — в снимке (`flyers`).
- **Сколько.** На входе в шаг 5 — сразу `HELLOWIN_ZOMBIE_MIN` событий `flyer` (после `zombies`, до реплики). После
  смерти: живых меньше `HELLOWIN_ZOMBIE_MIN` — сразу новый (на ближайшем тике, ~200 мс); иначе раз в `HELLOWIN_ZOMBIE_INTERVAL`, пока живых меньше
  `max(HELLOWIN_ZOMBIE_MIN, HELLOWIN_ZOMBIE_PER_PLAYER × фигурки на поле)` (вживую; ушли игроки — лишних не убивают). Пауза
  останавливает появление, включая добор до минимума; снятие паузы — сразу добор. Переключатель `zombies` на шагах 5–6 не
  действует; обычные (уходящие) зомби здесь не запускаются, вне шагов 5–6 — как раньше.
- **Выстрел** — обычный `shoot {flyer}`: первый под локом, событие `shot`, `slain + 1` и `cursed`; срок (`expiresAt`) у
  бродячего не проверяется.
- **Уход.** На входе в шаг 7, при сбросе и `again` — событие `gone {flyers: [id, …]}`: все живые бродячие убраны без
  попадания (не в метрику «улетел»). Клиент убирает и тех, кого держит сам, на любом `reset`.

```json
{"type":"flyer","round":1,"flyer":"f-5e0c71a2","kind":"zombie","depth":1,"from":{"x":38.5,"y":81},"points":2,"launchedAt":1760900000000,"wander":true}
{"type":"gone","round":1,"flyers":["f-5e0c71a2","f-0b9d2c41"]}
```

## Действие останавливает ход

**В работе** на backend (бриф №20). Правила — [`scenario.md`](scenario.md), «Игроки», «Действие останавливает ход».

- **Какие действия.** `shoot` — любой принятый вызов, попадание и промах (не принят: `anonymous`, лимит); `click` —
  принятый клик по тыкве, костру или кругу (ошибки — `locked`, неизвестный элемент — не останавливают); `strike`,
  `drink`, `roll` — только успешный ответ (`busy`, `not clinked`, кулдаун и прочие отказы не останавливают). Не
  останавливают `move`, `clink`, `clink.auto`, `bar.take`, `beer` — они сами про ходьбу.
- **Когда.** Только если фигурка игрока ещё идёт (серверное время < `arrivesAt`); стоящую не трогаем и `move` не шлём.
  Зомби-игроков (их водит сервер) не останавливаем.
- **Что.** Сервер обрезает `Walk` в точке пути по серверным часам в момент принятия действия, пишет её в KV и шлёт всем
  `move {player, walk: {path: [точка], startedAt: at, arrivesAt: at}, stop}` — стоячий путь (как у стоящей фигурки) и
  `stop` — имя действия: `shoot`, `click`, `strike`, `drink`, `dice` (у `roll`). Остановка — это ход: отменяет
  недошедшее чоканье по клику, `bar.take` и `beer`, как `move` без `clink`. Ответ RPC не меняется.
- **Порядок.** `move` со `stop` уходит **раньше** события самого действия (`shot`, `click`, `strike`, `drink`, `roll`).
- **Фронтенд** замирает там, где фигурка нарисована, играет анимацию действия и потом обычной ходьбой доходит до точки
  сервера (см. [`frontend.md`](frontend.md), «Ходьба без скачков»).

```json
{"type":"move","round":1,"player":{"id":"3f9c0a7d12b4e856"},"walk":{"path":[{"x":52.4,"y":88.1}],"startedAt":1760900004200,"arrivesAt":1760900004200},"stop":"shoot"}
```
