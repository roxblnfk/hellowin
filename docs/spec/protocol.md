## Подключение

1. Браузер открывает WebSocket к Centrifugo: URL из `data-centrifugo-url`. Centrifugo опубликован на своём порту
   (RoadRunner не реверс-прокси), поэтому сервер отдаёт полный URL: `CENTRIFUGO_WS_URL` вида `:<порт>/путь` (по
   умолчанию `:8000/connection/websocket`) он достраивает схемой и хостом, по которым открыта страница, —
   `ws://localhost:8000/connection/websocket` для `http://localhost:8080/`, `wss://…` для https
   (`App\Application\Web\ServiceUrl`). Полный `ws(s)://` URL из env отдаётся как есть, путь — тоже, его фронт
   достраивает до `ws(s)://<host>`.
2. Centrifugo вызывает connect proxy → `ConnectService`. Сервер сам подписывает клиента на канал `hellowin`
   (server-side subscription): клиент **не** вызывает `subscribe`, а слушает `centrifuge.on('publication', …)`.
3. Клиентам запрещено публиковать в канал и подписываться на другие каналы.
4. В `data` подключения браузер передаёт `{playerSecret}` — секрет из `localStorage`
   (`new Centrifuge(url, {data: {playerSecret}})`). Сервер отвечает `user: publicId`; без секрета подключение анонимное.
   Подробности — [`players.md`](players.md).
5. Модератор дополнительно передаёт `moderatorSecret` (`{playerSecret, moderatorSecret}`) — секрет из `localStorage`,
   куда страница кладёт его из `?moderator=<секрет>` (и убирает параметр из адреса). Совпал с
   `HELLOWIN_MODERATOR_SECRET` — подключение получает роль модератора (backend хранит её в meta/info подключения);
   не совпал или в env пусто — обычное подключение, без ошибки. Роль сообщает `me` (`moderator: true`).

## RPC

Вызов: `centrifuge.rpc(method, data)`. Ответ: `{ok: true, …}` или `{ok: false, error: <code>}`.

Лимит: каждый вызов, кроме вызовов модератора, сначала берёт токен из ведра своего игрока (у подключения без игрока —
из ведра подключения) для группы метода: у `click`, `shoot` и `move` свои вёдра, остальные методы делят `other`.
Пустое ведро — `{ok: false, error: 'rate limited'}`, метод не вызывается; ведро пополняется само, повторять можно
сразу, но лишние вызовы снова получат отказ. Вкладки одного игрока делят его вёдра. Пороги — `HELLOWIN_RPC_RATE_*`
([`engine.md`](engine.md), «Лимиты запросов»): быстрый честный темп кликов в них укладывается. Клиент пишет отказ в
`console.warn`, как прочие ошибки RPC.

### Модератор

**Реализовано**. RPC пульта — только подключению модератора, остальным —

ломаной с постоянной скоростью; стоящая — `path` из одной точки. Где фигурка сейчас, клиент считает сам по `now`
(«Время летунов» — те же часы).

## События канала `hellowin`

Каждое событие несёт `type` и `round`. Событие с `round`, отличным от текущего у клиента, означает пропущенный сброс:
клиент запрашивает `state`.

| `type` | Поля | Когда |
|---|---|---|
| `click` | `element`, `emoji`, `clicks`, `threshold`, `stage`, `player?` | каждый принятый клик |
| `pumpkin` | `element`, `stage`, `player?` | элемент — тыква, костёр (`element: "bonfire"`) или магический круг (`element: "circle"`) — перешёл в новую стадию (ровно одно событие на переход) |
| `scene` | `scene`, `stageMax`, `bonfireStageMax` (последняя стадия костра в новой сцене), `circleStageMax` (последняя стадия магического круга в новой сцене: `HELLOWIN_CIRCLE_STAGES` в финальной, 0 до неё), `item` (предмет фигурок в новой сцене), `walkers?` — при выходе из бара (0 → 1): все фигурки (`[<Walker>]`), переставленные в зону прогулки дня — стоят (`path` из одной точки), с предметом дня | сцена сменилась (ровно одно событие на смену) |

| `drinks` | `drunk`, `target` | выпито за раунд и цель бара: после каждого `drink` и смены цели; шкала в HUD |
| `leave` | `player: {id}` | у игрока нет подключений дольше `HELLOWIN_WALK_LEAVE_AFTER` мс — фигурка уходит |

В баре (сцена 0) — один раз за раунд, когда выпито `drunk ≥ target` (после `drink` или понижения цели) или модератор дал отмашку (`bar.ready`); следом реплика `bar-intro`, без `scene-ready`. В финальной сцене на шаге 5 (**реализовано** на backend) — ещё раз, когда выполнены обе цели проклятого мира (`ready` снят на входе в шаг 5); следом реплика `cursed-ready`, без `scene-ready`. **Реализовано** на backend (кости): на шаге 1 — первое 6-6-6 (`ready` снят на входе в шаг 1); следом реплика `dice-win` или `dice-owl-win`, без `scene-ready` |
| `finale` | `step`, `item` — предмет в руке всех фигурок с этого шага (до шага 5 — предмет финальной сцены, с шага 5 — `beer`; `null` — пустые руки; клиент меняет его всем фигуркам, как по `scene`), `reveal?` (на шаге 2 следом — `move` каждой фигурке к краю поля: от центра грядки наружу, путь тем же роутером, что у RPC `move`) | шаг финала; на шаге 4 и дальше — `reveal` (см. «Снимок»). На шаге 6 (**реализовано** на backend) поля `item` нет (не `null`: клиент предметы фигурок не трогает) — предмет у каждого свой (пиво, пустые руки, рапира); на шаге 7 `item: rapier` у всех и `zombie` снят со всех фигурок |

Авто-реплики: `scene-ready`, `last-pumpkin`, `bonfire-open`, `bonfire-done`, `circle-done`, `scene-{N}` (после события `scene`; с баром — `scene-1` … `scene-4`, `scene-1` — выход из бара), `finale-{N}` (после `finale`, кроме шага 0 — на нём `scene-{N}` финальной сцены), `witch-down`, `bar-empty` (`take` с `ok: false`, не чаще раза в 20 с), `bar-intro` (бар готов), `bar-again` (после `reset` с `again: true`); **реализовано** на backend — `cursed-ready` (готовность шага 5), `finale-6`, `finale-7` (по общему правилу `finale-{N}`) и `boss-down` (`params.player` — нанёсший последний удар, перед `finale-7`); **реализовано** на backend — `dice-win` (`params: {player, attempt}`, первое 6-6-6) и `dice-owl-win` (третий бросок совы) |

`player` — `{id, name}` игрока, совершившего действие (`name` может быть `null`); у анонимных действий поля нет.
`emoji` сервер выбирает из набора emoji элемента — фронтенд
может использовать его или игнорировать.

RoadRunner на горизонте — **не летун** (решение пользователя от 2026-10-28, **реализовано** на фронтенде): во всех
сценах, кроме бара, его рисует клиент по серверным часам (`now` снимка и смещение), без событий; расписание пробежек —
[`frontend.md`](frontend.md), «RoadRunner на горизонте». Летуна `roadrunner` клиент не рисует, даже если он пришёл:
сервер его больше не запускает (**реализовано** на backend).

Особые летуны (**реализовано**): `witch` — редкий, очки `HELLOWIN_FLYER_RARE_POINTS`; `zombie` — наземная цель проклятого мира: путь по
лужайке (зона `walk`) от края грядки наружу, `depth` 1, `via` нет, очки `HELLOWIN_ZOMBIE_POINTS`, частота
`HELLOWIN_ZOMBIE_INTERVAL`. `firefly` (**реализовано**, проклятый мир, набор `HELLOWIN_FLYER_KINDS_CURSED`) —
летун: мелкий, путь как у обычных (край или куст, `via` по шансу дуги), `depth` 1 или 2 (`bush` — только куст этих
глубин), `wobble` как у мышей, но вялый (`amp` 2–5, `waves` 1,5–3), `duration` — по глубине, очки —
`HELLOWIN_FLYER_FIREFLY_POINTS` на любой глубине.
`fly` (**реализовано** в движке, летун бара — сцена 0 из `HELLOWIN_FLYER_KINDS`) — муха:
быстро нарезает круги по залу, потом **садится** на поверхность (стол, стойку, кружку) на короткое время — тогда в неё
легко попасть; взлетает, кружит и садится снова. Синусоиды (`wobble`) у мухи нет. Путь задаёт сервер: `stops:
[{x, y, sit}]` — точки посадки в процентах экрана (на столешницах и стойке из `walk.bar`, по кружкам — на стойке, и на местах посадки `walk.bar.perches`) и
сколько муха сидит, мс (`HELLOWIN_FLYER_FLY_SIT`, по умолчанию 900–1600); `from` — откуда влетает, `to` — куда
улетает (внутри `walk.bar.area` или за край зала). Между точками муха летит петлями: 1–2 быстрых круга радиусом 3–6 % —
форму петель фронт строит детерминированно от id летуна, так что у всех одинаково; на каждый перелёт —
`HELLOWIN_FLYER_FLY_LEG` мс (по умолчанию 900). `duration` = сумма перелётов и посадок; `depth` 1, очки —
`HELLOWIN_FLYER_FLY_POINTS` (1), сбивается обычным `shoot` в любой момент (первый под локом), сервер принимает выстрел
до `expiresAt` + 500 мс, как у всех. Посадок 2–3 (`HELLOWIN_FLYER_FLY_STOPS`), две подряд — на
разных поверхностях; «за край зала» — на 3 % за левой или правой стороной `walk.bar.area`. `via`, `perch` и `wobble` у
мухи не приходят.
`worm` (**реализовано**, обычный летун сцены 4 из `HELLOWIN_FLYER_KINDS`) — наземная
цель: путь по лужайке (зона `walk`) из точки в точку внутри зоны — выползает из земли и уходит в землю, без краёв
экрана; обе точки вне эллипса грядки, и прямая между ними грядку не пересекает; извилистость — `wobble` (малый:
`amp` 0,8–2, `waves` 3–6); `depth` 1, `via` и `bush` нет, длительность и очки — как у летунов глубины 1. Червяк не зависит
от проклятого мира — обычный запуск тикера, как у всех летунов.

Летун: `flyer` — id вида `f-` + 8 hex, его же клиент шлёт в `shoot`; `depth` — от 0 (дальний) до N−1, где N — длина
`HELLOWIN_FLYER_DURATION` (по умолчанию 3); `duration` — мс от `from` до `to`, отсчёт — от `launchedAt` (см. «Время летунов»); `kind` —
случайный из набора текущей сцены `HELLOWIN_FLYER_KINDS` (по умолчанию: бар (0) — `fly`; 1 — `duck`, `chicken`; 2 — никого; 3 — `bat`; финал — `worm`), в проклятом мире (шаг финала 5) — из `HELLOWIN_FLYER_KINDS_CURSED` (по умолчанию `worm`, `bat`, `firefly`), или редкий летун сцены `HELLOWIN_FLYER_RARE` (по умолчанию — никого, **реализовано** на backend; `witch` — с пульта). Сервер принимает выстрел до `expiresAt` + 500 мс. Летун без попадания исчезает сам:
отдельного события «улетел» нет. Промах мимо летуна на сервер не шлётся.

`startedAt` — серверное время запуска RoadRunner в мс (аптайм для финала: шаг 3 в HUD, шаг 4 в
разоблачении); клиент считает аптайм по часам с тем же смещением, что у летунов. Перезапуск воркеров его не сбрасывает,
перезапуск RoadRunner (контейнера `app`) — сбрасывает: это аптайм сервера, а не стека с Valkey ([`engine.md`](engine.md), «Аптайм»).

`ready` — сцена готова и ждёт модератора; `finale` — `null` вне финальной сцены, в ней `{step, reveal?}`;
`k` — множитель порогов (`threshold` в снимке и у элементов — уже умноженный), `online` — сколько
игроков с персонажами сейчас на поле (`walkers`, на момент снимка; живое число для пульта — `players` в `limits`); `presence` (**реализовано** на backend) — `{players, connections}`, как событие `presence`, без `type` и `round`: кто онлайн вообще, а не на поле; `paused` — пауза прогресса (см. «Пауза прогресса»); `limits` (бриф №22, **реализовано** на backend) — как событие `limits`, без `type` и `round`. `reveal` — числа вечера с начала раунда для экрана
разоблачения: `{calls, clicks, jobs, burned, shot, drinks, lastPumpkin: {id, name} | null}` — `calls` (решение пользователя от
2026-10-23, **реализовано** на backend) — все RPC-действия игроков и модератора за раунд, кроме `time`, `state`, `reveal`,
`me`, `chat.history`, — это
число показывает карточка «обработал RoadRunner»; принятые клики, выполненные задачи
перехода (переходы тыкв, костра и круга + переходы сцен), отброшенные повторы `burned` (**реализовано** на backend — вся
идемпотентность проекта, каждый повтор один раз: дубли задач сцены и финала, повторы бросков, повторный `reset`, повторы
пульта, а также сгоревшие клики: сверх порога и после готовности тыквы;
клики `locked` по костру и кругу не принимаются и сюда не входят), сбитые летуны (и зомби), выпитые в баре кружки за
раунд (`drinks`; раунд начинается в баре, так что это кружки вечера), кто добил последний элемент
последней готовой сцены — тыкву, в сцене с костром — костёр, в финальной — круг (если элемент добит анонимно, остаётся
игрок прежней готовой сцены; `null`, если такого нет — добивали анонимно или сцены переключали `force`, не дождавшись;
имя поля осталось `lastPumpkin`). Как считаются — [`engine.md`](engine.md), «Сюжет». Рапира (**реализовано** на backend):
`drinks` — одно число вечера: кружки бара плюс кружки проклятого мира; новые поля `slain` — зомби-воркеры, сбитые с шага 5
(`cursed.slain`), и `damage` — весь урон по FrankenPHP (принятые `strike`); до шага 5 оба 0. Свежие числа приносят снимок
и следующие события `finale` (6, 7). Кости (**реализовано** на backend): `rolls` — броски костей за раунд (новые `roll` игроков, без бросков совы и повторов); как всё `reveal` — в событиях `finale` с шага 4 и в снимке (`hellowin:dice`, `rolls`).

Сброс (`reset`) возвращает и сюжет: `ready` — `false`, `finale` — `null`, `paused` — `false` (сброс и `again` снимают паузу,
бриф №22); `k` сохраняется — он про зал, а не про сюжет; ручные надбавки к лимитам (бриф №22) снимаются. Клиент применяет это сам по событию `reset`, без RPC. С баром
сброс ведёт в бар: `ready` — `false` (бар ждёт своей цели или отмашки), `bar` и `walkers` — из события `reset`; цель бара
(`target`) — по формуле «Лимиты и баланс» без надбавки, `drunk` начинается с 0.

`cursed` и `boss` (**реализовано** на backend, см. «Рапира»): `cursed` — `{drunk, slain, drinksTarget, zombiesTarget}` на шагах
финала 5+, иначе `null`; `boss` — `{hp, max}` с шага 6 после пробуждения FrankenPHP (на шаге 7 — `hp: 0`; если он так и
не проснулся — `null`), иначе `null`. Сброс
обнуляет оба (`null`).

`top` (**реализовано** на backend, см. «Топ стрелков»; было `dawn` — только на шаге 7) — `{board}` всегда, во всех сценах.

`auto` (**реализовано** на backend, см. «Автопилот») — `{on, next}`, как событие `auto`, без `type` и `round`; всегда, сброс и
`again` его не трогают. Сервер без автопилота поля не шлёт — пульт тогда прячет переключатель.

`flyers` (**реализовано** на backend, см. «Бродячие зомби») — живые бродячие зомби: список событий `flyer` с `wander: true` (без
`type` и `round`); на шагах 5–6, иначе `[]`. Обычные летуны в снимок не входят, как раньше.

`dice` (**реализовано** на backend, см. «Кости») — `{on, winner?, owl}` на шаге финала 1 и дальше (`owl` — сколько раз сова уже бросила, 0–3; бриф №22, **реализовано** на backend): `on` — режим костей включён, `winner` —
`{player: {id, name}, attempt}` или `{owl: true, attempt: 3}` после первого 6-6-6 (или нет поля, если шаг 2 взят `force`);
вне финальной сцены и на шаге 0 — `null`. Свою последнюю попытку клиент в снимке не получает: начинает с 1 и
выравнивается по `last` из ответа `bad attempt`. Сброс — `null`.

`bar` — стойка бара: `{mugs, max, pouring: {since, until, rumor?} | null, drunk, target}` (`drunk` — выпито за раунд, `target` — цель бара; `rumor` — см. событие `pour`) — сколько налитых кружек стоит (0…
`max` — число фигурок на поле, не меньше 1 и не больше `HELLOWIN_BAR_MUGS`; `max` приходит в снимке, в событии `mugs` и в `reset.bar`; игроки ушли — налитые кружки остаются, и `mugs` бывает больше `max`, пока их не разберут) и до какого серверного момента сова наливает следующую (`null` — не наливает: полно или сцена не
бар). Поле есть в снимке всегда; вне бара — `{mugs: 0, max, pouring: null, drunk, target}`: счёт и цель видны и после бара.
`roadrunner` (**реализовано** на backend) — `true`, пока за стойкой стоит RoadRunner (после «Снова в бар» — `reset` с `again: true`; снимает обычный сброс модератора, при котором `reset.bar.roadrunner` — `false`); приходит в снимке и в `reset.bar`. Место — `walk.bar.roadrunner {x, y}` (`y` — задний край стойки, как у совы), конфиг в разметке, не в снимке. Тосты RoadRunner фронтенд выбирает сам по серверному времени, сервер их не шлёт.

`bush` — id куста, из которого взлетает летун (тогда `from` — его точка, а `depth` летуна — `depth` куста, см.
[`scenario.md`](scenario.md), «Летуны»; `depth` в `bushes` снимка — **реализовано**); `wobble` (только у `kind: bat`, `worm` и `firefly`, у остальных поля нет) — кривая поверх базовой траектории: смещение поперёк пути
`amp · sin(2π · waves · t)` (`amp` — проценты экрана, `t` — доля полёта 0…1; `waves` — дробное число полных колебаний
за полёт); без поля — без колебаний; петли — `waves` с большой `amp` или отдельное поле, если понадобится (согласовать).
Диапазоны — [`engine.md`](engine.md), «Летуны». `via` — контрольная точка дуги
(квадратичная кривая), без неё полёт прямой. `x`/`y` — проценты экрана (на узких экранах фронтенд растягивает раскладку тыкв по x от центра — `spreadX`
в `public/js/layout.js`; и у тыкв, и в траекториях летунов: `from`/`to` могут выходить за 0–100 — летун влетает из-за края); `size` — `s` / `m` / `l` (у тыкв); `reachable` — тыква досягаема с лужайки для чоканья (у края грядки, **реализовано**; считает сервер из раскладки: тыква не дальше `walk.reach` процентов экрана от зоны прогулки; у каждой тыквы — `true` или `false`, у костра и круга поля нет); у магического круга (`type: circle`, id `circle`, без `size`) — как у костра:
свои `threshold` (лимит `circle`, см. «Лимиты и баланс») и `stageMax` (`HELLOWIN_CIRCLE_STAGES` в финальной сцене, 0 до неё),
кликабелен в финальной сцене на шаге 0, пока `stage` ниже `stageMax` (новую сцена приносит в `scene.circleStageMax`),
готовность финальной сцены — круг на `stageMax`, шаг финала 1 без готовности —
только `force`; у костра (`type: bonfire`, id `bonfire`, без `size`) — свои `threshold`
(лимит `bonfire`) и `stageMax` (последняя стадия костра в текущей сцене, из
`HELLOWIN_BONFIRE_STAGE_MAX`; новую сцена приносит в `scene.bonfireStageMax`), кликабелен, когда все тыквы на
`stageMax` сцены, а `stage` костра ниже его `stageMax` — клиент вычисляет это сам по снимку и событиям `pumpkin`;
`threshold` в событии `click` по костру — тоже его порог; `sceneStages` — номер финальной сцены (длина списка
`HELLOWIN_SCENE_STAGE_MAX`); `stageMax` — последняя стадия тыквы в текущей сцене, в финальной — та же, что в сцене
перед ней (см. [`scenario.md`](scenario.md)). `clicks` — клики с момента перехода тыквы в текущую стадию. `walkers` — фигурки игроков на поле
(`Walker`, см. «RPC»). Страница
`GET /` отдаёт снимок в шаблон `home` (переменные — см. [`frontend.md`](frontend.md)) вместе с `centrifugoUrl` и `chatMax`
(`HELLOWIN_CHAT_MAX`, длина сообщения чата, см. «Чат»).

### Время летунов

`launchedAt` и `expiresAt` в событии `flyer` — серверное Unix-время в мс; `now` в снимке — серверное время его сборки.
Клиент считает смещение часов `offset = now − Date.now()` (по снимку страницы или RPC `state`) и **не рисует летуна**,
если `Date.now() + offset >= expiresAt`; уже нарисованного убирает к `expiresAt`. Так свёрнутая вкладка, получившая
пачку отложенных публикаций при разворачивании, не выпускает птиц, которых уже нельзя сбить (сервер принимает
выстрел не позже `expiresAt` + 500 мс). Если смещение неизвестно — считать его 0.

## Слон

Решение пользователя от 2026-10-28; **реализовано** на backend, фронтенде и в лаборатории. Кулдаун пука вместо
одного пука на слона и низкая полоса высоты (решение пользователя от 2026-10-28) — **реализовано** на backend,
фронтенде и в лаборатории. Сюжет — [`scenario.md`](scenario.md), «Летуны», «Слон».

- **Летун.** Обычное событие `flyer` с `kind: elephant`, `depth: 0`, `points: 0`, без `via`, `bush` и `wobble`;
  `from` и `to` — по разные стороны экрана (`x` за краями, например −10 и 110), `y` — в небе над горизонтом:
  обычная полоса — 8–20 %, низкая — 22–26 % (слон с плакатом идёт над холмами у горизонта, выше плетня). Низкую
  полосу сервер выбирает с вероятностью `HELLOWIN_ELEPHANT_LOW_CHANCE` (по умолчанию 0.33) на полёт — и по таймеру,
  и с пульта; `from.y` и `to.y` — внутри одной полосы. Клиент рисует по `y` с сервера и всё равно держит слона в
  небе (не ниже горизонта − 14 арт-px). `from.x`/`to.x` задают только направление: клиент растягивает путь
  так, чтобы слон с плакатом целиком вошёл из-за одного края и ушёл за другой за `duration` (плакат длинный, на
  телефоне — больше половины ширины). `duration` — `HELLOWIN_ELEPHANT_DURATION` (по умолчанию 26000 мс), `expiresAt` —
  как у всех.
- **Запуск.** Свой таймер тикера, не редкий шанс: в любой сцене, кроме бара (в финале — на всех шагах), раз в
  `HELLOWIN_ELEPHANT_INTERVAL` — пауза между слонами, мин и макс в мс (по умолчанию `180000,360000`), случайно в
  этих границах; отсчёт — от прошлого слона (и от ручного тоже). Пока слон летит, второй не запускается. Пауза
  прогресса таймер не держит. Модератор — `flyer.special {kind: elephant}` (кнопка «Слон» на пульте), даже на паузе.
- **Выстрел.** `shoot {flyer}` по слону — всегда `{ok:true, hit:false}`: сбить нельзя, очков нет, `shot` нет.
  Принятый выстрел по живому слону (до `expiresAt` + 500 мс, под локом летуна) публикует `fart {flyer, player?: {id},
  at}`, если с прошлого пука этого слона прошло не меньше `HELLOWIN_ELEPHANT_FART_COOLDOWN_MS` (по умолчанию 1000;
  время прошлого пука — в KV летуна); иначе — просто `hit:false`, без событий. Только за **первым** пуком слона
  следует реплика `owl {line: fart-time}` (в счёт речи совы автопилота, как прочие) — сова не тараторит. Пустая
  кружка в руке летит как всегда (`throw` раньше `fart`).
- **Клиент.** Рисует каждый пук от его `at` по серверным часам: слон тужится, сзади вырывается зелёный дым и
  собирается в облако Fart Time, оно поднимается и тает за ~3,8 с; слон летит дальше. Пуки одного слона — каждый
  со своим кадром натуги, клубами и облаком; повтор того же `at` — один пук. Облаков у слона одновременно не больше
  четырёх: при переполнении самое старое тает быстрее. Звук — на каждый `fart` не старше 1,5 с; облако рисуется,
  пока не растаяло. Фигурка стрелка стреляет в слона, если событие свежее.
- **Метрика** — `hellowin_farts_total` (counter): сколько раз слоны выпустили газ (каждый `fart`); запущенные слоны — в общей
  `hellowin_flyers_launched_total{depth}`.

```json
{"type":"flyer","round":3,"flyer":"f-0e1ef4a7","kind":"elephant","depth":0,"from":{"x":-10,"y":12},"to":{"x":110,"y":14},"duration":26000,"points":0,"launchedAt":1760900000000,"expiresAt":1760900026000}
{"type":"fart","round":3,"flyer":"f-0e1ef4a7","player":{"id":"3f9c0a7d12b4e856"},"at":1760900011350}
{"type":"owl","round":3,"line":"fart-time"}
```

## Пробежка RoadRunner по кнопке

Решение пользователя от 2026-10-28; **реализовано** на backend, фронтенде и в лаборатории. Сюжет —
[`scenario.md`](scenario.md), «RoadRunner на горизонте — не летун»; рисование — [`frontend.md`](frontend.md),
«RoadRunner на горизонте».

- **RPC модератора** `runner {}` → `{ok:true, at, ltr}`: `at` — серверное время сейчас, мс, `ltr` — случайно. Где
  RoadRunner бегает по горизонту: все сцены, кроме бара; в финале — шаги 0–2 и 5–7 (на 3–4 у него своя постановка).
  Иначе — `not here`. Пока прошлая ручная пробежка идёт (`now < at + 6500`, 6500 — `HORIZON.runMs` в
  `public/js/pixel/runner-horizon.js`), — `busy`. Пауза прогресса не мешает; игроку — `forbidden`.
- **Событие** `runner {at, ltr}` всем (с `round`, как все). Клиент рисует пробежку от `at` по серверным часам: та же
  длительность и вид, что у плановой, без остановки и мипа; плановая, которая пересекается с ней во времени, прячется.
  Старое событие ничего не рисует: пробежка кончилась.
- **Снимок** (и `state`) — `runner: {at, ltr} | null`, последняя ручная пробежка раунда: страница, открытая посреди
  неё, подхватывает ту же фазу; закончившуюся клиент не рисует, поэтому сервер может отдавать её и после конца.
  `reset` (и `again`) её чистит. Страница `GET /` — атрибут `data-runner` у `#app` (JSON, как `data-flyers`).
- Клик модератора по бегущему — обычный `meep {}`.

```json
{"type":"runner","round":3,"at":1760900011350,"ltr":false}
```

## Бар

**Реализовано** на backend. Правила — [`scenario.md`](scenario.md), «Сцена 0 — «Бар»»; механизм — [`engine.md`](engine.md), «Бар»; здесь — порядок сообщений.

- **Геометрия** — `walk.bar` в `app/config/hellowin.php` (раскладку правит фронтенд, как `walk.area` и `walk.patch`):
  `area {x1, y1, x2, y2}` — пол зала; `obstacles` — список препятствий: столы — эллипсы `{cx, cy, rx, ry}`, стойка —
  прямоугольник `{x1, y1, x2, y2}`; `counter {x1, x2, y}` — место у стойки, отрезок, куда встают за кружкой; `spawn
  {y1, y2}` — полоса появления (новых фигурок, если нет `door`, и фигурок, переставленных сбросом); `clink_reach` — до скольких процентов экрана между фигурками сервер
  признаёт `clink.auto`; `door {x, y}` (**реализовано**) — порог входной двери на линии задней стены и пола (левый угол
  зала), `roadrunner {x, y}` — место RoadRunner за стойкой (`y` — задний край стойки, как у совы; пример — `{x: 74, y: 46}`), и `door_in` — на сколько процентов экрана вниз (+y) новая фигурка входит от порога (по умолчанию 6); `perches` (**реализовано**) — места посадки мух: список `{x1, x2, y, name}` — полоса x от `x1` до `x2` на высоте `y` (точка, если `x1 == x2`), `y` — верх поверхности, на которой муха стоит: `beam` (балка), `lintel` (притолока двери), `mantel` (полка камина), `shelf-top` и `shelf` (полки над стойкой), `shield-1` … `shield-N` (кромки щитов), `barrels` (крышки бочек); каждая — своя поверхность для правила «две посадки подряд — на разных». Отдаётся клиенту в разметке (см. [`frontend.md`](frontend.md)), снимок её не несёт: это
  конфиг, а не состояние. В баре `move`, `clink` и `bar.take` строят путь по зоне бара: цель приводится на пол вне
  препятствий, путь обходит препятствия.
- **Розлив.** Пока сцена — бар, кружек меньше `max` (число фигурок на поле, 1…`HELLOWIN_BAR_MUGS`) и никто не наливается, сервер начинает розлив:
  `pouring = {since: now, until: now + HELLOWIN_BAR_POUR_MS}`, событие `pour {since, until, batch}`. Когда `until` наступил — `mugs + batch`,
  `pouring = null`, событие `mugs {mugs}`, и если места ещё есть — сразу следующий `pour`. Ведёт тикер (раз в 200 мс),
  точность — до тика. `batch` — партия: сколько кружек сова ставит за один розлив (решение пользователя от 2026-10-28,
  **реализовано** на backend): по свободным местам на стойке в начале розлива, `free = max − mugs`,
  `batch = min(free, ceil(free / HELLOWIN_BAR_POUR_PER))`, `HELLOWIN_BAR_POUR_PER` по умолчанию 10 — до 10 свободных мест
  по одной, 11–20 — по две, 21–30 — по три. `pour` несёт `batch`, клиент показывает его у крана («×3», при 1 — ничего),
  без поля — 1. Чтобы мест хватало большому залу, `HELLOWIN_BAR_MUGS` по умолчанию 60 (было 12). Клиент рисует розлив по фазе между `since` и `until` (узнавший посреди — с той же фазы, что у всех), а кружку на
  стойке ставит по событию `mugs`; `pouring` с прошедшим `until` в снимке — кружка вот-вот встанет, розлив не рисуется.
- **Взять.** `bar.take` → ответ с `walk` и событие `move` всем → по прибытии (тикер, как у чоканья по клику) событие
  `take`: `ok: true` несёт оставшиеся `mugs` (отдельного `mugs` при взятии нет), у фигурки `item: beer`; `ok: false` —
  следом реплика `owl` `bar-empty` (не чаще раза в 20 с). Если стойка была полной, следом пойдёт `pour`.
- **Чокнуться.** По клику — `clink {walker}` как в проклятом мире (`move` с `clink`, затем `clink`), засчитывает обоим.
  Автоматически — браузер каждого участника сам шлёт `clink.auto {walker: партнёр}` в момент удара, засчитывается только
  ему; событий нет. Засчитанное чоканье — флаг кружки в записи фигурки на сервере; `take` начинает новую кружку без
  флага.
- **Выпить.** `drink` → `{ok:true}` и событие `drink {player}` всем; `not clinked` — ответ только вызвавшему, подсказку
  «Сначала чокнись, потом пей!» показывает его клиент, ничего не рассылается.
  `busy` — чоканье этой кружкой ещё играет (до `clinkedUntil`) или глоток предыдущей ещё идёт
  (`HELLOWIN_DRINK_MS`); тоже только вызвавшему, клиент молчит. Повторный `clink`/`clink.auto` той же кружкой — `{ok:true}`
  без изменений.
- **Выход на грядку.** `scene.next` из бара: событие `scene {scene: 1, item: pistol, walkers}` — кружки на стойке и в
  руках сгорают (`bar` → `{mugs: 0, pouring: null}`), недошедшие `bar.take` и чоканья отменяются без событий; клиент
  заменяет фигурки списком `walkers` без ходьбы (другая локация), следом — реплика `scene-1`.
- **Сброс** ведёт в бар: событие `reset` несёт `walkers` на полу бара с пустыми руками и `bar` с полной стойкой.

Решения backend (были открытыми вопросами спеки):

1. Перестановка фигурок при смене локации — полный список `walkers` в событиях `scene` (0 → 1) и `reset`, а не `move`
   нулевой длины на каждую. Новая точка — ближайшая точка новой зоны к прежней позиции (координаты бара и лужайки —
   проценты одного экрана); лок лужайки занят — событие уходит без `walkers`.
2. Ключи `walk.bar.{area, obstacles, counter, spawn, clink_reach}` и формы препятствий — как предложено. Обход — граф
   видимости по точкам вокруг каждого препятствия, кратчайший путь ([`engine.md`](engine.md), «Фигурки на поле»).
   Стойка в конфиге заходит за верх и правый край пола: за стойкой нет полоски пола, куда можно было бы встать.
3. `pour` и `pouring` несут `since` и `until` (и `rumor`, если сова приговаривает).
4. Ошибка `clink` вне проклятого мира и бара — `not cursed`; в баре без пива — `no beer` (после `not cursed`).
5. `barLayout` — массив `walk.bar` в шаблоне `home` (`HomeController`); без `walk.bar` в конфиге — `null`.
6. `drinks` — в записи игрока ([`players.md`](players.md)); выпитые за раунд — ключ `hellowin:drinks`
   (`{round, count}`), из него `drunk` и `reveal.drinks` ([`engine.md`](engine.md), «Бар»).
7. Бар — сцена 0, только если первый элемент `HELLOWIN_SCENE_STAGE_MAX` равен 0; без него сцена 0 — день, бара нет
   (старый формат списка продолжает работать).

## Рапира

**Реализовано** на backend. Правила — [`scenario.md`](scenario.md), «Рапира»; здесь — порядок сообщений. Шаги финала 5–7: цель
проклятого мира, сова с рапирой и босс, рассвет.

- **Шаг 5.** `finale {step: 5, item: beer}`, следом `cursed {drunk: 0, slain: 0, drinksTarget, zombiesTarget}` и
  сразу `HELLOWIN_ZOMBIE_MIN` событий `flyer` с `wander` (бродячие зомби, см. «Бродячие зомби»). Цели — лимиты `drinks` и
  `zombies` формулы «Лимиты и баланс» + надбавка модератора, не ниже 1; n меняется — новое `cursed`. Надбавка живёт до
  конца раунда. (Событие `zombies` и переключатель пульта удалены — бриф №22.)
  - **Пиво из тыквы.** `beer {pumpkin}` → ответ с `walk` и `move` всем → по прибытии (тикер, как у `bar.take`)
    `take {player, pumpkin, ok: true}`, у фигурки `item: beer`. `take` несёт `until` — прибытие +
    `HELLOWIN_BEER_HANDOVER_MS`; пиво в руке (и `drink`) — с `until`, до него фронтенд играет передачу.
  - **Точка у кружки** (**реализовано** на backend, решение пользователя от 2026-10-28; фронтенд и лаборатория — по
    новому правилу). Куда встаёт фигурка для `beer {pumpkin}` и `clink {pumpkin}`: сбоку от тыквы, со стороны её
    кружки, на расстоянии вытянутой руки от кружки — не внутри тыквы и не за ней. Тыквы с прыжка на закате нарисованы
    дальше от корня, чем их точки конфига, поэтому точка считается от тыквы «после прыжка»:
    `S = (ROOT + (p − ROOT) × walk.pumpkin_stand.out) + (side × walk.pumpkin_stand.gap[size], 0)`, где `p` — x, y
    тыквы из конфига, `ROOT` — `walk.patch.cx`, `walk.patch.cy`, `out` = 1.18, `gap` = `{l: 10, m: 9, s: 8}` (проценты
    экрана), `side` — сторона кружки (правило выше); затем `S` приводится в зону лужайки (`clamp`: ближайшая точка).
    Значения — те же, что `PUMPKIN_STAND` в `public/js/layout.js`: фронтенд узнаёт «стоит у тыквы» по концу пути не
    дальше `near` (2.5) от `S` и рисует фигурку у нарисованной кружки (на любом экране тыквы стоят по-разному).
    Две фигурки у одной тыквы получают одну и ту же точку, как и раньше.
  - **Чокнуться и выпить** — как в баре: `clink {walker}` и `clink {pumpkin}` засчитывают чоканье кружке (с тыквой —
    подошедшему), автоматическое — браузеры участников шлют `clink.auto` (на шаге 5+ тоже, не только в баре); `drink` →
    `drink {player}`, `drinks + 1` игроку, `drunk + 1` проклятого мира и событие `cursed`. Ошибки `drink`, `clink.auto`
    вне бара и проклятого мира — `not bar` (имя кода прежнее). Пить без чоканья можно, только если игрок на поле один.
  - **Зомби.** Каждый `shot` по `kind: zombie` на шаге 5+ — `slain + 1` и событие `cursed`. Вид смерти сервер не шлёт:
    фронтенд выбирает его по id летуна (см. [`frontend.md`](frontend.md), «Рапира»).
  - **Готово** — `drunk ≥ drinksTarget` и `slain ≥ zombiesTarget` (после `drink`, `shot` или понижения цели): `ready`
    финальной сцены — `true`, событие `ready {scene: <финальная>}` (один раз за раунд), следом реплика `cursed-ready`.
    Сам шаг не меняется: шаг 6 — `finale.step {step: 6}` модератора; без готовности — `not ready`, с `force` — можно.
    На входе в шаг 5 (`finale {step: 5}`) `ready` финальной сцены снова `false`.
- **Шаг 6.** `finale {step: 6}` без `item`, реплика `finale-6` (три части — каталог фронтенда). `beer` → `not cursed`,
  `clink {pumpkin}` → `no target`; `clink {walker}` и `drink` с пивом в руке — как на шаге 5.
  - **Слово.** `word {text}` → `{ok:true, correct}` вызвавшему и событие `word {player, ok}` всем. Нормализация на
    сервере: нижний регистр, кириллица → латиница, только `a-z`; верно, если начинается с `rapir`, или
    `levenshtein(норма, 'rapira') ≤ 1` (решение backend: при 2 проходили «пира», «рапа», «рапорт»), или `metaphone(норма) == metaphone('rapira')`. Список форм и проверка — только в
    backend: фронтенд не содержит ни ответа, ни правил и не проверяет ввод сам (кроме пустой строки). `ok: true` → у
    фигурки `item: rapier`; `ok: false` → `zombie: true`.
  - **Зомби-игрок.** Его фигурку водит сервер: тикер раз в 2–4 с даёт ей обычный ход по лужайке — событие `move`, как
    любой ход, — так все видят одно и то же. Его RPC `move`, `clink`, `clink.auto`, `beer`, `drink`, `strike`, `word`,
    `cure` → `zombified`. Ушёл с поля и вернулся — остаётся зомби.
  - **Расколдовать.** `cure {walker}` — первый под локом фигурки: `zombie` снят, событие `cure {player, by}`; опоздавшие
    получают `{ok:true, cured:false}`. Расколдованный стоит, где стоял, и снова может молвить слово.
  - **Босс.** Первое `word` с `ok: true` будит FrankenPHP: `boss = {hp: max, max}`, `max` — лимит `boss` формулы «Лимиты и баланс» (бриф №22) + надбавка модератора, событие `boss {hp, max}` (по `boss` фронтенд надевает очки и включает фразы
    босса). `max` округляется вверх. `strike {}` → `strike {player, hp}`; на `hp = 0` — `owl boss-down {player}` и переход на шаг 7 (ключ
    `{round}:finale:7`); удары после нуля — `not now`.
- **Шаг 7.** `finale {step: 7, item: rapier}`, реплика `finale-7`: все фигурки — `zombie` снят, в руке рапира; новые
  фигурки появляются с рапирой. Зомби не запускаются, бродячие убираются событием `gone`; летуны — из `HELLOWIN_FLYER_KINDS_DAWN` с паузой
  `HELLOWIN_FLYER_INTERVAL_DAWN`, `shoot` как всегда.
- **Сброс** — как обычно, в бар: `cursed` и `boss` — `null`, `zombie` и рапиры уходят вместе с перестановкой фигурок.
- **Снова в бар.** На шаге 7 `scene.next {scene}` модератора — то же, что `reset`: событие `reset {again: true, item, walkers,
  bar}` (фигурки сразу на полу бара, `bar.roadrunner: true` — за стойкой RoadRunner), следом `owl bar-again`; ответ
  `{ok:true, round}`. Обычный сброс пульта — `bar.roadrunner: false`.

Решения backend (были открытыми вопросами спеки):

1. **Чоканье в проклятом мире — как в баре:** `clink` и `clink.auto` на шагах 5–6 требуют пиво у себя (`no beer`) и у
   фигурки-цели (`no target` — без пива или зомби); по прибытии пиво должно быть у обоих. `clink {pumpkin}` — только на
   шаге 5 (иначе `no target`), засчитывается подошедшему. На рассвете (шаг 7) чоканья нет — `not cursed`. Порог
   `clink.auto` вне бара — тот же `walk.bar.clink_reach`.
2. **Предмет с шага 5** — свой у каждой фигурки, как в баре: вошедшие в шаг 5 получают пиво, пришедшие позже — пустые
   руки (пиво — из тыквы). Рапира не переживает уход с поля (вернувшийся молвит слово снова); зомби переживает: ушедший
   зомби записывается в `hellowin:zombies` раунда и возвращается зомби.
3. **Счётчики** `drunk` и `slain` считают на шагах 5 и 6 (событие `cursed` — на обоих), готовность — только на шаге 5.
   На шаге 7 зомби не запускаются.
4. **Зомби-игрок** бредёт каждые 2–4 с к случайной точке лужайки в 6–12 % от себя (путь — роутер `move`).
5. **Шаг 7 от последнего удара** — задача `TransitionFinale` в очереди переходов с ключом `{round}:finale:7` (метрики
   `kind="finale"`); `boss-down` уходит сразу с `strike`, `finale {step: 7}` и `finale-7` — когда задача выполнится.
6. **Сброс без бара** снимает с фигурок заклятие зомби (с баром это делает перестановка в бар).

## Кости

**Реализовано** на backend. Правила — [`scenario.md`](scenario.md), «Кости 6-6-6»; здесь — порядок сообщений. Режим — состояние
`dice` внутри шага финала 1.

- **Вход в шаг 1.** `finale {step: 1}` (`ready` финальной сцены снят), реплика `finale-1` (вторая часть объявляет кости) и
  `dice {on: true}`.
- **Бросок.** `roll {attempt}` → ответ `{ok:true, attempt, dice}` вызвавшему и событие `roll {player, attempt, dice, at}`
  всем. Кости — настоящий случайный выбор (CSPRNG, как `random_int`): три числа 1–6, предсказать их не может никто, и
  сервер тоже. Бросок тянется один раз: ответ попытки хранится в хранилище идемпотентности по ключу
  `{round}:roll:{player}:{attempt}` `HELLOWIN_DICE_IDEMPOTENCY_TTL` с, а грани последней попытки игрока записаны в
  `hellowin:dice` вместе с её номером (`{round, players: {id: {attempt, at, dice}}, winner, owl, rolls}`) — повтор получает
  тот же ответ, перебросить повтором нельзя ([`engine.md`](engine.md), «Кости»). Попытка = последняя — повтор с
  тем же результатом, без события и счёта; = последняя + 1 — новый бросок; иначе `bad attempt` с `last` — клиент берёт
  `last + 1` и бросает заново. Пауза между новыми бросками игрока — `HELLOWIN_DICE_COOLDOWN_MS` (`busy`), повтор ей не
  подчиняется.
- **6-6-6.** Первое — под локом костей: `dice.on = false`, `winner`, события `dice {on: false, winner}`, `ready {scene}`,
  реплика `dice-win {player, attempt}`. Следующие `roll` — `not now`.
- **Сова бросает.** `dice.owl {}` (пульт) → `roll {owl: true, attempt, dice, at}`; 3-я попытка — 6-6-6 и та же победа
  (`winner {owl: true, attempt: 3}`, реплика `dice-owl-win`). «Дайте я попробую!» перед каждым броском совы показывает
  фронтенд по событию.
- **Шаг 2** — `finale.step {step: 2}` модератора: без `ready` — `not ready`, с `force` — режим выключается
  (`dice {on: false}` без `winner`).
- **Сброс** — `dice` → `null`, попытки и победитель забываются.

```json
{"type":"dice","round":1,"on":true}
{"type":"roll","round":1,"player":{"id":"3f9c0a7d12b4e856","name":"Jack"},"attempt":4,"dice":[6,2,6],"at":1760900002000}
{"type":"roll","round":1,"owl":true,"attempt":2,"dice":[3,6,6],"at":1760900009000}
{"type":"dice","round":1,"on":false,"winner":{"player":{"id":"3f9c0a7d12b4e856","name":"Jack"},"attempt":7}}
```

## Топ стрелков

**Реализовано** на backend (правки пользователя к №19: очки вместо сбитых, таблица всегда; было — событие `dawn` со
`shots` только на шаге 7). Правила — [`scenario.md`](scenario.md), «Рапира», «Топ стрелков вечера».

- **Счёт.** `points` — очки игрока за сбитых летунов за весь вечер, то есть `points` из записи игрока (по глубине, у
  редких, мух, светлячков, зомби — свои; бегун — 0): доска ведётся на каждое засчитанное попадание **в любой сцене** и
  переживает сброс и `reset` с `again`. В доску пишется абсолютное `points`, которое вернуло попадание (`max(старое,
  новое)`), поэтому порядок прихода и повторы не дают двойного счёта; игрок с 0 очков (только бегун) в доску не попадает.
  Порядок — `points` по убыванию, при равенстве — `at` (когда набран текущий счёт) по возрастанию, затем `id`. Анонимные
  попадания не считаются.
- **Событие** `top {board}` — в любой сцене: тикер публикует доску, когда она изменилась, не чаще `HELLOWIN_TOP_INTERVAL`
  мс (склейка: полный список каждому клиенту на каждое попадание — слишком много при полном зале). Отдельной публикации на
  входе в рассвет нет: доска и так в снимке и в последнем событии. `board` — **весь** упорядоченный список
  `[{player: {id, name}, points}]` (не больше `HELLOWIN_TOP_BOARD`). Своё место клиент находит в списке сам (индекс + 1) —
  личных полей в ответе `shoot` и в `me` нет; игрок за пределами `HELLOWIN_TOP_BOARD` своей строки не увидит.
- **Снимок** (и `state`) — `top {board}` всегда, во всех сценах; `reset` и `again` его не чистят.
- Событие `leaderboard` и поле `top` в ответе `me` убраны (**реализовано** на backend): таблица одна — `top`; живое число
  игроков пульт берёт из `players` в `limits`, `online` остаётся в снимке.

```json
{"type":"top","round":1,"board":[{"player":{"id":"8a01b2c3d4e5f607","name":"Ann"},"points":27},{"player":{"id":"3f9c0a7d12b4e856","name":"Jack"},"points":19}]}
```

## Бродячие зомби

**Реализовано** на backend (решение пользователя). Правила — [`scenario.md`](scenario.md), «Рапира», «Зомби-воркеров
больше». На шагах финала 5–6 зомби не уходят, а бродят, пока их не убьют.

- **Появление.** Событие `flyer {flyer, kind: 'zombie', depth, from, points, launchedAt, wander: true}` — без `to`,
  `duration`, `expiresAt`; `from` — точка, где он встаёт (на лужайке или грядке, внутри зоны `walk`). Дальше его ведёт
  фронтенд, детерминированно от id и серверного времени; позиций сервер не знает и не проверяет. В индексе летунов он
  хранится без `expiresAt`, чистильщик тикера его не трогает; живые — в снимке (`flyers`).
- **Сколько.** На входе в шаг 5 — сразу `HELLOWIN_ZOMBIE_MIN` событий `flyer` (до реплики). После
  смерти: живых меньше `HELLOWIN_ZOMBIE_MIN` — сразу новый (на ближайшем тике, ~200 мс); иначе раз в `HELLOWIN_ZOMBIE_INTERVAL`, пока живых меньше
  `max(HELLOWIN_ZOMBIE_MIN, HELLOWIN_ZOMBIE_PER_PLAYER × фигурки на поле)` (вживую; ушли игроки — лишних не убивают). Пауза
  прогресса появление не останавливает. Обычные (уходящие) зомби здесь не запускаются, вне шагов 5–6 — как раньше.
- **Выстрел** — обычный `shoot {flyer}`: первый под локом, событие `shot`, `slain + 1` и `cursed`; срок (`expiresAt`) у
  бродячего не проверяется.
- **Уход.** На входе в шаг 7, при сбросе и `again` — событие `gone {flyers: [id, …]}`: все живые бродячие убраны без
  попадания (не в метрику «улетел»). Клиент убирает и тех, кого держит сам, на любом `reset`.

```json
{"type":"flyer","round":1,"flyer":"f-5e0c71a2","kind":"zombie","depth":1,"from":{"x":38.5,"y":81},"points":2,"launchedAt":1760900000000,"wander":true}
{"type":"gone","round":1,"flyers":["f-5e0c71a2","f-0b9d2c41"]}
```

## Действие останавливает ход

**Реализовано** на backend (бриф №20). Правила — [`scenario.md`](scenario.md), «Игроки», «Действие останавливает ход».

- **Какие действия.** `shoot` — любой принятый вызов, попадание и промах (не принят — лимит; у анонима фигурки нет, останавливать нечего); `click` —
  принятый клик по тыкве, костру или кругу (ошибки — `locked`, неизвестный элемент — не останавливают); `strike`,
  `drink`, `roll` — только успешный ответ, повтор `roll` с той же `attempt` — нет: остановил исходный бросок (`busy`, `not clinked`, кулдаун и прочие отказы не останавливают). Не
  останавливают `move`, `clink`, `clink.auto`, `bar.take`, `beer` — они сами про ходьбу.
- **Когда.** Только если фигурка игрока ещё идёт (серверное время < `arrivesAt`); стоящую не трогаем и `move` не шлём.
  Зомби-игроков (их водит сервер) не останавливаем.
- **Что.** Сервер обрезает `Walk` в точке пути по серверным часам в момент принятия действия, пишет её в KV и шлёт всем
  `move {player, walk: {path: [точка], startedAt: at, arrivesAt: at}, stop}` — стоячий путь (как у стоящей фигурки) и
  `stop` — имя действия: `shoot`, `click`, `strike`, `drink`, `dice` (у `roll`). Остановка — это ход: отменяет
  недошедшее чоканье по клику, `bar.take` и `beer`, как `move` без `clink`. Ответ RPC не меняется.
- **Порядок.** `move` со `stop` уходит **раньше** события самого действия (`shot`, `click`, `strike`, `drink`, `roll`).
- **Фронтенд** замирает там, где фигурка нарисована, играет анимацию действия и потом обычной ходьбой доходит до точки
  сервера (см. [`frontend.md`](frontend.md), «Ходьба без скачков»).

```json
{"type":"move","round":1,"player":{"id":"3f9c0a7d12b4e856"},"walk":{"path":[{"x":52.4,"y":88.1}],"startedAt":1760900004200,"arrivesAt":1760900004200},"stop":"shoot"}
```

## Пустая кружка

**Реализовано** на backend (решение пользователя от 2026-10-28); фронтенд — **реализовано**. Правила — [`scenario.md`](scenario.md),
«Бар» и «Шаг 5».

- **Предмет.** `drink` (бар и проклятый мир) ставит фигурке `item: mug`, а не `null` — в записи фигурки, значит, и в
  снимке (`walkers[].item`) и в `walker`.
- **Новое пиво.** С `mug` `bar.take` и `beer {pumpkin}` работают, как с пустыми руками (`has beer` — только с `beer`);
  `mug` заменяется на `beer`. `drink` с `mug` — `no beer`; `clink` и `clink.auto` в баре с `mug` — как с пустыми руками.
- **Бросок.** `shoot {flyer}` игрока с `mug` в руке: сервер ставит `item: null` и шлёт всем
  `throw {player: {id}, flyer, at}` — всегда, при попадании и при промахе (летуна нет, уже сбит, улетел). Попадание
  считается как обычно: `shot`, очки, смерть летуна, `slain` зомби. Порядок: `move` со `stop` (если фигурка шла) →
  `throw` → `shot`. Ответ RPC прежний. Бросок — только там, где `item` у фигурки свой (бар, шаги 5–6): на рассвете
  кружка в записи не видна (у всех рапира) и не бросается.
- **Фронтенд** рисует полёт и разбивание от `at` и роняет сбитого летуна в момент удара (`THROW.impact`,
  `public/js/pixel/mug-throw.js`); `throw` старше 1,5 с не рисуется и не звучит.

```json
{"type":"throw","round":1,"player":{"id":"3f9c0a7d12b4e856"},"flyer":"f-3a9c01d2","at":1760900004200}
```

## Чат

**Реализовано** на backend (бриф №21). Правила — [`scenario.md`](scenario.md), «Игроки», «Чат».

- **Сказать.** `say {text}` — игрок с фигуркой на поле. Чистка на сервере: обрезка, управляющие символы и переводы
  строк — в пробел, пробелы схлопываются; длина после чистки — 1…`HELLOWIN_CHAT_MAX` символов (`mb_strlen`, по
  умолчанию 120), иначе `invalid text`; клиент ограничивает поле тем же `maxlength` — переменная `$chatMax` шаблона
  `home` (`HomeController`). Ведро `say` —
  `HELLOWIN_RPC_RATE_SAY` (`<в секунду>,<burst>`, по умолчанию `1,3`). Чат — не действие №20: ход не
  останавливает. Говорить можно в любой сцене, в том числе на паузе.
- **Событие** `say {player: {id, name}, text, at}` — всем, ровно одно на принятый `say`. У зомби-игрока (`zombie` в
  `Walker`) — `{player, zombie: true, at}` **без** `text`: фразу («Мммм… мозги…») фронтенд берёт из своего
  каталога по FNV-хешу `{player.id}:{at}`, у всех одну; исходный текст наружу не уходит. Показывается как текст, не
  HTML.
- **История** — KV `hellowin:chat`: последние `HELLOWIN_CHAT_HISTORY` (по умолчанию 50) сообщений
  `{id, player: {id, name}, text, zombie?, at}` (`id` — сквозной номер сообщения за вечер) с **исходным** текстом; живёт весь вечер — сброс и `reset` с `again` её
  не чистят. Игрокам она не отдаётся (в снимке её нет); модератору — `chat.history`.
- **Заглушить.** `chat.mute {player, on}` — заглушённые в KV `hellowin:chat:muted`, переживают сброс; их `say` —
  `muted`. Событий нет: игрок узнаёт по отказу.
- **Пульт модератора** на открытии зовёт `chat.history`, дальше дописывает из событий `say` (у зомби — пометка
  «зомби» и фраза бабла; исходный текст — после следующего `chat.history`).

```json
{"type":"say","round":1,"player":{"id":"3f9c0a7d12b4e856","name":"Jack"},"text":"кто украл мою метлу?!","at":1760900004200}
{"type":"say","round":1,"player":{"id":"8a01b2c3d4e5f607","name":"Ann"},"zombie":true,"at":1760900005100}
```

## Эмоции

**Реализовано** на backend (решение пользователя от 2026-10-28). Игрок с фигуркой на поле жмёт эмодзи на панели — эмодзи появляется
над его фигуркой у всех на несколько секунд.

- **Набор** — env `HELLOWIN_EMOTES`, список через запятую, по умолчанию `🎃` `👻` `💀` `😂` `😱` `😍` `👍` `👏` `🔥` `🍺` `🤘` `🙏` `🎉`; порядок — порядок кнопок
  панели. Клиент берёт набор из снимка (`emotes` — массив строк) и шлёт эмодзи как есть; сервер принимает только
  эмодзи из набора (`unknown emoji`: точное совпадение строки, без нормализации variation selector — клиент шлёт строку из `emotes` как есть).
- **RPC** `emote {emoji}` → `{ok:true}` и событие `emote {player: {id}, emoji, at}` всем, в том числе самому
  игроку (он рисует эмоцию по событию, как все). Без фигурки — `no character`, аноним — `anonymous`. Чаще, чем раз в
  `HELLOWIN_EMOTE_COOLDOWN_MS` (по умолчанию 1000) на игрока, — `busy`, без события. Ведро — общее `other`.
- **Ничего не хранится**: ни в снимке, ни в истории — опоздавший эмоцию не увидит, как и пузырь чата. Ход не
  останавливает, паузе прогресса и сцене не подчиняется (можно в любой сцене и на любом шаге, зомби-игроку тоже).
- **Счёт**: `emote` — действие игрока, идёт в `calls` «Чисел вечера»; метрика `hellowin_emotes_total{emoji}`.

## Лимиты и баланс

**Реализовано** на backend (бриф №22). Правила — [`scenario.md`](scenario.md), «Модератор и сова»; env и дефолты —
[`engine.md`](engine.md).

- **Формула.** Каждый лимит — `max(1, ceil(k × (BASE + PER_PLAYER × (n − 1)))) + надбавка`: n — фигурки на поле (минимум
  1, то же число, что `online`), `k` — множитель модератора (`thresholds`), BASE и PER_PLAYER — env элемента
  `HELLOWIN_<X>_BASE` / `HELLOWIN_<X>_PER_PLAYER`, надбавка — ручная, до конца раунда (`bar.target`, `cursed.target`,
  `boss.hp`; у кликовых элементов её нет). Лимиты: `pumpkin`, `bonfire`, `circle` — кликов на стадию (число стадий не
  меняется); `bar` — кружек бара; `drinks`, `zombies` — цели проклятого мира; `boss` — запас здоровья FrankenPHP.
  Заменяют `HELLOWIN_CLICKS_PER_STAGE`, `HELLOWIN_BONFIRE_CLICKS_PER_STAGE`, `HELLOWIN_CIRCLE_CLICKS_PER_STAGE`,
  `HELLOWIN_BAR_DRINKS`, `HELLOWIN_CURSED_PER_PLAYER`, `HELLOWIN_BOSS_HP_BASE`, `HELLOWIN_BOSS_HP_PER_PLAYER`.
- **Пересчёт вживую.** n берётся тикером раз в секунду и применяется, когда продержался 3 с (дебаунс). Лимит, упавший
  ниже накопленного прогресса, прогресс не теряет: сервер сам ставит переход стадии или `ready`, не дожидаясь клика
  (переходы идемпотентны). Здоровье босса: `hp = max(1, max − урон)`, урон сохраняется.
- **Событие** `limits {players, k, burst, limits}` — при любом изменении: `players` — n, `burst` — у текущего набора
  есть летуны (кнопка волны на пульте), `limits` — только лимиты текущего контекста: тыквы — в сценах 1–3, костёр — в тех из них, где у него есть стадии (`bonfireStageMax` > 0),
  круг — финал, шаг 0; `bar` — бар; `drinks` и `zombies` — шаг 5; `boss` — шаг 6, пока босс жив. Снимок — `limits`
  того же вида. Поле `threshold` в `click` и у элементов снимка остаётся.

## Пауза прогресса

**Реализовано** на backend (бриф №22, п. 1; решение пользователя), в том числе пауза без отказов (бриф №24, решение пользователя
от 2026-10-23: «пауза не должна останавливать игроков делать действия, мы просто их не засчитываем»; было — отказ
`paused`). Модератор ставит на паузу **набор прогресса по задаче сцены**. Игроки паузу не видят: их действия проходят
как обычно — анимации, звуки, события всем, — только задача сцены не двигается.

- **Что не засчитывается.** `click` — тыквы, костёр, круг; `drink` — в баре и в проклятом мире; `strike` — босс;
  `roll` — кости. Все проверки метода прежние (`anonymous`, `locked`, `no beer`, `busy`, ведро и т. п.); прошедшее
  их действие принимается: `{ok:true, …, counted:false}`, фигурка останавливается, как всегда («Действие останавливает
  ход»), событие уходит всем с тем же полем `counted: false`. Задача при этом стоит:
  - `click` — `clicks` и `stage` элемента не меняются (событие `click` несёт прежние), перехода нет;
  - `drink` — пиво выпито (`item` → `null`, событие `drink`), но `drunk` бара и кружки проклятого мира не растут,
    события `drinks` нет;
  - `strike` — молния бьёт (событие `strike`), `hp` прежнее, `boss-down` не наступает;
  - `roll` — кости катятся (событие `roll`, попытка расходуется), но 6-6-6 на паузе не выигрывает: `dice {on:false,
    winner}` не шлётся. Повтор той же попытки отвечает как раньше, с тем же `counted`.
  Счётчики игрока и вечера (`clicks`, `drinks`, `damage`, `rolls` игрока, числа `reveal`, метрики кружек) идут как
  всегда — не засчитывается только задача сцены. Без паузы поля `counted` нет (значит `true`).
- **Что идёт.** Плановые летуны, добор бродячих зомби, `flyers.burst`, `flyer.special`; `shoot` засчитывается игроку
  (`flyers`, `points`, топ рассвета). Подбитый на паузе бродячий зомби засчитывается игроку, но цель «зомби» проклятого
  мира (`slain`) не растёт. Не трогаются `move`, `clink`, `clink.auto`, `bar.take`, `beer`, `say`, `word`,
  `cure` и сюжетные RPC модератора (`scene.next`, `finale.step`, `force`).
- **Кто видит.** Событие `pause` и `paused` снимка остаются — для пульта модератора. Клиент игрока паузу не
  показывает и `counted` никак не подсвечивает.
- **Готовность.** На паузе `ready` не наступает. Снятие паузы — сервер сам догоняет: переходы стадий, бар, цели
  проклятого мира (тот же пересчёт, что при снижении лимита, см. «Лимиты и баланс»). Отмашка бара (`bar.ready`) и
  бросок совы (`dice.owl`) — решения модератора, как `force`: их готовность пауза не держит.
- **Сброс** и `reset` с `again` снимают паузу (`pause {on: false}` не шлётся: `paused` снимает само событие `reset`).

## Автопилот

**Реализовано** на backend (решение пользователя от 2026-10-28); пульт и лаборатория — **реализовано** на фронтенде. Правила и
таблица переходов — [`scenario.md`](scenario.md), «Автопилот»; здесь — сообщения, хранение и счёт.

- **Включение.** `auto {on}` (модератор) → `{ok:true, on}` и событие `auto` всем. Флаг — в KV (`hellowin:auto`), не в
  сюжете: сброс и `again` его не трогают, рестарт сервера — тоже.
- **Ход** — те же действия, что RPC пульта, с теми же событиями и репликами, как будто нажал модератор:

  | `action` | Что делает | Когда (см. таблицу `scenario.md`) |
  |---|---|---|
  | `bar.ready` | отмашка бара (`bar.ready`) | только по `HELLOWIN_AUTO_STALL_MS` |
  | `scene.next` | `scene.next {scene: текущая, force?}`, `to` — новая сцена | готовая сцена 0…N−1 |
  | `finale.step` | `finale.step {step: to, force?}` | готовый шаг 0, 1, 5; шаги 2–4 по постановке; на шаге 6 — только по `HELLOWIN_AUTO_STALL_MS` |
  | `dice.owl` | «Сова бросает» (`dice.owl`) | шаг 1 без 6-6-6 за `HELLOWIN_AUTO_DICE_MS` |
  | `again` | `scene.next {scene: финальная}` на шаге 7 — «В бар» (`reset` с `again`, `bar-again`) | срок рассвета прошёл |

  Ходы автопилота — не RPC: в `calls` «Чисел вечера» и в `hellowin_rpc_calls_total` не идут. Один ход на состояние, поэтому
  в `burned` (отброшенные повторы) они не попадают; повтор хода, не давшего результата за 5 с, — может.
- **Событие** `auto {on, next}` — при включении и выключении и когда изменился `next` (тикер сравнивает с последним
  сказанным). `next` — `null`, пока автопилот выключен; иначе — что он сделает дальше:
  - `action` — из таблицы выше; `to` — номер сцены у `scene.next`, номер шага у `finale.step`;
  - `at` — серверное время хода, мс: ход известен (сова договорит + пауза, конец постановки, срок рассвета, бросок
    совы); пульт сам отсчитывает «через 0:12» по своим часам сервера;
  - без `at` — `wait`: `room` — ждёт задачу зала (готовность сцены или шага; на шаге 6 — последний удар по FrankenPHP),
    `pause` — стоит на паузе прогресса;
  - `force: true` — ход без готовности (только по `HELLOWIN_AUTO_STALL_MS`).

  `at` меняется, когда сова начинает новую реплику (автоматическую или модератора): тогда приходит новое `auto`.
- **Снимок** — `auto {on, next}` (см. «Снимок»).
- **Таблица речи совы** `public/autopilot.json` — её ведёт фронтенд (пересобирается из `public/js/owl.js` и
  `public/js/pixel/finale-timeline.js`, тест сверяет её с ними), сервер читает при старте:

  ```json
  {
    "showMs": {"base": 4500, "perChar": 158, "min": 7900, "max": 27000},
    "holdMs": 5600,
    "nameChars": 24,
    "lines": {"bar-intro": {"ms": 27012, "hold": 15156}, "finale-1": {"ms": 28118, "hold": 14840, "delay": 3000}, "…": {}},
    "steps": {"1": 5200, "2": 2200, "3": 6800, "4": 0, "5": 5600, "6": 2650, "7": 8000}
  }
  ```

  - `lines[id]` — реплика каталога: `ms` — сколько сова её говорит со всеми частями (самый длинный вариант по сценам и
    шагам, ru и en, `{player}` — имя в `nameChars` букв), `hold` — сколько она держит пузырь, прежде чем следующая
    реплика может её сменить, `delay` — сколько она ждёт после отправки (`finale-1` — отсчёт «Призыв через 3…»).
  - Свой текст модератора (`text`) и неизвестный id: `ms = min(max, max(min, base + perChar × длина))` (длина — в символах
    после обрезки), `hold = min(ms, holdMs)`; неизвестный id — `ms = max`, `hold = holdMs`.
  - `steps[N]` — сколько от события `finale {step: N}` играет постановка шага: раньше автопилот не ходит.
  - **Счёт речи.** Сервер хранит `{until, hold}` (KV `hellowin:owl`) и на каждое опубликованное `owl` (и `owlText`)
    делает: `start = max(now + delay, hold)`, `until = max(until, start + ms)`, `hold = start + hold реплики`. «Сова
    договорила» — `now ≥ until`.
- **Счёт времени хода.** Тикер хранит запись (KV `hellowin:auto`) `{on, ctx, since, readyAt, dawnUntil, owlRollAt, acted,
  resumedAt, paused}`: `ctx` — `{round}:{scene}:{step}`; сменился — `since = now`, `readyAt` и `dawnUntil` сброшены;
  `readyAt` — первый тик, увидевший `ready`. Ход:
  - готовая сцена или готовый шаг 0, 1, 5 — `at = max(readyAt, since + steps[step], until) + PAUSE` (нет шага в `steps` — 0);
  - шаги 2–4 — `at = max(since + steps[step], until) + PAUSE`;
  - шаг 1 без 6-6-6 при включённых костях — `dice.owl`, `at = max(since + steps[1] + DICE, owlRollAt + PAUSE)`;
  - рассвет — `dawnUntil = since + случайное MIN…MAX` (один раз), `at = max(dawnUntil, since + steps[7], until + PAUSE)`;
  - ждёт зал — `wait: room`; с `STALL` > 0 — `at = since + STALL`, `force: true`;
  - пауза прогресса — `wait: pause`; после снятия `at` не раньше `resumedAt + PAUSE`.
  PAUSE, DICE, STALL, MIN, MAX — env ниже. Включение стирает запись: всё считается от момента включения.
- **Env:**

  | Переменная | По умолчанию | Смысл |
  |---|---|---|
  | `HELLOWIN_AUTO_PAUSE_MS` | 4000 | пауза после того, как сова договорила, перед ходом; и между бросками совы |
  | `HELLOWIN_AUTO_DAWN_MIN_MS`, `HELLOWIN_AUTO_DAWN_MAX_MS` | 300000, 600000 | сколько длится рассвет до «В бар»: случайно в этих границах |
  | `HELLOWIN_AUTO_DICE_MS` | 90000 | сколько зал бросает кости сам, прежде чем бросает сова; 0 — сова не бросает |
  | `HELLOWIN_AUTO_STALL_MS` | 0 | через сколько без готовности ходить с `force`; 0 — никогда |
