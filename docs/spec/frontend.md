# Фронтенд

Статус: страница с тыквами и «Как это работает» — **реализовано** для старой модели (один порог); поддержка сцены,
стадий тыкв и событий новой модели — **в работе** у backend в минимальном виде; дизайн сцен — **задача фронтенда**.

## Зона и ограничения

- Файлы фронтенда: `app/views/**` (Stempler), `public/css/**`, `public/js/**`, `public/` (картинки, шрифты).
- Без сборщиков и npm-зависимостей в рантайме: обычные CSS/JS файлы. Внешние библиотеки — только с CDN с точной
  версией (как `centrifuge@5.7.4` в `home.dark.php`).
- Протокол и данные — [`protocol.md`](protocol.md); правила игры — [`scenario.md`](scenario.md). Если фронтенду нужно
  новое поле или событие — сначала правка `protocol.md`, затем backend.

## Главная страница (`GET /`, шаблон `home`)

Переменные шаблона — поля снимка состояния из `protocol.md` (`round`, `scene`, `sceneStages`, `threshold`,
`elements` со `stage`/`clicks`) и `centrifugoUrl`. Layout — `app/views/layout/base.dark.php`: стеки `styles`
и `scripts`, атрибут состояния на `<body>`.

Правила рендеринга:

- **Только из событий.** Свой клик клиент не рисует локально: эффект появляется, когда из канала приходит `click`,
  у кликнувшего так же, как у всех. Задержка круга браузер → сервер → браузер — часть демонстрации.
- **Состояние на DOM.** Сцена — атрибут `<body data-scene>`, стадия тыквы — `data-stage` на её элементе; вид сцен
  и стадий описывается CSS по этим атрибутам.
- **Пересинхронизация.** После переподключения и при событии с чужим `round` — RPC `state` и полный перерендер
  состояния.
- Тыква — элемент с `data-element="{id}"` и `data-type`; клик по нему → `centrifuge.rpc('click', {element})`.
  Служебные ссылки (например, тыква с «?» на `/how-it-works`) — обычные `<a>` без `data-element`.

DOM-хуки, на которые опираются feature-тесты (`tests/Feature/Controller/HomeControllerTest.php`):
`data-element`, `data-type`, `data-stage`, `data-centrifugo-url`, `data-threshold`, `data-clicks`, ссылка
`href="/how-it-works"`. Меняешь хук — меняй тест в том же коммите.

## Страница «Как это работает» (`GET /how-it-works`)

- Вводный блок + вкладки (WAI-ARIA Tabs, `public/js/how-it-works.js`, вкладка в `location.hash`, без JS — все
  разделы подряд). Новая вкладка = ссылка `role="tab"` в `tabs__list` + `<section role="tabpanel">`; JS и тест не
  трогать.
- Схемы — inline SVG; цвета через CSS-переменные, подписи без обводки, ширина до 1360px. Схемы показывают реальный
  механизм: имена классов, каналов, ключей и портов берутся из кода, не из памяти.
- Запланировано: вкладка «Идемпотентный переход» — после движка.

## Проверка

- Быстрый цикл без пересборки: dev-override (`docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d
  --build -V`) монтирует код, шаблоны и статика подхватываются сразу.
- Прод-стек копирует код в образ: после правок `docker compose up -d --build app`.
- Скриншоты — headless Edge (команда в `AGENTS.md`), минимум на ширине 1600 и 390 px; смотреть их глазами.
- Клик сквозь стек без браузера — node-клиент centrifuge (см. `infra.md`, раздел про e2e).
- `composer test` — feature-тесты проверяют разметку обеих страниц.
