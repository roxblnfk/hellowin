# Фронтенд

Статус: страница с тыквами и «Как это работает» — **реализовано** для старой модели (один порог); пиксельная сцена
на PixiJS, переход главной на снимок и сцена 0 «День: подготовка» — **в работе** у фронтенда; сцены после 0
и вкладка «Идемпотентный переход» — **запланировано**.

## Зона и ограничения

- Файлы фронтенда: `app/views/**` (Stempler), `public/css/**`, `public/js/**`, `public/` (картинки, шрифты).
- Без сборщиков и npm-зависимостей в рантайме: обычные CSS и нативные ES-модули (`<script type="module">`). Внешние
  библиотеки — только с CDN с точной версией: `centrifuge@5.7.4` (UMD, глобальный `Centrifuge`),
  `pixi.js@8.22.0` (`dist/pixi.min.mjs`).
- Протокол и данные — [`protocol.md`](protocol.md); правила игры — [`scenario.md`](scenario.md). Если фронтенду нужно
  новое поле или событие — сначала правка `protocol.md`, затем backend.
- Скиллы: `pixijs` (роутер по `pixijs-*`), `pixel-art`, `pixel-art-sprites` — подключены в `skills.json`.

## Главная страница (`GET /`, шаблон `home`)

Переменные шаблона — поля снимка состояния из `protocol.md` (`round`, `scene`, `sceneStages`, `stageMax`,
`threshold`, `elements` со `size`/`stage`/`clicks`) и `centrifugoUrl`. Layout — `app/views/layout/base.dark.php`:
стеки `styles` и `scripts`, атрибуты состояния на `<body>`.

### Отрисовка: гибрид canvas + DOM

- **PixiJS рисует**, на весь экран, `<canvas>` под разметкой: небо, грядка, корень в центре, побеги к тыквам,
  тыквы, частицы. Пиксельный режим: `antialias: false`, текстуры `scaleMode: 'nearest'`, `roundPixels: true`,
  масштаб «арт-пикселя» — целое число экранных пикселей, подбирается от размера окна.
- **DOM держит состояние и ввод.** Тыквы — прозрачные `<button>` поверх своего спрайта: клик, фокус с клавиатуры,
  скринридер, хуки тестов. Canvas состояние не хранит — читает атрибуты DOM и слушает их изменения через API сцены.
- Спрайты — код: матрицы индексов палитры в JS, запекаются в текстуры при старте. Картинок-файлов нет.
- Без WebGL/WebGPU (или если PixiJS не загрузился) страница остаётся рабочей: кнопки видны с emoji-запасным видом.

### Модули (`public/js/`)

| Файл | Что |
|---|---|
| `app.js` | вход: соединение с Centrifugo, модель клиента, атрибуты DOM, вызовы API сцены |
| `pixel/palette.js` | палитра (именованные цвета) |
| `pixel/sprites.js` | спрайты: тыква по `(stage, size)`, побеги, частицы `chunk` / `seed` / `pulp`, фон |
| `pixel/scene.js` | PixiJS-приложение: раскладка, слои, анимации; API ниже |

API сцены — единственная связь `app.js` с canvas:

```js
const scene = await createScene(rootEl, snapshot); // null, если рендер недоступен
scene.render(snapshot);              // полный перерендер (state, reset)
scene.click(id, {stage, clicks, threshold}); // эффект клика: тряска + частицы по стадии
scene.pumpkin(id, stage);            // переход стадии: вспышка, смена спрайта
scene.setScene(n, stageMax);         // смена сцены
```

### Разметка и DOM-хуки

| Где | Атрибут | Значение |
|---|---|---|
| `<body>` | `data-scene` | текущая сцена |
| `<body>` | `data-final` | присутствует, когда `scene == sceneStages` |
| `#app` | `data-centrifugo-url`, `data-round`, `data-scene-stages`, `data-stage-max`, `data-threshold` | из снимка |
| тыква (`<button>`) | `data-element`, `data-type`, `data-size`, `data-stage`, `data-clicks` | из `elements[]` |
| тыква | `data-ready` | `clicks >= threshold` и `stage < stageMax`, переход ещё не пришёл |
| тыква | `data-done` | `stage >= stageMax`: в этой сцене тыква готова |

Хуки feature-тестов (`tests/Feature/Controller/HomeControllerTest.php`): `data-element`, `data-type`, `data-stage`,
`data-centrifugo-url`, `data-threshold`, `data-clicks`, ссылка `href="/how-it-works"`. `data-clicks` — на тыкве.

### Правила рендеринга

- **Только из событий.** Свой клик клиент не рисует локально: эффект появляется, когда из канала приходит `click`,
  у кликнувшего так же, как у всех. Задержка круга браузер → сервер → браузер — часть демонстрации.
- Клик по тыкве → `centrifuge.rpc('click', {element})`. Служебные ссылки (тыква с «?» на `/how-it-works`) — обычные
  `<a>` без `data-element`.

### Модель клиента

Клиент держит `round` и применяет события канала:

| Событие | DOM | Сцена |
|---|---|---|
| `click` | `data-clicks`, `data-ready` | `scene.click` |
| `pumpkin` | `data-stage`, `data-clicks = 0`, снять `data-ready`, `data-done` по `stageMax` | `scene.pumpkin` |
| `scene` | `<body data-scene>`, `data-final`, `#app[data-stage-max]`, пересчёт `data-done` | `scene.setScene` |
| `reset` | новый `round`, всё в 0 (сцена, стадии, клики) без RPC | `scene.render` |

- **Пересинхронизация.** После переподключения (кроме первого) и при любом событии, кроме `reset`, с `round`,
  отличным от текущего, — RPC `state` и `scene.render` из снимка. События, пришедшие до ответа, отбрасываются.
- Ошибки RPC (`busy`, `unknown element`, сеть) — в `console.warn`, на экране не показываются.

### Сцена 0 «День: подготовка»

- **Фон.** Дневное небо, солнце, земля грядки. В центре — корень/кочка, от него к каждой тыкве идёт изогнутый побег
  с листьями (лист — 2–3 тона зелёного). Побеги рисуются от центра к позиции тыквы, поэтому раскладка из конфига
  автоматически даёт «круг».
- **Тыквы** трёх размеров (`s`/`m`/`l` — разная пиксельная сетка, не растяжение), с хвостиком; ограниченная палитра
  с hue-shift (тени к красно-коричневому, блики к жёлтому), выборочный контур, без сглаживания. Стадии — по таблице
  в `scenario.md`: 0 целая → 1 глаз → 2 два глаза → 3 рот, верхушка срезана, видна мякоть → 4 пустая (тёмное нутро).
- **Клик** (событие `click`): короткая тряска/сплющивание тыквы (2–3 кадра) и частицы по стадии:
  стадии 0–2 — оранжевые куски `chunk` разлетаются от места выреза, падают с гравитацией и исчезают;
  стадия 3 — семечки `seed` и волокна мякоти `pulp` фонтаном из верхушки; стадия 4 (`data-done`) — сгоревший клик:
  пара серых искр, без частиц тыквы.
- **Переход** (событие `pumpkin`): белая вспышка-силуэт на 1 кадр, смена спрайта, «отскок».
- Готовность: тыква с `data-ready` мерцает контуром; с `data-done` — лёгкое покачивание.
- HUD: статус соединения, раунд, сцена, «готово N из M» (`data-done`). Пиксельный шрифт — системный моно
  или bitmap через `BitmapText`.
- `prefers-reduced-motion`: без тряски и частиц, переходы — мгновенная смена спрайта.
- От 390 px по ширине: позиции в процентах, масштаб арт-пикселя меньше, HUD в две строки.

## Страница «Как это работает» (`GET /how-it-works`)

- Вводный блок + вкладки (WAI-ARIA Tabs, `public/js/how-it-works.js`, вкладка в `location.hash`, без JS — все
  разделы подряд). Новая вкладка = ссылка `role="tab"` в `tabs__list` + `<section role="tabpanel">`; JS и тест не
  трогать.
- Схемы — inline SVG; цвета через CSS-переменные, подписи без обводки, ширина до 1360px. Схемы показывают реальный
  механизм: имена классов, каналов, ключей и портов берутся из кода, не из памяти.
- Запланировано: вкладка «Идемпотентный переход» — после движка: клик → очередь `transitions` с дублями →
  `#[Idempotent]` с ключом `{round}:{pumpkinId}:{toStage}` → одна публикация `pumpkin`; рядом — панель
  `pushed − transitions` из Grafana.

## Проверка

- Песочница без backend: `public/dev/lab.html` поднимает сцену на фиктивном снимке и генерирует события `click` /
  `pumpkin` локально (кнопки «клик», «авто»). Только для разработки, ссылок на неё со страниц нет.
- Быстрый цикл без пересборки: dev-override (`docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d
  --build -V`) монтирует код, шаблоны и статика подхватываются сразу.
- Прод-стек копирует код в образ: после правок `docker compose up -d --build app`.
- Скриншоты — headless Edge (команда в `AGENTS.md`), минимум на ширине 1600 и 390 px; смотреть их глазами. Для
  WebGL в headless добавить `--use-angle=swiftshader --enable-unsafe-swiftshader` и `--virtual-time-budget=3000`.
- Клик сквозь стек без браузера — node-клиент centrifuge (см. `infra.md`, раздел про e2e).
- `composer test` — feature-тесты проверяют разметку обеих страниц.
