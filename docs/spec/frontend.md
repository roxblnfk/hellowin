# Фронтенд

Статус: пиксельная сцена на PixiJS, главная на снимке и сцена 1 «День: подготовка» — **реализовано** (идёт доводка
вида); «Как это работает» с вкладкой «Идемпотентный переход» — **реализовано** (страницу ведёт backend); курошлёпка — **реализовано**; экран входа, персонажи и прогулка по полю — **реализовано** на фронтенде и
проверено в лаборатории, **в работе** — ждёт backend (`look` в `register`, `move`, `walker`/`move`/`leave`,
`walkers` в снимке); пульт модератора, сова с пузырём, модель сюжета (`ready`, `finale`, `pause`, `zombies`),
новые летуны (вороны, мыши с `wobble`, призраки, ведьма), птица-бегун и зомби, временная панель разоблачения —
**реализовано** и проверено в лаборатории и на живом стеке; вид сцен 2–4 (свет по сценам, стадии тыкв 5–11, костёр,
прыжок тыкв, взрыв и пепелище) — **реализовано** и проверено в лаборатории и на живом стеке; магический круг (элемент,
рисунок по стадии, `circleStageMax`) и червяки финальной сцены — **реализовано** и проверено в лаборатории и на живом
стеке; финал (шаги 0–5: ритуальная поза, силуэт, молнии и FrankenPHP, RoadRunner, разоблачение с аптаймом, проклятый
мир с фразами FrankenPHP и чоканьем — автоматическим и по клику (по клику — в лаборатории, против контракта backend), строка связи в HUD; красный огонёк, пиво ночью) — **реализовано** и проверено в лаборатории, на живом стеке — шаги 0–2;
множитель порогов (группа «Пороги» на пульте, событие `thresholds`, `k` и `online`) — **реализовано** и проверено в
лаборатории и на живом стеке; звук (движок `audio/**`, подключение по событиям, кнопка «Звук» в HUD) — **реализовано**, проверено
тестами маршрутизации и в лаборатории (`?sound=1`), на слух на живом стеке — **в работе**; игроки на странице (лидеры, своя статистика) — **запланировано**; бар (сцена 0: зал, сова-бармен,
кружки, «взять», «выпить», чоканье, цель бара со шкалой, слухи и тосты за PHP) и сдвиг номеров сцен на единицу —
**реализовано** и проверено в лаборатории, на живом стеке — **в работе** (ждёт backend), см. «Бар и сдвиг номеров
сцен»; рапира (цель проклятого мира со шкалами, пиво из тыкв, смерти зомби, возвращение совы, поле слова, зомби-игроки,
босс FrankenPHP с очками и здоровьем, золотая молния, рассвет) — **запланировано**, см. «Рапира»; дверь бара и новый цикл
вечера («В бар» на рассвете, `reset` с `again`) — **запланировано**, см. «Бар и сдвиг номеров сцен». Номера сцен ниже — после сдвига: бар — 0, день — 1, закат — 2, ночь — 3, финал — `sceneStages` (по умолчанию 4).

## Зона и ограничения

- Файлы фронтенда: `app/views/**` (Stempler), `public/css/**`, `public/js/**`, `public/` (картинки, шрифты).
- Без сборщиков и npm-зависимостей в рантайме: обычные CSS и нативные ES-модули (`<script type="module">`). Внешние
  библиотеки — только с CDN с точной версией: `centrifuge@5.7.4` (UMD, глобальный `Centrifuge`),
  `pixi.js@8.22.0` (`dist/pixi.min.mjs`).
- Протокол и данные — [`protocol.md`](protocol.md); правила игры — [`scenario.md`](scenario.md). Если фронтенду нужно
  новое поле или событие — сначала правка `protocol.md`, затем backend.
- Скиллы: `pixijs` (роутер по `pixijs-*`), `pixel-art`, `pixel-art-sprites` — подключены в `skills.json`.

## Главная страница (`GET /`, шаблон `home`)

Переменные шаблона — поля снимка состояния из `protocol.md` (`round`, `scene`, `sceneStages`, `stageMax`,
`threshold`, `elements` со `size`/`stage`/`clicks`) и `centrifugoUrl`. Layout — `app/views/layout/base.dark.php`:
стеки `styles` и `scripts`, атрибуты состояния на `<body>`.

### Отрисовка: гибрид canvas + DOM

- **PixiJS рисует**, на весь экран, `<canvas>` под разметкой: небо, грядка, корень в центре, побеги к тыквам,
  тыквы, частицы. Пиксельный режим: `antialias: false`, текстуры `scaleMode: 'nearest'`, `roundPixels: true`,
  масштаб «арт-пикселя» — целое число экранных пикселей, подбирается от размера окна.
- **DOM держит состояние и ввод.** Тыквы — прозрачные `<button>` поверх своего спрайта: клик, фокус с клавиатуры,
  скринридер, хуки тестов. Canvas состояние не хранит — читает атрибуты DOM и слушает их изменения через API сцены.
- Спрайты — код: матрицы индексов палитры в JS, запекаются в текстуры при старте. Картинок-файлов нет.
- **Глубина — алгоритм художника.** Плоское (небо, дальний план, почва, газон) запекается в фон; всё, что стоит на земле
  (трава и сорняки, кусты, реквизит, плетень, дерево, тыквы, корень), — один контейнер, отсортированный по y опорной
  точки (низ спрайта): дальнее рисуется раньше, ближнее перекрывает его. Летуны в воздухе — вне этой сортировки.
- Без WebGL/WebGPU (или если PixiJS не загрузился) страница остаётся рабочей: кнопки видны с emoji-запасным видом.

`scene.js` и `join.js` (оба тянут `characters.js`) `app.js` грузит динамически: если они не загрузились, тыквы
и счёт работают на emoji-кнопках. `audio/engine.js` и `sound.js` — тоже динамически, параллельно со сценой: без них
страница работает молча, кнопка «Звук» скрыта.

API сцены — единственная связь `app.js` с canvas:

```js
const scene = await createScene(rootEl, snapshot); // null, если рендер недоступен
scene.render(snapshot);              // полный перерендер (state, reset)
scene.click(id, {stage, clicks, threshold, player}); // эффект клика: тряска + частицы по сцене; у костра и круга — тряска и искры; фигурка player стреляет в элемент
scene.pumpkin(id, stage);            // переход стадии: вспышка, смена спрайта; у костра — вспышка света и искры
scene.setScene(n, stageMax);         // смена сцены: перекраска, закат, прыжок тыкв, взрыв костра 3 → 4, бар → грядка
scene.circle(progress);              // магический круг на пепелище, 0–1 (0 — не рисуется); ведёт client.js по стадии круга
scene.setServerClock(fn);            // источник серверного времени (Date.now() + offset) для летунов и фигурок
scene.flyer(event); scene.shot(event); // летуны: запуск, падение (+ выстрел фигурки игрока из event.player)
scene.flyerAt(clientX, clientY);     // id летуна под указателем или null
scene.walker(w);                     // фигурка появилась или сменила вид/имя (Walker)
scene.move(id, walk, clink);         // фигурка пошла (Walk); clink — цель, если идёт чокаться по клику (иначе null)
scene.leave(id);                     // фигурка ушла
scene.setMe(id);                     // своя фигурка: имя другим цветом
scene.walkerAt(id);                  // где фигурка нарисована (координаты конфига); для проверок лаборатории
scene.walkerHit(clientX, clientY);   // id фигурки под указателем (ближняя к камере) или null; что делает клик — решает клиент
scene.clink(event);                  // событие clink: пара чокается от at; старше 3 с — не играется
scene.groundAt(clientX, clientY);    // {x, y} земли в координатах конфига (обратный spreadX) или null над небом
scene.perch();                       // {x, y, px}: точка на ветке (после отлёта совы — над FrankenPHP), CSS-пиксели от #app; px — CSS-пикселей в арт-пикселе
scene.owl({ms, hoot});               // сова говорит ms: клюв и крыло; hoot — драматичная реплика, сначала нахохлится;
                                     // возвращает 0; после отлёта совы реплика просто показывается над FrankenPHP
scene.setFinale({step, ready});      // шаг финала (null вне финальной сцены) и замкнут ли круг; следующий шаг играется
                                     // с анимацией, любой другой (перезагрузка, ресинк, reduced motion) — сразу итогом
scene.onCue(fn);                     // моменты для звука без события канала: fn({type: 'owl-away'}) — сова взлетает на шаге 5,
                                     // {type: 'franken', text, x} — началась фраза FrankenPHP (пойманная позже 1,5 с — нет),
                                     // {type: 'clink', x, sides} — удар автоматического чоканья (раз на чоканье, позже 0,4 с — нет); x — % ширины,
                                     // sides — [{id, x, y}] участники в координатах конфига (бар: clink.auto)
scene.owlGone();                     // сова улетела: её реплики теперь над FrankenPHP
```

### Разметка и DOM-хуки

| Где | Атрибут | Значение |
|---|---|---|
| `<body>` | `data-scene` | текущая сцена |
| `<body>` | `data-final` | присутствует, когда `scene == sceneStages` |
| `#app` | `data-centrifugo-url`, `data-round`, `data-scene-stages`, `data-stage-max`, `data-threshold` | из снимка |
| `#app` | `data-k`, `data-online` | `k` (множитель порогов, `$k ?? 1`) и `online` (`$online ?? 0`) снимка; клиент держит их в модели и обновляет атрибуты по `thresholds` / `leaderboard` |

| `#app` | `data-now` | `now` снимка: первая оценка смещения серверных часов (дальше — замеры RPC `time`) |
| `#app` | `data-started-at` | `startedAt` снимка: запуск RoadRunner, аптайм финала (0 — не известен) |

### Правила рендеринга

- **Только из событий.** Свой клик клиент не рисует локально: эффект появляется, когда из канала приходит `click`,
  у кликнувшего так же, как у всех. Задержка круга браузер → сервер → браузер — часть демонстрации.
- Клик по тыкве → `centrifuge.rpc('click', {element})`. Служебные ссылки (тыква с «?» на `/how-it-works`) — обычные
  `<a>` без `data-element`; ссылки на «Как это работает» (тыква с «?», кнопка в разоблачении) открываются в новой
  вкладке (`target="_blank" rel="noopener"`), чтобы не уводить со сцены.

### Пульт модератора

`<aside data-debug-panel hidden>` в правом верхнем углу; содержимое строит `debug.js`. **Только модератору**: панель
видна, когда RPC `me` вернул `moderator: true`; остальным её нет вовсе (их RPC пульта сервер всё равно отклонит
`forbidden`). Секрет: `?moderator=<секрет>` → `localStorage['hellowin.moderator']` (в `try/catch`; без хранилища —
до перезагрузки), параметр убирается из адреса (`history.replaceState`), секрет уходит в `data` подключения рядом с
`playerSecret`; `?moderator=` (пусто) забывает секрет.

- **Свернуть/развернуть**: заголовок «🦉 Пульт» (`data-console-toggle`, рядом — сводка `data-console-summary`: сцена или
  шаг финала, «готова», «пауза»), клавиша «`» (не в полях ввода), `?debug=1` / `?debug=0`. Состояние запоминается в
  `localStorage['hellowin:console']`; по умолчанию развёрнут на экране шире 600 px, на телефоне свёрнут.
- **Сюжет**: «Следующая сцена» (`data-action="scene-next"`, RPC `scene.next {scene}`; при `ready` подсвечена и
  срабатывает сразу, без `ready` — двойное нажатие «Не готово. Точно?» и `force: true`; в финальной сцене скрыта; **запланировано**: на шаге финала 7 снова видна — «В бар», новый цикл вечера);
  «Шаг финала N» (`data-action="finale-step"`, RPC `finale.step {step: текущий + 1}`; только в финальной сцене, после
  шага 5 — «Финал пройден», выключена; шаг 1 при замкнутом круге подсвечен, без него — двойное нажатие «Круг не
  замкнут. Точно?» и `force: true`); «Заново» (`data-action="reset"`, двойное нажатие, RPC `reset {round}`).
- **Сова**: кнопка на каждую реплику каталога с `button` (`data-owl-line="<id>"`, RPC `owl.say {line}`); «Повторить…»
  (`data-owl-repeat`) — авто-реплики без подстановок; поле своего текста (`data-owl-form`, `data-owl-input`, до 200
  символов) → `owl.say {text}`. Реплики с `{player}` с пульта не говорятся — некого подставить.
- **Нечисть**: «Ведьма», «Бегун» (`data-action="witch|roadrunner"`, RPC `flyer.special {kind}`), «Зомби: вкл/выкл» и
  «Пауза: вкл/выкл» (`data-action="zombies|pause"`, `aria-pressed`, RPC `zombies` / `pause {on}`).
- **Пороги** (scenario.md, «Множитель порогов»): текущий множитель «×1,00» (`data-k-value`), «÷1,25» и «×1,25»
  (`data-action="k-down|k-up"`, RPC `thresholds {k}` с `k` модели, делённым или умноженным на 1,25, округлённым до
  сотых и зажатым в 0,1–10), поле (`data-k-form`, `data-k-input`: текст с `inputmode="decimal"`, запятая или точка,
  плейсхолдер — текущее `k`) и «OK» (`data-action="k-set"`, `k` до сотых; вне диапазона уходит на сервер — его
  `invalid k` и показывается, не число — та же надпись без RPC; при успехе — «✓» и поле очищается). Ниже — действующие
  пороги «тыква N · костёр N · круг N» (`data-console-thresholds`) и «онлайн: N» (`data-console-online`), оба из модели:
  пороги приходят от сервера (снимок, событие `thresholds`), базовых значений клиент не знает. При `k` ≠ 1 сводка в
  заголовке показывает «×k».
- **Рапира** (**запланировано**, см. «Рапира»): группы «Проклятый мир» (шаг 5) и «Босс» (шаг 6); «Шаг финала» — до 7.
- **Отладка**: «Клик по всем» (`data-action="click-all"`, RPC `click` по каждой тыкве с разносом ~30 мс).
- Ответ сервера кнопка показывает надписью на несколько секунд (`data-note`): успех действий без состояния — «✓»,
  ошибка — «Нет прав» (`forbidden`), «Не готово», «Уже финал», «Не финал», «Пустой текст», «Занято», «0,1–10»
  (`invalid k`), прочее — «Не вышло».
  Состояние (подписи, подсветка, `aria-pressed`) — только из модели клиента: результат любой кнопки приходит событием
  канала, как у всех.
- На телефоне пульт — колонка шириной экрана минус поля, тело прокручивается, поверх панели разоблачения.

`scene` снимает `ready`, вне финальной сцены — и `finale` (в финальную `finale {step: 0}` приходит следом). `reset`
снимает `ready`, `finale` и `zombies`, `paused` и `k` оставляет (пауза и множитель — про зал, а не про сюжет). Пульт перерисовывается
после каждого применённого события и снимка (`onChange` клиента).

Кто «я»: `player.id` из ответа RPC `me` (после каждого подключения) или `register` → `client.setMe(id)`. Ходить
(`client.canWalk()`) может браузер, чья фигурка (`walkers[].id == me`) есть на поле. Модель держит `reachable` тыкв
(из `data-reachable` разметки и из снимка: без поля — `false`) и `clink` фигурок (из снимка и `move`).

Маршрутизация клика по сцене (`app.js`): выстрел по летуну (`bindShooting`, `pointerdown` в фазе захвата) — первым;
затем, только в проклятом мире (`client.cursed()`: финальная сцена, шаг 5+) и только с фигуркой (`canWalk`), —
чоканье: клик или тап по **чужой** фигурке (`scene.walkerHit` → `client.clinksWalker(id)`) — RPC `clink {walker}`
(`bindClinking`, `click` в фазе захвата после выстрелов; клик гасится и до земли и кнопки тыквы не доходит;
клавиатурный клик, `detail` 0, оставлен кнопке), клик по кнопке тыквы с `reachable` (`client.clinksPumpkin(id)`) — RPC
`clink {pumpkin}` вместо `click`, по дальней — `click`; иначе — `move` по земле (`bindWalking`), клик по своей
фигурке — тоже `move`. По клику ничего не рисуется: путь приходит событием `move`, чоканье — событием `clink`; отказ
(`busy`, `no target`…) — `console.warn`. Над чужой фигуркой в проклятом мире у `#app` — `data-clink-hover`
(курсор-рука; на тач-устройствах не ставится); у кнопок тыкв курсор-рука и так.

- **Пересинхронизация.** После переподключения (кроме первого) и при любом событии, кроме `reset`, с `round`,
  отличным от текущего, — RPC `state` и `scene.render` из снимка. События, пришедшие до ответа, отбрасываются.
- Ошибки RPC (`busy`, `unknown element`, сеть) — в `console.warn`, на экране не показываются.

### Сцена 1 «День: подготовка»

- **Фон.** Камера низко, взгляд вдоль земли: горизонт на 37% высоты, над ним небо с солнцем и облаками, у горизонта
  дальние холмы и кромка леса (дымка — дизеринг с цветом неба). Грядка — сильно сплющенный эллипс (полуоси ~47% ширины
  и до 25% высоты), борозды сходятся к горизонту, вдали всё мельче и реже. В центре
  корень, от него к хвостику каждой тыквы идёт изогнутый побег с густой листвой (лопастные тыквенные листья
  2–3 размеров, усы). Вокруг грядки — сорняки и высокая трава, гуще к краям экрана.
- **Плотная грядка.** Грядка небольшая (полуось ~33% ширины), тыквы крупные (l 44×38, m 34×30, s 26×23 арт-px) и стоят
  тесно: спрайты ближних перекрывают дальние. Хит-зона кнопки — ядро тела (~72% спрайта, без хвостика), ядра не
  перекрываются, `z-index` кнопки растёт с `y`. Кнопки позиционирует CSS через `--x`/`--y` и `--spread`
  (`spreadX(width)` из `public/js/layout.js`, общий для DOM и сцены вместе с центром корня): на узких экранах раскладка
  растягивается по x от центра. Побеги извилистые, с боковыми отростками; толщина 4 → 2 арт-px.
- **Раскладка тыкв** — `elements` в `app/config/hellowin.php` (правит фронтенд): ~18 тыкв неровным кольцом-эллипсом
  вокруг корня (50%/63%, `ROOT` в `scene.js`), ближе-дальше от центра вразнобой; дальние (выше на экране) чаще мельче.
- **Дерево** — слева, дальше грядки (за ней по глубине), ветка тянется к середине экрана. На ветке есть точка
  `perch` (спрайт `DECOR.tree`) — туда в будущей сцене прилетит сова; сцена держит её экранные координаты.
- **Тыквы** трёх размеров (`s`/`m`/`l` — разная пиксельная сетка, не растяжение), с хвостиком; ограниченная палитра
  с hue-shift (тени к красно-коричневому, блики к жёлтому), выборочный контур, без сглаживания. Стадии — по таблице
  в `scenario.md`: 0 целая → 1 глаз → 2 два глаза → 3 рот, верхушка срезана, видна мякоть → 4 пустая (тёмное нутро).
  До выскабливания (стадии 1–3) в прорезях и в срезе верхушки — мякоть, а не тёмная дыра: бледная оранжево-жёлтая
  (`pulp`) с семечками и волокнами, сверху и слева затенена (`pulpShade`) — край кожуры нависает, вырез читается
  углублением; освещается как кожура (не светится). Тёмное нутро — только со стадии 4.
- **Вариативность.** Вид тыквы детерминирован от `seedOf(id)` (CRC32 id): какой глаз вырезается первым, форма глаз
  (треугольник, круг, полумесяц, косые), форма рта (зигзаг, улыбка, «О», один зуб…), число долек, оттенок, хвостик.
  Одна и та же тыква выглядит одинаково у всех и после перезагрузки.
- **Слои.** Тыква — стопка слоёв, а не один спрайт: `back` (задняя стенка и нутро, видно сквозь вырезы), `body`
  (кожура с вырезанными отверстиями), `rim` (кромка мякоти по краям вырезов), `stem` (хвостик), `glow` (маска
  отверстий и среза — в ночной сцене туда кладётся свечение изнутри). Днём `glow` скрыт.
- **Клик** (событие `click`): короткая тряска/сплющивание тыквы (2–3 кадра) и частицы по стадии:
  стадии 0–2 — оранжевые куски `chunk` разлетаются от места выреза, падают с гравитацией и исчезают;
  стадия 3 — семечки `seed` и волокна мякоти `pulp` фонтаном из верхушки; стадия 4 (`data-done`) — сгоревший клик:
  пара серых искр, без частиц тыквы.
- **Переход** (событие `pumpkin`): белая вспышка-силуэт на 1 кадр, смена спрайта, «отскок».
- Готовность: тыква с `data-ready` мерцает контуром; с `data-done` — лёгкое покачивание.
- HUD: статус соединения, раунд, сцена, «готово N из M» (`data-done`). Пиксельный шрифт — системный моно
  или bitmap через `BitmapText`.
- `prefers-reduced-motion`: без тряски и частиц, переходы — мгновенная смена спрайта.
- От 390 px по ширине: позиции в процентах, масштаб арт-пикселя меньше, HUD в две строки.

### Летуны

Механика — [`scenario.md`](scenario.md), события `flyer` / `shot` и RPC `shoot` — [`protocol.md`](protocol.md).

- Полёт клиент считает сам по серверному времени: прогресс `(Date.now() + offset − launchedAt) / duration`, где
  `offset` — смещение серверных часов: `now` снимка страницы — только первая оценка (он вписан при рендере, и доставка
  страницы и загрузка скриптов, а после «Назад» из bfcache — и того больше, сдвигают его, и у двух браузеров рядом птицы
  вылетали бы в разное время); затем при каждом подключении, возврате во вкладку и `pageshow` из bfcache клиент делает 5
  замеров RPC `time` (без него — `state`) и берёт замер с минимальным RTT: `offset = serverNow + rtt/2 − t1`;
  летун при `Date.now() + offset >= expiresAt` не рисуется и убирается. Путь — прямая `from → to` или квадратичная
  кривая через `via`. Глубина `depth` задаёт масштаб (дальние мельче), слой (дальние позади дерева, ближние перед
  грядкой) и скорость взмахов. Утка из куста: куст шуршит, утка взлетает из его точки.
- Летуны движутся каждый кадр, поэтому попадание проверяет **canvas** (PixiJS hit-test по спрайту с запасом), а не DOM:
  клик по утке → `centrifuge.rpc(shoot, {flyer})`. Клик мимо — без RPC. Как и с тыквами, по своему выстрелу
  ничего не рисуется: падение — только по событию `shot` (перья, утка кувыркается вниз, всплывают очки).
- Кусты (`#app[data-bushes]`, JSON) и траектории летунов — в процентах экрана **без** `spreadX`, как на сервере.
- Перехват: `bindShooting` (`public/js/client.js`) слушает `pointerdown` на `#app` в фазе захвата, `scene.flyerAt(x, y)`
  проверяет летунов от ближних к дальним по хит-боксу тела (~60% спрайта, без крыльев и хвоста — сбить должно быть
  непросто); при попадании клик гасится и до кнопки тыквы не доходит.
- Слои: летун никогда не позади дальнего плана (холмы — за километры). `depth` 0 — перед холмами, за деревом, плетнём
  и наземными объектами, с лёгкой дымкой к цвету неба; `depth` 1 и 2 — над наземными объектами. Полный рендер (resync, `reset`) убирает летунов.
- Спрайты — `public/js/pixel/flyers.js`, живой пример — `public/dev/flyers.html`.
- **Светлячок** (`firefly`, проклятый мир, **реализовано** в лаборатории): нарисован по глубинам вручную (точка 3×2,
  ~8×5, ~12×9): тёмные надкрылья, красный щиток, бледные крылья машут, фонарик на хвосте. Тело рисуется как у любого
  летуна; фонарик — слой `glow` (3 уровня: тусклый, средний, яркий) цветами свечения FrankenPHP поверх тела без
  перекраски и аддитивный ореол `halo(…, 'franken')` под телом. Мигает по своему ритму: раз в 1,7 с яркий ~0,5 с с
  дрожью, иначе тусклый (`prefers-reduced-motion` — ровный средний). Путь — с `wobble`. Сбитый гаснет: фонарик и ореол
  пропадают, тело падает как у мыши, вместо перьев — лаймовые искры.
- **Муха** (`fly`, бар, **реализовано** в лаборатории и проверено на событиях живого backend): один спрайт на все
  глубины (`FLYERS.fly`, 6×5, якорь под лапками): тёмное тельце с красным глазом и бликом на спинке, крылья — самые
  светлые пиксели двух тонов, меняются каждые 35 мс (4 кадра), и мельтешение читается как прозрачные крылья; рисуется
  как нарисована, как все летуны в воздухе (без перекраски светом бара и без свечения), — бледные крылья не тонут в
  тёплом дереве. Сидя — крылья сложены «крышей» на спине, раз в 1,4 с муха потирает передние лапки (420 мс, два
  кадра) и вздрагивает крыльями. Путь — `public/js/pixel/fly-path.js` (`flyPlan`, `flyAt`; без DOM, его же берёт
  `sound.js`): точки `from → stops… → to`, перелёт — `(duration − Σsit) / (число stops + 1)`, на каждой точке муха
  сидит `sit` мс ровно в ней. На перелёте — прямая плюс окружность через точку на прямой, пройденная 1–2 раза:
  смещение `r·(cos(φ+a) − cos φ, sin(φ+a) − sin φ)`, `a = ±2π·loops·s`, в начале и конце перелёта оно нулевое, так что
  муха садится точно в точку; число петель, радиус (3–6 % меньшей стороны экрана, по x делится на соотношение сторон —
  петля круглая), направление и `φ` (центр петли над прямой, ±0,6 рад — муха кружит над столом, а не сквозь него)
  — из FNV-хеша `flyer#номер перелёта`, у всех зрителей одинаково. Прогресс `s` — с плавностью: первый перелёт
  влетает с ходу и тормозит (`1−(1−t)²`), между посадками — взлёт и посадка мягкие (smoothstep), последний разгоняется
  к `to` (`t²`), один перелёт без посадок — ровно. Смотрит туда, куда летит по кривой (знак производной по x), сидя —
  как подлетела. Хит-бокс — по постоянной рамке тела (`box`) плюс 2 px вокруг, одинаковый в полёте и сидя. Сбитая
  (`shot`): кадр попадания 120 мс, сидевшая сразу, летевшая — 260 мс падает вниз (до ~12 px), затем клякса (`splat`)
  и четыре тёмные капли; клякса мигает и пропадает к 1,2 с; перьев нет. Фигурка-стрелок в баре поворачивается к мухе
  как к тыкве по клику (вбок, лицом или спиной — по dx/dy, а не «небо всегда за грядкой») и стреляет тем, что в руке
  (пиво — пузыри отрыжки, пустые руки — жест).

### Экран входа и персонажи

**Фронтенд — реализовано** (проверено в лаборатории), **в работе** — ждёт backend. Правила — [`players.md`](players.md)
(«Персонаж», «На поле»), протокол — `register {name, look}`, `move`, события `walker` / `move` / `leave`, `walkers` в
снимке.

- **Секрет игрока** — `localStorage['hellowin.secret']` (UUID, при первом визите), уходит только в `data` подключения
  (`{playerSecret}`). Без `localStorage` секрет живёт до перезагрузки страницы.
- **Экран входа** — `<dialog data-join>` поверх главной (`public/js/join.js`, разметка в `home.dark.php`): при первом
  визите (в `localStorage` нет `hellowin.look`) и по кнопке «Персонаж» в HUD. Поле имени `data-join-name`; по каждой
  части `look` — строка «‹ название ›» (`data-part="body|cloak|face|eyes|hat"`, у глаз — квадратик цвета); «Случайно»;
  превью — персонаж крупно, поворачивается спереди → сбоку → сзади → другим боком и шагает на месте (при
  `prefers-reduced-motion` — стоит лицом); «На поле» → `register {name, look}`, при успехе `hellowin.name`/`hellowin.look`
  запоминаются в `localStorage` для следующего входа; ошибку показывает под полем (`invalid name` — правило имени,
  `invalid look`, `anonymous`, прочее — «Не вышло»). «Просто смотреть» и Esc закрывают экран без регистрации —
  зритель не ходит, а при следующем визите экран покажется снова. Превью рисуется обычным 2D-canvas
  (`image-rendering: pixelated`), без PixiJS. Доступ к `localStorage` — в `try/catch`.
- **Персонажи — сборные спрайты** (`pixel/characters.js`). Каталог частей с подписями (`CATALOG`), части по
  умолчанию, `randomLook()`, сборка кадра из слоёв: накидка сзади → тело → лицо (цвет глаз — замена пикселей
  палитры) → шапка → накидка спереди → рука с предметом. Тело задаёт по кадру смещение головы и точку кисти;
  шапки, лица и предметы рисуются один раз на направление и ставятся по этим точкам — так частей много, а кадров мало.
  Неизвестный id части — часть по умолчанию.
- **Направления** — спереди, сзади, сбоку (влево — зеркало). **Позы**: стойка (дыхание), переминание, ходьба
  (4 кадра), стойка с согнутой в локте рукой, держащей предмет (`item`: пиво, метла, пистоль…), выстрел (`shoot`:
  пистоль — свои спрайты прицела с отдачей, другой предмет — на вытянутой руке, пустая рука — указывает).
- **Ходьба.** Фигурки — в `groundLayer`, сортируются по y ступней вместе с тыквами и реквизитом. Позиция — по `walk` и
  серверным часам (то же смещение, что у летунов): постоянная скорость вдоль ломаной, длина — в единицах конфига, как
  `HELLOWIN_WALK_SPEED` на сервере; направление — по экранному наклону текущего отрезка (сбоку, если |dx| ≥ 0,8·|dy|,
  влево — зеркало). Координаты `walk` → экран тем же преобразованием, что тыквы (`spreadX`); на узком экране
  лужайка шире экрана, и фигурка за его краем рисуется прижатой к краю (10 арт-px), а не пропадает. Клик по земле (не
  по тыкве, не по летуну, не по HUD и панелям) у игрока с фигуркой на поле → `move {x, y}` в координатах конфига
  (`scene.groundAt`: обратный `spreadX`, 0,1 %; над горизонтом — `null`, без RPC). Свою фигурку клиент локально не
  двигает: она пойдёт, когда придёт `move`, — как и всё остальное, только из событий.
- **Ходьба без скачков** (решение пользователя). Где фигурка «на самом деле» сейчас, клиенту не важно: важно, чтобы
  нарисованная позиция была непрерывной. Фигурка идёт по своему треку — ломаной в координатах конфига на часах сцены.
  Новый путь (`move` — клик посреди пути или разбегание шага 2; `walker` с новым `walk`; снимок при ресинке и полном
  рендере) продолжается из нарисованной точки: трек — от неё через точки серверного пути, ещё лежащие впереди (точки
  до конца ближайшего к фигурке отрезка отбрасываются, в т. ч. `path[0]`), с момента обработки события, со скоростью
  серверного пути (длина / (`arrivesAt − startedAt`); у стоящего — последняя известная). Дойдёт чуть позже `arrivesAt`
  — не страшно. Направление — по текущему отрезку трека, поворот мгновенный. Задержка и оценка смещения часов меняют
  только момент, не позицию; запоздавший первый `move` тоже не прыгает туда, «где фигурка по серверу сейчас». Прыгает
  только фигурка, нарисованная дальше 15 % от серверной позиции (долгий сон вкладки), и новая — она появляется там,
  где её видит сервер. Слоты «живости» отсчитывают прибытие по треку. Проверка — `scene.walkerAt(id)` в лаборатории:
  кадр за кадром при частых кликах и с `?skew=` сдвиг между кадрами не больше одного тика ходьбы.
- **Имя** — PixiJS `Text` отдельным слоем поверх увеличенной арт-текстуры, в экранном разрешении (моно-шрифт HUD,
  12 px, кремовый с тёмной обводкой; своё имя — золотое), над верхним непрозрачным рядом кадра. Текст внутри
  арт-текстуры размылся бы при целочисленном увеличении, а свой пиксельный шрифт не покрыл бы кириллицу; DOM-подписи
  пришлось бы двигать каждый кадр. У края экрана подпись не обрезается.
- **Живость** — детерминированно, одинаково у всех: время делится на слоты `3500 + crc32(id) % 2000` мс со сдвигом
  `crc32(id)`; хеш `(crc32(id), номер слота)` даёт сторону (чаще лицом) и в трети слотов — переминание в начале слота.
  До первого слота после прибытия фигурка смотрит туда, куда шла. На `shot` с `player` стоящей фигурки (идущая не
  останавливается) — поворот к летуну (сбоку, если он заметно левее/правее, иначе спиной — птицы над дальним
  планом) и «выстрел» тем, что в руке (решение пользователя; см. «Выстрел»), затем обычная поза.
- **Выстрел** (**реализовано**, лаборатория). Эффект летит из точки предмета (`muzzle` кадра: дуло, `fx`-пиксель
  предмета, кончик пальца) туда, где летун был в момент `shot`; попадание по-прежнему решает сервер, анимация — только по
  событию. Поза `shoot`: кадр прицела, со 110 мс — второй кадр (у пистоля — отдача).
  - **Пистоль** (сцена 1): вспышка у дула по стволу — 3 кадра (до 50/110/170 мс: белое ядро с лучами, оторванный язык
    с искрами, рыжие клочья), 4 искры-уголька вперёд; после заката — тёплый свет на земле (`halo` 16×6, 0,9 → 0,3) и в
    воздухе у дула; на 110–230 мс фигурка дёргается на 1 арт-px назад; 8 клубов дыма: 4 выдуты из дула (летят по стволу
    и тормозят), 4 — струйки с поднятого ствола до 900 мс; клуб растёт (радиус до 3–4), всплывает, сносится ветром,
    редеет ступенями Байера и гаснет за 1,5–3 с; дым в свете точки, вспышка — без перекраски. Поза держится 1,2 с.
  - **Свеча** (и факел): вспышка пламени к цели (те же 3 кадра, направление — 16 шагов) и огненный шар (7×7, 2 кадра),
    летит 520 арт-px/с со шлейфом угольков и рассыпается угольками там, где кончился путь.
  - **Книга**: зелёная молния из книги в цель — три зубчатых варианта по 50 мс (ломаная с шагом ~7 px, ответвление,
    зелёный ореол), затем тающий, всего 260 мс; у книги — зелёная звезда и ореол после заката; в цели — искры `magic`.
  - **Пиво** (проклятый мир): отрыжка — 6 пузырей за 80–540 мс летят от кружки к цели, покачиваясь, и лопаются (кадр
    «хлопка»); пузыри не перекрашиваются, иначе ночью их не видно.
  - **Красный огонёк** (сцена 4, шаг финала 0): красный всполох у огонька к цели (кадры вспышки свечи в красных круга,
    16 направлений) и искра — четырёхлучевая звезда цвета круга (5×5, 2 кадра) летит 640 арт-px/с с плотным шлейфом
    красных угольков (выглядит полосой) и рассыпается угольками там, где кончился путь; после заката — красный ореол у
    огонька. `prefers-reduced-motion` — только всполох.
  - Пустая рука — указывает на цель без эффекта; метла, вилы — замах без эффекта. Поза — 0,9 с.
  - Дёшево: текстуры эффектов кэшируются, на выстрел — до ~20 частиц; молния — один `Graphics` на 260 мс.
    `prefers-reduced-motion`: вспышки и позы остаются, без искр и шлейфов; один неподвижный клуб дыма, молния — один
    кадр, у пива — один хлопок у кружки, у свечи — только вспышка.
  - Книга в руке — раскрытая книга, видная с одного взгляда: фиолетовая обложка по краям и снизу, корешок
    (тёмная полоса посередине), две кремовые страницы с зелёными строками; сбоку — в три четверти к камере
    (ближняя страница шире). Во всех направлениях и позах, в т. ч. `shoot`; эффект выстрела прежний.
- **Выстрел по клику** (**реализовано**, лаборатория; решение пользователя). Клик по тыкве, костру или кругу —
  тоже выстрел: на событие `click` с `player` фигурка этого игрока (если она на поле) поворачивается к элементу и
  стреляет тем, что в руке, — те же поза `shoot` и эффекты, что по летуну, только цель — элемент: середина тыквы,
  куча костра, круг на пепелище. Днём пистоль «режет» тыкву выстрелами, на закате вспышка свечи её поджигает, ночью
  молния из книги заколдовывает, в финальной сцене искра красного огонька рисует круг, в проклятом мире — пиво
  (по дальней тыкве; по досягаемой — чоканье, как раньше). Частицы клика у элемента — прежние (`scene.click`).
  - Только из события: свой клик локально ничего не рисует. Анонимный клик (без `player`) или игрок без фигурки на
    поле — без анимации. Не стреляет идущая, пьющая, разводящая руками и чокающаяся фигурка; в баре кликов по
    элементам нет. Поворот — сбоку, если цель заметно левее/правее (|dx| ≥ 0,8·|dy|), иначе лицом или спиной.
  - Прореживание (клики частые): фигурка стреляет заново не чаще раза в 420 мс после своего последнего выстрела
    (по летуну тоже); клик в эти 420 мс только поворачивает её к новой цели и держит прицел ещё 500 мс — без нового
    снаряда. На всю сцену — не больше 10 выстрелов по клику за 500 мс: сверх этого фигурка целится и даёт вспышку,
    но ничего не летит. У выстрела по клику меньше дыма (3 клуба вместо 8) и отрыжки (3 пузыря вместо 6).
  - Звук — прежний звук клика по элементу (`pumpkin.*`, `bonfire.click`, `circle.click`), `shot.*` на клик не
    играется: клики идут десятками в секунду, звук элемента уже и есть «попадание», а второй звук на каждый
    выстрел превратил бы ритуал в шум.

API сцены для фигурок: `scene.walker(w)` (появилась или сменила вид), `scene.move(id, walk, clink)`, `scene.leave(id)`,
`scene.setMe(id)`, `scene.groundAt(clientX, clientY)` → `{x, y}` в координатах конфига или `null`,
`scene.walkerHit(clientX, clientY)` → id фигурки под указателем (хит-бокс ±8 арт-px по x, 30 вверх от опоры) или `null`,
`scene.clink(event)`;
`scene.render(snapshot)` заменяет фигурки списком `walkers` из снимка (без поля — оставляет свои). Перехват кликов по
земле — `bindWalking(root, scene, canWalk, move)`, по чужим фигуркам в проклятом мире — `bindClinking(root, scene,
client, clink)` в `client.js`.

### Финал

**Реализовано** (лаборатория; живой стек — шаги 0–2). Сюжет — [`scenario.md`](scenario.md) («Финал», «Проклятый мир»),
арт — `pixel/finale.js` (макет шагов — `public/dev/finale.html`), постановка — `pixel/finale-stage.js` и `scene.js`.
Сцена получает шаг и `ready` через `scene.setFinale` (клиент — по `finale`, `ready` и снимку).

- **Время шагов.** Всё — функции шага и `t` (мс от события шага по часам сцены, таймлайн `T`). Анимацию играет только
  следующий шаг (`step == прежний + 1`) без `prefers-reduced-motion`; перезагрузка, ресинк, прыжок через шаги и
  reduced motion ставят `t` далеко в прошлое — те же функции рисуют итог шага, ничего не проигрывая заново. Сброс
  (`reset`, `render` без `finale`) возвращает всё к бару (сцена 0). Повторяющееся (дыхание FrankenPHP, хоровод, бег
  RoadRunner по горизонту в проклятом мире, фразы) идёт по часам сцены или по серверным часам.
- **Шаг 0, ритуальная поза.** Как только круг замкнут (`ready` в финальной сцене), стоящие фигурки встают в позу
  `ritual` лицом к кругу (сбоку, если круг заметно левее или правее, иначе спиной или лицом), кадры по 380 мс со
  сдвигом по `crc32(id)`; огоньки в ладонях — слой `glow` кадра, отдельным спрайтом без перекраски, в цвете глаз.
  Идущая фигурка идёт как обычно и встаёт в позу, когда остановилась: шаг — ход сервера, его видно честно, а поза —
  стоячая. Выстрел (`shot`) на миг важнее позы. Поза держится на шаге 1 и до молний шага 2.
- **Шаг 1, пробуждение** (сова `finale-1`). 0–270 мс — вспышка круга (`FX.flash`, 3 кадра); с 180 мс — красный столб
  (`FX.column`, аддитивно 0,55, кадры по 90 мс); с 300 мс — облако дыма за силуэтом и перед ним (`FX.smoke.cloud`,
  220 мс, переднее — 0,85); 600–2200 мс силуэт поднимается из круга (`SILHOUETTE.rise`, 4 кадра по 400 мс), дальше
  дышит (`idle`, 500 мс). Земля трясётся 2,2 с (экран — целыми арт-пикселями: 2 первые 0,5 с, потом 1). Тыквы за
  1,5 с стягиваются с мест на кольцо вокруг круга (0,92 × 0,72 полуосей грядки, на телефоне — в пределах экрана),
  поровну, в том порядке, в каком стояли вокруг, поднимаются выше (+6 арт-px) и кружат хороводом (оборот ~11 с).
  Итог шага: столб, облако, силуэт, хоровод.
- **Шаг 2, это не он** (сова «Что это? Что мы… ЧТО ВЫ НАДЕЛАЛИ?»). Три удара молнии в силуэт на 0, 380 и 760 мс
  (`FX.lightning`, 3 кадра по 60 мс), каждый — бело-голубая вспышка экрана (вуаль 0,45 → 0,1). На 780 мс, под
  вспышкой третьего удара, — смена света без перехода: кровавая луна → ночь (`nightOf`), столб гаснет. С 900 мс дым
  уходит, силуэт за 3 кадра по 150 мс (`SILHOUETTE.reveal`) становится FrankenPHP; огни тыкв гаснут (`lightsOut`:
  световые слои и ореолы скрыты, нутро — тон `spent` в `sprites.js`), за 0,7 с они летят из хоровода на свои места и
  падают на землю с приземлением; по земле стелется дым (`FX.smoke.creep`, 4 полосы вокруг круга, дрейф) — до шага 4.
  Фигурки выходят из позы; разбегаются они по `move` сервера.
- **Шаг 3, мип-мип** (сова — две реплики подряд: «Походу… ошибочка вышла.», затем «RoadRunner никогда не умирал…»; в каталоге
  `then`: вторая сразу после первой, если пузырь не занят другой репликой). RoadRunner: 0–4,6 с — по одной диагонали от
  правого края экрана на линии горизонта (у кромки холмов) вниз к игрокам до точки справа от круга (0,2 ширины от
  центра, ступни на 78 CSS px выше низа), в перспективе: доля пути `k = p^1,8` (у горизонта медленно и мелко, ближе —
  быстрее), до `k` 0,1 — дальний спрайт в дымке (`RUNNER.far`, слой дальних летунов), дальше растёт `s` → `m` → `l` →
  `xl` (0,15 / 0,4 / 0,7); встаёт и поворачивается к центру (`stop`), 5–6,8 с — `meep` и пузырь
  «Мип-мип!», дальше стоит. Вблизи RoadRunner перекрашен светом наполовину (`runnerBake`, кроме контура), иначе ночью он
  тонет. Строка связи в HUD — «RoadRunner: работает · аптайм …» сразу с события шага. Итог шагов 3–4: RoadRunner стоит
  в этой точке.
- **Шаг 4, разоблачение** — панель `reveal.js` (см. выше); в сцене ничего нового.
- **Шаг 5, проклятый мир** (сова «Живите теперь…»). Тыквы за 1 с поднимаются и снова парят, огни — зелёные
  (`tone: 'franken'`: светятся только прорези, без `aura`; тыквы держат пиво, см. «Тыквы проклятого мира»),
  ореолов на земле под тыквами нет, частицы клика — зелёные `magic`; под FrankenPHP — широкий лаймовый ореол.
  RoadRunner 1,2–5,6 с бежит обратно по той же диагонали к правому краю на горизонте (размеры в обратном порядке, у
  горизонта — дальний спрайт) и за край; дальше раз в 15 с (по серверным часам, направление — хеш слота) молча пробегает по горизонту за
  6,5 с; летуны `roadrunner` с сервера — сами по себе. Сова договаривает реплику и улетает: не раньше 3 с от события
  (реплика может ждать пузырь), `OWL_FLIGHT.takeOff` 150 мс, затем взмахи по 90 мс 2,5 с вверх-влево за край экрана.
  Итог: совы нет, RoadRunner — на горизонте по расписанию, FrankenPHP на круге, зелёные тыквы, червяки и зомби как
  прежде.
- **Чоканье** — два режима: автоматическое по близости и по клику; общие позы, пена, пузыри тостов и таймлайн `CLINK`.
  **Автоматическое** (**реализовано**, лаборатория; только фронтенд, без сообщений; `pixel/clink.js`, тосты — `toasts.js`).
  Время делится на слоты по 6 с. В начале слота (серверное время) фигурки с пивом, которые по своему серверному пути в
  этот момент стоят (до старта пути — в его первой точке, после прибытия — в последней), собираются в группы: соседи —
  в эллипсе 9 × 6 единиц конфига (не экрана, поэтому размер окна не важен), группа — цепочка соседей (3+ — одна группа,
  один тост). Группа — кандидат только в каждом 4-м слоте, в фазе по хешу её id, и там с шансом 75 % по хешу (id, слот);
  кандидат чокается, если никакие двое из него не были вместе в другом кандидате трёх слотов до (компания сменилась) —
  пара чокается не чаще раза в 24 с. Правило смотрит только на кандидатов, а не на свои прошлые ответы, поэтому
  открывший страницу только что видит то же, что смотревший всё время. Тост — хеш (группа, слот) → индекс в `TOASTS`.
  Слот вычисляется один раз и заново — только при смене пути или предмета у фигурки. Анимация (мс от 0,3 с слота):
  0–400 поворот боком к центру группы (над/под ним — по порядку в группе), 400–750 кружка вперёд (`clink` 0), 750–1100
  удар (`clink` 1): брызги пены (6 капель цвета пива ночью) и блик `SHOT_FX.pop`, фигурка наклоняется к центру до 6
  арт-px, чтобы кружки сошлись; 1100–1400 обратно; 1400–3200 кружка поднята над головой (`toast`, 2 кадра по 450 мс);
  дальше обычная стойка. Пузырь тоста — над группой с 800 мс, `2000 + 65 мс × символ`, не дольше слота без 0,5 с;
  тост на два голоса — реплика над первой фигуркой до 2400 мс, затем ответ над второй. Идущая фигурка идёт и
  присоединяется, когда встала, если чоканье ещё идёт; выстрел на миг важнее. Пузырь — тот же, что у FrankenPHP
  (`pixel/bubble.js`). `prefers-reduced-motion`: позы без наклона-анимации и без капель, блик остаётся.
  **По клику** (**реализовано** в лаборатории против контракта `protocol.md`; маршрутизация клика — «Модель клиента»).
  Играется событие `clink` от его `at` по серверным часам тем же таймлайном `CLINK`; старше 3 с на приходе
  (`CLINK_STALE_MS`) — не играется. Пара — подошедший (`player`) и цель: с фигуркой оба поворачиваются боком к
  середине между ними и наклоняются к ней, удар с пеной, кружки вверх; тост `TOASTS[toast % TOASTS.length]` — одной
  строкой над парой (середина голов), на два голоса — реплика над подошедшим до 2400 мс, ответ над целью. С тыквой
  фигурка поворачивается к точке на 6 арт-px от середины тыквы в свою сторону, а тыква в те же моменты поднимает
  кружку кадрами `pumpkinArms` (0–400 держит, 400–1400 на полпути, 1400–3200 поднята; при `reduced motion` — без
  «на полпути»), её случайный подъём на это время подавлен; ответ тоста — над тыквой. Пузырь — до `2000 + 65 мс ×
  символ` (+1600 у двух голосов), не дольше 4,5 с от `at`. Новое чоканье того же игрока, фигурки-цели или тыквы
  заменяет прежнее. Идущая фигурка (по своему треку) идёт и в чоканье не участвует; выстрел на миг важнее.
  **Совмещение режимов** (одинаково у всех зрителей): фигурка с `clink` (идёт чокаться по клику — поле из `move` и
  снимка) в планировщик не попадает — до события `clink`, `move` без поля или, если события так и нет (чоканье не
  случилось, сервер ничего не шлёт), до 1 с после прибытия её и фигурки-цели, как в следующем снимке; группа
  планировщика, в которой есть фигурка с чоканьем по клику, пересекающимся с анимацией группы (`[at, at + 3200)`
  против `[at, until)` группы), пропускается в этом слоте целиком. Дополнительной паузы после чоканья по клику нет:
  открывший страницу позже прошлого события не видит и разошёлся бы с остальными.
- **Реплика после отлёта совы** (решение пользователя): любая реплика после отлёта (свой текст модератора, кнопка,
  `zombies`) просто выводится пузырём над FrankenPHP — сова не возвращается, FrankenPHP её не «говорит» (без
  кадров речи); `scene.perch()` отдаёт точку над его головой.
- **Свет.** Шаги 0–1 и начало шага 2 — кровавая луна, с 780 мс шага 2 и дальше — ночь (без тёплого круга костра).
  FrankenPHP и силуэт запекаются `frankenBake`: светящееся (искры, красный кант) — без перекраски, лайм логотипа —
  наполовину между днём и светом сцены, остальное — светом сцены, так логотип читается ночью. Ключи
  `FINALE_EMISSIVE` — в `EMISSIVE` (`night.js`).
- **Глубина.** FrankenPHP и силуэт — на точке круга в `groundLayer` поверх пепелища (вспышка, столб, заднее облако,
  фигура — по порядку над ним); переднее облако, стелющийся дым и RoadRunner вблизи — по своей точке на земле; молнии —
  слой `fxLayer` поверх всего, кроме вуали; дальний RoadRunner — слой дальних летунов.
- **Фразы FrankenPHP** (`franken.js`): каталог `PHRASES` (расширяется добавлением в конец); время делится на слоты по
  10 с, хеш номера слота решает, говорит ли он (примерно в половине слотов), и выбирает фразу (не ту же, что в слоте
  перед ним); фраза — с 0,9 с слота, `2400 + 65 мс × символ`, не дольше слота без 1,2 с. Только на шаге 5 и не в
  первые 14 с после события шага (поверх прощания совы); у открывшего страницу на шаге 5 — сразу. Пока фраза видна —
  кадры `talk` (180 мс, изредка жест); без фразы — дыхание и искры с болтов раз в 2,4 с. Пузыри RoadRunner и
  FrankenPHP — PixiJS в экранном разрешении поверх увеличенного мира (`labelLayer`, как имена): кремовый, ступенчатая
  рамка и хвост к голове, как у пузыря совы.

### Бар и сдвиг номеров сцен

**Реализовано** и проверено в лаборатории (живой стек — ждёт backend). Сюжет — [`scenario.md`](scenario.md) («Сцена 0 —
«Бар»», «Чоканье»), сообщения — [`protocol.md`](protocol.md) («Бар», RPC `bar.take`, `clink.auto`, `drink`,
`bar.target`, `bar.ready`, события `pour`, `mugs`, `take`, `drink`, `drinks`, `walkers` в `scene` / `reset`, `bar` в
снимке).

**Номера сцен.** Бар — сцена 0, день — 1, закат — 2, ночь — 3, финал — `sceneStages` (по умолчанию 4). Номера, от которых
зависит вид, — `SCENE` в `layout.js` (`{bar, day, sunset, night}`) и `isBar(scene)`; финальная сцена — всегда
`sceneStages` снимка, литералов нет.

- `layout.js`: `jumpedOut` — закат (все тыквы на `stageMax`) и всё после него; в баре тыквы не прыгают и не парят
  (`floats`), костра нет (`bonfireOpen`).
- `pixel/scene.js`: свет `lightingOf` — бар `firelight`, день `day`, закат `sunset`, ночь `night`, финальная — кровавая
  луна; костёр со заката (`hasBonfire`), частицы клика — закат `ember`/`cinder`, с ночи `magic`; ночные глаза совы
  (`glowing()`) — с ночи; переход день → закат (4 с) и взрыв ночь → финал — как раньше, по новым номерам.
- `owl.js`: `scene-1` «Вот оно — магическое место! Ух-ху!» → «Но сначала всё подготовим к ритуалу: вырезайте тыквам мордашки и вычищайте их!» (выход из бара, `then`), прежние `scene-1`/`2`/`3` —
  `scene-2`/`3`/`4`; ключи `scenes` у `scene-ready`, `hurry`, `flyers` на единицу больше, ключ 0 — у реплик бара.
- `client.js`: названия сцен в HUD (`Бар`, `День: подготовка`, `Закат`, `Ночь`); `reset` → бар.
- `sound.js` — см. «Звук»; `debug.js` — сводка «бар».

**Локация** (`buildBar` в `scene.js`, арт — `pixel/bar.js`). В сцене 0 вместо неба, грядки, дерева, кустов, бабочек,
тыкв и костра — зал: фон `paintBar`, огни `barLights` (в слое побегов, над фоном и под всем стоящим; ореолы на полу —
`halo(…, 'warm')`, 0,35), мебель `barProps` в `groundLayer` по линии опоры вместе с фигурками (свеча стола — слой
`glow`). Координаты — `walk.bar` из `#app[data-bar-layout]` (без него — `BAR_LAYOUT` в `layout.js`, копия конфига) в
процентах экрана **без** `spreadX`: фигурки в баре (`walkerArt`, `groundAt`) тоже без растяжки, клик в любую точку зала
— `move` (сервер приводит на пол). Сервер водит фигурки по точке ног в обход препятствий, поэтому стол со скамьями и стойка
рисуются внутри своего препятствия с запасом в полфигурки (`WALKER_HALF` по бокам, 1 арт-px спереди и сзади): стол
подбирается под эллипс в арт-px текущего экрана, у стойки сужается край, рядом с которым есть пол; бочки по
прямоугольникам после первого — тоже с отступом. Препятствия `walk.bar` задаёт фронтенд (ключи раскладки в
`app/config/hellowin.php`, копии — `BAR_LAYOUT` и `DEFAULT_BAR_LAYOUT`); проверка — `public/dev/bar.html?boxes`: красный
контур пола под мебелью с запасом лежит внутри зелёного препятствия. Свет — `firelight` (свет листа `public/dev/bar.html`); фигурки и сова
перекрашены им, пиво — `keepHue`. Кнопки тыкв, костра и круга в баре скрыты (`body[data-bar]`, `visibility`), клик по
ним не отправляется (`client.clickable`). Летунов в баре нет (сервер их не запускает). Без canvas — фон-заглушка и
DOM-кнопки (стойка, «Выпить»).

**Дверь** (**запланировано**, бриф «Снова в бар»). Массивная викингская входная дверь — тёмные доски с железными
полосами, кованые петли-завитки, кольцо-ручка, каменный порог — на задней стене в `walk.bar.door.x`: по центру этой
точки, порог — на линии пола (`door.y`), высота — так, чтобы верх притолоки пришёлся на `y` места посадки `lintel`
(см. «Места посадки»). Свободный декор стены (знамёна, лишние щиты, факелы) раскладывается по пролётам между столбами и
обходит дверь: в её пролёте он не рисуется или уходит в соседний, факелы — по бокам двери; щиты и бочки из мест посадки
стоят там, где их задаёт конфиг, и не двигаются (`paintBar` в `pixel/bar.js`, проверка — `public/dev/bar.html`). Дверь **открыта**, пока путь хоть одной фигурки начинается в точке
двери (`walk.path[0]` в пределах 0,5 % от `door`): от `startedAt` до `arrivesAt` + 600 мс — створка распахивается внутрь
(3 кадра по 90 мс), в проёме — ночная улица с холодным светом на полу, затем закрывается (3 кадра). Всё — по путям фигурок
и серверным часам, без своего состояния: перезагрузка посреди входа покажет ту же фазу. Фигурка в проёме рисуется за
косяком (сортировка по опоре), входящая — обычная ходьба по пути из события `walker`. `reduced motion` — дверь сразу
открыта/закрыта, без промежуточных кадров. Без `door` в раскладке — двери нет, фигурки появляются, как раньше.

**Места посадки** (**запланировано**). `walk.bar.perches` — источник, как столы и стойка: арт рисует поверхности
там, где на них садятся мухи сервера (`{x1, x2, y, name}`, `y` — верх поверхности). Щиты — в точках `shield-N`, кромка
щита сверху на `y` (вместо прежних рядов щитов по пролётам; декоративные щиты сверх них остаются, где ни с чем не
сталкиваются); камин — по центру `mantel` (`(x1 + x2) / 2`), размер такой, что верх полки камина на `y` и полка
перекрывает `x1…x2`; дверь — верх притолоки на `y` `lintel`; полки над стойкой — верх на `y` `shelf-top` и `shelf` в
пределах `x1…x2`; крышки бочек — на `y` `barrels`, бочки в пределах `x1…x2`; верх стяжной балки под потолком — на `y`
`beam`. Муха на настенной посадке (щит, притолока, балка) рисуется как на столе — якорь под лапками, сидячие кадры те
же. Проверка — `public/dev/bar.html?boxes`: каждая полоса посадки — жёлтая линия, лежит на верхнем крае своей
поверхности.

**Снова в бар** (**запланировано**). `reset` с `again: true` — как любой сброс (`scene.render`, фигурки сразу на полу
бара через `scene.setWalkers`, без двери), свет рассвета гаснет в свет бара затуханием 3 с (а не мгновенно, как сброс
пульта); следом — реплика `bar-again` «Ну что, по пиву?» (`LINES`, `hoot`). На пульте на шаге 7 «Следующая сцена»
называется «В бар» (см. «Рапира», «Пульт»).

**Сова за стойкой.** Кадры `OWL_BAR` (`pixel/owl.js`), якорь — в `barOwlSpot`, сортируется по своей опоре за стойкой:
стойка закрывает нижнюю часть; пиво в кадре — `bakeBar`. `scene.perch()` в баре — точка совы, пузырь — как обычно.
Покой — `idle` с морганием по серверным часам (слоты как на ветке). **Розлив** — `pourFrame(phase)`, `phase = (now −
since) / (until − since)` по серверным часам (узнавший посреди — с той же фазы); `pouring` с прошедшим `until` не
рисуется. `bar` снимка страницы (`#app[data-bar]`) сцена берёт сразу при создании: `state` клиент перечитывает только
после переподключения или пропуска. На событие `mugs` — два кадра `set` по 180 мс, новая кружка встаёт на стойку с
толчком в 1 арт-px. На стойке — ровно `bar.mugs` кружек `BAR_MUG` по `mugSlots` (до 12), сразу за стойкой по глубине. Речь — `talk`; пока наливает,
кадр розлива важнее. `prefers-reduced-motion`: вместо розлива — `set[0]` (полная кружка в крыле, без струи), без толчка
и мерцания.

**Ввод в баре** (`bindBar` в `client.js`, подключают `app.js` и лаборатория; только с фигуркой на поле):

- Кнопка `[data-bar-counter]` поверх стойки (позиция — `--counter-x|y|w|h` от `counterBox`, без canvas — запасные
  проценты; «Взять пиво») — RPC `bar.take {}`, если `client.takesBeer()` (бар, фигурка, пустые руки); иначе
  `aria-disabled="true"` и клик не уходит. Персонаж пойдёт, когда придёт `move`.
- Клик по чужой фигурке — RPC `clink {walker}`, если `client.clinksWalker(id)`: в баре — у меня и у неё пиво (`item`
  модели), иначе клик идёт в `move`. Курсор-рука (`data-clink-hover`) — по тому же правилу.
- **Пробел** (`isDrinkKey`): только `Space` без модификаторов и автоповтора, не в `input`/`textarea`/`select`,
  `contenteditable`, не на кнопке (`button`, `[role=button]`; кроме кнопки стойки — фокус остаётся на ней после клика
  мышью, а с пивом в руке ей пробел не нужен), не при открытом `<dialog>` (экран входа); если
  `client.drinks()` (бар, фигурка, пиво в руке — флаг `clinked` не нужен, решает сервер) — `preventDefault` и RPC `drink`.
  Ответ `not clinked` — личная подсказка над своей фигуркой: случайная фраза отказа из `REFUSALS` (`toasts.js`, `refusal()`); кнопка «Выпить» видна и без чоканья, если моя фигурка на поле одна (`scene.hint`, пузырь
  `pixel/bubble.js`, 2,5 с), только у себя.
- Кнопка **«Выпить»** `[data-drink]` в HUD — видна, когда я в баре с пивом и модель знает, что этой кружкой я чокнулся
  (`model.clinked`: ставят событие `clink`, где я `player` или `walker`, и успешный ответ `clink.auto`; снимают мой
  `take` с `ok: true`, мой `drink`, выход из бара, сброс; снимок оставляет флаг, пока пиво в руке). Нажатие — RPC `drink`.
- Отказы (`has beer`, `not bar`, `no beer`, `no target`, `not clinked`) — `console.warn`.

**Предметы и анимации.** `item` фигурки в баре — свой: по снимку и `walker`; `take` с `ok: true` → `beer`; `drink` →
модель сразу `null`, сцена (`scene.drink`) 1,2 с играет позу `drink` (3 кадра, кружка в кадре) и дальше — пустые руки.
`take` с `ok: false` — `scene.shrug(id)`: поза `shrug` 0,8 с. Выход на грядку (`scene` 0 → 1 с `walkers`) и сброс с
`walkers` — `scene.setWalkers(list)`: фигурки ставятся сразу, без «ходьбы без скачков» (другая локация); свет меняется
затуханием старого кадра, 3 с.

**Автоматическое чоканье в баре.** Тот же планировщик `pixel/clink.js` (`clinksNow` в баре, как в проклятом мире),
участники — фигурки с `item: beer`. В момент удара сцена шлёт `onCue({type: 'clink', x, sides: [{id, x, y}]})`
(координаты конфига, раз на чоканье, позже 0,4 с — нет); `app.js` в видимой вкладке спрашивает
`client.autoClinkPartner(cue)` — ближайший ко мне участник с пивом, если моя фигурка в группе и у меня пиво, — и шлёт RPC
`clink.auto {walker}`; успешный ответ — `client.clinkedAuto()`. Скрытая вкладка не шлёт (кадры не идут). В проклятом
мире `clink.auto` не шлётся.

**Тосты.** В баре чоканье по клику и автоматическое берут тост из `BAR_TOASTS` (`toasts.js`, за PHP; расширяется
добавлением в конец), в проклятом мире — из `TOASTS`; номер тоста — тот же (`toast` события, хеш группы и слота).
`toastAt(n, list)`, `toastOf(hash, slot, list)`, `clinkOf(event, list)`, `createClinks().at(now, walkers, list)`.

**Цель бара и шкала.** `bar.drunk` / `bar.target` — из снимка, события `drinks` и `reset` (без `target` в событии сброса
цель остаётся прежней — она про зал). В HUD вместо «готово N из M» — шкала `[data-hud-drinks]` (`role="progressbar"`,
`aria-valuenow`/`aria-valuemax`/`aria-valuetext`): пиксельный стакан с пеной на уровне, `--fill` = `drunk / target`
(0–1), полная — `data-full`, рядом «Выпито 12 из 30» (`[data-hud-drinks-text]`), до 120 px, на 390 px помещается.
Готовность бара — событием `ready` (шкала полна или отмашка), тогда в HUD — «сцена готова — ждём ведущего», на пульте
«Следующая сцена ›» подсвечена; до неё — двойное нажатие и `force`, как у любой сцены.

**Пульт в баре.** Группа «Бар» (только в сцене 0): «+5 бокалов» / «−5 бокалов» — RPC `bar.target {delta: ±5}`,
«Отмашка» — RPC `bar.ready {}` (выключена, когда бар уже готов), строка «цель N · выпито M»
(`[data-console-bar]`). Реплики-кнопки `bar-who`, `bar-crowd`, `bar-clink` (флаг `bar` в каталоге) видны только в баре.

**Сова приговаривает.** `RUMORS` в `owl.js` (расширяется добавлением в конец), `rumorAt(n)` — `RUMORS[n % length]`.
`pour` с `rumor` (и снимок, где `pouring.rumor` ещё наливается) → `owl.rumor(n, left)`: слух показывается, только если
пузырь свободен — нет текущей реплики, её удержания и ждущей реплики; держится 4,5–9 с (по длине и остатку розлива) и
ничего не удерживает: любая следующая реплика сменяет его сразу. `bar-intro` (авто, `hoot`, две части через `then`)
— каталог; `intro` осталась кнопкой.

**Модель клиента — события бара:** `pour` → `bar.pouring = {since, until, rumor?}`, `scene.pour(since, until)`,
слух; `mugs` → `bar.mugs`, `pouring = null`, `scene.mugs(n)`; `take` → `ok` — `item: beer` фигурке (`scene.walker`),
`bar.mugs`, `scene.mugs(n)` (без кадров `set`: кружка ушла), иначе `scene.shrug(id)`; `drink` → `item: null`,
`scene.drink(id)`; `drinks` → `bar.drunk`, `bar.target`; `scene` с `walkers` и `reset` с `walkers`/`bar` — заменить фигурки
(`scene.setWalkers`). API сцены для бара: `scene.pour`, `scene.mugs`, `scene.shrug`, `scene.drink`, `scene.hint(id,
text)`, `scene.setWalkers(list)`; `render(snapshot)` берёт `bar` и `barLayout` снимка.

**Лаборатория.** Без `?scene` лаборатория стартует в баре; `?scene=N` — прочие сцены (стадии тыкв `0,4,8,11`, костра
`0,0,4,7`), `?next` с `?scene=1` — закат, с `?scene=3` — взрыв. Фиктивный движок играет бар как сервер: тикер 200 мс
наливает по одной (`?mugs=N` — стартовые кружки, по умолчанию 5; `?pour=ms` — длительность, по умолчанию 2500), примерно
каждый третий налив — с `rumor`; `bar.take` — путь к ближайшей точке места у стойки, проверка по прибытии, `take`
`ok:false` и `bar-empty` (не чаще 20 с); `drink` с `not clinked`, счётчик `drunk` и событие `drinks`; цель `?target=N`
(по умолчанию 10; `?drunk=N` — уже выпито), `bar.target`, `bar.ready` с пульта (`?mod=1`), готовность — `ready` и
`bar-intro` один раз за раунд; `clink {walker}` в баре с `no beer` / `no target` и засчитыванием обоим; `clink.auto` с
проверкой расстояния (`clink_reach`) — шлёт мой браузер, за ботов — лаборатория. Боты в баре берут пиво, чокаются (по
клику и рядом) и пьют. `?bar=1` — боты с пивом стоят у столов парами (`?bar=1&walkers=8&epoch=18000&freeze=5100` —
удар, `6400` — тосты за PHP). `?bardemo=1` — сценка: две кружки, налив 8 с, трое ботов идут к стойке, дальний
разводит руками и слышит `bar-empty`, первые двое чокаются по клику и пьют, опоздавший берёт следующую. `?me=1` — играть
самому (стойка, пробел, «Выпить»). Выход на грядку — `walkers` в `scene`, сброс — в бар с `walkers` и `bar`. Зона бара —
пол минус препятствия, путь — прямо или через углы препятствий. **Запланировано**: `?walkin=N` — N ботов входят в дверь один
за другим (раз в 1,5 с, путь от `door` на `door_in` вниз, как у сервера), а новая своя фигурка в баре (`?me=1`, экран входа)
тоже входит в дверь; `?walkin=1&freeze=300` — дверь распахнута, `1500` — закрывается. На рассвете (`?finale=7&mod=1`)
«В бар» играет новый цикл: `reset` с `again: true` и `bar-again`.

### Рапира

**Запланировано**. Сюжет — [`scenario.md`](scenario.md), «Рапира»; сообщения — [`protocol.md`](protocol.md), «Рапира»
(RPC `beer`, `word`, `cure`, `strike`, `cursed.target`, `boss.hp`, события `cursed`, `word`, `cure`, `boss`, `strike`,
`take` с `pumpkin`, `zombie` в `Walker`, `cursed` и `boss` в снимке). Шаги финала 5–7; `CURSED_STEP` в `client.js`
остаётся 5 (проклятый мир — шаги 5 и 6), рассвет — `DAWN_STEP = 7`.

**Модель клиента.** `cursed` — `{drunk, slain, drinksTarget, zombiesTarget}` из снимка и события `cursed`; `boss` —
`{hp, max}` из снимка и событий `boss` / `strike` (`hp` из `strike`); `zombie` фигурок — из снимка, `walker`, `word`
(`ok: false` → `true`), `cure` (→ снять), `finale` 7 и `reset` (→ снять у всех); `item` — `word` с `ok: true` → `rapier`,
`take` с `pumpkin` → `beer`, `finale` с полем `item` → всем (без поля — не трогать). Правила для ввода:
`client.beersPumpkin(id)` (шаг 5, фигурка не зомби, пустые руки, тыква `reachable`), `client.curesWalker(id)` (шаг 6, я с
фигуркой и не зомби, цель — чужая фигурка-зомби), `client.strikes()` (шаг 6, `boss.hp > 0`, у меня рапира, не зомби),
`client.asksWord()` (шаг 6, моя фигурка на поле, без рапиры, не зомби), `client.zombified()` — моя фигурка зомби.

**Ввод.** Маршрутизация клика: выстрел по летуну — первым (на рассвете — рапирой); затем клик по чужой фигурке — `cure
{walker}`, если `curesWalker`, иначе чоканье, как раньше; клик по досягаемой тыкве на шаге 5 — `beer {pumpkin}` с пустыми
руками, `clink {pumpkin}` с пивом; на шаге 6 тыквы — обычный `click`; клик по FrankenPHP — `strike {}`, если `strikes()`,
иначе ничего; затем `move`. Пробел и «Выпить» — как в баре, на шагах 5–6 (`client.drinks()`); `clink.auto` в проклятом мире
теперь шлётся, как в баре. Зомби (`zombified()`): ходьба, чоканье, пиво, пробел, удары и поле слова выключены, клик ничего не
отправляет. Над фигуркой-зомби, которую я могу расколдовать, — курсор-рука (`data-clink-hover`, как у чоканья).

**Поле слова** — DOM-форма сверху по центру экрана, над сценой и под пультом: «Молви слово» — поле и кнопка «Молвить»
(Enter). Видна, пока `asksWord()`; ответ проверяет только сервер — фронтенд не знает ни слова, ни правил, ни форм и сам
ничего, кроме пустой строки, не отклоняет. Ответ `correct: true` — форма закрывается (предмет и свечение придут событием
`word`); `false` — форма закрывается, моя фигурка станет зомби по событию, вместо формы — строка «Ты зомби-воркер. Жди, пока
расколдуют» (`[data-word-zombie]`), после `cure` форма открывается снова. Ошибки (`not now`, `has rapier`, `zombified`,
`invalid text`) — подпись под полем на 3 с. Пока форма в фокусе, пробел — пробел, а не «Выпить» (`isDrinkKey` и так
пропускает поля ввода).

**HUD.** На шаге 5 внизу вместо «готово N из M» — две шкалы, как шкала бара: «Выпито 7 из 20» (стакан с пеной) и «Зомби 3
из 20» (череп, зелёная заливка), `--fill` = счётчик / цель (0–1), полная — `data-full`. Обе полны — проклятый мир готов
(событие `ready` финальной сцены на шаге 5): шкалы остаются полными, рядом — «сцена готова — ждём ведущего»
(`data-hud-ready`), над FrankenPHP — `cursed-ready`. Модель снимает `ready` на `finale {step: 5}`. С шага 6 шкал нет. На
телефоне шкалы — в одну строку, по 120 px.

**Полоса здоровья** — DOM над головой FrankenPHP (чёткие цифры и `role="progressbar"`; сцене не нужно каждый кадр
перерисовывать текст): пиксельная рамка, заливка от лаймового к красному по доле, «HP 57 / 90»; позицию публикует сцена
(`--boss-x|y` на `#app`, CSS-пиксели); на `strike` — вздрагивает на 1 арт-px и белая вспышка заливки 80 мс. Видна, пока
есть босс и `hp > 0`. Без canvas — сверху по центру.

**Арт.**

- **Пиво из тыквы** (`take` с `pumpkin`): тыква кадрами `pumpkinArms` опускает свою кружку, лезет ручкой в верхнюю прорезь,
  достаёт новую кружку (вспышка пены) и протягивает её к фигурке — ~900 мс от события; у фигурки с этого момента пиво.
  `reduced motion` — сразу пиво.
- **Смерти зомби-воркеров** — вид по id летуна: `DEATHS[crc32(flyer) % DEATHS.length]` (`pixel/flyers.js`, расширяется
  добавлением в конец); у всех одинаково, сервер его не шлёт. `pieces` — разваливается на куски (голова, руки, торс
  разлетаются с гравитацией и подскоком), `meat` — мясной взрыв (вспышка, ошмётки и брызги, лужа), `dust` — рассыпается в
  прах сверху вниз (серый песок осыпается горкой и сдувается), `head` — голова отлетает дугой и катится, тело падает
  следом, `fire` — сгорает зелёным огнём (огонь цвета FrankenPHP, эмиссивный; обугленный силуэт оседает пеплом), `sink` —
  проваливается в землю (трясётся, уходит по пояс, по плечи, над ямой — комья и пыль). До ~1,8 с, частиц — до ~24; затем
  мигает и исчезает. `reduced motion` — один кадр смерти и затухание.
- **Сова возвращается** (шаг 6): прилетает из-за левого края на ветку — обратный `OWL_FLIGHT` (взмахи по 90 мс, 2,5 с,
  посадка 150 мс), `scene.owlBack()` — реплики снова над совой. Рапира совы — кадры `OWL.rapier`: достаёт (2 кадра) на
  второй части `finale-6` и держит поднятой; клинок — эмиссивный слой с ореолом `halo(…, 'gold')`; в этот момент — cue
  `{type: 'owl-rapier'}` для звука. Перезагрузка на шаге 6+ — сова уже на ветке с рапирой.
- **Тыквы шага 6** — тон `franken`, без ручек и кружек (`pumpkinArms` скрыт), светятся и парят, как на шаге 5.
- **Рапира в руке** (`rapier` в `ITEM_DEFS`): тонкий длинный клинок, золотая чашка-гарда; клинок — слой `glow` без
  перекраски (как пламя свечи), мерцание по хешу; во всех позах с предметом. **Светящийся игрок** — фигурка с рапирой:
  золотой ореол на земле `halo(…, 'gold')` и тонкий эмиссивный контур кадра, дышит раз в 1,6 с.
- **Зомби-игрок** (`zombie: true`): та же собранная фигурка, кожа и лицо перекрашены в зомби-зелень (замена пикселей
  палитры, как цвет глаз), поза `shamble` — руки вперёд, ходьба вразвалку (4 кадра по 150 мс); имя — серо-зелёное. На
  `word` с `ok: false` — превращение 0,8 с: зелёная вспышка и дым. На `cure` — от фигурки `by` к нему летит белая искра,
  вспышка, перекраска уходит за 0,5 с.
- **FrankenPHP-босс**: при `boss` надевает **чёрные очки** (слой `glasses` поверх кадров `FRANKEN`, блик по стеклу раз в
  3 с) и говорит фразы `BOSS_PHRASES` (`franken.js`, расширяется добавлением в конец) тем же механизмом слотов, что
  `PHRASES`, только слоты по 7 с и говорит в ~двух третях слотов; пока есть босс, прежние фразы не звучат. Кнопка поверх
  спрайта (`[data-franken]`, хит-зону `--hit-*-franken` публикует сцена) — удар.
- **Золотая цепная молния** (`FX.chain`: `strike` и выстрел рапиры по летуну): из кончика рапиры к цели — зубчатая ломаная
  с 2–3 ответвлениями, белое ядро и золотая кромка, три варианта по 50 мс, затем тает, всего ~300 мс; в цели — золотые
  искры. Прореживание — как у выстрела по клику: фигурка бьёт заново не чаще раза в 420 мс, на сцену — не больше 10 молний
  за 500 мс (сверх — только поза). На `strike` FrankenPHP вздрагивает (кадр `hit`, 120 мс).
- **Груда пепла** (`hp = 0` или шаг 7): FrankenPHP темнеет, трескается и осыпается за ~1,6 с (кадры `FRANKEN.collapse`),
  на круге остаётся груда пепла (`ASH_PILE`) с редкими лаймовыми угольками и струйкой дыма; очки падают сверху на груду.
  Перезагрузка на шаге 7 — сразу груда.
- **Рассвет** (шаг 7): свет `dawn` в `LIGHTINGS` (`night.js`) — розово-золотое небо, солнце поднимается из-за холмов;
  переход из ночи — затухание старого кадра за 6 с; зелёные огни тыкв гаснут, тыквы опускаются на землю. Утки и куры —
  как днём.

**Пульт.** Группа «Проклятый мир» (шаг 5): «+5 кружек» / «−5 кружек» и «+5 зомби» / «−5 зомби» — RPC `cursed.target {goal:
'drinks'|'zombies', delta: ±5}`, строка «кружки 7/20 · зомби 3/20» (`[data-console-cursed]`). «Шаг финала 6» при
готовности (`ready` на шаге 5 — цели выполнены) подсвечен и срабатывает сразу, иначе — двойное нажатие «Цели не выполнены. Точно?» и `force`. Группа «Босс» (шаг 6): «HP +10»
/ «HP −10» — RPC `boss.hp {delta: ±10}` (выключены без босса), строка «HP 57 / 90» (`[data-console-boss]`). «Шаг финала 7» —
только двойным нажатием «Босс жив. Точно?» и `force`; после шага 7 «Шаг финала» скрыта, а «Следующая сцена» снова видна
с подписью **«В бар»** (подсвечена, срабатывает сразу; RPC `scene.next {scene}` — новый цикл вечера, см. «Снова в бар»).

### Звук

Движок — `public/js/audio/engine.js` (не зона фронтенда, только вызовы). `app.js` создаёт `createAudio()`,
`audio.unlockOn(document)` (до первого нажатия или клавиши все вызовы молчат) и отдаёт `createSound(audio, {serverNow,
owlGone})` клиенту (`createClient(…, {sound})`), сове (`createOwl(…, {onShow})`) и сцене (`scene.onCue`). Mute и
громкости хранит сам движок (`localStorage['hellowin.audio']`), фоновую вкладку он приостанавливает.

**Правило — как у рисования: только из событий.** Звучит событие канала или момент серверных часов; свой клик по тыкве,
выстрел, шаг ничего не играют, пока не вернётся событие. Исключение — щелчок `ui.click` по кнопкам HUD и пульта.

- Громкость: своё действие (`player.id` события — я) — 1, чужое и анонимное — 0,6. Панорама — `clamp((x − 50) / 50, −1, 1) × 0,8`
  по x элемента, летуна, фигурки (процент ширины).
- **Музыка** — `audio.setMusic(trackOf({scene, sceneStages, finale}))` при старте, снимке (ресинк), `scene`, `finale`,
  `reset`: бар, день, закат, ночь, кровавая луна финала, `cursed` с шага 5; номера сцен — как есть. С ночи (сцена N−1) эффекты финала
  рендерятся заранее (`whenReady('finale')`). Снимок играет только музыку, без эффектов.
- **Интенсивность** — `0,2 + 0,8 × доля пройденных стадий сцены`: тыквы — от стадии, с которой началась сцена (`stageMax`
  прошлой; открывшему страницу посреди сцены — от самой низкой тыквы), до `stageMax`; в финальной сцене — стадия круга;
  при `ready` и с шага финала 1 — 1; в баре — всегда 0,2. Пересчёт по `click`, `pumpkin`, `scene`, `finale`, снимку; `reset` — 0,2.
- `click`: по тыкве — `pumpkin.burned`, если `clicks > threshold`, тыква на `stageMax` или сцена финальная; иначе день —
  `pumpkin.carve` (стадии 0–2) / `pumpkin.scoop` (стадия 3 — вычищают), закат — `pumpkin.ignite`, ночь —
  `pumpkin.enchant`; по костру — `bonfire.click`, по кругу — `circle.click`. Выстрел фигурки по клику своего звука не
  имеет (`shot.*` — только по `shot`, см. «Выстрел по клику»).
- `pumpkin`: тыква днём / на закате / ночью — `pumpkin.stage` / `pumpkin.lit` / `pumpkin.charged`; костёр — `bonfire.stage`; круг —
  `circle.stage`, на своём `stageMax` — `circle.done`.
- `ready` — `ui.ready`. `scene` в финальную — `bonfire.explode`. `reset` — `stopAll()`, `ui.reset`. `zombies {on: true}` — `zombie.groan`.
- `flyer` по `kind`: duck — `duck.quack`, chicken — `chicken.cluck`, bat — `bat.squeak`, worm — `worm.squelch`, firefly —
  `firefly.ding`, witch — `witch.cackle`, zombie — `zombie.groan`, roadrunner — `runner.steps`, crow — `crow.caw`, ghost —
  `ghost.wail`, fly — `fly.buzz`. Панорама — по `from.x`, громкость по глубине 0/1/2 — 0,5/0,75/1, с `bush` — ещё `bush.rustle` у куста.
  Не звучит летун, чей `expiresAt` прошёл или запущенный больше 1,5 с назад.
- `shot` — `flyer.hit` и `flyer.fall` (+0,05 с) там, где летун сейчас (по его пути); летун, которого страница не видела
  или давно улетевший, — молча. Фигурка стрелка на поле — `shot.<item>` (pistol, candle, book, beer, `red-flame` →
  `shot.redflame`; пустые руки — нет); звука очков за своё попадание нет.
- `move` моей фигурки — `walk.step` каждые 0,35 с пути (не больше 12, таймерами: следующий `move` и `reset` отменяют
  неуслышанные); чужие шаги молчат.
- `clink` не старше 3 с — `clink.glass` в момент удара (`at + CLINK.strike`) и `clink.cheer` при поднятых кружках
  (`at + CLINK.raise`); часть, прошедшая больше чем на 0,25 с, не играется. Автоматическое чоканье — `clink.glass` с громкостью 0,5
  по `scene.onCue` в момент удара.
- **Бар** (имена — предложение агенту звука; неизвестное движку имя молчит): `pour` — `bar.pour` (только свежий, позже
  0,4 с от `since` — нет; панорама — по середине места у стойки), `mugs` — `bar.mug`, `take` с `ok` — `bar.take`,
  без — `bar.empty`, `drink` — `bar.gulp` (громкость и панорама — по фигурке); чоканье — как в проклятом мире.
  **Запланировано**: `walker`, вошедший в дверь бара (путь начинается в `door`, событие свежее — не позже 0,4 с от
  `startedAt`), — `bar.door`, панорама — по `door.x`.
- `walker` моей фигурки, которой не было на поле (после `register` или подключения с `look`), — `ui.join`; смена вида — нет.
- **Сова**: когда пузырь действительно открылся (`onShow` в `owl.js`, в т. ч. вторая часть реплики) — `audio.speak('owl',
  text)`, у драматичной (`hoot`) — сначала `owl.hoot`, речь — с задержкой 0,95 с; после отлёта совы реплика над FrankenPHP — `audio.speak('franken', text)`,
  как и его фразы по серверным часам (`scene.onCue`).
- **Финал** — только следующий шаг вживую (как анимирует сцена; перезагрузка, ресинк, скачок — молча), задержки — из `T`
  (`finale-timeline.js`): шаг 1 — `finale.wake`; 2 — `finale.strike` на каждой молнии (`T.strikes`: 0; 0,38; 0,76 с) и
  `finale.tada` на разоблачении (`T.reveal`, 0,9 с); 3 — `finale.run` и `finale.meep` (`T.meep`, 5 с); 4 — `finale.reveal`;
  5 — `finale.owlAway`, когда сова взлетает (`scene.onCue`), музыка `cursed` — сразу с событием (`trackOf`).
- **Рапира** (**запланировано**; имена — предложение агенту звука, неизвестное движку имя молчит). Музыка: `boss` — пока есть
  босс с `hp > 0` (`trackOf({scene, sceneStages, finale, boss})`), `dawn` — с шага 7; новый цикл (`reset` с `again`) —
  `bar`, обычной сменой трека (`NEXT_TRACK.dawn = 'bar'`, кроссфейд); `again` не играет `ui.reset` и `stopAll()` не
  обрывает музыку. Эффекты: `shot` по зомби — `flyer.hit`
  и вместо `flyer.fall` звук его смерти `zombie.die.<вид>` (`pieces`, `meat`, `dust`, `head`, `fire`, `sink` — по `DEATHS`);
  `take` с `pumpkin` — `pumpkin.beer` у тыквы; cue `owl-rapier` — `owl.rapier`; `word` с `ok: true` — `word.ok` у фигурки,
  с `ok: false` — `word.fail` (только своё слово, громкость 1) и `player.zombify` у фигурки (+0,3 с); `cure` —
  `player.cure`; выстрел рапирой по летуну — `shot.rapira` (`SHOT_SOUNDS`: `rapier` → `shot.rapira`, имя композитора);
  `strike` — `shot.rapira` у фигурки и `franken.hit` у FrankenPHP, не чаще раза в 120 мс на всю сцену; `boss-down` или шаг 7
  с живым боссом — `franken.die`, когда он начинает осыпаться. Шаг 6 вживую — `finale.owlBack` при прилёте совы (если
  движок его знает).
- **Фон.** В скрытой вкладке и 0,6 с после её возвращения события не звучат: так отсекается пачка придержанных публикаций.

## Страница «Как это работает» (`GET /how-it-works`)

- Вводный блок + вкладки (WAI-ARIA Tabs, `public/js/how-it-works.js`, вкладка в `location.hash`, без JS — все
  разделы подряд). Новая вкладка = ссылка `role="tab"` в `tabs__list` + `<section role="tabpanel">`; JS и тест не
  трогать.
- Схемы — inline SVG; цвета через CSS-переменные, подписи без обводки, ширина до 1360px. Схемы показывают реальный
  механизм: имена классов, каналов, ключей и портов берутся из кода, не из памяти.
- Вкладка «Идемпотентный переход» (`#idempotency`): клик → очередь `transitions` с дублями → `#[Idempotent]` с ключом
  `{round}:{pumpkinId}:{toStage}` → одна публикация `pumpkin`. Тесты страницы — `HowItWorksPageTest`.

  `cy − ry/2`, x в `cx ± rx/2` — и верх стойки, **запланировано** — и места посадки `perches`, подряд не на одну поверхность, сидит 900–1600 мс, перелёт 900 мс,
  вход и выход наполовину из-за боковой стены); `?flies=N` — N мух сразу, по зерну (кадры `?freeze` повторяются),
  `?flyshot=ms` — первая фигурка сбивает первую муху: `?flies=3&freeze=500` — петли, `1400` — сидят,
  `?flies=3&walkers=3&flyshot=1000&freeze=1300` — клякса.
  Выстрел по клику: событие `click` несёт кликнувшего, как на сервере, — свой клик по элементу идёт от своей фигурки
  (если она на поле), «клик», «авто» и `?auto=1` — от случайного бота или, в доле `?anon=0..1` (0,25), анонимно;
  `?still=1` — боты стоят на месте и не бродят: `?scene=1&auto=1&still=1&walkers=8` — толпа стреляет по тыквам.
  Инструменты лаборатории (утка, клик, авто, выстрел, стадия) — отдельной панелью
  `[data-lab-panel]`. Все параметры (`?walkers=N`, `?me=1`, `?join=1`, `?shooter=1` и прочие) — в комментарии в
  начале `lab.html`; `window.lab` — `{client, engine, scene}` для проверок из консоли. `?sound=1` — настоящий звук, как
  в `app.js` (первое нажатие разблокирует, кнопка «Звук» в HUD, `window.audio` — движок); без него лаборатория молчит.
