## Зона и ограничения

- Файлы фронтенда: `app/views/**` (Stempler), `public/css/**`, `public/js/**`, `public/` (картинки, шрифты).
- Без сборщиков и npm-зависимостей в рантайме: обычные CSS и нативные ES-модули (`<script type="module">`). Внешние
  библиотеки — только с CDN с точной версией: `centrifuge@5.7.4` (UMD, глобальный `Centrifuge`),
  `pixi.js@8.22.0` (`dist/pixi.min.mjs`).
- Протокол и данные — [`protocol.md`](protocol.md); правила игры — [`scenario.md`](scenario.md). Если фронтенду нужно
  новое поле или событие — сначала правка `protocol.md`, затем backend.
- Скиллы: `pixijs` (роутер по `pixijs-*`), `pixel-art`, `pixel-art-sprites` — подключены в `skills.json`.

## Главная страница (`GET /`, шаблон `home`)

Переменные шаблона — поля снимка состояния из `protocol.md` (`round`, `scene`, `sceneStages`, `stageMax`,
`threshold`, `elements` со `size`/`stage`/`clicks`) и `centrifugoUrl`. Layout — `app/views/layout/base.dark.php`:
стеки `styles` и `scripts`, атрибуты состояния на `<body>`.

### Отрисовка: гибрид canvas + DOM

- **PixiJS рисует**, на весь экран, `<canvas>` под разметкой: небо, грядка, корень в центре, побеги к тыквам,
  тыквы, частицы. Пиксельный режим: `antialias: false`, текстуры `scaleMode: 'nearest'`, `roundPixels: true`,
  масштаб «арт-пикселя» — целое число экранных пикселей, подбирается от размера окна.
- **DOM держит состояние и ввод.** Тыквы — прозрачные `<button>` поверх своего спрайта: клик, фокус с клавиатуры,
  скринридер, хуки тестов. Canvas состояние не хранит — читает атрибуты DOM и слушает их изменения через API сцены.
- Спрайты — код: матрицы индексов палитры в JS, запекаются в текстуры при старте. Картинок-файлов нет.
- **Глубина — алгоритм художника.** Плоское (небо, дальний план, почва, газон) запекается в фон; всё, что стоит на земле
  (трава и сорняки, кусты, реквизит, плетень, дерево, тыквы, корень), — один контейнер, отсортированный по y опорной
  точки (низ спрайта): дальнее рисуется раньше, ближнее перекрывает его. Летуны в воздухе — вне этой сортировки.
- Без WebGL/WebGPU (или если PixiJS не загрузился) страница остаётся рабочей: кнопки видны с emoji-запасным видом.

`scene.js` и `join.js` (оба тянут `characters.js`) `app.js` грузит динамически: если они не загрузились, тыквы
и счёт работают на emoji-кнопках. `audio/engine.js` и `sound.js` — тоже динамически, параллельно со сценой: без них
страница работает молча, кнопка «Звук» скрыта.

API сцены — единственная связь `app.js` с canvas:

```js
const scene = await createScene(rootEl, snapshot); // null, если рендер недоступен
scene.render(snapshot);              // полный перерендер (state, reset)
scene.click(id, {stage, clicks, threshold, player}); // эффект клика: тряска + частицы по сцене; у костра и круга — тряска и искры; фигурка player стреляет в элемент
scene.pumpkin(id, stage);            // переход стадии: вспышка, смена спрайта; у костра — вспышка света и искры
scene.setScene(n, stageMax);         // смена сцены: перекраска, закат, прыжок тыкв, взрыв костра 3 → 4, бар → грядка
scene.circle(progress);              // магический круг на пепелище, 0–1 (0 — не рисуется); ведёт client.js по стадии круга
scene.setServerClock(fn);            // источник серверного времени (Date.now() + offset) для летунов и фигурок
scene.flyer(event); scene.shot(event); // летуны: запуск, падение (+ выстрел фигурки игрока из event.player)
scene.flyerAt(clientX, clientY);     // id летуна под указателем или null
scene.walker(w);                     // фигурка появилась или сменила вид/имя (Walker)
scene.move(id, walk, clink, stop);   // фигурка пошла (Walk); clink — цель, если идёт чокаться по клику (иначе null);
                                     // stop — действие, остановившее ход (иначе null)
scene.leave(id);                     // фигурка ушла
scene.setMe(id);                     // своя фигурка: имя другим цветом
scene.walkerAt(id);                  // где фигурка нарисована (координаты конфига); для проверок лаборатории
scene.walkerHit(clientX, clientY);   // id фигурки под указателем (ближняя к камере) или null; что делает клик — решает клиент
scene.clink(event);                  // событие clink: пара чокается от at; старше 3 с — не играется
scene.groundAt(clientX, clientY);    // {x, y} земли в координатах конфига (обратный spreadX) или null над небом
scene.perch();                       // {x, y, px}: точка на ветке (после отлёта совы — над FrankenPHP), CSS-пиксели от #app; px — CSS-пикселей в арт-пикселе
scene.owl({ms, hoot});               // сова говорит ms: клюв и крыло; hoot — драматичная реплика, сначала нахохлится;
                                     // возвращает 0; после отлёта совы реплика просто показывается над FrankenPHP
scene.setFinale({step, ready});      // шаг финала (null вне финальной сцены) и замкнут ли круг; следующий шаг играется
                                     // с анимацией, любой другой (перезагрузка, ресинк, reduced motion) — сразу итогом
scene.onCue(fn);                     // моменты для звука без события канала: fn({type: 'owl-away'}) — сова взлетает на шаге 5,
                                     // {type: 'franken', text, x} — началась фраза FrankenPHP (пойманная позже 1,5 с — нет),
                                     // {type: 'clink', x, sides} — удар автоматического чоканья (раз на чоканье, позже 0,4 с — нет); x — % ширины,
                                     // sides — [{id, x, y}] участники в координатах конфига (бар: clink.auto)
scene.owlGone();                     // сова улетела: её реплики теперь над FrankenPHP
// Рапира (см. «Рапира»); клиент зовёт их с ?., эффект — до scene.walker с новым состоянием фигурки:
scene.owl({ms, hoot, line, part, rapier}); // line — id реплики (null у своего текста), part — номер части, rapier — на ней сова достаёт рапиру
scene.takeFromPumpkin(pumpkinId, playerId, until); // take с pumpkin: тыква отдаёт свою кружку к until и достаёт новую (серверные часы; null — сейчас + 900 мс); следом scene.walker с item: beer
scene.word(event);                   // word: ok — свечение и рапира, иначе превращение в зомби; следом scene.walker
scene.cure(event);                   // cure: искра от by к player, перекраска уходит; следом scene.walker без zombie
scene.boss(boss);                    // {hp, max} или null: проснулся (очки, фразы BOSS_PHRASES), hp сменился, hp 0 — пепел
scene.strike(event);                 // strike: золотая молния от player к FrankenPHP, вздрагивание; следом scene.boss
scene.render(snapshot, {again});     // снимок несёт cursed и boss; again: true — reset «В бар», рассвет гаснет в бар за 3 с
// Кости и мип-мип (см. «Кости»):
scene.roll(event);                   // roll: маленькие кости над фигуркой player или рядом с совой, ~2 с от at
scene.diceWin();                     // первое 6-6-6: у силуэта вспыхивают глаза
scene.meep(flyer);                   // meep: пузырь над бегуном flyer или RoadRunner сцены; x в % ширины или null — его не видно
scene.runnerAt(flyer);               // x этого RoadRunner в % ширины или null (панорама звука)
scene.flyerKind(id);                 // вид летуна или null: клик модератора по roadrunner — meep
// Чат (см. «Чат»):
scene.say(id, text, until);          // бабл реплики над нарисованной фигуркой id до until (серверные часы); новая заменяет
                                     // прежнюю; фигурки нет или until прошло — ничего
```

### Правила рендеринга

- **Цифры прогресса — только модератору** (**реализовано**, решение пользователя от 2026-10-23; scenario.md, «Цифры
  прогресса»). Прогресс задачи сцены игрок видит одними шкалами: тыквы («Готово»), бар («Выпито»), проклятый мир
  («Выпито», «Зомби»), здоровье босса (без подписи). У модератора (`model.moderator`, RPC `me`) те же шкалы с числами:
  «Готово 3 из 8», «Выпито 12 из 30», «Зомби 3 из 20», «HP 57 / 90». Одно правило в `client.js`: шкалы строит
  `meterOf(label, n, target)` (`drinksOf`, `pumpkinsDoneOf`, `goalsOf`), подпись и ARIA ставят `paintMeter` /
  `paintProgress`. Игроку `role="progressbar"` отдаёт долю: `aria-valuenow` — проценты (0–100), `aria-valuemax="100"`,
  без `aria-valuetext`; модератору — сами числа и `aria-valuetext` с текстом подписи. `client.setModerator`
  перерисовывает шкалы. Сервер шлёт числа всем; прячет их только клиент.
- **Только из событий.** Свой клик клиент не рисует локально: эффект появляется, когда из канала приходит `click`,
  у кликнувшего так же, как у всех. Задержка круга браузер → сервер → браузер — часть демонстрации.
- Клик по тыкве → `centrifuge.rpc('click', {element})`. Служебные ссылки (тыква с «?» на `/how-it-works`) — обычные
  `<a>` без `data-element`; ссылки на «Как это работает» (тыква с «?», кнопка в разоблачении) открываются в новой
  вкладке (`target="_blank" rel="noopener"`), чтобы не уводить со сцены.

### Пульт модератора

`<aside data-debug-panel hidden>` в правом верхнем углу; содержимое строит `debug.js`. **Только модератору**: панель
видна, когда RPC `me` вернул `moderator: true`; остальным её нет вовсе (их RPC пульта сервер всё равно отклонит

до перезагрузки), параметр убирается из адреса (`history.replaceState`), секрет уходит в `data` подключения рядом с
`playerSecret`; `?moderator=` (пусто) забывает секрет.

- **Свернуть/развернуть**: заголовок «🦉 Пульт» (`data-console-toggle`, рядом — сводка `data-console-summary`: сцена или
  шаг финала, «готова», «×k»; перед ней — золотая плашка «пауза» `data-console-paused`, пока включена пауза прогресса), клавиша «`» (не в полях ввода), `?debug=1` / `?debug=0`. Состояние запоминается в
  `localStorage['hellowin:console']`; по умолчанию развёрнут на экране шире 600 px, на телефоне свёрнут.
- **Сюжет**: «Следующая сцена» (`data-action="scene-next"`, RPC `scene.next {scene}`; при `ready` подсвечена и
  срабатывает сразу, без `ready` — двойное нажатие «Не готово. Точно?» и `force: true`; в финальной сцене скрыта; **запланировано**: на шаге финала 7 снова видна — «В бар», новый цикл вечера);
  «Шаг финала N» (`data-action="finale-step"`, RPC `finale.step {step: текущий + 1}`; только в финальной сцене, после

  замкнут. Точно?» и `force: true`); «Заново» (`data-action="reset"`, двойное нажатие, RPC `reset {round}`); «Пауза

  что делает: задача сцены замирает — клики, кружки, удары и кости не засчитываются, летуны и зомби летают, снимается и

  закат — «Поторопить», «Улики»; ночь — «Поторопить», «Про летунов»; финал — «Поторопить» на шагах 0, 1, 5, 6, 7 (текст
  по шагу), «Прощание» — только на шаге 7; на шагах 2–4 (кино) кнопок реплик нет. `title` кнопки — текст, который
  услышит зал сейчас (`lineText` с текущими сценой и шагом). Авто-реплик в меню нет («Повторить…» убран), «Начало»
  (`intro`) убрано — его заменило вступление бара `bar-intro`. Поле своего текста (`data-owl-form`, `data-owl-input`,
  до 200 символов) → `owl.say {text}` — всегда. Реплики с `{player}` с пульта не говорятся — некого подставить.
- **Нечисть**: «Ведьма» (`data-action="witch"`) — во всех сценах, кроме бара (0); «Бегун» (`data-action="roadrunner"`) —
  в сценах, где он редкий летун сцены (`HELLOWIN_FLYER_RARE`, по умолчанию все, кроме бара; в финале — до шага 3); оба — RPC `flyer.special {kind}`. «Пуск летунов»
  (`data-action="flyers-burst"`, бриф №22) — видна, пока `limits.burst === true` (у набора летунов сцены, проклятого мира
  или рассвета есть виды); RPC `flyers.burst {}`, ответ `{count}` — надпись «+N летунов» (с согласованием: летун, летуна,
  летунов) на несколько секунд; кулдауна и потолка нет — каждое нажатие даёт волну; `no flyers` — «Нет летунов», как
  прочие ошибки. Переключателя «Зомби» нет (бриф №22: RPC и событие `zombies` удалены). Пауза прогресса — в «Сюжете».
- **Лимиты** (бриф №22; protocol.md, «Лимиты и баланс»): текущий множитель «×1,00» (`data-k-value`, `title` и
  `aria-label` «Множитель лимитов»), «÷1,25» и «×1,25» (`data-action="k-down|k-up"`, RPC `thresholds {k}` с `k` модели,
  делённым или умноженным на 1,25, округлённым до сотых и зажатым в 0,1–10), поле (`data-k-form`, `data-k-input`: текст
  с `inputmode="decimal"`, запятая или точка, плейсхолдер — текущее `k`) и «OK» (`data-action="k-set"`, `k` до сотых; вне
  диапазона уходит на сервер — его `invalid k` и показывается, не число — та же надпись без RPC; при успехе — «✓» и поле
  очищается). Ниже — «онлайн: P · подключений: C» (`data-console-online`, из `presence`; решение пользователя от 2026-10-26), «на поле: n» (`data-console-players`; n — `limits.players`, число фигурок после дебаунса сервера, не
  `online`; без `limits` — «—») и лимиты текущего контекста (`data-console-limits`, `limitsText` в `debug.js`) — только
  пришедшие ключи, по порядку: «тыква N кл./стадию», «костёр N кл./стадию», «круг N кл./стадию», «бар N кружек» (с
  согласованием), «кружки N», «зомби N», «HP босса N»; пустой объект — «в этой сцене лимитов нет», `limits` ещё не
  пришли — «лимиты ещё не пришли». Всё из модели: лимиты считает сервер, формулы клиент не знает. При `k` ≠ 1 сводка в
  заголовке показывает «×k».
- **Надбавки**: «±5 бокалов» (бар), «±5 кружек» / «±5 зомби» (проклятый мир), «HP ±10» (босс) — надбавки поверх формулы
  лимитов до конца раунда (`bar.target`, `cursed.target`, `boss.hp`); подписи прежние, `title` — «… больше/меньше:
  надбавка до конца раунда».
- **Рапира** (см. «Рапира»): группы «Проклятый мир» (шаг 5) и «Босс» (шаг 6, пока босс жив); «Шаг финала» — до 7.
- **Кости** (**реализовано**, см. «Кости»): «Сова бросает» на шаге 1, пока режим костей включён.
- **Чат** (**реализовано**, см. «Чат»): история чата, «заглушить» / «вернуть слово», список заглушённых.
- **Мип-мип** (**реализовано**, бриф «Мип-мип по клику»): у модератора RoadRunner кликабелен везде, где виден. Бегун на
  горизонте — `scene.flyerAt` находит летуна `roadrunner`: модератору вместо `shoot` — RPC `meep {flyer}` (игрокам —
  `shoot`, как раньше, всегда промах). RoadRunner финала (шаг 3+) — хит-зона `[data-rr-meep]` только у модератора,
  идёт за ним (`--rr-meep-x|y|w|h` публикует сцена; скрыта, пока его не видно) → `meep {}`. В баре после рассвета клик
  модератора по `[data-roadrunner]` — `meep {}` вместо чоканья. Событие `meep` у всех → `scene.meep(flyer)`: пузырь
  «Мип-мип!» (`pixel/bubble.js`, 1,6 с) и кадр `meep` над бегуном `flyer` или, без поля, над RoadRunner сцены; кого
  сейчас не видно — ничего; старше 1,5 с по `at` — не рисуется. Состояния нет. Хит-зона финала — не меньше 28 CSS px по
  каждой стороне (дальний бегун — несколько арт-px), видна при `#app[data-rr-shown]` (его ставит сцена). У RoadRunner
  за стойкой кадра `meep` нет (кадры с кружкой) — только пузырь; его тост на это время уступает пузырь.
- **Отладка**: «Клик по всем» (`data-action="click-all"`, RPC `click` по каждой тыкве с разносом ~30 мс); «Сбросить статистику» (`data-action="stats-reset"`, решение пользователя от 2026-10-28; двойное нажатие — первое взводит кнопку «Стереть у всех. Точно?», второе шлёт RPC `stats.reset`, ответ — «обнулено: N»; лаборатория очищает топ; `busy` — «Занято», нажать ещё раз; **реализовано**).
- Ответ сервера кнопка показывает надписью на несколько секунд (`data-note`): успех действий без состояния — «✓»,
  ошибка — «Нет прав» (`forbidden`), «Не готово», «Уже финал», «Не финал», «Пустой текст», «Занято», «0,1–10»
  (`invalid k`), «Нет летунов» (`no flyers`), прочее — «Не вышло».
  Состояние (подписи, подсветка, `aria-pressed`) — только из модели клиента: результат любой кнопки приходит событием
  канала, как у всех.
- На телефоне пульт — колонка шириной экрана минус поля, тело прокручивается, поверх панели разоблачения.

`scene` снимает `ready`, вне финальной сцены — и `finale` (в финальную `finale {step: 0}` приходит следом). `reset`
снимает `ready`, `finale` и `paused` (сброс и «В бар» снимают паузу прогресса, `pause {on: false}` не приходит), `k` и
`limits` оставляет (новые лимиты бара приходят событием `limits`; множитель — про зал, а не про сюжет). Пульт перерисовывается
после каждого применённого события и снимка (`onChange` клиента).

Снимок несёт `limits` (как событие) и `dice.owl` — сколько раз сова бросила кости в раунде: модель держит его в
`owlRolls` (из снимка — максимум с уже виденным, новый раунд — 0; дальше — по событиям `roll` с `owl`), так пульт и после
перезагрузки предлагает верную попытку «Сова бросает (N/3)».

Кто «я»: `player.id` из ответа RPC `me` (после каждого подключения) или `register` → `client.setMe(id)`. Ходить
(`client.canWalk()`) может браузер, чья фигурка (`walkers[].id == me`) есть на поле. Модель держит `reachable` тыкв
(из `data-reachable` разметки и из снимка: без поля — `false`) и `clink` фигурок (из снимка и `move`).

Маршрутизация клика по сцене (`app.js`): выстрел по летуну (`bindShooting`, `pointerdown` в фазе захвата) — первым;
затем, только в проклятом мире (`client.cursed()`: финальная сцена, шаг 5+) и только с фигуркой (`canWalk`), —
чоканье: клик или тап по **чужой** фигурке (`scene.walkerHit` → `client.clinksWalker(id)`) — RPC `clink {walker}`
(`bindClinking`, `click` в фазе захвата после выстрелов; клик гасится и до земли и кнопки тыквы не доходит;
клавиатурный клик, `detail` 0, оставлен кнопке), клик по кнопке тыквы с `reachable` (`client.clinksPumpkin(id)`) — RPC
`clink {pumpkin}` вместо `click`, по дальней — `click`; иначе — `move` по земле (`bindWalking`), клик по своей
фигурке — тоже `move`. По клику ничего не рисуется: путь приходит событием `move`, чоканье — событием `clink`; отказ
(`busy`, `no target`…) — `console.warn`. Над чужой фигуркой в проклятом мире у `#app` — `data-clink-hover`
(курсор-рука; на тач-устройствах не ставится); у кнопок тыкв курсор-рука и так.

- **Пересинхронизация.** После переподключения (кроме первого) и при любом событии, кроме `reset`, с `round`,
  отличным от текущего, — RPC `state` и `scene.render` из снимка. События, пришедшие до ответа, отбрасываются.
- Ошибки RPC (`busy`, `unknown element`, сеть) — в `console.warn`, на экране не показываются. Отказа `paused` больше
  нет (protocol.md, «Пауза прогресса»): на паузе `click`, `drink`, `strike`, `roll` принимаются с `counted: false`, и
  клиент рисует их события как обычные — тряска и частицы клика с прежними `clicks`/`stage`, глоток без `drinks`,
  молния `strike` с прежним `hp`, кости `roll`. `counted` нигде не подсвечивается; единственное, что он меняет, —
  6-6-6 с `counted: false` не выигрывает и на странице (`winsRoll` в `dice.js`, см. «Кости»).

### Сцена 1 «День: подготовка»

- **Фон.** Камера низко, взгляд вдоль земли: горизонт на 37% высоты, над ним небо с солнцем и облаками, у горизонта
  дальние холмы и кромка леса (дымка — дизеринг с цветом неба). Грядка — сильно сплющенный эллипс (полуоси ~47% ширины
  и до 25% высоты), борозды сходятся к горизонту, вдали всё мельче и реже. В центре
  корень, от него к хвостику каждой тыквы идёт изогнутый побег с густой листвой (лопастные тыквенные листья
  2–3 размеров, усы). Вокруг грядки — сорняки и высокая трава, гуще к краям экрана.
- **Плотная грядка.** Грядка небольшая (полуось ~33% ширины), тыквы крупные (l 44×38, m 34×30, s 26×23 арт-px) и стоят
  тесно: спрайты ближних перекрывают дальние. Хит-зона кнопки — ядро тела (~72% спрайта, без хвостика), ядра не
  перекрываются, `z-index` кнопки растёт с `y`. Кнопки позиционирует CSS через `--x`/`--y` и `--spread`
  (`spreadX(width)` из `public/js/layout.js`, общий для DOM и сцены вместе с центром корня): на узких экранах раскладка
  растягивается по x от центра. Побеги извилистые, с боковыми отростками; толщина 4 → 2 арт-px.
- **Раскладка тыкв** — `elements` в `app/config/hellowin.php` (правит фронтенд): ~18 тыкв неровным кольцом-эллипсом
  вокруг корня (50%/63%, `ROOT` в `scene.js`), ближе-дальше от центра вразнобой; дальние (выше на экране) чаще мельче.
- **Дерево** — слева, дальше грядки (за ней по глубине), ветка тянется к середине экрана. На ветке есть точка
  `perch` (спрайт `DECOR.tree`) — туда в будущей сцене прилетит сова; сцена держит её экранные координаты.
- **Тыквы** трёх размеров (`s`/`m`/`l` — разная пиксельная сетка, не растяжение), с хвостиком; ограниченная палитра
  с hue-shift (тени к красно-коричневому, блики к жёлтому), выборочный контур, без сглаживания. Стадии — по таблице
  в `scenario.md`: 0 целая → 1 глаз → 2 два глаза → 3 рот, верхушка срезана, видна мякоть → 4 пустая (тёмное нутро).
  До выскабливания (стадии 1–3) в прорезях и в срезе верхушки — мякоть, а не тёмная дыра: бледная оранжево-жёлтая
  (`pulp`) с семечками и волокнами, сверху и слева затенена (`pulpShade`) — край кожуры нависает, вырез читается
  углублением; освещается как кожура (не светится). Тёмное нутро — только со стадии 4.
- **Вариативность.** Вид тыквы детерминирован от `seedOf(id)` (CRC32 id): какой глаз вырезается первым, форма глаз
  (треугольник, круг, полумесяц, косые), форма рта (зигзаг, улыбка, «О», один зуб…), число долек, оттенок, хвостик.
  Одна и та же тыква выглядит одинаково у всех и после перезагрузки.
- **Слои.** Тыква — стопка слоёв, а не один спрайт: `back` (задняя стенка и нутро, видно сквозь вырезы), `body`
  (кожура с вырезанными отверстиями), `rim` (кромка мякоти по краям вырезов), `stem` (хвостик), `glow` (маска
  отверстий и среза — в ночной сцене туда кладётся свечение изнутри). Днём `glow` скрыт.
- **Клик** (событие `click`): короткая тряска/сплющивание тыквы (2–3 кадра) и частицы по стадии:
  стадии 0–2 — оранжевые куски `chunk` разлетаются от места выреза, падают с гравитацией и исчезают;
  стадия 3 — семечки `seed` и волокна мякоти `pulp` фонтаном из верхушки; стадия 4 (`data-done`) — сгоревший клик:
  пара серых искр, без частиц тыквы.
- **Переход** (событие `pumpkin`): белая вспышка-силуэт на 1 кадр, смена спрайта, «отскок».
- Готовность: тыква с `data-ready` мерцает контуром; с `data-done` — лёгкое покачивание.
- HUD: лампочка связи, название сцены, шкала тыкв «Готово» (`data-done` тыкв; только в сценах 1–3; у модератора —
  «Готово N из M», см. «Цифры прогресса» в «Правилах рендеринга»). Пиксельный шрифт — системный моно
  или bitmap через `BitmapText`.
- `prefers-reduced-motion`: без тряски и частиц, переходы — мгновенная смена спрайта.
- От 390 px по ширине: позиции в процентах, масштаб арт-пикселя меньше, HUD в две строки.

### Летуны

Механика — [`scenario.md`](scenario.md), события `flyer` / `shot` и RPC `shoot` — [`protocol.md`](protocol.md).

- Полёт клиент считает сам по серверному времени: прогресс `(Date.now() + offset − launchedAt) / duration`, где
  `offset` — смещение серверных часов: `now` снимка страницы — только первая оценка (он вписан при рендере, и доставка
  страницы и загрузка скриптов, а после «Назад» из bfcache — и того больше, сдвигают его, и у двух браузеров рядом птицы
  вылетали бы в разное время); затем при каждом подключении, возврате во вкладку и `pageshow` из bfcache клиент делает 5
  замеров RPC `time` (без него — `state`) и берёт замер с минимальным RTT: `offset = serverNow + rtt/2 − t1`;
  летун при `Date.now() + offset >= expiresAt` не рисуется и убирается. Путь — прямая `from → to` или квадратичная
  кривая через `via`. Глубина `depth` задаёт масштаб (дальние мельче), слой (дальние позади дерева, ближние перед
  грядкой) и скорость взмахов. Утка из куста: куст шуршит, утка взлетает из его точки.
- Летуны движутся каждый кадр, поэтому попадание проверяет **canvas** (PixiJS hit-test по спрайту с запасом), а не DOM:
  клик по утке → `centrifuge.rpc(shoot, {flyer})`. Клик мимо — без RPC. Как и с тыквами, по своему выстрелу
  ничего не рисуется: падение — только по событию `shot` (перья, утка кувыркается вниз, всплывают очки).
- Кусты (`#app[data-bushes]`, JSON) и траектории летунов — в процентах экрана **без** `spreadX`, как на сервере.
- Перехват: `bindShooting` (`public/js/client.js`) слушает `pointerdown` на `#app` в фазе захвата, `scene.flyerAt(x, y)`
  проверяет летунов от ближних к дальним по хит-боксу тела (~60% спрайта, без крыльев и хвоста — сбить должно быть
  непросто); при попадании клик гасится и до кнопки тыквы не доходит.
- Слои: летун никогда не позади дальнего плана (холмы — за километры). `depth` 0 — перед холмами, за деревом, плетнём
  и наземными объектами, с лёгкой дымкой к цвету неба; `depth` 1 и 2 — над наземными объектами. Полный рендер (resync, `reset`) убирает летунов.
- Спрайты — `public/js/pixel/flyers.js`, живой пример — `public/dev/flyers.html`.
- **Светлячок** (`firefly`, проклятый мир, **реализовано** в лаборатории): нарисован по глубинам вручную (точка 3×2,
  ~8×5, ~12×9): тёмные надкрылья, красный щиток, бледные крылья машут, фонарик на хвосте. Тело рисуется как у любого
  летуна; фонарик — слой `glow` (3 уровня: тусклый, средний, яркий) цветами свечения FrankenPHP поверх тела без
  перекраски и аддитивный ореол `halo(…, 'franken')` под телом. Мигает по своему ритму: раз в 1,7 с яркий ~0,5 с с
  дрожью, иначе тусклый (`prefers-reduced-motion` — ровный средний). Путь — с `wobble`. Сбитый гаснет: фонарик и ореол
  пропадают, тело падает как у мыши, вместо перьев — лаймовые искры.
- **Муха** (`fly`, бар, **реализовано** в лаборатории и проверено на событиях живого backend): один спрайт на все
  глубины (`FLYERS.fly`, 6×5, якорь под лапками): тёмное тельце с красным глазом и бликом на спинке, крылья — самые
  светлые пиксели двух тонов, меняются каждые 35 мс (4 кадра), и мельтешение читается как прозрачные крылья; рисуется
  как нарисована, как все летуны в воздухе (без перекраски светом бара и без свечения), — бледные крылья не тонут в
  тёплом дереве. Сидя — крылья сложены «крышей» на спине, раз в 1,4 с муха потирает передние лапки (420 мс, два
  кадра) и вздрагивает крыльями. Путь — `public/js/pixel/fly-path.js` (`flyPlan`, `flyAt`; без DOM, его же берёт
  `sound.js`): точки `from → stops… → to`, перелёт — `(duration − Σsit) / (число stops + 1)`, на каждой точке муха
  сидит `sit` мс ровно в ней. На перелёте — прямая плюс окружность через точку на прямой, пройденная 1–2 раза:
  смещение `r·(cos(φ+a) − cos φ, sin(φ+a) − sin φ)`, `a = ±2π·loops·s`, в начале и конце перелёта оно нулевое, так что
  муха садится точно в точку; число петель, радиус (3–6 % меньшей стороны экрана, по x делится на соотношение сторон —
  петля круглая), направление и `φ` (центр петли над прямой, ±0,6 рад — муха кружит над столом, а не сквозь него)
  — из FNV-хеша `flyer#номер перелёта`, у всех зрителей одинаково. Прогресс `s` — с плавностью: первый перелёт
  влетает с ходу и тормозит (`1−(1−t)²`), между посадками — взлёт и посадка мягкие (smoothstep), последний разгоняется
  к `to` (`t²`), один перелёт без посадок — ровно. Смотрит туда, куда летит по кривой (знак производной по x), сидя —
  как подлетела. Хит-бокс — по постоянной рамке тела (`box`) плюс 2 px вокруг, одинаковый в полёте и сидя. Сбитая
  (`shot`): кадр попадания 120 мс, сидевшая сразу, летевшая — 260 мс падает вниз (до ~12 px), затем клякса (`splat`)
  и четыре тёмные капли; клякса мигает и пропадает к 1,2 с; перьев нет. Фигурка-стрелок в баре поворачивается к мухе
  как к тыкве по клику (вбок, лицом или спиной — по dx/dy, а не «небо всегда за грядкой») и стреляет тем, что в руке
  на экране (пиво — пузыри отрыжки; без пива — пистолет: прицел, отдача, дымок, как днём; см. «Бар и сдвиг номеров
  сцен», «Предметы и анимации»).

### Экран входа и персонажи

**Фронтенд — реализовано** (проверено в лаборатории), **в работе** — ждёт backend. Правила — [`players.md`](players.md)
(«Персонаж», «На поле»), протокол — `register {name, look}`, `move`, события `walker` / `move` / `leave`, `walkers` в
снимке.

- **Секрет игрока** — `localStorage['hellowin.secret']` (UUID, при первом визите), уходит только в `data` подключения
  (`{playerSecret}`). Без `localStorage` секрет живёт до перезагрузки страницы.
- **Экран входа** — `<dialog data-join>` поверх главной (`public/js/join.js`, разметка в `home.dark.php`): при первом
  визите (в `localStorage` нет `hellowin.look`) и по кнопке «Персонаж» в HUD. Поле имени `data-join-name`; по каждой
  части `look` — строка «‹ название ›» (`data-part="body|cloak|face|eyes|hat"`, у глаз — квадратик цвета); «Случайно»;
  превью — персонаж крупно, поворачивается спереди → сбоку → сзади → другим боком и шагает на месте (при
  `prefers-reduced-motion` — стоит лицом); «На поле» → `register {name, look}`, при успехе `hellowin.name`/`hellowin.look`
  запоминаются в `localStorage` для следующего входа; ошибку показывает под полем (`invalid name` — правило имени,
  `invalid look`, `anonymous`, прочее — «Не вышло»). «Просто смотреть» и Esc закрывают экран без регистрации —
  зритель не ходит, а при следующем визите экран покажется снова. Превью рисуется обычным 2D-canvas
  (`image-rendering: pixelated`), без PixiJS. Доступ к `localStorage` — в `try/catch`.
- **Персонажи — сборные спрайты** (`pixel/characters.js`). Каталог частей с подписями (`CATALOG`), части по
  умолчанию, `randomLook()`, сборка кадра из слоёв: накидка сзади → тело → лицо (цвет глаз — замена пикселей
  палитры) → шапка → накидка спереди → рука с предметом. Тело задаёт по кадру смещение головы и точку кисти;
  шапки, лица и предметы рисуются один раз на направление и ставятся по этим точкам — так частей много, а кадров мало.
  Неизвестный id части — часть по умолчанию. Тела: скелет, ведьма, балахон, рестлер, вампир, мумия, зомби, пугало,
  кот, PHP-слоник (`elephant`, синий PHP-цвет), Go-гофер (`gopher`), священник (`priest`), робот (`robot`), качок (`bodybuilder`), динозавр (`dino`), клоун (`clown`), терминатор (`terminator`). Своё у
  тела — необязательные хуки: кошачьи уши (только без шапки), морда, усы, хвост; у слоника уши по бокам головы и хобот
  видны с любой шапкой и лицом, хвост с кисточкой — сбоку и сзади. У гофера свои большие белые глаза, зрачки —
  цветом из слота глаз (с тёмной точкой, как глаза лиц), бежевая морда с носом и два резца — поверх слота лица (от лица
  видно только то, что вокруг них), круглые ушки — только без шапки, живот расширен юбкой. Священник — чёрная ряса до пола
  (подол — юбка, как у балахона: на ходу из-под неё видны только ботинки), белая колоратка, золотой крест на цепочке.
  У робота квадратная голова целиком своя: латунные динамики по бокам видны всегда, две антенны с красными шариками —
  только без шапки; лицевая панель (глаза в латунных оправах, линзы — цветом из слота глаз, нос-заклёпка, решётка зубов в
  латунной рамке) закрывает слот лица целиком; на груди шкала со стрелкой и кнопки, кисти большие круглые. Качок — в
  духе Рэмбо: голый загорелый торс с грудью и прессом, накачанные руки и бёдра (хук `brawn`: бицепс и бедро выпирают на
  пиксель наружу, плечи с дельтами — поза, предмет и прицел те же, что у всех), штаны хаки с тёмными пятнами, чёрные
  длинные волосы, красная повязка на лбу (видна с любой шапкой, кроме тыквы, капюшона и «Кепки Валеры»; хвостики узла — только без
  шапки, как кошачьи уши). Динозавр — лаймовый (светлее газона) малыш-тираннозавр: своя морда поверх слота лица (от лица
  остаются глаза): спереди светлая морда с ноздрями и зубастой улыбкой, сбоку челюсть выдаётся вперёд; светлое брюшко;
  оранжевые шипы — гребень на макушке (только без шапки, как кошачьи уши), сзади цепочка по затылку и спине, сбоку на
  спине; толстый хвост с шипами сбоку и сзади (сзади свисает между ног и ложится на землю поверх них, спереди его не
  видно). Клоун — белое лицо в гриме (синие штрихи над и под глазами, красные губы под ртом лица — рот любого лица ложится
  на красное), красный нос-шарик поверх слота лица, лысая макушка и рыжие кудрявые пучки по бокам (торчат из-под любой
  шапки), мешковатый костюм пополам фиолетовый/оранжевый с кремовыми помпонами и жабо, белые перчатки, большие красные
  башмаки (хук `bigShoe`: спереди и сзади шире наружу, сбоку длинный круглый нос). Терминатор — T-800: чёрная кожаная
  куртка поверх серой футболки, тёмный «ёжик»; правая половина лица персонажа (спереди — слева от зрителя, сбоку — та,
  что видна) сорвана до стального черепа с красным машинным глазом и рваным краем кожи — поверх слота лица, второй глаз
  (спереди) — цветом из слота глаз. Машинный глаз (`cyborgEye`, `cyborgEyeHot`) ночью светится, как зелёные и
  фиолетовые глаза (`night.js`, `EMISSIVE`), в зомби-перекраске остаётся красным (это не слот глаз). Зомби-перекраска у них общая: кожа и кисти зеленеют, глаза белеют (зрачки гофера и линзы
  робота тоже), у качка зеленеет весь загар. Пиратский набор: шапка «Треуголка» (`tricorn`: чёрная, золотой кант, белый
  черепок спереди) и лицо «Повязка на глаз» (`eyepatch`: повязка с ремешком через лоб и вокруг затылка — у лица есть вид
  сзади, второй глаз цветом глаз, кривая ухмылка; сбоку повязка закрывает видимый глаз; повязка с ремешком — то, что лицо
  «надевает» (`worn`): у тел со своей мордой поверх слота лица (`snout`) она рисуется поверх морды — у гофера и робота на
  их собственном глазу (`wornOn`: у гофера закрывает весь большой белый глаз, у робота — линзу с оправой, ремешок к
  макушке), у слоника, динозавра, клоуна и терминатора — на месте глаза лица; у терминатора спереди повязка на
  человеческом глазу, а красный светит, сбоку — на видимом, машинном). Шапка «Ирокез» (`mohawk`):
  панковский гребень из торчащих прядей-шипов ото лба до затылка, бока не закрыты (видна голова тела как есть: кожа,
  маска, волосы). Цвет идёт от корня наружу: у корня ярко-розовый (`mohawk`, тень — `mohawkShade`), кончики прядей —
  цветом из слота глаз, середина — оттенок посередине между ними по кругу тонов (розовый и зелёный встречаются в
  оранжевом, а не в буром). Спереди и сзади — узкая полоса с кончиками, торчащими в обе стороны (сзади полоса ещё
  сбегает по затылку), сбоку — гребень веером из четырёх шипов. Гребень растёт из головы: контур у него только там, где
  он торчит за голову (`grown`), а не поперёк макушки. Как у других шапок, кошачьи уши, ушки гофера, антенны робота и
  хвостики узла повязки качка с ним скрыты; сзади полоса гребня ложится поверх узла повязки. В зомби-перекраске кончики
  белеют вместе с глазами (середина — сиреневая), корень остаётся розовым, как и прочие шапки не меняют цвет. Ночью у
  зелёных и фиолетовых глаз кончики светятся, как сами глаза. Шапка «Кепка Валеры» (`valera`, en «Valera's cap»): тёмно-серая бейсболка в духе New Balance (`capLight`,
  `cap`, `capShade`, надпись — `capLogo`). Спереди — купол с пуговкой на макушке, светлая надпись «NB» (N — 4×4, B —
  3×4 пикселя) и козырёк: светлая верхняя кромка шире купола и тень под ней. Сидит низко: козырёк кончается за ряд до
  глаз, его контур ложится на лоб, а не на глаза; повязку качка он закрывает целиком. Сбоку козырёк торчит вперёд за
  лицо на четыре пикселя, кончик чуть загнут вниз. Сзади — купол без надписи, над серым регулятором ремешка тёмный
  вырез. Как прочие шапки, скрывает кошачьи уши, ушки гофера, антенны робота, хвостики узла качка и гребень динозавра,
  в зомби-перекраске цвет не меняет, поднятые в ритуале руки проходят под козырьком. Глаза «Чёрные» (`black`): в
  каждом глазу от трёх пикселей — белый блик в верхнем левом пикселе (одно-пиксельные глаза, как у «Черепа», — без
  блика); огоньки над ладонями в ритуале у чёрных глаз — бледно-голубые, кончики ирокеза — шерсть кота (`crow`), на
  ступень светлее контура, иначе слились бы с ним. Новые части встают в конец своих списков:
  сохранённые виды не меняются, `randomLook()` делит шансы поровну.
- **Направления** — спереди, сзади, сбоку (влево — зеркало). **Позы**: стойка (дыхание), переминание, ходьба
  (4 кадра), стойка с согнутой в локте рукой, держащей предмет (`item`: пиво, метла, пистоль…), выстрел (`shoot`:
  пистоль — свои спрайты прицела с отдачей, другой предмет — на вытянутой руке, пустая рука — указывает).
- **Ходьба.** Фигурки — в `groundLayer`, сортируются по y ступней вместе с тыквами и реквизитом. Позиция — по `walk` и
  серверным часам (то же смещение, что у летунов): постоянная скорость вдоль ломаной, длина — в единицах конфига, как
  `HELLOWIN_WALK_SPEED` на сервере; направление — по экранному наклону текущего отрезка (сбоку, если |dx| ≥ 0,8·|dy|,
  влево — зеркало). Координаты `walk` → экран тем же преобразованием, что тыквы (`spreadX`); на узком экране
  лужайка шире экрана, и фигурка за его краем рисуется прижатой к краю (10 арт-px), а не пропадает. Клик по земле (не
  по тыкве, не по летуну, не по HUD и панелям) у игрока с фигуркой на поле → `move {x, y}` в координатах конфига
  (`scene.groundAt`: обратный `spreadX`, 0,1 %; над горизонтом — `null`, без RPC). Свою фигурку клиент локально не
  двигает: она пойдёт, когда придёт `move`, — как и всё остальное, только из событий.
- **Ходьба без скачков** (решение пользователя). Где фигурка «на самом деле» сейчас, клиенту не важно: важно, чтобы
  нарисованная позиция была непрерывной. Фигурка идёт по своему треку — ломаной в координатах конфига на часах сцены.
  Новый путь (`move` — клик посреди пути или разбегание шага 2; `walker` с новым `walk`; снимок при ресинке и полном
  рендере) продолжается из нарисованной точки: трек — от неё через точки серверного пути, ещё лежащие впереди (точки
  до конца ближайшего к фигурке отрезка отбрасываются, в т. ч. `path[0]`), с момента обработки события, со скоростью
  серверного пути (длина / (`arrivesAt − startedAt`); у стоящего — последняя известная). Дойдёт чуть позже `arrivesAt`
  — не страшно. Направление — по текущему отрезку трека, поворот мгновенный. Задержка и оценка смещения часов меняют
  только момент, не позицию; запоздавший первый `move` тоже не прыгает туда, «где фигурка по серверу сейчас». Прыгает
  только фигурка, нарисованная дальше 15 % от серверной позиции (долгий сон вкладки), и новая — она появляется там,
  где её видит сервер. Слоты «живости» отсчитывают прибытие по треку. Проверка — `scene.walkerAt(id)` в лаборатории:
  кадр за кадром при частых кликах и с `?skew=` сдвиг между кадрами не больше одного тика ходьбы.
- **Действие останавливает ход** (бриф №20; **реализовано**, проверено в лаборатории).
  `move` со `stop` (`shoot`, `click`, `strike`, `drink`, `dice`; [`protocol.md`](protocol.md), «Действие
  останавливает ход») приходит раньше события действия: фигурка замирает в нарисованной точке (трек обрывается там же,
  без скачка), стоит, пока играет анимация действия, и затем обычной ходьбой тем же механизмом, что новый путь,
  доходит до точки сервера (`path[0]`) — если та дальше 1,5 арт-px; иначе просто стоит. Пауза — по `stop` и предмету в
  руке на экране на момент `move` (в баре пустые руки — пистолет): `shoot` и `click` — поза выстрела, с пистолем 1200 мс (`SHOT_MS`), с другим предметом или
  пустыми руками 900 мс (`ITEM_SHOT_MS`); `strike` — 900 мс (поза с рапирой, `ITEM_SHOT_MS`); `drink` — глоток,
  1200 мс (`DRINK_MS`); `dice` — кости над головой, 2000 мс (`ROLL_SHOW_MS`); неизвестный `stop` — без паузы.
  Новый `move` во время паузы отменяет её и продолжается из нарисованной точки, как всегда; `walker` с новым `walk`
  и снимок — тоже. Фигурка дальше 15 % от точки сервера прыгает, как при любом новом пути. Ничего не предсказывается:
  без `stop` фигурка идёт, как шла (и на ходу не принимает позу действия). API — `scene.move(id, walk, clink, stop)`.
  Проверка — лаборатория, `?walkstop=shoot|click|strike|drink|dice&scene=1&freeze=ms` (`?stopat`, `?stoplag`, `?walkon`; `lab.walkTrace` —
  нарисованная точка по кадрам; см. шапку `public/dev/lab.html`).
- **Имя** — PixiJS `Text` отдельным слоем поверх увеличенной арт-текстуры, в экранном разрешении (моно-шрифт HUD,
  12 px, кремовый с тёмной обводкой; своё имя — золотое), над верхним непрозрачным рядом кадра. Текст внутри
  арт-текстуры размылся бы при целочисленном увеличении, а свой пиксельный шрифт не покрыл бы кириллицу; DOM-подписи
  пришлось бы двигать каждый кадр. У края экрана подпись не обрезается.
- **Живость** — детерминированно, одинаково у всех: время делится на слоты `3500 + crc32(id) % 2000` мс со сдвигом
  `crc32(id)`; хеш `(crc32(id), номер слота)` даёт сторону (чаще лицом) и в трети слотов — переминание в начале слота.
  До первого слота после прибытия фигурка смотрит туда, куда шла. На `shot` с `player` стоящей фигурки (идущая не
  останавливается) — поворот к летуну (сбоку, если он заметно левее/правее, иначе спиной — птицы над дальним
  планом) и «выстрел» тем, что в руке (решение пользователя; см. «Выстрел»), затем обычная поза.
- **Выстрел** (**реализовано**, лаборатория). Эффект летит из точки предмета (`muzzle` кадра: дуло, `fx`-пиксель
  предмета, кончик пальца) туда, где летун был в момент `shot`; попадание по-прежнему решает сервер, анимация — только по
  событию. Поза `shoot`: кадр прицела, со 110 мс — второй кадр (у пистоля — отдача).
  - **Пистоль** (сцена 1): вспышка у дула по стволу — 3 кадра (до 50/110/170 мс: белое ядро с лучами, оторванный язык
    с искрами, рыжие клочья), 4 искры-уголька вперёд; после заката — тёплый свет на земле (`halo` 16×6, 0,9 → 0,3) и в
    воздухе у дула; на 110–230 мс фигурка дёргается на 1 арт-px назад; 8 клубов дыма: 4 выдуты из дула (летят по стволу
    и тормозят), 4 — струйки с поднятого ствола до 900 мс; клуб растёт (радиус до 3–4), всплывает, сносится ветром,
    редеет ступенями Байера и гаснет за 1,5–3 с; дым в свете точки, вспышка — без перекраски. Поза держится 1,2 с.
  - **Свеча** (и факел): вспышка пламени к цели (те же 3 кадра, направление — 16 шагов) и огненный шар (7×7, 2 кадра),
    летит 520 арт-px/с со шлейфом угольков и рассыпается угольками там, где кончился путь.
  - **Книга**: зелёная молния из книги в цель — три зубчатых варианта по 50 мс (ломаная с шагом ~7 px, ответвление,
    зелёный ореол), затем тающий, всего 260 мс; у книги — зелёная звезда и ореол после заката; в цели — искры `magic`.
  - **Пиво** (проклятый мир): отрыжка — 6 пузырей за 80–540 мс летят от кружки к цели, покачиваясь, и лопаются (кадр
    «хлопка»); пузыри не перекрашиваются, иначе ночью их не видно.
  - **Красный огонёк** (сцена 4, шаг финала 0): красный всполох у огонька к цели (кадры вспышки свечи в красных круга,
    16 направлений) и искра — четырёхлучевая звезда цвета круга (5×5, 2 кадра) летит 640 арт-px/с с плотным шлейфом
    красных угольков (выглядит полосой) и рассыпается угольками там, где кончился путь; после заката — красный ореол у
    огонька. `prefers-reduced-motion` — только всполох.
  - Пустая рука — указывает на цель без эффекта; метла, вилы — замах без эффекта. Поза — 0,9 с.
  - Дёшево: текстуры эффектов кэшируются, на выстрел — до ~20 частиц; молния — один `Graphics` на 260 мс.
    `prefers-reduced-motion`: вспышки и позы остаются, без искр и шлейфов; один неподвижный клуб дыма, молния — один
    кадр, у пива — один хлопок у кружки, у свечи — только вспышка.
  - Книга в руке — раскрытая книга, видная с одного взгляда: фиолетовая обложка по краям и снизу, корешок
    (тёмная полоса посередине), две кремовые страницы с зелёными строками; сбоку — в три четверти к камере
    (ближняя страница шире). Во всех направлениях и позах, в т. ч. `shoot`; эффект выстрела прежний.
- **Выстрел по клику** (**реализовано**, лаборатория; решение пользователя). Клик по тыкве, костру или кругу —
  тоже выстрел: на событие `click` с `player` фигурка этого игрока (если она на поле) поворачивается к элементу и
  стреляет тем, что в руке, — те же поза `shoot` и эффекты, что по летуну, только цель — элемент: середина тыквы,
  куча костра, круг на пепелище. Днём пистоль «режет» тыкву выстрелами, на закате вспышка свечи её поджигает, ночью
  молния из книги заколдовывает, в финальной сцене искра красного огонька рисует круг, в проклятом мире — пиво
  (по дальней тыкве; по досягаемой — чоканье, как раньше). Частицы клика у элемента — прежние (`scene.click`).
  - Только из события: свой клик локально ничего не рисует. Анонимный клик (без `player`) или игрок без фигурки на
    поле — без анимации. Не стреляет идущая, пьющая, разводящая руками и чокающаяся фигурка; в баре кликов по
    элементам нет. Поворот — сбоку, если цель заметно левее/правее (|dx| ≥ 0,8·|dy|), иначе лицом или спиной.
  - Прореживание (клики частые): фигурка стреляет заново не чаще раза в 420 мс после своего последнего выстрела
    (по летуну тоже); клик в эти 420 мс только поворачивает её к новой цели и держит прицел ещё 500 мс — без нового
    снаряда. На всю сцену — не больше 10 выстрелов по клику за 500 мс: сверх этого фигурка целится и даёт вспышку,
    но ничего не летит. У выстрела по клику меньше дыма (3 клуба вместо 8) и отрыжки (3 пузыря вместо 6).
  - Звук — прежний звук клика по элементу (`pumpkin.*`, `bonfire.click`, `circle.click`), `shot.*` на клик не
    играется: клики идут десятками в секунду, звук элемента уже и есть «попадание», а второй звук на каждый
    выстрел превратил бы ритуал в шум.
- **Бросок кружки** (решение пользователя от 2026-10-28; **реализовано** на фронтенде, проверено в лаборатории; backend —
  **реализовано** (0b70a0f: `item: mug`, событие `throw` только в баре и на шагах 5–6, protocol.md «Пустая кружка»); на
  живом стеке — **не проверено**).
  - **Предмет `mug`** (`characters.js`, `ITEM_DEFS.mug`) — кружка пива, выпитая досуха: та же стеклянная кружка 5×6,
    внутри — бледное стекло (`hazeLight`) с бликом (`skyLight`) по ближней стенке, у края — кольцо пены, по стенкам —
    капли (`white`/`cream`, слой `beer`: ночью не тускнеют). Во всех направлениях и позах, где рисуется пиво (стойка,
    переминание, ходьба, прицел); позы `drink` с ней нет. После `drink` модель и сцена ставят `mug` (не `null`); в баре
    `shownItem` её не трогает — пистолет только у пустых рук.
  - **Ввод.** С `mug` — как с пустыми руками: стойка (`takesBeer`) и досягаемая тыква (`beersPumpkin`) — за новым
    пивом, не чоканье; пробел и «Выпить» (`drinks`) не шлют `drink`, чоканье по клику в баре недоступно. Предмет меняют
    только события, своя фигурка не предсказывается.
  - **Бросок** по событию `throw {player, flyer, at}` (`client.throw` → `scene.throwMug`): у бросившего сразу
    `item: null`. Таймлайн от `at` (`pixel/mug-throw.js`): до `THROW.release` (120 мс) кружка в вытянутой руке (поза
    `shoot`, кадр прицела), дальше рука пустая, поза держится `THROW.pose` (900 мс, как пауза `stop: shoot`); кружка
    летит дугой (подъём — 30 % расстояния, 8–26 арт-px) к летуну, где он сейчас, и кувыркается четвертями
    (`SHOT_FX.mug`, 4 кадра с ручкой и контуром, влево — зеркально); в `THROW.impact` (540 мс) — разбивание
    (`SHOT_FX.glint` на 120 мс, 9 осколков `SHOT_FX.shards` в свете точки, 6 капель пены `SHOT_FX.foam` без перекраски,
    все с гравитацией). Исчез летун — кружка летит туда, где его видели последним; не видели вовсе — вперёд-вверх.
    Идущая фигурка (без `stop`) бросает на ходу, без позы.
  - **Попадание без рассинхрона.** `shot` того же игрока по тому же летуну приходит сразу за `throw`; сцена его
    придерживает и роняет летуна в момент удара (`impact` от `at` — у всех один), выстрела предметом при этом нет.
    Пересборка сцены (resize) роняет придержанных сразу.
  - `throw` старше `THROW_STALE_MS` (1,5 с) по `at` не рисуется и не звучит; предмет всё равно `null`, а его `shot`
    не стреляет предметом. `prefers-reduced-motion` — блик и 2 осколка, без пены.

API сцены для фигурок: `scene.walker(w)` (появилась или сменила вид), `scene.move(id, walk, clink, stop)`, `scene.leave(id)`,
`scene.setMe(id)`, `scene.groundAt(clientX, clientY)` → `{x, y}` в координатах конфига или `null`,
`scene.walkerHit(clientX, clientY)` → id фигурки под указателем (хит-бокс ±8 арт-px по x, 30 вверх от опоры) или `null`,
`scene.clink(event)`;
`scene.render(snapshot)` заменяет фигурки списком `walkers` из снимка (без поля — оставляет свои). Перехват кликов по
земле — `bindWalking(root, scene, canWalk, move)`, по чужим фигуркам в проклятом мире — `bindClinking(root, scene,
client, clink)` в `client.js`.

протокол — [`protocol.md`](protocol.md) («Модератор», события `owl`, `ready`, `finale`, `pause`, `limits`).

- **Пульт модератора** — см. «Пульт модератора» выше.
- **Сова** — спрайт `OWL` в `groundLayer` сразу перед деревом (zIndex дерева + 1), якорь (когти) — на `perch`. Покой
  — по серверным часам, одинаково у всех: слоты по 5 с, хеш `(константа, номер слота)` даёт момент моргания и в 4 из 9
  слотов поворот головы (в одну сторону; изредка — затылком к зрителю), между ними — дыхание `idle`. Пока показан
  пузырь — `talk` (клюв через 160 мс, иногда крыло); драматичная реплика (`hoot` в каталоге: начало, сцены, финал,
  зомби, костёр) — сначала 0,9 с `hoot`. С ночи (сцена ≥ 2) — `glowing()`. `prefers-reduced-motion`: стоит и
  говорит одним кадром.
- **Пузырь** — DOM `[data-owl-bubble]` над canvas (чёткая кириллица): вверх-вправо от совы по `scene.perch()`, хвост

  320 px; без canvas — сверху по центру. Время показа — `4500 + 158 мс × символ`, от 7,9 до 27 с (на четверть короче прежнего по решению пользователя от 2026-10-28; зал смотрит
  на сцену и читает между кликами). Новая реплика сменяет текущую, когда та провисела 5,6 с (короткая — всё своё
  время); реплика из двух частей (`then`) держит пузырь всю первую часть и 5,6 с второй; до этого новая ждёт в одном
  слоте (последняя побеждает) — так пара `last-pumpkin` → `scene-ready` читается целиком, вторая часть не теряется,
  а пачка реплик не копится. Свой текст модератора не ждёт: ведущий говорит вживую. Свободный текст — `textContent`, не HTML.

  канала идут по порядку, поэтому к реплике у всех зрителей уже применён один и тот же шаг (`finale` приходит раньше
  `owl`), и текст один у всех. Где какие кнопки — `MENU` (см. «Пульт модератора»). Кроме id из

  ждёт его, и цикл продолжается сразу по ответу. Ответ `{ok: true, reveal}` рисуется как `reveal` снимка и держится,
  пока шаг тот же (тик аптайма его не сбрасывает); новое `finale` или снимок приносят свои числа, ответ на запрос,
  заданный на прошлом шаге, отбрасывается. `ok: false` (в т. ч. `unknown method`, пока backend без метода), сеть, ответ
  без объекта — молча, на панели остаются последние числа. Опция `request` у `createReveal` (в `app.js` — через
  Centrifuge, в лаборатории — счётчики движка).

  `reset`) и рисуется по `ITEM_DEFS` (`characters.js`); id без рисунка — пустая рука.
- **Летуны** (**реализовано**): `crow`, `bat`, `ghost`, `witch` — наборы `FLYERS` как у уток (перья — свои, у
  дальних — одноцветные пиксели своего цвета); `wobble` (мыши) — смещение поперёк базового пути
  `amp · sin(2π · waves · t)` в процентах экрана. `roadrunner` бежит по горизонту на глубине 0 (якорь — ступни, шаг
  70 мс), за деревом и плетнём: `x` — с сервера, `y` сервера (`horizon` конфига, 38 %) сцена не берёт — ступни на
  своей линии горизонта (37 % высоты арта) минус 1 арт-px, у подножия холмов; дальний спрайт — 7×4 с дымкой; сбить нельзя (сервер всегда отвечает промахом), но клик по нему уходит в `shoot` как

  `worm` (сцена 4) — тоже наземная цель в `groundLayer` на координатах фигурок, сортировка по точке на земле. Спрайт
  16×9 на всех глубинах, якорь — на земле под серединой, голова вправо (влево — зеркало по `to.x < from.x`); спина,
  седло и глаз светятся фиолетовым (`EMISSIVE`: под кровавой луной обычный цвет тонет в бордовом газоне), брюшко — в
  свете сцены. Кадры: `emerge` ×3 по 130 мс — выползает из холмика в точке `from`, ползёт (`fly`, 4 кадра гусеницы по
  150 мс) весь путь за оставшееся время, `burrow` ×2 по 150 мс — ныряет в землю в точке `to`. Путь — прямая с `wobble`
  поперёк в процентах конфига (поэтому петляет). Хит-бокс — непрозрачные границы кадра (`box`) плюс 2 арт-px; сбитый

  холмик с искрой) и мигает до 1,7 с; перья — комья земли и фиолетовая искра.

### Финал

**Реализовано** (лаборатория; живой стек — шаги 0–2). Сюжет — [`scenario.md`](scenario.md) («Финал», «Проклятый мир»),
арт — `pixel/finale.js` (макет шагов — `public/dev/finale.html`), постановка — `pixel/finale-stage.js` и `scene.js`.
Сцена получает шаг и `ready` через `scene.setFinale` (клиент — по `finale`, `ready` и снимку).

- **Время шагов.** Всё — функции шага и `t` (мс от события шага по часам сцены, таймлайн `T`). Анимацию играет только
  следующий шаг (`step == прежний + 1`) без `prefers-reduced-motion`; перезагрузка, ресинк, прыжок через шаги и
  reduced motion ставят `t` далеко в прошлое — те же функции рисуют итог шага, ничего не проигрывая заново. Сброс
  (`reset`, `render` без `finale`) возвращает всё к бару (сцена 0). Повторяющееся (дыхание FrankenPHP, хоровод, бег
  RoadRunner по горизонту в проклятом мире, фразы) идёт по часам сцены или по серверным часам.
- **Шаг 0, ритуальная поза.** Как только круг замкнут (`ready` в финальной сцене), стоящие фигурки встают в позу
  `ritual` лицом к кругу (сбоку, если круг заметно левее или правее, иначе спиной или лицом), кадры по 380 мс со
  сдвигом по `crc32(id)`; огоньки в ладонях — слой `glow` кадра, отдельным спрайтом без перекраски, в цвете глаз.
  Идущая фигурка идёт как обычно и встаёт в позу, когда остановилась: шаг — ход сервера, его видно честно, а поза —
  стоячая. Выстрел (`shot`) на миг важнее позы. Поза держится на шаге 1 и до молний шага 2.
- **Призыв** (**реализовано**, проверено в лаборатории). Живой переход 0 → 1 (событие `finale {step: 1}`, когда клиент
  показывает шаг 0) начинается с отсчёта совы: пузырь «Призыв через 3…», «2…», «1…» по секунде, всего `SUMMON_MS`
  (3000 мс, `pixel/finale-timeline.js`); каждая цифра — удар `circle.stage` вместо речи. Отсчёт держит один клиент
  (`client.js`, один таймер `later`): модель уже на шаге 1 (пульт видит его сразу), а страница показывает шаг 0 —
  `scene.setFinale` (вспышка, `T` шага 1 идёт от конца отсчёта), кости (`dice {on}` приходит сразу, панель и «Бросить» —
  после), звук шага (`finale.wake`, трек `rise`, интенсивность) и реплики совы, пришедшие за это время (`finale-1` идёт
  сразу за `finale`), ждут конца отсчёта и проигрываются в нём. События канала приходят всем одновременно, так что и
  отсчёт у всех один. Снимок или ресинк уже на шаге 1 отсчёта не показывает — сразу итог шага. Сброс отменяет отсчёт со
  всем отложенным (пузырь гаснет); следующий шаг обрывает его — шаг 1 встаёт сразу, молча, и следующий играет от него,
  как после двух быстрых нажатий. `reduced motion` — отсчёт тот же (это текст). Часы — `later` клиента и совы:
  лаборатория под `?freeze` передаёт свои.
- **Шаг 1, пробуждение** (сова `finale-1`, после «Призыва»; время ниже — от его конца). 0–270 мс — вспышка круга (`FX.flash`, 3 кадра); с 180 мс — красный столб
  (`FX.column`, аддитивно 0,55, кадры по 90 мс); с 300 мс — облако дыма за силуэтом и перед ним (`FX.smoke.cloud`,
  220 мс, переднее — 0,85); 600–2200 мс силуэт поднимается из круга (`SILHOUETTE.rise`, 4 кадра по 400 мс), дальше
  дышит (`idle`, 500 мс). Земля трясётся 2,2 с (экран — целыми арт-пикселями: 2 первые 0,5 с, потом 1). Тыквы за
  1,5 с стягиваются с мест на кольцо вокруг круга (0,92 × 0,72 полуосей грядки, на телефоне — в пределах экрана),
  поровну, в том порядке, в каком стояли вокруг, поднимаются выше (+6 арт-px) и кружат хороводом (оборот ~11 с).
  Итог шага: столб, облако, силуэт, хоровод.
- **Шаг 2, это не он** (сова «Что это?.. Это разве RoadRunner?!», затем «Что мы… ЧТО ВЫ НАДЕЛАЛИ?»). Три удара молнии в силуэт на 0, 380 и 760 мс
  (`FX.lightning`, 3 кадра по 60 мс), каждый — бело-голубая вспышка экрана (вуаль 0,45 → 0,1). На 780 мс, под
  вспышкой третьего удара, — смена света без перехода: кровавая луна → ночь (`nightOf`), столб гаснет. С третьего
  удара (760 мс) из точки удара вырывается клуб дыма (`strikeSmokeAt`, клубы `FX.smoke.billow`, светом сцены) и за
  0,3 с закрывает силуэт и облако шага 1: 10 клубов перед фигурой, 10 за ней и выше головы, 6 по земле вокруг круга.
  Клубы ползут вверх и в стороны, держатся плотными 0,65–1,8 с (передние — первыми, после смены облика) и редеют
  четырьмя ступенями Байера: перед фигурой дым сходит к 3–5 с, за ней — к 4–7 с, по земле — к 6–8 с; с 1,5 до ~10 с
  с плеч, болтов и головы FrankenPHP поднимаются струйки (по 1,7 с, реже со временем). При reduced motion клубы не
  клубятся и без струек. На 900 мс в дыму силуэт за 3 кадра по 150 мс (`SILHOUETTE.reveal`) становится FrankenPHP;
  огни тыкв гаснут (`lightsOut`: световые слои и ореолы скрыты, нутро — тон `spent` в `sprites.js`), за 0,7 с они
  летят из хоровода на свои места и падают на землю с приземлением; по земле стелется дым (`FX.smoke.creep`, 4 полосы вокруг круга, дрейф) — до шага 4.
  Фигурки выходят из позы; разбегаются они по `move` сервера.
- **Шаг 3, мип-мип** (сова — две реплики подряд: «Походу… ошибочка вышла.», затем «RoadRunner никогда не умирал…»; в каталоге
  `then`: вторая сразу после первой, если пузырь не занят другой репликой). RoadRunner: 0–4,6 с — по одной диагонали от
  правого края экрана на линии горизонта (у кромки холмов) вниз к игрокам до точки справа от круга (0,2 ширины от
  центра, ступни на 78 CSS px выше низа), в перспективе: доля пути `k = p^1,8` (у горизонта медленно и мелко, ближе —
  быстрее), до `k` 0,1 — дальний спрайт в дымке (`RUNNER.far`, слой дальних летунов), дальше растёт `s` → `m` → `l` →
  `xl` (0,15 / 0,4 / 0,7); встаёт и поворачивается к центру (`stop`), 5–6,8 с — `meep` и пузырь
  «Мип-мип!», дальше — перебежки (см. ниже). Вблизи RoadRunner перекрашен светом наполовину (`runnerBake`, кроме контура), иначе ночью он
  тонет. Рядом с лампочкой связи в HUD — подпись «RoadRunner: работает · аптайм …» сразу с события шага (`data-hud-runner`). Итог шагов 3–4: RoadRunner
  на переднем плане по расписанию перебежек.
- **Перебежки RoadRunner** (**реализовано** на фронтенде, проверено тестом расписания и в лаборатории; решение
  пользователя от 2026-10-28: при толпе игроков RoadRunner не было видно). На шагах 3 (после его «Мип-мип!», с 6,8 с) и 4
  RoadRunner бегает по переднему плану, `pixel/runner-dash.js`. Время делится на слоты по 10 с по серверным часам: стоит
  в своей точке справа от круга (`home`), через 2,5–5 с от начала слота (хеш слота) за 1 с перебегает влево
  (`out`, кадры `run` размера `xl`, разгон и торможение), там стоит 1,9 с лицом к центру — через 150 мс кадр `meep` и
  пузырь «Мип-мип!» на 1,3 с (`MEEP`) со звуком `rr.meep` (cue сцены `rr-meep`, один раз за слот, пойманный позже 1,5 с —
  без звука), — и за 1 с бежит обратно (`back`), до конца слота стоит. Дальний конец — левее круга, дальше, чем `home`
  справа: `cx − (home − cx) − 0,1 · artW`, не ближе 30 арт-px к левому краю; ступни на той же линии над HUD — путь на
  экране и на телефоне 390, и на десктопе. За ногами на бегу — пыль (`FX.smoke.billow`, светом сцены, тает за 480 мс).
  Всё — функция серверного времени: все видят одну перебежку, открывший страницу посреди неё попадает туда же. Слот,
  который уже идёт к концу «Мип-мип!» шага 3, на живом шаге отстаивается в точке (и на шаге 4 тоже, чтобы переход 3 → 4
  не прыгнул в середину пробежки); перезагрузившийся видит этот слот с перебежкой — разница в один слот. Шаг 5 уводит
  его с того места, где застал (сначала стоит до 1,2 с, затем диагональ к горизонту от этой точки). Вблизи (не дальний
  спрайт) вокруг него — синее свечение: `runnerAura` (`finale.js`, дизеринг как у ореола FrankenPHP, тона `eyeBlue` /
  `shieldBlue`), аддитивно, за ним — видно каёмкой вокруг контура, дышит 0,4–0,64 четырьмя ступенями за 1,8 с. В размере
  `xl` RoadRunner, его свечение и пыль рисуются поверх фигурок (выше любой глубины поля): у HUD толпа его иначе закрывает,
  а ближе низа экрана никто не стоит. Подписи имён фигурок — экранный слой, остаются поверх. При reduced motion он не
  бегает: стоит в `home` со свечением (без пульсации) и «Мип-мип!» по тому же расписанию. Дальний RoadRunner на
  горизонте (шаги 5–7) — без свечения и перебежек, как прежде.
- **Шаг 4, разоблачение** — панель `reveal.js` (см. выше); в сцене — перебежки RoadRunner.
- **Шаг 5, проклятый мир** (сова «Живите теперь…»). Тыквы за 1 с поднимаются и снова парят, огни — зелёные
  (`tone: 'franken'`: светятся только прорези, без `aura`; тыквы держат пиво, см. «Тыквы проклятого мира»),
  ореолов на земле под тыквами нет, частицы клика — зелёные `magic`; под FrankenPHP — широкий лаймовый ореол.
  RoadRunner 1,2–5,6 с бежит обратно по той же диагонали к правому краю на горизонте (размеры в обратном порядке, у
  горизонта — дальний спрайт) и за край; дальше раз в 15 с (по серверным часам, направление — хеш слота) молча пробегает по горизонту за
  6,5 с (на рассвете — с остановками и «Мип-мип!», см. «Рассвет»; расписание — `pixel/runner-horizon.js`); летуны `roadrunner` с сервера — сами по себе. Сова договаривает реплику и улетает: не раньше 3 с от события
  (реплика может ждать пузырь), `OWL_FLIGHT.takeOff` 150 мс, затем взмахи по 90 мс 2,5 с вверх-влево за край экрана.
  Итог: совы нет, RoadRunner — на горизонте по расписанию, FrankenPHP на круге, зелёные тыквы, червяки и зомби как
  прежде.
- **Чоканье** — два режима: автоматическое по близости и по клику; общие позы, пена, пузыри тостов и таймлайн `CLINK`.
  **Автоматическое** (**реализовано**, лаборатория; только фронтенд, без сообщений; `pixel/clink.js`, тосты — `toasts.js`).
  Время делится на слоты по 6 с. В начале слота (серверное время) фигурки с пивом, которые по своему серверному пути в
  этот момент стоят (до старта пути — в его первой точке, после прибытия — в последней), собираются в группы: соседи —
  в эллипсе 9 × 6 единиц конфига (не экрана, поэтому размер окна не важен), группа — цепочка соседей (3+ — одна группа,
  один тост). Группа — кандидат только в каждом 4-м слоте, в фазе по хешу её id, и там с шансом 75 % по хешу (id, слот);
  кандидат чокается, если никакие двое из него не были вместе в другом кандидате трёх слотов до (компания сменилась) —
  пара чокается не чаще раза в 24 с. Правило смотрит только на кандидатов, а не на свои прошлые ответы, поэтому
  открывший страницу только что видит то же, что смотревший всё время. Тост — хеш (группа, слот) → индекс в `TOASTS`.
  Слот вычисляется один раз и заново — только при смене пути или предмета у фигурки. Анимация (мс от 0,3 с слота):
  0–400 поворот боком к центру группы (над/под ним — по порядку в группе), 400–750 кружка вперёд (`clink` 0), 750–1100
  удар (`clink` 1): брызги пены (6 капель цвета пива ночью) и блик `SHOT_FX.pop`, фигурка наклоняется к центру до 6
  арт-px, чтобы кружки сошлись; 1100–1400 обратно; 1400–3200 кружка поднята над головой (`toast`, 2 кадра по 450 мс);
  дальше обычная стойка. Пузырь тоста — над группой с 800 мс, `2000 + 65 мс × символ`, не дольше слота без 0,5 с;
  тост на два голоса — реплика над первой фигуркой до 2400 мс, затем ответ над второй. Идущая фигурка идёт и
  присоединяется, когда встала, если чоканье ещё идёт; выстрел на миг важнее. Пузырь — тот же, что у FrankenPHP
  (`pixel/bubble.js`). `prefers-reduced-motion`: позы без наклона-анимации и без капель, блик остаётся.
  **По клику** (**реализовано** в лаборатории против контракта `protocol.md`; маршрутизация клика — «Модель клиента»).
  Играется событие `clink` от его `at` по серверным часам тем же таймлайном `CLINK`; старше 3 с на приходе
  (`CLINK_STALE_MS`) — не играется. Пара — подошедший (`player`) и цель: с фигуркой оба поворачиваются боком к
  середине между ними и наклоняются к ней, удар с пеной, кружки вверх; тост `TOASTS[toast % TOASTS.length]` — одной
  строкой над парой (середина голов), на два голоса — реплика над подошедшим до 2400 мс, ответ над целью. С тыквой
  фигурка поворачивается к тыкве и тянется к её кружке (наклон 3 арт-px при ударе), а тыква в те же моменты
  встречает её кружкой (кадры `pumpkinArms`: 0–400 держит, 400–575 опускает, 575–750 протягивает, 750–1100 удар —
  кружки касаются, 1100–1250 опускает, 1250–1400 держит, 1400–1540 на полпути, дальше поднята для тоста; при
  `reduced motion` — держит, с 1400 поднята), её случайный подъём на это время подавлен; ответ тоста — над тыквой. Пузырь — до `2000 + 65 мс ×
  символ` (+1600 у двух голосов), не дольше 4,5 с от `at`. Новое чоканье того же игрока, фигурки-цели или тыквы
  заменяет прежнее. Идущая фигурка (по своему треку) идёт и в чоканье не участвует; выстрел на миг важнее.
  **Совмещение режимов** (одинаково у всех зрителей): фигурка с `clink` (идёт чокаться по клику — поле из `move` и
  снимка) в планировщик не попадает — до события `clink`, `move` без поля или, если события так и нет (чоканье не
  случилось, сервер ничего не шлёт), до 1 с после прибытия её и фигурки-цели, как в следующем снимке; группа
  планировщика, в которой есть фигурка с чоканьем по клику, пересекающимся с анимацией группы (`[at, at + 3200)`
  против `[at, until)` группы), пропускается в этом слоте целиком. Дополнительной паузы после чоканья по клику нет:
  открывший страницу позже прошлого события не видит и разошёлся бы с остальными.
- **Реплика после отлёта совы** (решение пользователя): любая реплика после отлёта (свой текст модератора, кнопка)
  просто выводится пузырём над FrankenPHP — сова не возвращается, FrankenPHP её не «говорит» (без
  кадров речи); `scene.perch()` отдаёт точку над его головой.
- **Свет.** Шаги 0–1 и начало шага 2 — кровавая луна, с 780 мс шага 2 и дальше — ночь (без тёплого круга костра).
  FrankenPHP и силуэт запекаются `frankenBake`: светящееся (искры, красный кант) — без перекраски, лайм логотипа —
  наполовину между днём и светом сцены, остальное — светом сцены, так логотип читается ночью. Ключи
  `FINALE_EMISSIVE` — в `EMISSIVE` (`night.js`).
- **Глубина.** FrankenPHP и силуэт — на точке круга в `groundLayer` поверх пепелища (вспышка, столб, заднее облако,
  фигура — по порядку над ним); переднее облако, стелющийся дым и RoadRunner вблизи — по своей точке на земле; молнии —
  слой `fxLayer` поверх всего, кроме вуали; дальний RoadRunner — слой дальних летунов.
- **Фразы FrankenPHP** (`franken.js`): каталог `PHRASES` (расширяется добавлением в конец); время делится на слоты по
  7 с, хеш номера слота решает, говорит ли он (примерно в 85 % слотов — в среднем раз в 8 с), и выбирает фразу (не ту же, что в слоте
  перед ним); фраза — с 0,9 с слота, `2400 + 65 мс × символ`, не дольше слота без 1,2 с. Только на шаге 5 и не в
  первые 14 с после события шага (поверх прощания совы); у открывшего страницу на шаге 5 — сразу. Пока фраза видна —
  кадры `talk` (180 мс, изредка жест); без фразы — дыхание и искры с болтов раз в 2,4 с. Пузыри RoadRunner и
  FrankenPHP — PixiJS в экранном разрешении поверх увеличенного мира (`labelLayer`, как имена): кремовый, ступенчатая
  рамка и хвост к голове, как у пузыря совы.

### Бар и сдвиг номеров сцен

**Реализовано** и проверено в лаборатории (живой стек — ждёт backend). Сюжет — [`scenario.md`](scenario.md) («Сцена 0 —
«Бар»», «Чоканье»), сообщения — [`protocol.md`](protocol.md) («Бар», RPC `bar.take`, `clink.auto`, `drink`,
`bar.target`, `bar.ready`, события `pour`, `mugs`, `take`, `drink`, `drinks`, `walkers` в `scene` / `reset`, `bar` в
снимке).

**Номера сцен.** Бар — сцена 0, день — 1, закат — 2, ночь — 3, финал — `sceneStages` (по умолчанию 4). Номера, от которых
зависит вид, — `SCENE` в `layout.js` (`{bar, day, sunset, night}`) и `isBar(scene)`; финальная сцена — всегда
`sceneStages` снимка, литералов нет.

- `layout.js`: `jumpedOut` — закат (все тыквы на `stageMax`) и всё после него; в баре тыквы не прыгают и не парят
  (`floats`), костра нет (`bonfireOpen`).
- `pixel/scene.js`: свет `lightingOf` — бар `firelight`, день `day`, закат `sunset`, ночь `night`, финальная — кровавая
  луна; костёр со заката (`hasBonfire`), частицы клика — закат `ember`/`cinder`, с ночи `magic`; ночные глаза совы
  (`glowing()`) — с ночи; переход день → закат (4 с) и взрыв ночь → финал — как раньше, по новым номерам.
- `owl.js`: `scene-1` «Вот оно — магическое место! Ух-ху!» → «Но сначала всё подготовим к ритуалу: вырезайте тыквам мордашки и вычищайте их!» (выход из бара, `then`), прежние `scene-1`/`2`/`3` —
  `scene-2`/`3`/`4`; ключи `scenes` у `scene-ready`, `hurry`, `flyers` на единицу больше, ключ 0 — у реплик бара.
- `client.js`: названия сцен в HUD (`Бар`, `День: подготовка`, `Закат`, `Ночь`); `reset` → бар.
- `sound.js` — см. «Звук»; `debug.js` — сводка «бар».

**Локация** (`buildBar` в `scene.js`, арт — `pixel/bar.js`). В сцене 0 вместо неба, грядки, дерева, кустов, бабочек,
тыкв и костра — зал: фон `paintBar`, огни `barLights` (в слое побегов, над фоном и под всем стоящим; ореолы на полу —
`halo(…, 'warm')`, 0,35), мебель `barProps` в `groundLayer` по линии опоры вместе с фигурками (свеча стола — слой
`glow`). Координаты — `walk.bar` из `#app[data-bar-layout]` (без него — `BAR_LAYOUT` в `layout.js`, копия конфига) в
процентах экрана **без** `spreadX`: фигурки в баре (`walkerArt`, `groundAt`) тоже без растяжки, клик в любую точку зала
— `move` (сервер приводит на пол). Сервер водит фигурки по точке ног в обход препятствий, поэтому стол со скамьями и стойка
рисуются внутри своего препятствия с запасом в полфигурки (`WALKER_HALF` по бокам, 1 арт-px спереди и сзади): стол
подбирается под эллипс в арт-px текущего экрана, у стойки сужается край, рядом с которым есть пол; бочки по
прямоугольникам после первого — тоже с отступом. Препятствия `walk.bar` задаёт фронтенд (ключи раскладки в
`app/config/hellowin.php`, копии — `BAR_LAYOUT` и `DEFAULT_BAR_LAYOUT`); проверка — `public/dev/bar.html?boxes`: красный
контур пола под мебелью с запасом лежит внутри зелёного препятствия. Свет — `firelight` (свет листа `public/dev/bar.html`); фигурки и сова
перекрашены им, пиво — `keepHue`. Кнопки тыкв, костра и круга в баре скрыты (`body[data-bar]`, `visibility`), клик по
ним не отправляется (`client.clickable`). Летунов в баре нет (сервер их не запускает). Без canvas — фон-заглушка и
DOM-кнопки (стойка, «Выпить»).

**Дверь** (**запланировано**, бриф «Снова в бар»). Массивная викингская входная дверь — тёмные доски с железными
полосами, кованые петли-завитки, кольцо-ручка, каменный порог — на задней стене в `walk.bar.door.x`: по центру этой
точки, порог — на линии пола (`door.y`), высота — так, чтобы верх притолоки пришёлся на `y` места посадки `lintel`
(см. «Места посадки»). Свободный декор стены (знамёна, лишние щиты, факелы) раскладывается по пролётам между столбами и
обходит дверь: в её пролёте он не рисуется или уходит в соседний, факелы — по бокам двери; щиты и бочки из мест посадки
стоят там, где их задаёт конфиг, и не двигаются (`paintBar` в `pixel/bar.js`, проверка — `public/dev/bar.html`). Дверь **открыта**, пока путь хоть одной фигурки начинается в точке
двери (`walk.path[0]` в пределах 0,5 % от `door`): от `startedAt` до `arrivesAt` + 600 мс — створка распахивается внутрь
(3 кадра по 90 мс), в проёме — ночная улица с холодным светом на полу, затем закрывается (3 кадра). Всё — по путям фигурок
и серверным часам, без своего состояния: перезагрузка посреди входа покажет ту же фазу. Створка с проёмом — слой над
стеной и под всем стоящим (`barDoor` в `pixel/bar.js`, кадры 0 — закрыта … `DOOR_OPEN` — распахнута; петли — со стороны
ближней торцевой стены), поэтому входящая фигурка всегда рисуется перед дверью и выходит из проёма; её ход — обычная
ходьба по пути из события `walker`. Ширина двери — две трети высоты, на узком экране — меньше: дверь не уходит за край
и не наезжает на щиты мест посадки рядом (так же камин сужается, не доставая до щитов). `reduced motion` — дверь сразу
открыта/закрыта, без промежуточных кадров. Без `door` в раскладке — двери нет, фигурки появляются, как раньше.

**Места посадки** (**запланировано**). `walk.bar.perches` — источник, как столы и стойка: арт рисует поверхности
там, где на них садятся мухи сервера (`{x1, x2, y, name}`, `y` — верх поверхности). Щиты — в точках `shield-N`, кромка
щита сверху на `y` (вместо прежних рядов щитов по пролётам; декоративные щиты сверх них остаются, где ни с чем не
сталкиваются); камин — по центру `mantel` (`(x1 + x2) / 2`), размер такой, что верх полки камина на `y` и полка
перекрывает `x1…x2`; дверь — верх притолоки на `y` `lintel`; полки над стойкой — верх на `y` `shelf-top` и `shelf` в
пределах `x1…x2`; крышки бочек — на `y` `barrels`, бочки в пределах `x1…x2`; верх стяжной балки под потолком — на `y`
`beam`. Муха на настенной посадке (щит, притолока, балка) рисуется как на столе — якорь под лапками, сидячие кадры те
же. Проверка — `public/dev/bar.html?boxes`: каждая полоса посадки — жёлтая линия, лежит на верхнем крае своей
поверхности.

**Снова в бар** (**запланировано**). `reset` с `again: true` — как любой сброс (`scene.render`, фигурки сразу на полу
бара через `scene.setWalkers`, без двери), свет рассвета гаснет в свет бара затуханием 3 с (а не мгновенно, как сброс
пульта); следом — реплика `bar-again` «Ну что, по пиву?» (`LINES`, `hoot`). На пульте на шаге 7 «Следующая сцена»
называется «В бар» (см. «Рапира», «Пульт»).

**RoadRunner за стойкой** (**запланировано**, бриф «RoadRunner в баре»). Пока `bar.roadrunner` (снимок, `reset.bar`;
клиент ставит его и сам на `reset` с `again: true`, обычный сброс снимает) — в точке `walk.bar.roadrunner {x, y}` за
стойкой рядом с совой стоит RoadRunner: арт `RUNNER` (`pixel/finale.js`, крупный `l`), перекрашенный светом бара, в позе
с кружкой в крыле (кадры `bar`: стоит, поднимает кружку — 2 кадра, держит поднятой под клювом), лицом к залу (кадр
отражён); `y` — задний край стойки (`barRunnerSpot` в `pixel/bar.js` берёт его, как место совы), опора — на
`RR_BAR_HIDE` строк ниже, стойка закрывает ноги и низ туловища, кружка у груди стоит на ней. Сортируется по заднему краю
стойки, а не по опоре: за совой тоже — на узком экране короткая стойка, и его хвост уходит за сову, а не закрывает её. Пиво в кружке — `bakeBar` (хранит цвет). **Тосты** —
`RR_TOASTS` (`toasts.js`, расширяется добавлением в конец), выбор по серверному времени, как фразы FrankenPHP: слоты по
8 с, хеш номера слота решает, говорит ли он (примерно в двух третях слотов), и выбирает тост (не тот же, что в слоте
перед ним); тост — с 0,6 с слота, `2000 + 65 мс × символ`, не дольше слота без 1 с; на каждом тосте он поднимает кружку
(подъём 400 мс, держит, пока виден пузырь). Пузырь — `pixel/bubble.js`, как у FrankenPHP. Каждый тост — cue
`{type: 'rr-toast', x}` (пойманный позже 1,5 с — нет). Клик — кнопка `[data-roadrunner]` поверх него (позиция —
`--rr-x|y|w|h` от сцены, как кнопка стойки; «Чокнуться с RoadRunner»): если `client.clinksRoadrunner()` (бар,
`bar.roadrunner`, моя фигурка с пивом) — RPC `clink {roadrunner: true}`, иначе `aria-disabled="true"`; кнопка лежит
поверх кнопки стойки, поэтому с пустыми руками клик по нему — клик по стойке (`bar.take`, если `client.takesBeer()`).
Отказы (`not bar`, `no target`, `no beer`, `busy`, `zombified`) — только предупреждение, как у любого `clink`.
Чоканье по клику — событие `clink` с `roadrunner: true`: моя фигурка у стойки поворачивается к его кружке (точка встречи —
кружка, вынесенная к залу), он поднимает её навстречу (кадры `bar`), удар с пеной, тост — `BAR_TOASTS`, ответ тоста — над RoadRunner; в модели — `clinked`, как у
чоканья с фигуркой. Его случайный тост на время чоканья подавлен. Сова и автоматическое чоканье — без изменений.
`reduced motion` — без подъёма кружки, пузыри остаются.

**Сова за стойкой.** Кадры `OWL_BAR` (`pixel/owl.js`), якорь — в `barOwlSpot`, сортируется по своей опоре за стойкой:
стойка закрывает нижнюю часть; пиво в кадре — `bakeBar`. `scene.perch()` в баре — точка совы, пузырь — как обычно.
Покой — `idle` с морганием по серверным часам (слоты как на ветке). **Розлив** — `pourFrame(phase)`, `phase = (now −
since) / (until − since)` по серверным часам (узнавший посреди — с той же фазы); `pouring` с прошедшим `until` не
рисуется. `bar` снимка страницы (`#app[data-bar]`) сцена берёт сразу при создании: `state` клиент перечитывает только
после переподключения или пропуска. На событие `mugs` — два кадра `set` по 180 мс, новые кружки встают на стойку с
толчком в 1 арт-px. Речь — `talk`; пока наливает, кадр розлива важнее. `prefers-reduced-motion`: вместо розлива — `set[0]`
(полная кружка в крыле, без струи), без толчка и мерцания.

**Партии и переполнение стойки** (frontend **реализовано**, в лаборатории проверено; на живом стеке — **не проверено**,
ждёт backend-партий из protocol.md, «Розлив»). Сова наливает партию `batch` из `pour` и `bar.pouring` снимка
(`pourBatch` в `pixel/bar.js`: нет поля или не целое > 1 — одна кружка); клиент кладёт `batch` в `model.bar.pouring` и
передаёт `scene.pour(since, until, batch)`. Пока идёт розлив партии больше 1 — у крана, справа от наливаемой кружки,
метка «×N» пиксельным шрифтом счёта (`digitsSprite` из `pixel/flyers.js`, знак «×»), без перекраски светом зала, перед
стойкой и совой; при 1 — ничего. На стойке — ровно `bar.mugs` кружек: `BAR_MUG` по `mugSlots` (сколько поместится на
нарисованной стойке, один-два ряда, задний ряд глубже переднего), сразу за стойкой по глубине. Не поместившиеся
(`counterMugs`) — метка «+N» тем же шрифтом на левом конце переднего ряда: она занимает столько крайних мест ряда,
сколько нужно по ширине (обычно одно-два), `N` = кружки минус нарисованные. Новые кружки партии (индексы от прежнего
`mugs` до нового) подпрыгивают вместе; если часть ушла в «+N» — подпрыгивает и метка. Взятие кружки не зависит от мест:
путь к стойке строит сервер. На телефоне стойка вмещает 1–2 кружки, остальное — «+N». Бар освещён только `firelight`;
метки не перекрашиваются и читаются при любом свете.

**Ввод в баре** (`bindBar` в `client.js`, подключают `app.js` и лаборатория; только с фигуркой на поле):

- Кнопка `[data-bar-counter]` поверх стойки (позиция — `--counter-x|y|w|h` от `counterBox`, без canvas — запасные
  проценты; «Взять пиво») — RPC `bar.take {}`, если `client.takesBeer()` (бар, фигурка, пустые руки); иначе
  `aria-disabled="true"` и клик не уходит. Персонаж пойдёт, когда придёт `move`.
- Клик по чужой фигурке — RPC `clink {walker}`, если `client.clinksWalker(id)`: в баре — у меня и у неё пиво (`item`
  модели), иначе клик идёт в `move`. Курсор-рука (`data-clink-hover`) — по тому же правилу.
- **Пробел** (`isDrinkKey`): только `Space` без модификаторов и автоповтора (`event.repeat`), не в
  `input`/`textarea`/`select`, `contenteditable`, не на кнопке (`button`, `[role=button]`; кроме кнопок-объектов —
  `[data-element]` (тыквы, костёр, круг), стойка, RoadRunner, FrankenPHP, `[data-rr-meep]`: фокус остаётся на них после
  клика мышью, и пробел там — наш), не при открытом `<dialog>` (экран входа); если `client.drinks()` (бар, фигурка, пиво
  в руке — флаг `clinked` не нужен, решает сервер) — `preventDefault` и RPC `drink`, если кружка не занята (ниже).
  Ответ `not clinked` — личная подсказка над своей фигуркой: случайная фраза отказа из `REFUSALS` (`toasts.js`, `refusal()`); кнопка «Выпить» видна и без чоканья, если моя фигурка на поле одна (`scene.hint`, пузырь
  `pixel/bubble.js`, 2,5 с), только у себя.
- Кнопка **«Выпить»** `[data-drink]` в HUD — видна, когда я в баре с пивом и модель знает, что этой кружкой я чокнулся
  (`model.clinked`: ставят событие `clink`, где я `player` или `walker`, и успешный ответ `clink.auto`; снимают мой
  `take` с `ok: true`, мой `drink`, выход из бара, сброс; снимок оставляет флаг, пока пиво в руке). Нажатие — RPC `drink`.
- Отказы (`has beer`, `not bar`, `no beer`, `no target`, `not clinked`) — `console.warn`.
- **Против пропуска анимации** (**реализовано** на фронтенде; сервер — `busy`, см. `protocol.md`, `drink`, `bar.take`,
  `beer`). Кнопка нажимается пробелом на его `keyup`: без защиты одно нажатие на тыкве или стойке в фокусе было бы и
  `drink` (наш `keydown`), и `beer`/`clink`/`bar.take` (нативный клик кнопки). Поэтому `bindObjectKeys` (`client.js`, подключают `app.js` и лаборатория): Space на кнопке-объекте —
  `preventDefault` и на `keydown` (с автоповтором), и на `keyup`, нативного нажатия нет; Enter нажимает их, как раньше.
  **Кружка занята** (`client.mugBusy()`) — пока играет моё чоканье этой кружкой (событие `clink`, где я `player` или
  `walker`: до `at` + `CLINK.end` из `pixel/clink.js`; успешный `clink.auto` — от ответа + `CLINK.end`, повторный с той же
  кружкой не продлевает), пока идёт мой глоток (`HELLOWIN_DRINK_MS`, на клиенте — 1200, как поза `drink`: от `{ok:true}`
  на мой `drink` и от события `drink`), пока тыква передаёт мне кружку (до `until` события `take` с `pumpkin`, без поля —
  `HELLOWIN_BEER_HANDOVER_MS` по умолчанию, 900; по `until` же сцена играет руки тыквы, `scene.takeFromPumpkin(…, until)`)
  и пока мой предыдущий `drink`/`beer`/`bar.take`/`clink` без ответа (`client.mugRpc(method, send)`). Пока занята, эти
  RPC не уходят: пробел и «Выпить» (кнопка видна по правилу ниже, но `disabled`), клик по стойке, RoadRunner, тыкве
  (клик не превращается в `click`) и по чужой фигурке (не превращается в `move`); `cure` и `meep` модератора — не
  кружка. Ответ `busy` — молча, без подсказки и `console.warn`.
- **Рамка фокуса** у кнопок-объектов (золотой пунктир `:focus-visible`) — только при навигации Tab: браузер включает
  `:focus-visible` и от пробела после клика мышью. `bindObjectKeys` ставит `data-kbd` на `<html>` по Tab и снимает
  по `pointerdown`; без `data-kbd` рамки у `[data-element]`, `.bar-counter`, `.roadrunner`, `.franken`, `.rr-meep` нет.

**Предметы и анимации.** `item` фигурки в баре — свой: по снимку и `walker`; `take` с `ok: true` → `beer`; `drink` →
модель сразу `mug`, сцена (`scene.drink`) 1,2 с играет позу `drink` (3 кадра, кружка в кадре) и дальше — пустая кружка (см. «Бросок кружки»).
**Пустые руки в баре на экране — пистолет**, как днём: серверный `item` остаётся `null`, а рисует его пистолетом
одно правило у всех клиентов (`shownItem(item, scene)` в `layout.js`: в баре `null` → `pistol`, иначе как есть) —
в стойке, ходьбе, выстреле по мухе (поза и эффекты пистолета, пауза хода — `SHOT_MS`) и в звуке выстрела. Это только
презентация: «взять пиво», глоток, чоканье, «Выпить» и пробел смотрят на серверный `item`; `shrug` по-прежнему
показывает пустые ладони; RoadRunner за стойкой и сова — не фигурки и не затронуты.
`take` с `ok: false` — `scene.shrug(id)`: поза `shrug` 0,8 с. Выход на грядку (`scene` 0 → 1 с `walkers`) и сброс с
`walkers` — `scene.setWalkers(list)`: фигурки ставятся сразу, без «ходьбы без скачков» (другая локация); свет меняется
затуханием старого кадра, 3 с.

**Автоматическое чоканье в баре.** Тот же планировщик `pixel/clink.js` (`clinksNow` в баре, как в проклятом мире),
участники — фигурки с `item: beer`. В момент удара сцена шлёт `onCue({type: 'clink', x, sides: [{id, x, y}]})`
(координаты конфига, раз на чоканье, позже 0,4 с — нет); `app.js` в видимой вкладке спрашивает
`client.autoClinkPartner(cue)` — ближайший ко мне участник с пивом, если моя фигурка в группе и у меня пиво, — и шлёт RPC
`clink.auto {walker}`; успешный ответ — `client.clinkedAuto()`. Скрытая вкладка не шлёт (кадры не идут). В проклятом
мире `clink.auto` не шлётся.

**Тосты.** В баре чоканье по клику и автоматическое берут тост из `BAR_TOASTS` (`toasts.js`, за PHP; расширяется
добавлением в конец), в проклятом мире — из `TOASTS`; номер тоста — тот же (`toast` события, хеш группы и слота).
`toastAt(n, list)`, `toastOf(hash, slot, list)`, `clinkOf(event, list)`, `createClinks().at(now, walkers, list)`.

**Цель бара и шкала.** `bar.drunk` / `bar.target` — из снимка, события `drinks` и `reset` (без `target` в событии сброса
цель остаётся прежней — она про зал). В HUD вместо шкалы тыкв — шкала `[data-hud-drinks]` (`role="progressbar"`,
`aria-valuenow`/`aria-valuemax`, у модератора и `aria-valuetext`): пиксельный стакан с пеной на уровне, `--fill` = `drunk / target`
(0–1), полная — `data-full`, рядом «Выпито» (`[data-hud-drinks-text]`; у модератора — «Выпито 12 из 30»), до 120 px, на 390 px помещается.
Готовность бара — событием `ready` (шкала полна или отмашка), тогда на пульте «Следующая сцена ›»
подсвечена (в HUD готовность не пишется — зал узнаёт её от совы); до неё — двойное нажатие и `force`, как у любой сцены.

**Пульт в баре.** Группа «Бар» (только в сцене 0): «+5 бокалов» / «−5 бокалов» — RPC `bar.target {delta: ±5}`,
«Отмашка» — RPC `bar.ready {}` (выключена, когда бар уже готов), строка «цель N · выпито M»
(`[data-console-bar]`). Реплики-кнопки `bar-who`, `bar-crowd`, `bar-clink` (флаг `bar` в каталоге) видны только в баре.

**Сова приговаривает.** `RUMORS` в `owl.js` (расширяется добавлением в конец), `rumorAt(n)` — `RUMORS[n % length]`.
`pour` с `rumor` (и снимок, где `pouring.rumor` ещё наливается) → `owl.rumor(n, left)`: слух показывается, только если
пузырь свободен — нет текущей реплики, её удержания и ждущей реплики; держится 4,5–9 с (по длине и остатку розлива) и
ничего не удерживает: любая следующая реплика сменяет его сразу. `bar-intro` (авто, `hoot`, две части через `then`)
— каталог; `intro` осталась кнопкой.

**Модель клиента — события бара:** `pour` → `bar.pouring = {since, until, rumor?}`, `scene.pour(since, until)`,
слух; `mugs` → `bar.mugs`, `pouring = null`, `scene.mugs(n)`; `take` → `ok` — `item: beer` фигурке (`scene.walker`),
`bar.mugs`, `scene.mugs(n)` (без кадров `set`: кружка ушла), иначе `scene.shrug(id)`; `drink` → `item: mug`, `throw` → `item: null` (`scene.throwMug`),
`scene.drink(id)`; `drinks` → `bar.drunk`, `bar.target`; `scene` с `walkers` и `reset` с `walkers`/`bar` — заменить фигурки
(`scene.setWalkers`). API сцены для бара: `scene.pour`, `scene.mugs`, `scene.shrug`, `scene.drink`, `scene.hint(id,
text)`, `scene.setWalkers(list)`; `render(snapshot)` берёт `bar` и `barLayout` снимка.

**Лаборатория.** Без `?scene` лаборатория стартует в баре; `?scene=N` — прочие сцены (стадии тыкв `0,4,8,11`, костра
`0,0,4,7`), `?next` с `?scene=1` — закат, с `?scene=3` — взрыв. Фиктивный движок играет бар как сервер: тикер 200 мс
наливает партиями: `max` — фигурки на поле (`?players=N` — насовсем) не больше 60 (`HELLOWIN_BAR_MUGS`), партия
`min(free, ⌈free / 10⌉)` в начале розлива, по прибытии `mugs = max(mugs, min(mugs + batch, max))`, `mugs` несёт `max`
(`?mugs=N` — стартовые кружки, по умолчанию 5; `?pour=ms` — длительность партии, по умолчанию 2500; `?walkers=0&players=50&mugs=20` —
«×3» у крана, `?walkers=0&players=60&mugs=40` — «×2» и «+N» на стойке), примерно
каждый третий налив — с `rumor`; `bar.take` — путь к ближайшей точке места у стойки, проверка по прибытии, `take`
`ok:false` и `bar-empty` (не чаще 20 с); `drink` с `not clinked`, счётчик `drunk` и событие `drinks`; цель `?target=N`
(по умолчанию 10; `?drunk=N` — уже выпито), `bar.target`, `bar.ready` с пульта (`?mod=1`), готовность — `ready` и
`bar-intro` один раз за раунд; `clink {walker}` в баре с `no beer` / `no target` и засчитыванием обоим; `clink.auto` с
проверкой расстояния (`clink_reach`) — шлёт мой браузер, за ботов — лаборатория. Боты в баре берут пиво, чокаются (по
клику и рядом) и пьют. `?bar=1` — боты с пивом стоят у столов парами (`?bar=1&walkers=8&epoch=18000&freeze=5100` —
удар, `6400` — тосты за PHP). `?bardemo=1` — сценка: две кружки, налив 8 с, трое ботов идут к стойке, дальний
разводит руками и слышит `bar-empty`, первые двое чокаются по клику и пьют, опоздавший берёт следующую. `?me=1` — играть
самому (стойка, пробел, «Выпить»). Выход на грядку — `walkers` в `scene`, сброс — в бар с `walkers` и `bar`. Зона бара —
пол минус препятствия, путь — прямо или через углы препятствий. **Запланировано**: `?walkin=N` — N ботов входят в дверь один
за другим (раз в 1,5 с, путь от `door` на `door_in` вниз, как у сервера), а новая своя фигурка в баре (`?me=1`, экран входа)
тоже входит в дверь; `?walkin=1&freeze=300` — дверь распахнута, `1200` — закрывается. На рассвете (`?finale=7&mod=1`)
«В бар» играет новый цикл: `reset` с `again: true` (с `bar.roadrunner: true`) и `bar-again`. `?roadrunner=1` — бар сразу с
RoadRunner за стойкой (тосты по часам, `clink {roadrunner: true}` с ошибками `not bar`, `no target`, `no beer`, боты с пивом
иногда чокаются с ним); `?roadrunner=1&freeze=600` — первый тост, `?rrclink=1` — бот чокается с ним на старте.

### Рапира

**Запланировано**. Сюжет — [`scenario.md`](scenario.md), «Рапира»; сообщения — [`protocol.md`](protocol.md), «Рапира»
(RPC `beer`, `word`, `cure`, `strike`, `cursed.target`, `boss.hp`, события `cursed`, `word`, `cure`, `boss`, `strike`,
`take` с `pumpkin`, `zombie` в `Walker`, `cursed` и `boss` в снимке). Шаги финала 5–7; `CURSED_STEP` в `client.js`
остаётся 5 (проклятый мир — шаги 5 и 6), рассвет — `DAWN_STEP = 7`.

**Модель клиента.** `cursed` — `{drunk, slain, drinksTarget, zombiesTarget}` из снимка и события `cursed`; `boss` —
`{hp, max}` из снимка и событий `boss` / `strike` (`hp` из `strike`); `zombie` фигурок — из снимка, `walker`, `word`
(`ok: false` → `true`), `cure` (→ снять), `finale` 7 и `reset` (→ снять у всех); `item` — `word` с `ok: true` → `rapier`,
`take` с `pumpkin` → `beer`, `finale` с полем `item` → всем (без поля — не трогать). Правила для ввода:
`client.beersPumpkin(id)` (шаг 5, фигурка не зомби, пустые руки, тыква `reachable`), `client.curesWalker(id)` (шаг 6, я с
фигуркой и не зомби, цель — чужая фигурка-зомби), `client.strikes()` (шаг 6, `boss.hp > 0`, у меня рапира, не зомби),
`client.asksWord()` (шаг 6, моя фигурка на поле, без рапиры, не зомби), `client.zombified()` — моя фигурка зомби.

**Ввод.** Маршрутизация клика: выстрел по летуну — первым (на рассвете — рапирой); затем клик по чужой фигурке — `cure
{walker}`, если `curesWalker`, иначе чоканье, как раньше; клик по досягаемой тыкве на шаге 5 — `beer {pumpkin}` с пустыми
руками, `clink {pumpkin}` с пивом; на шаге 6 тыквы — обычный `click`; клик по FrankenPHP — `strike {}`, если `strikes()`,
иначе ничего; затем `move`. Пробел и «Выпить» — как в баре, на шагах 5–6 (`client.drinks()`, занятая кружка —
`client.mugBusy()`, см. «Против пропуска анимации»); кнопку тыквы, как и кнопку стойки, пробел не нажимает (после клика
мышью фокус остаётся на ней), её нажимает Enter; `clink.auto` в проклятом мире
теперь шлётся, как в баре. Зомби (`zombified()`): ходьба, чоканье, пиво, пробел, удары и поле слова выключены, клик ничего не
отправляет. Над фигуркой-зомби, которую я могу расколдовать, — курсор-рука (`data-clink-hover`, как у чоканья).

**Поле слова** — DOM-форма сверху по центру экрана, над сценой и под пультом: «Молви слово» — поле и кнопка «Молвить»
(Enter). Видна, пока `asksWord()`; ответ проверяет только сервер — фронтенд не знает ни слова, ни правил, ни форм и сам
ничего, кроме пустой строки, не отклоняет. Ответ `correct: true` — форма закрывается (предмет и свечение придут событием
`word`); `false` — форма закрывается, моя фигурка станет зомби по событию, вместо формы — строка «Ты зомби-воркер. Жди, пока
расколдуют» (`[data-word-zombie]`), после `cure` форма открывается снова. Ошибки (`not now`, `has rapier`, `zombified`,
`invalid text`) — подпись под полем на 3 с. Пока форма в фокусе, пробел — пробел, а не «Выпить» (`isDrinkKey` и так
пропускает поля ввода).

**HUD.** На шаге 5 внизу вместо шкалы тыкв — две шкалы, как шкала бара: «Выпито» (стакан с пеной) и «Зомби» (череп,
зелёная заливка; у модератора — «Выпито 7 из 20» и «Зомби 3 из 20»), `--fill` = счётчик / цель (0–1), полная — `data-full`. Обе полны — проклятый мир готов
(событие `ready` финальной сцены на шаге 5): шкалы остаются полными, в сводке пульта — «готова», над FrankenPHP — `cursed-ready`. Модель снимает `ready` на `finale {step: 5}`. С шага 6 шкал нет. На
телефоне шкалы — в одну строку, по 120 px.

**Полоса здоровья** — DOM над головой FrankenPHP (чёткие цифры и `role="progressbar"`; сцене не нужно каждый кадр
перерисовывать текст): пиксельная рамка, заливка от лаймового к красному по доле; «HP 57 / 90» под ней — только у
модератора (у игрока `data-boss-hp-text` пуст и `hidden`); позицию публикует сцена
(`--boss-x|y` на `#app`, CSS-пиксели); на `strike` заливка плавно укорачивается (0,25 с), без вспышек и вздрагиваний — решение пользователя. Видна, пока
есть босс и `hp > 0`. Без canvas — сверху по центру.

**Арт.**

- **Пиво из тыквы** (`take` с `pumpkin`): тыква кадрами `pumpkinArms` опускает свою кружку, лезет ручкой в верхнюю прорезь,
  достаёт новую кружку (вспышка пены) и протягивает её к фигурке — от события до его `until` (**запланировано**; без поля — ~900 мс); у фигурки с этого момента пиво.
  `reduced motion` — сразу пиво.
- **Смерти зомби-воркеров** — вид по id летуна: `DEATHS[crc32(flyer) % DEATHS.length]` (`pixel/flyers.js`, расширяется
  добавлением в конец); у всех одинаково, сервер его не шлёт. `pieces` — разваливается на куски (голова, руки, торс
  разлетаются с гравитацией и подскоком), `meat` — мясной взрыв (вспышка, ошмётки и брызги, лужа), `dust` — рассыпается в
  прах сверху вниз (серый песок осыпается горкой и сдувается), `head` — голова отлетает дугой и катится, тело падает
  следом, `fire` — сгорает зелёным огнём (огонь цвета FrankenPHP, эмиссивный; обугленный силуэт оседает пеплом), `sink` —
  проваливается в землю (трясётся, уходит по пояс, по плечи, над ямой — комья и пыль). До ~1,8 с, частиц — до ~24; затем
  мигает и исчезает. `reduced motion` — один кадр смерти и затухание.
- **Бродячие зомби** (шаги 5–6, **реализовано** на фронтенде, решение пользователя; протокол — «Бродячие зомби»). `flyer` с
  `wander: true` (и `flyers` снимка) — зомби-воркер без конца пути: встаёт из земли в `from` (кадры `rise`, 600 мс —
  руки из холмика, затем по пояс, комья земли; кадры `rise` и `under` — `wanderArt()` в `pixel/deaths.js`), дальше бродит
  сам. Маршрут — `wanderAt(id, from, мс от launchedAt, memo?)` в `pixel/wander.js` (реэкспорт из `pixel/flyers.js`) без
  DOM: от `launchedAt` по серверным часам цепочка отрезков, каждый — из FNV-хеша `id#номер отрезка`: следующая точка в
  зоне прогулки `walk` (лужайка и выжженная грядка чуть внутри краёв — `WANDER_AREA`, вне круга в центре —
  `WANDER_CIRCLE`; отрезок круг не пересекает, зажатый в угол идёт к середине своей четверти лужайки), шаг 4–14 % на скорости шарканья
  (≈ треть скорости фигурок), затем пауза 0,6–2,5 с (стоит, покачивается, иногда поворачивается); у всех зрителей одно и
  то же, открывший страницу позже считает с `launchedAt` (зомби из `#app[data-flyers]` встают уже в `createScene`).
  На экран точка маршрута ложится через `wanderOnScreen` (`pixel/wander.js`): по x зона раздвигается от корня грядки
  как фигурки (`spreadX`), пока её края остаются в `WALKER_MARGIN` от краёв экрана, иначе — уже (телефон: без этого
  треть зоны прижималась к краям); по y низ зоны сжимается выше нижних панелей (`.hud`, `[data-dawn-top]` в нижней
  половине `#app`, замер раз в 500 мс), иначе на телефоне зомби уходил под HUD, где по нему не выстрелить. На широком
  экране без панелей над низом зоны — ровно позиция фигурок. Сам маршрут в процентах конфига у всех один. Анимация — шаркающая ходьба зомби (шаг 150 мс), сортировка по
  ступням вместе с фигурками, перекраска светом сцены. Хит-бокс идёт за ним (как у обычного зомби). Смерть — тот же вид по
  id (`DEATHS`). `gone {flyers}` и вход в шаг 7 (даже без `gone`) — оставшиеся проваливаются в землю за 0,8 с (кадры
  `under`, комья; `reduced motion` — исчезают); проваливающегося не сбить. `reset` уводит сцену в бар — они уходят вместе
  со сценой (срез или затухание `again`), не проваливаясь.
  У обычного зомби (с `expiresAt`) всё как раньше.
- **Сова возвращается** (шаг 6): прилетает из-за левого края на ветку — обратный `OWL_FLIGHT` (взмахи по 90 мс, 2,5 с,
  посадка 150 мс), `scene.owlBack()` — реплики снова над совой. Рапира совы — кадры `OWL.rapier`: достаёт (2 кадра) на
  второй части `finale-6` и держит поднятой; клинок — эмиссивный слой с ореолом `halo(…, 'gold')`; в этот момент — cue
  `{type: 'owl-rapier'}` для звука. Перезагрузка на шаге 6+ — сова уже на ветке с рапирой.
- **Тыквы шага 6** — тон `franken`, без ручек и кружек (`pumpkinArms` скрыт), светятся и парят, как на шаге 5.
- **Рапира в руке** (`rapier` в `ITEM_DEFS`): тонкий длинный клинок, золотая чашка-гарда; клинок — слой `glow` без
  перекраски (как пламя свечи), мерцание по хешу; во всех позах с предметом. **Светящийся игрок** — фигурка с рапирой:
  золотой ореол на земле `halo(…, 'gold')` и тонкий эмиссивный контур кадра, дышит раз в 1,6 с.
- **Зомби-игрок** (`zombie: true`): та же собранная фигурка, кожа и лицо перекрашены в зомби-зелень (замена пикселей
  палитры, как цвет глаз), поза `shamble` — руки вперёд, ходьба вразвалку (4 кадра по 150 мс); имя — серо-зелёное. На
  `word` с `ok: false` — превращение 0,8 с: зелёная вспышка и дым. На `cure` — от фигурки `by` к нему летит белая искра,
  вспышка, перекраска уходит за 0,5 с.
- **FrankenPHP-босс**: при `boss` надевает **чёрные очки** (слой `glasses` поверх кадров `FRANKEN`, блик по стеклу раз в
  3 с) и говорит фразы `BOSS_PHRASES` (`franken.js`, расширяется добавлением в конец) тем же механизмом слотов, что
  `PHRASES`, только слоты по 6,5 с и говорит в ~90 % слотов (в среднем раз в 7 с); пока есть босс, прежние фразы не звучат. Кнопка поверх
  спрайта (`[data-franken]`, хит-зону `--hit-*-franken` публикует сцена) — удар.
- **Золотая цепная молния** (`FX.chain`: `strike` и выстрел рапиры по летуну): из кончика рапиры к цели — зубчатая ломаная
  с 2–3 ответвлениями, белое ядро и золотая кромка, три варианта по 50 мс, затем тает, всего ~300 мс; в цели — золотые
  искры. Прореживание — как у выстрела по клику: фигурка бьёт заново не чаще раза в 420 мс, на сцену — не больше 10 молний
  за 500 мс (сверх — только поза). На `strike` FrankenPHP вздрагивает (кадр `hit`, 120 мс).
- **Груда пепла** (`hp = 0` или шаг 7, **реализовано**, решение пользователя — «красивый огонь»): FrankenPHP сгорает
  за ~3 с (таймлайн `BURN` в `finale-timeline.js`, кадры `bossBurn()` в `finale.js`). Пламя тёплое, в палитре костра
  (`flameCore`, `pumpkinShine` … `pumpkinDeep`), без перекраски светом сцены. Оно вспыхивает кольцом на земле у ног и за
  0,7 с поднимается по фигуре рваным фронтом. Языки — 4 кадра мерцания по 90 мс: раскачиваются и поднимаются на ~24
  арт-пикселя. Под огнём фигура темнеет, следом снизу обугливается: пепел и уголь с тлеющей кромкой (`ember`, искры
  `flameCore`) и лаймовыми трещинами. С 1,15 с фигура осыпается сверху вниз в растущую груду (тлеющий рваный излом,
  падающие крупинки); к 2,6 с остаётся груда, пламя на ней опадает к 3,2 с. Тело — 12 кадров по 220 мс. Вверх летят и
  покачиваются искры, крестики огня и хлопья пепла с угольком — до 21 разом; `burnSparksAt` выводит каждую из её номера,
  без случайности. Свет — два аддитивных `halo(…, 'warm')`, вокруг фигуры и лужей на земле: мерцает с пламенем, после
  него груда светит слабее и гаснет к 5,2 с. Очки держатся на лице, пока излом не дойдёт до глаз (1,45 с), затем падают на
  груду. Дальше — груда пепла (`BOSS.ash`) с редкими лаймовыми угольками и струйкой дыма. Пока ночь затухает в рассвет
  (шаг 7, `startFade`), горящий FrankenPHP с огнём и светом рисуется поверх затухающего кадра (слой `overFade` сцены):
  иначе старый ночной кадр закрыл бы пламя. Кто стоит перед ним, на эти секунды оказывается под огнём. Всё — функция
  `down`, мс с начала сгорания по часам сцены (от `strike` с `hp = 0` или от события шага 7), поэтому зрители видят одно и
  то же. Перезагрузка на шаге 7 и на шаге 6 при `hp = 0` — сразу груда: в снимке нет времени начала шага, и попасть в кадр
  посреди сгорания нельзя. `reduced motion` — сразу груда, без огня. Кадры сгорания строятся заранее, в простое на шагах
  5–6. Лаборатория: `?finale=6&boss=10,100&walkers=1&bossdown=0&freeze=ms` — последний удар в начале, `freeze` — момент
  сгорания; `?finale=6&boss=60,100&walkers=1&play=0&freeze=ms` — шаг 7 с живым боссом; лист кадров —
  `public/dev/finale.html?only=rapier`.
- **Рассвет** (шаг 7): свет `dawn` в `LIGHTINGS` (`night.js`) — розово-золотое небо, солнце поднимается из-за холмов;
  переход из ночи — затухание старого кадра за 6 с; зелёные огни тыкв гаснут, тыквы опускаются на землю. Утки и куры —
  как днём. RoadRunner бегает по горизонту, как на шагах 5–6, но примерно в половине слотов (хеш слота) встаёт на
  1,7 с у правого края (0,84–0,94 ширины: середину горизонта закрывает плетень грядки, левую часть — дерево) и через

  один и тот же мип. Клик модератора по нему (`meep {}`) работает и на остановке. На шагах 5–6 он по-прежнему молчит.

### Топ стрелков

**Реализовано на фронтенде, проверено в лаборатории; backend — в работе** (решение пользователя к брифу №19: таблица по
очкам видна всегда; было — «Топ рассвета» только на шаге 7). `dawn.js`, `paintDawn` в `client.js`. Сюжет —
[`scenario.md`](scenario.md), «Рапира», «Топ стрелков вечера»; сообщения — [`protocol.md`](protocol.md), «Топ стрелков»
(событие `top {board}`, `top` в снимке).

- **Переход `dawn` → `top`.** Пока backend не переименовал, фронт понимает оба: событие `top` и `dawn` (один
  обработчик), снимок `top` или `dawn` (`top` важнее; шаблон пишет в `#app[data-dawn]` `$top ?? $dawn ?? null`, RPC
  `state` — `snapshot.top ?? snapshot.dawn`), строки `points` или `shots` (`dawnOf`). Событие `leaderboard` и `top` в
  ответе `me` таблице не нужны: пришедший `leaderboard` меняет только `online`. Внутри модель и хуки по-прежнему зовутся
  `dawn` — тесты и лаборатория на них.
- **Модель.** `dawn.board` — из снимка и каждого события `top` / `dawn` (полный список заменяет прежний; событие без
  `board` доску не трогает). Счёт — за весь вечер, поэтому `scene`, `finale` и `reset` (и с `again`) доску **не**
  обнуляют; только `finale {step: 7}` без доски даёт пустую `{board: []}` — призыв рассвета. Своё место клиент ищет в
  `board` по `me` (индекс + 1), поэтому оно не отстаёт.
- **Когда видна.** Всегда, во всех сценах, когда в доске есть хоть одна строка. Пустая доска вне рассвета — таблица
  скрыта (показывать нечего, лишняя плашка не мешает); на рассвете пустая — «Сбивайте уток рапирой!».
- **Свёрнута / раскрыта.** По умолчанию свёрнута: заголовок «Лучшие стрелки вечера», три лидера (`DAWN_FOLDED`) и, если
  меня нет в тройке, под чертой моя строка «#8 · ты · 4»; внизу справа мелкая кнопка «весь топ ▾» (`data-dawn-toggle`;
  скрыта, пока в доске не больше трёх строк). Раскрытая — шапка колонок «место · имя · очки» (`data-dawn-head`, только
  в раскрытой) и 10 строк (`DAWN_TOP`): если меня нет в первых девяти, но я в `board` — девять строк топа и десятой, под
  чертой, «#23 · ты · 4»; нет в `board` — обычная десятка; кнопка — «свернуть ▴». Выбор игрока хранится в
  `localStorage['hellowin:dawn-top']` (`'open'` / `'closed'`, `try/catch`; без хранилища — свёрнута).
- **Рассвет** (шаг 7 на экране — после отсчёта призыва, `step()`): при входе таблица раскрывается заново, даже если игрок
  её свернул (сохранённый выбор не трогается); клик на рассвете — снова выбор игрока; уход с рассвета (`reset`, «В бар»)
  возвращает сохранённый выбор. Перезагрузка на рассвете — тоже вход.
- **Где.** DOM в правом верхнем углу (`top: 16px; right: 16px`, ширина 236 px): там небо или стена бара, а стойка,
  грядка, круг и фигурки ниже; свёрнутая — около 165 px высоты, раскрытая — около 315 px. Под свёрнутым пультом
  модератора — `top: 64px`; открытый пульт она обходит слева, за его шириной. На средней ширине панели сверху посередине
  доходят до угла — таблица опускается под них (`top: 176px`): форма слова (`.word`, `.word-zombie`) — до 960 px, кости —
  до 800 px. Пропускает нажатия к летунам за ней (`pointer-events: none`), кроме кнопки.
- **Перестановка** — FLIP: строки — по `player.id`, перед обновлением запоминается их y, после — сдвиг `transform` от
  старой позиции к новой за 300 мс; обогнавшая строка на миг вспыхивает, новая въезжает справа, вытесненная из топа
  уезжает вниз. Счёт меняется сразу. Сворачивание, смена ширины и появление таблицы — без анимации (другая форма — просто
  новые строки). `reduced motion` — без анимации, просто новый порядок.
- **Телефон** (до 600 px, `DAWN_COMPACT_PX` в `client.js` по ширине `#app`; высоту HUD `client.js` кладёт в `--hud-h`):
  свёрнутая — полоска «#3 · ты · 7 · топ ▾» по центру над HUD, без заголовка (меня нет в `board` — «Топ стрелков ▾»,
  пустая доска на рассвете — «Сбивайте уток рапирой! ▾»); по тапу — тройка и моя строка под чертой, на рассвете — 5 строк
  (`DAWN_TOP_PHONE`: четыре + моя пятой, если я ниже четвёртой). Состояние то же, что на широком экране: одно на оба,
  рассвет раскрывает.

|---|---|---|

**Лаборатория.** Фиктивный движок ведёт доску, как сервер: каждое попадание игрока **в любой сцене** прибавляет очки
летуна (бегун — 0, в доску не попадает), порядок — очки, при равенстве раньше набравший, затем id; сброс и «В бар» доску
не чистят. Событие `top {board}` — со склейкой 500 мс (`HELLOWIN_TOP_INTERVAL`), снимок — `top`. `?dawntop=N` — N ботов
стреляют по летунам с разной меткостью в любой сцене; `?dawnboard=15` — сразу доска из 15 стрелков, я на 12-м месте (с
`?me=1`); `?dawntop=8&freeze=…` — кадры обгона (замороженный кадр показывает конец сдвига: DOM-анимации идут по настоящим
часам); `?dawnopen=1|0` — таблица раскрыта / свёрнута (на рассвете `0` сворачивает её после старта, как клик игрока);
`?topold=1` — сервер до переименования: `dawn` в снимке и событиях. Например, с `&dawnboard=15&me=1`: `?scene=0` — бар,
`?scene=1` — день, `?finale=5` — проклятый мир, `?finale=7` — рассвет; `&mod=1` — с пультом, окно 390 px с `&ui=0` —
телефон.

### Кости

**Реализовано** и проверено в лаборатории. Сюжет — [`scenario.md`](scenario.md), «Кости 6-6-6»; сообщения — [`protocol.md`](protocol.md), «Кости»
(RPC `roll`, `dice.owl`, события `dice`, `roll`, `dice` в снимке, реплики `dice-win`, `dice-owl-win`).

**Модель клиента.** `dice` — `{on, winner?}` из снимка и события `dice`; `ready` шага 1 — событием `ready`, как у других
сцен (модель снимает `ready` на `finale {step: 1}`). Живой шаг 1 показывает кости после отсчёта совы («Финал», «Призыв»): до его конца `client.rolls()` — нет, панель скрыта. Своя попытка — `myAttempt` в памяти: с 1 при загрузке, после
успешного ответа — следующая; ответ `bad attempt` с `last` — `last + 1` и бросок заново (один раз, без петли); снимок её
не несёт; новый раунд (`reset`, снимок другого раунда) начинает снова с 1. `client.rolls()` — шаг 1, `dice.on`, моя фигурка
на поле, не зомби, мой бросок не катится и RPC не в пути.

**Ввод.** Кнопка «Бросить» сверху по центру (место костей, `[data-dice-roll]`) или **пробел** (`isRollKey`: те же правила,
что у `isDrinkKey` — без модификаторов и автоповтора, не в полях ввода, не на кнопке (кроме кнопок-объектов), не при
открытом `<dialog>`; на шаге 1
пробел — только бросок, «Выпить» там нет) → RPC `roll {attempt}`, если `client.rolls()`; иначе кнопка `aria-disabled` и
ничего не уходит. Клик по земле — по-прежнему `move`. `busy`, `not now` — `console.warn`; кнопка снова доступна, когда
мой бросок докатился.

**Свой бросок — крупно сверху.** Как всё на странице — только из события: на нажатие кнопка сразу выключается, а
анимация начинается с моего события `roll` (`player.id` — я; ответ RPC нужен только для попытки и ошибок; ответ-повтор без
события — через 800 мс без своего события — сразу итог тех же чисел). Три кости ~48 CSS px в области `[data-dice]`: катятся, кувыркаясь, со сменой граней (кадры по 70 мс), с
отскоком встают на свои числа к 1,6 с, держатся до 2 с и тускнеют; пока катятся — кнопка выключена. 6-6-6 — кости
вспыхивают красным и дрожат; 6-6-6 с `counted: false` (пауза прогресса) — не победа: обычные кости, без вспышки и хора
(`winsRoll`; то же у маленьких костей над фигуркой и в звуке). Кости — DOM/CSS-пиксели (`image-rendering: pixelated`), без canvas. `reduced motion` — сразу
итог.

**Броски над фигурками.** Каждое событие `roll` (у себя своё — ещё и крупно сверху) → над фигуркой `player`
три маленькие кости с точками (арт `DICE` в `pixel/finale.js`, 7×7 арт-px на кость — точки 3×3 в светлой грани с
пикселем поля: в 5×5 контур сливается с ночным фоном и грань не читается; слой `labelLayer` над именем)
~2 с: 300 мс кувыркаются, затем стоят на числах, мигают и исчезают. `roll` старше 2 с по `at` не рисуется. Бросок совы
(`owl: true`) — те же кости справа от совы на ветке (над её головой — пузырь) и пузырь «Дайте я попробую!» (`owl.aside`
локально, только из события, без реплики
сервера; не перебивает реплику, которая ещё не провисела 5,6 с — тогда кости без пузыря).

**Режим включён** (`dice.on`): сверху — «Бросайте кости! Нужно 6-6-6» и кнопка; после победы (`dice {on: false, winner}`)
— «6-6-6 выбросил {имя} с {attempt}-й попытки» (у совы — «сова, с 3-й попытки») до шага 2, кнопки нет. У силуэта в
круге на победе — красная вспышка глаз (`SILHOUETTE` кадр `eyes`, 2,4 с, первые 0,6 с мерцает). Пузырь совы, который
задел бы панель костей (или поле слова шага 6), встаёт под сову.

**Пульт.** «Сова бросает» (`data-console-dice`, RPC `dice.owl {}`) — видна на шаге 1, пока `dice.on`; подпись —
«Сова бросает (N/3)» по числу бросков совы: `dice.owl` снимка и события `roll` с `owl`. «Шаг финала 2» при `ready` подсвечен, без него —
двойное нажатие «Нет 6-6-6. Точно?» и `force`.

FNV-хешем от `(раунд, игрок, попытка)` ради воспроизводимых кадров (сервер бросает случайно), повтор — тот же результат, `bad attempt` с `last`, пауза 1800 мс (`busy`),

анимации), `?bots666=N` — бот выбросит 6-6-6 на N-й попытке (по умолчанию боты бросают раз в 2–4 с и не выигрывают);
`dice.owl` с пульта (`?mod=1`) — 1-я и 2-я не 6-6-6, 3-я — 6-6-6; `?owlroll=ms[,ms…]` — «Сова бросает» в эти моменты

за стойкой; с `?mod=1` — клик по бегуну, по RoadRunner финала и за стойкой. `client.forgetDice()` — повтор
замороженного прогона начинает попытки заново.

### Чат

**Реализовано** (бриф №21): фронтенд проверен в лаборатории, backend — в master; на живом стеке вместе не проверялось.
Сюжет — [`scenario.md`](scenario.md), «Игроки», «Чат»; сообщения — [`protocol.md`](protocol.md), «Чат» (RPC `say`, событие
`say`, `chat.history`, `chat.mute`).

- **Модуль** `chat.js` без PixiJS (его грузят node-тесты): каталог фраз зомби `ZOMBIE_LINES` («Мммм… мозги…», «Ммм-ааа…»,
  «Мозгиии…», «Ыыыы… обработать…», «Ммм… ещё запрос…», «Ааа… воркер… голоден…», «Хрррр… мозги…», «Ммм… пинг… понг…»;
  новые — только в конец), `zombieLine(playerId, at)` — `ZOMBIE_LINES[hash('{player.id}:{at}') % length]`, FNV-1a
  `hash` из `pixel/clink.js` (тот же, что у чоканья), у всех одна; `sayText(event)` — текст бабла (у `zombie: true` —
  фраза, даже если пришёл `text`, иначе `text` после `trim`, пустой — `null`); `chatShowMs(text)` = 2500 + 80 мс на
  символ, не меньше `CHAT_MIN_MS` = 4000 и не больше `CHAT_MAX_MS` = 12000 (у совы — 7,9–27 с); поле `bindChat` и
  раздел пульта `createChatConsole`.
- **Поле.** Кнопка «Чат» в HUD (`data-chat-open`, `aria-expanded`) — у игрока с фигуркой на поле, **и у зомби**
  (`client.onField()`: `client.canWalk()` зомби исключает, а зомби говорит — фразой); без фигурки её нет, открытое поле
  закрывается. Поле (`data-chat` над HUD по центру, рамка как у формы слова; `input` `data-chat-input` с `maxlength` из
  `#app[data-chat-max]`, без атрибута — 120; кнопка «Сказать» `data-chat-submit`) открывается кнопкой (повторное нажатие
  закрывает — на телефоне нет Esc) или Enter, когда фокус не на элементе, которому Enter нужен самому (`input`,
  `textarea`, `select`, кнопка, ссылка, `contenteditable`: экран входа, слово рапиры, пульт, кнопки тыкв), и не открыт
  `<dialog>`; Enter с модификатором или автоповтором не открывает. Enter в поле — `say {text}` (пустое не уходит, поле
  закрывается), при `ok` поле очищается и закрывается; Esc — закрыть без отправки (текст остаётся до следующего
  открытия). Закрытие снимает фокус, чтобы пробел снова был глотком или броском. Пока фокус в поле, клавиши в игру не
  уходят: глоток (`isDrinkKey`) и бросок (`isRollKey`) не берут пробел у `input`, `bindObjectKeys` гасит пробел только на
  кнопках объектов, «`» пульта пропускает поля ввода; Tab остаётся обходом фокуса браузера. Клик по полю — не выстрел и
  не ход (`[data-chat]` в `UI` клиента). Отказы: `muted` — от поля остаётся только «Сова отобрала у тебя слово» на 3 с,
  затем оно закрывается; `rate limited` — «Не так быстро», `invalid text` — «От 1 до N знаков»: текст остаётся, поле
  вздрагивает (`chat--shake`, ступенями по 2–4 px, без анимации при reduced motion); прочие (`no character` — нет
  фигурки на поле) — в `console.warn`.
- **Бабл** — `scene.say(playerId, text, until)`: пиксельный пузырь тем же `bubble.js`, что у тостов и RoadRunner, над
  нарисованной точкой фигурки (`w.drawn`): едет вместе с ней и стоит, где она стоит; хвост — выше подписи имени
  (`SAY_OVER_LABEL` = 15 CSS px), имя не закрывается. Новая реплика того же игрока заменяет прежнюю; фигурки нет на
  поле — пропустить, ушла — бабл пропадает. Текст — только `Text` PixiJS, не HTML. `until` — серверное `at` +
  `chatShowMs`: опоздавшее событие (фон, переподключение) показывает остаток, просроченное не показывается. Над своей
  фигуркой — так же.
- **Пульт модератора** — раздел «Чат» между «Порогами» и «Отладкой»: `chat.history` при каждом показе пульта модератору
  и каждом его разворачивании (заголовок, «`»), дальше дописывает строки из событий `say` (клиент зовёт `onSay`); `say`,
  пришедшие во время запроса, не теряются. Строк не больше `CHAT_LOG_MAX` = 50 (умолчание `HELLOWIN_CHAT_HISTORY`; если
  `chat.history` принёс больше — столько, сколько принёс), старые уходят; список прокручивается внутри группы, новые
  внизу. Строка — «чч:мм · имя · текст» как текст (время — по часам зрителя); у зомби — пометка «зомби» и фраза бабла,
  после `chat.history` — ещё и исходный текст («хотел: …»). У строки — кнопка «заглушить» / «вернуть слово»
  (`chat.mute {player, on}`), заглушённые — списком «Без слова» под историей с кнопкой «вернуть слово»; ответ `muted`
  заменяет список. Ошибка кнопки — надпись на ней на 3 с («Нет прав», «Нет такого», прочее — «Не вышло»). `id`
  сообщения истории (сквозной номер за вечер) строке не нужен: история каждый раз заменяет список целиком.

| Где | Атрибут | Значение |
|---|---|---|
| `#app` | `data-chat-max` | `HELLOWIN_CHAT_MAX` (шаблонная переменная `chatMax`, запасное — 120) |
| HUD | `data-chat-open`, `aria-expanded` | кнопка «Чат», `hidden` без фигурки |
| поле | `data-chat`, `hidden`; внутри `data-chat-input`, `data-chat-submit`, `data-chat-note` — подсказка об отказе; классы `chat--shake`, `chat--told` (`muted`) | ввод сообщения |
| пульт | `data-chat-log` — история, `data-chat-row` (`data-player`, `data-zombie`), `data-chat-mute` (`data-player`, `data-on` — `1` заглушить / `0` вернуть); `data-chat-muted` — заглушённые | история чата |

**Лаборатория.** Фиктивный движок чистит `say` как сервер (управляющие символы и переводы строк — в пробел, пробелы
схлопываются, 1–120 символов), ведро 1 в секунду с запасом 3, заглушённому — `muted`; `chat.history` / `chat.mute`
отвечают по протоколу (`no target`, затем `invalid on`). `?chat=N` — N ботов говорят случайные фразы раз в 6 с (под
`?freeze` — один раз в начале: `?scene=1&walkers=6&chat=4&freeze=1500` — баблы); `?chatzombie=1` — каждый второй из них
зомби; `?mod=1` — пульт с короткой историей (одна строка — зомби с исходным текстом) и кнопкой «заглушить». С `?me=1`
своя фигурка: «Чат» или Enter.

### Эмоции

**Реализовано** на фронтенде (решение пользователя от 2026-10-28): проверено node-тестом и в лаборатории (1280 и 390,
ru и en); на живом стеке — **в работе**: backend готов, вместе не проверялось. Сюжет — [`scenario.md`](scenario.md),
«Эмоции»; сообщения — [`protocol.md`](protocol.md), «Эмоции» (RPC `emote`, событие `emote`, `emotes` снимка).

- **Модуль** `emote.js` без PixiJS (его грузят node-тесты). Набор — `#app[data-emotes]` (`emotes` снимка) как есть:
  строки без нормализации (сервер сравнивает точно, вариационный селектор U+FE0F — другая строка), повторы и пустые
  отбрасываются; пусто или сломано — `DEFAULT_EMOTES`, байт в байт умолчание `HELLOWIN_EMOTES` (🎃 👻 💀 😂 😱 😍 👍 👏 🔥
  🍺 🤘 🙏 🎉). Колонки ряда — по числу эмодзи набора (`--emotes`, на телефоне вдвое меньше — `--emotes-half`). Набор берётся раз при загрузке страницы: он меняется только env.
- **Панель — кнопка в HUD и ряд над HUD.** Кнопка «😀» (`data-emote-open`, `aria-expanded`, `aria-label` «Эмоции»)
  рядом с «Чат» — по тому же правилу (`client.onField()`: игрок с фигуркой на поле, зомби тоже); без фигурки её нет,
  открытый ряд закрывается. Ряд (`data-emote-panel`, `role="group"`) — над HUD по центру, на месте поля чата: на
  широком экране одна строка кнопок по 36 px (13 при наборе по умолчанию), на узком (контейнер ≤ 600 px) — две строки кнопок по 40 px (по 7).
  Свёрнут по умолчанию: всегда видимый ряд на телефоне занял бы полосу над HUD, где поле чата и полоска топа, а на
  ПК — середину поля у фигурок. Открывается и закрывается «😀», закрывается Esc (фокус — на «😀»); ряд и поле чата
  вытесняют друг друга (открытие ряда закрывает поле, открытие поля — ряд). После нажатия ряд остаётся открытым.
  У кнопок `aria-label` и `title` — «Эмоция: тыква» / «Emote: pumpkin» (имена — `emote.js`, `pick` по языку
  страницы; эмодзи вне набора по умолчанию назван самим собой).
- **RPC** `emote {emoji}` — эмодзи как в наборе. Нажатие ставит ряду передышку `EMOTE_COOLDOWN_MS` = 1000 мс (умолчание
  `HELLOWIN_EMOTE_COOLDOWN_MS`): кнопки `aria-disabled="true"` (не `disabled` — фокус клавиатуры не теряется),
  нажатия не уходят. `busy` молчит; прочие отказы (`anonymous`, `no character`, `unknown emoji`) и сбой RPC — в
  `console.warn`. Своя эмоция рисуется по событию, как у всех.
- **Над фигуркой** — `scene.emote(playerId, emoji, at)` по событию `emote`: эмодзи `Text` PixiJS в слое подписей (цветной
  глиф в пиксель-арт не рисуется), 26 CSS px (22 на узком), с тёмной тенью. Стоит над всем, что над головой: над
  именем, над костями шага 1 и над баблом чата того же игрока (`top` из `bubble.js`) — ничего из этого не закрывает;
  по x — над именем, в пределах экрана. Живёт `EMOTE_MS` = 3000 мс от серверного `at`: возникает с толчком (масштаб
  0,4 → чуть больше 1 → 1 за 220 мс), всплывает на 10 px и гаснет последние 600 мс; при `prefers-reduced-motion` —
  сразу целиком, без всплытия и угасания. Новая эмоция игрока заменяет прежнюю; фигурки нет — не рисуется, ушла
  (`leave`) — эмоция пропадает. Ничего не хранится: опоздавшее событие показывает остаток, просроченное и снимок —
  ничего.

| Где | Атрибут | Значение |
|---|---|---|
| `#app` | `data-emotes` | JSON `emotes` снимка (шаблонная переменная `emotes`, запасное — `[]`) |
| HUD | `data-emote-open`, `aria-expanded`, `aria-controls="emotes"` | кнопка «😀», `hidden` без фигурки |
| ряд | `data-emote-panel` (`#emotes`), `hidden`; кнопки `data-emote` — эмодзи, `aria-disabled` на передышке | панель эмоций |

**Лаборатория.** Фиктивный `emote` — как сервер: `anonymous` (нет своего игрока), `no character`, `unknown emoji`
(точное совпадение с набором), `busy` чаще раза в 1000 мс без события; событие `{type: 'emote', round, player: {id},
emoji, at}` всем. Набор — по умолчанию (`data-emotes` в лаборатории нет). `?emotes=N` — N ботов показывают случайные
эмоции раз в 4 с (под `?freeze` — раз в начале, с `?me=1` — и своя): `?scene=1&me=1&walkers=4&chat=2&emotes=4&freeze=1500`
— эмоции рядом с баблами.

### Звук

Движок — `public/js/audio/engine.js` (не зона фронтенда, только вызовы). `app.js` создаёт `createAudio()`,
`audio.unlockOn(document)` (до первого нажатия или клавиши все вызовы молчат) и отдаёт `createSound(audio, {serverNow,
owlGone})` клиенту (`createClient(…, {sound})`), сове (`createOwl(…, {onShow})`) и сцене (`scene.onCue`). Mute и
громкости хранит сам движок (`localStorage['hellowin.audio']`), фоновую вкладку он приостанавливает.

**Правило — как у рисования: только из событий.** Звучит событие канала или момент серверных часов; свой клик по тыкве,
выстрел, шаг ничего не играют, пока не вернётся событие. Исключение — щелчок `ui.click` по кнопкам HUD и пульта.

- Громкость: своё действие (`player.id` события — я) — 1, чужое и анонимное — 0,6. Панорама — `clamp((x − 50) / 50, −1, 1) × 0,8`
  по x элемента, летуна, фигурки (процент ширины).
- **Музыка** — `audio.setMusic(trackOf({scene, sceneStages, finale}))` при старте, снимке (ресинк), `scene`, `finale`,
  `reset`: бар, день, закат, ночь, кровавая луна финала, `cursed` с шага 5; номера сцен — как есть. С ночи (сцена N−1) эффекты финала
  рендерятся заранее (`whenReady('finale')`). Снимок играет только музыку, без эффектов.
- **Интенсивность** — `0,2 + 0,8 × доля пройденных стадий сцены`: тыквы — от стадии, с которой началась сцена (`stageMax`
  прошлой; открывшему страницу посреди сцены — от самой низкой тыквы), до `stageMax`; в финальной сцене — стадия круга;
  при `ready` и с шага финала 1 — 1; в баре — всегда 0,2. Пересчёт по `click`, `pumpkin`, `scene`, `finale`, снимку; `reset` — 0,2.
- `click`: по тыкве — `pumpkin.burned`, если `clicks > threshold`, тыква на `stageMax` или сцена финальная; иначе день —
  `pumpkin.carve` (стадии 0–2) / `pumpkin.scoop` (стадия 3 — вычищают), закат — `pumpkin.ignite`, ночь —
  `pumpkin.enchant`; по костру — `bonfire.click`, по кругу — `circle.click`. Выстрел фигурки по клику своего звука не
  имеет (`shot.*` — только по `shot`, см. «Выстрел по клику»).
- `pumpkin`: тыква днём / на закате / ночью — `pumpkin.stage` / `pumpkin.lit` / `pumpkin.charged`; костёр — `bonfire.stage`; круг —
  `circle.stage`, на своём `stageMax` — `circle.done`.
- `ready` — `ui.ready`. `scene` в финальную — `bonfire.explode`. `reset` — `stopAll()`, `ui.reset`.
- `flyer` по `kind`: duck — `duck.quack`, chicken — `chicken.cluck`, bat — `bat.squeak`, worm — `worm.squelch`, firefly —
  `firefly.ding`, witch — `witch.cackle`, zombie — `zombie.groan`, roadrunner — `runner.steps`, crow — `crow.caw`, ghost —
  `ghost.wail`, fly — `fly.buzz`. Панорама — по `from.x`, громкость по глубине 0/1/2 — 0,5/0,75/1, с `bush` — ещё `bush.rustle` у куста.
  Не звучит летун, чей `expiresAt` прошёл или запущенный больше 1,5 с назад.
  Бродячий зомби (`wander`, **реализовано** на фронтенде) — `zombie.rise` (без него — `zombie.groan`; сейчас его нет), только
  по свежему событию (не старше 1,5 с от `launchedAt`) и не чаще раза в 400 мс (толпа на входе в шаг 5 — один стон), из
  снимка — молча; дальше изредка стонет — не чаще одного стона на всю сцену раз в
  6–10 с (случайный живой бродячий, громкость 0,4); `gone` — молча.
- `shot` — `flyer.hit` и `flyer.fall` (+0,05 с) там, где летун сейчас (по его пути); летун, которого страница не видела
  или давно улетевший, — молча. Фигурка стрелка на поле — `shot.<item>` (pistol, candle, book, beer, `red-flame` →

  чужое 0,6; старше 1,5 с — молча. `shot` после своего `throw` — `flyer.hit` и падение в момент удара, `shot.<item>` нет.
- `move` моей фигурки — `walk.step` каждые 0,35 с пути (не больше 12, таймерами: следующий `move` и `reset` отменяют
  неуслышанные); чужие шаги молчат.
- `clink` не старше 3 с — `clink.glass` в момент удара (`at + CLINK.strike`) и `clink.cheer` при поднятых кружках
  (`at + CLINK.raise`); часть, прошедшая больше чем на 0,25 с, не играется. Автоматическое чоканье — `clink.glass` с громкостью 0,5
  по `scene.onCue` в момент удара.
- **Бар** (имена — предложение агенту звука; неизвестное движку имя молчит): `pour` — `bar.pour` (только свежий, позже
  0,4 с от `since` — нет; панорама — по середине места у стойки), `mugs` — `bar.mug`, `take` с `ok` — `bar.take`,

  движке — `finale.meep`, громкость 0,4, панорама — по его x; чоканье с ним — как любое `clink`.
- `walker` моей фигурки, которой не было на поле (после `register` или подключения с `look`), — `ui.join`; смена вида — нет.
- **Сова**: когда пузырь действительно открылся (`onShow` в `owl.js`, в т. ч. вторая часть реплики) — `audio.speak('owl',
  text)`, у драматичной (`hoot`) — сначала `owl.hoot`, речь — с задержкой 0,95 с; после отлёта совы реплика над FrankenPHP — `audio.speak('franken', text)`,
  как и его фразы по серверным часам (`scene.onCue`).
- **Финал** — только следующий шаг вживую (как анимирует сцена; перезагрузка, ресинк, скачок — молча), задержки — из `T`
  (`finale-timeline.js`): шаг 1 — `finale.wake` (после отсчёта совы: клиент отдаёт звуку событие шага в конце `SUMMON_MS`, цифры отсчёта — `circle.stage`); 2 — `finale.strike` на каждой молнии (`T.strikes`: 0; 0,38; 0,76 с) и
  `finale.tada` на разоблачении (`T.reveal`, 0,9 с); 3 — `finale.run` и `finale.meep` (`T.meep`, 5 с); 4 — `finale.reveal`;
  5 — `finale.owlAway`, когда сова взлетает (`scene.onCue`), музыка `cursed` — сразу с событием (`trackOf`).
- **Рапира** (**запланировано**; имена — предложение агенту звука, неизвестное движку имя молчит). Музыка: `boss` — пока есть
  босс с `hp > 0` (`trackOf({scene, sceneStages, finale, boss})`), `dawn` — с шага 7; новый цикл (`reset` с `again`) —
  `bar`, обычной сменой трека (`NEXT_TRACK.dawn = 'bar'`, кроссфейд); `again` не играет `ui.reset` и `stopAll()` не
  обрывает музыку. Эффекты: `shot` по зомби — `flyer.hit`
  и вместо `flyer.fall` звук его смерти `zombie.die.<вид>` (`pieces`, `meat`, `dust`, `head`, `fire`, `sink` — по `DEATHS`);

  с `ok: false` — `word.fail` (только своё слово, громкость 1) и `player.zombify` у фигурки (+0,3 с); `cure` —
  `player.cure`; выстрел рапирой по летуну — `shot.rapira` (`SHOT_SOUNDS`: `rapier` → `shot.rapira`, имя композитора);

  с живым боссом — `franken.die`, когда он вспыхивает. Шаг 6 вживую — `finale.owlBack` при прилёте совы (если
  движок его знает).
- **Кости** (**реализовано**). `roll` — `dice.roll` (~1,5–2 с; своё — громкость 1,
  чужое — 0,6, панорама — по фигурке или сове) и `dice.land`, когда кости встают (+1,6 с у своего крупного броска, +0,3 с у
  маленьких над фигуркой); бросок 6-6-6 — ещё `dice.666` (зловещий хор) на `dice.land`, кроме `counted: false`. Свежесть — как у летунов: `roll`
  старше 1,5 с по `at` молчит.
- **Мип-мип** (**реализовано**): событие `meep` — `rr.meep` (`finale.meep` как запасной не нужен: движок его знает); панорама — по x
  RoadRunner, если он виден (не виден — молча). «Мип-мип!» перебежки (cue сцены `rr-meep`, см. «Перебежки RoadRunner») —

  рассвета — тот же cue с полем `volume` 0,35 (cue без `volume` — 0,7).
- **Фон.** В скрытой вкладке и 0,6 с после её возвращения события не звучат: так отсекается пачка придержанных публикаций.

## Локализация

**Реализовано** на backend и фронтенде, проверено тестами и в лаборатории, на живом стеке — **в работе** (решение
пользователя от 2026-10-27, вариант «язык выбирает сервер, шаблоны — переводчик Spiral»). Языки —
`ru` (исходный, по умолчанию) и `en`. Сервер шлёт коды и id, а не фразы, поэтому язык — дело страницы: игроки на разных
языках играют в одном зале, реплика совы `{line, params}` у каждого звучит на его языке.

- **Выбор языка — backend.** Порядок: `?lang=ru|en` (ставит cookie `hellowin_lang` на год, путь `/`), cookie,
  `Accept-Language` (первый из `ru`/`en` по весу), иначе `ru`. Выбранный язык — локаль переводчика на запрос и переменная
  шаблона; layout пишет его в `<html lang>` (`@{locale}`). Ответы страниц — с `Vary: Cookie, Accept-Language`.
- **Шаблоны — переводчик Spiral** (`spiral/translator`, Stempler: `[[Текст]]` — ключ и есть русский текст). Каталог
  английского — `app/locale/en/messages.php` (содержимое ведёт фронтенд). Так переводятся `home` и layout.
- **«Как это работает»** — целым текстом: `how-it-works.dark.php` (русский) и `how-it-works.en.dark.php` (английский);
  контроллер берёт файл по языку. 700 строк прозы удобнее вести текстом, а не ключами; при правке одной версии правится и
  другая в том же коммите.
- **JS — свои каталоги.** `public/js/i18n.js`: `lang` — язык страницы из `<html lang>` (вне `ru`/`en` и без DOM, в тестах,
  — `ru`), `pick({ru, en})` — вариант на язык страницы (нет `en` — `ru`). Язык за жизнь страницы не меняется: переключатель
  перезагружает её с `?lang=`, поэтому модули выбирают тексты один раз при загрузке (`const PHRASES = pick({...})`).
  Числа — `Intl.NumberFormat(lang)`, склонения — по правилам языка (в `en` две формы).
- **Каталоги-шутки выровнены.** Где фраза выбирается детерминированно по серверному времени или числу из события
  (тосты, фразы FrankenPHP, слухи бармена, реплики совы по id), английский список той же длины и в том же порядке: у
  игроков на разных языках одна и та же по смыслу фраза в один момент. Шутки адаптируются, а не переводятся дословно:
  отсылки к PHP-сообществу остаются, игра слов заменяется своей.
- **Не переводятся:** чат, свой текст совы от модератора, имена игроков. Магическое слово сервер принимает и «рапира», и
  «rapier» ([`scenario.md`](scenario.md), «Рапира»).
- **Переключатель** — кнопка в HUD «EN» / «RU» (`data-lang-switch`, ссылка на `?lang=` другого языка) и такая же ссылка в
  шапке «Как это работает».
- **Пульт модератора** переводится вместе со всем интерфейсом.

## Страница «Как это работает» (`GET /how-it-works`)

- Вводный блок + вкладки (WAI-ARIA Tabs, `public/js/how-it-works.js`, вкладка в `location.hash`, без JS — все
  разделы подряд). Новая вкладка = ссылка `role="tab"` в `tabs__list` + `<section role="tabpanel">`; JS и тест не
  трогать.
- Схемы — inline SVG; цвета через CSS-переменные, подписи без обводки, ширина до 1360px. Схемы показывают реальный
  механизм: имена классов, каналов, ключей и портов берутся из кода, не из памяти.
- Выдержки кода (**реализовано**) — `<figure class="code">`: `figcaption` с путём файла и `Класс::метод()`, затем
  `<pre><code>`; перед ней — фраза-подводка. Код только настоящий, 5–15 строк, скопирован из репозитория: убирать можно
  комментарии и куски с пометкой `// …` (`# …` в YAML), переписывать нельзя. В обеих версиях страницы выдержки
  одинаковые, переводятся только подводки. Внутри кода экранируются `&`, `<`, `>`, а также то, что прочли бы Stempler и
  переводчик: `${` → `&#36;{`, `@` → `&#64;`, `{{`/`{!` и `[[`/`]]` — первая скобка сущностью. Выдержка устаревает
  вместе с кодом: меняя показанный метод, обнови её. Сверку держит тест `tests/Unit/HowItWorksExcerptsTest.php`
  (в `composer test`): путь он берёт из первого `<code>` в `figcaption`, декодирует HTML и ищет каждую строку выдержки в
  этом файле в том же порядке, без учёта отступов; строки `// …` и `# …` — вырезки. Новые выдержки — в той же разметке. Сейчас: «Модули» — `.rr.yaml` (`http`, `centrifuge`/`jobs`);
  «Клик» — `RPCService::handle()`, `ChannelPublisher::click()`; «Стадии и лок» — `RitualStore::click()`, `::locked()`;
  «Идемпотентный переход» — `TransitionPumpkin`, `TransitionQueue::pumpkinKey()`/`::pumpkin()`, хранилище
  `transitions`; «Кости» — `DiceService::roll()`, хранилище `dice`; «Модератор, фигурки, летуны» —
  `ChannelPublisher::move()`/`::publish()`; «Метрики» — `PlayMetrics::declare()`/`::rpc()`.
- Вкладка «Идемпотентный переход» (`#idempotency`): клик → очередь `transitions` с дублями → `#[Idempotent]` с ключом
  `{round}:{pumpkinId}:{toStage}` → одна публикация `pumpkin`. Тесты страницы — `HowItWorksPageTest`.
- Вкладка «Кости» (`#dice`, **реализовано**; ведёт backend): `roll {attempt}` → ключ идемпотентности
  `{round}:roll:{player}:{attempt}` → случайный бросок (`random_int`), ответ сохраняется в хранилище spiral/idempotency на
  `HELLOWIN_DICE_IDEMPOTENCY_TTL` с, грани последней попытки — ещё и в `hellowin:dice`; повтор той же попытки получает
  сохранённый ответ (идемпотентность с сохранённым ответом), поэтому переподключение или двойной клик не перебросят; лок
  костей решает, чьё 6-6-6 первое.

- Песочница без backend: `public/dev/lab.html` поднимает сцену на фиктивном снимке и генерирует события `click` /

  виден; без него RPC пульта отвечают `forbidden`), сцена готова, когда все тыквы готовы (`ready`, реплики

  лаборатории; RPC `reveal` панели отвечает ими же); реплики совы (авто и с пульта); особые летуны и волна «Пуск летунов»; бродячие зомби — на шагах 5–6; пауза
  прогресса — как на сервере (protocol.md, «Пауза прогресса»): `click`, `drink`, `strike`, `roll` принимаются с
  `counted: false` в ответе и событии — клик с прежними `clicks`/`stage`, глоток без `drinks`, удар с прежним `hp`,
  6-6-6 не выигрывает (повтор попытки — с тем же `counted`); стадии, цели и готовность не наступают, летуны, зомби и
  выстрелы идут (подбитый на паузе зомби не идёт в цель «зомби»), снятие паузы догоняет пропущенное, `reset` (и «В бар»)
  снимает её без события `pause`; игроку пауза не видна, только пульту (`?mod=1`); цифры шкал — тоже только с
  `?mod=1`; летуны и предметы — по сценам; бар (по умолчанию) — «Бар и сдвиг номеров сцен», «Лаборатория». Параметры старта: `?scene=N`, `?ready=1`,

  сразу; `?zshot=ms` сбивает зомби). Костёр — как на сервере: заперт, пока тыквы сцены не готовы (клик по нему тогда не
  уходит), свой лимит `bonfire` (`?bclicks=N` — ровно N вместо формулы) и стадии `0,0,4,7` по сценам, реплики `last-pumpkin` → `bonfire-open`, затем

  финальной сцене на шаге 0, лимит `circle` (`?cclicks=N` — ровно N), 4 стадии, замкнут → `ready`, `circle-done`, `scene-ready`;
  `?circle=N` — стартовая стадия, `?nocircle=1` — без круга. Лимиты — как на сервере (protocol.md, «Лимиты и баланс»):
  `max(1, ceil(k × (BASE + PER_PLAYER × (n − 1)))) + надбавка` с дефолтами `engine.md`; n — фигурки на поле, новое число
  принимается, продержавшись 3 с (тикер раз в секунду), `?players=N` — n зафиксировано; `k` с пульта (`thresholds`)
  переживает сброс, надбавки (`bar.target`, `cursed.target`, `boss.hp`) — нет; `?k=N` — стартовый множитель; `?target=N`

  текущего контекста, с догоном: тыква с кликами выше нового порога переходит сама, цель бара ≤ `drunk` — бар готов;
  `?boss=hp,max` — надбавка босса добирает `max`. `flyers.burst` — `ceil(5 + 0,2 × (n − 1))` летунов текущего
  набора разом, без кулдауна и потолка, без набора — `no flyers`. `?owlrolls=N` (с `?finale=1&dice=1`) — сова уже бросила N раз
  (`dice.owl` снимка). `online` — число фигурок, в снимке и в событии
  `leaderboard` раз в 5 с (только `online`). Финал: шаг 1 — только из замкнутого круга (иначе `not
  ready`, с пульта — `force`), на шаге 2 каждой фигурке — `move` от центра грядки к краю лужайки, `startedAt` снимка — за
  3 ч 07 мин до старта; `?finale=N` — сразу итог шага N (боты стоят вокруг грядки и не бродят до шага 2), `?ritual=1` —
  шаг 0 с замкнутым кругом, `?play=ms` с `?freeze` жмёт «Шаг финала» (`force`) в этот момент: `?finale=1&play=0&freeze=1000`
  — середина шага 2; `?ritual=1&play=0&freeze=500` — «Призыв через 3…», `2500` — «1…», `3300` — вспышка круга после отсчёта. Летуны финальной сцены — червяки (путь по лужайке
  12–25 %, вне грядки, `wobble` 0,8–2 × 3–6); `?worms=1` — три червяка сразу в любой сцене (`?wshot=ms` сбивает первого). `?next=ms` с `?freeze` жмёт
  «Следующая сцена» (`force`) в этот момент: без `?scene` — выход из бара, с `?scene=1` — закат, с `?scene=3` — взрыв. `?stage=N` — до 11.
  `?scene=N` ставит тыквы и костёр на последние стадии сцены перед ней, `?ready=1` — на стадии своей сцены.
  Предметы — как `items` и `finale_items`: в финальной сцене на шаге 0 красный огонёк, на шагах 1–4 пустые руки, с шага 5

  «Мип-мип!» на горизонте рассвета: `?rrmeep=N` с `?freeze` — середина N-го мипа после начала часов:
  `?finale=7&rrmeep=1&freeze=8000`.
  Перебежки RoadRunner: `?rrdash=home|out|away|back` с `?freeze` выбирает начало часов так, что замороженный момент — в
  середине этой фазы (`?rrslot=N` — другой слот), `?rrcrowd=1` ставит ботов в полосу у HUD, где он бегает; ботов —
  до 60 (`?walkers=N`, после восьми именных — `Bot-N`): `?finale=3&walkers=40&rrcrowd=1&rrdash=out&freeze=1500` — посреди
  пробежки сквозь толпу, `away` — «Мип-мип!» на дальнем конце, `home` — стоит со свечением (на шаге 4 сцену закрывает
  панель разоблачения).
  Чоканье по клику — как `WalkService::clink`: досягаемые тыквы — `pumpkin-3,5,7,9,10,11,13,15,17` (`data-reachable`),
  к фигурке — сбоку от конца её пути на 4 % по x со стороны подошедшего (у края — с другой стороны), к тыкве — ближайшая
  точка «у кружки» (`pumpkinStand`, приведённая в зону); `move` с `clink`, событие `clink` (случайный `toast`), когда оба прибыли, +100 мс тикера; ошибки
  `no character`, `not cursed`, `no target`, `busy` (3200 мс от `at`). С `?me=1` в проклятом мире — клик по боту или
  досягаемой тыкве. `?clickclink=1` ставит ботов поодаль и не даёт им бродить, а боты сами чокаются по клику: 1-й со
  2-м (тост на два голоса), 3-й с `pumpkin-10`, 4-й с 5-м — на старте и раз в 9 с (дальше тосты случайные), `?toast=N`
  — всем тост N: `?finale=5&clickclink=1&walkers=5&freeze=1900` — удар, `2700` — тосты, `3700` — ответ.
  Пиво и чоканье с тыквами: `?finale=5&pumpkinbeer=1&walkers=9&zmin=0` — по боту у каждой досягаемой тыквы, раз в
  9 с бот допивает, подходит к кружке за пивом, чокается с тыквой и отходит; с `?freeze`: `1600` — на подходе,
  `2000`–`2800` — передача, `2900`–`3500` — новая кружка, `4000`–`4450` — тыква протягивает кружку и удар, `5200` — тост.
  Пустая кружка: `drink` оставляет `mug`, `bar.take` и `beer` меняют её на пиво, `shoot` с ней — `throw` раньше `shot` и
  пустые руки; `?item=mug&flies=3&walkers=3&still=1&flyshot=1000&freeze=1300` — кружка в полёте, `1580` — разбилась о
  муху, `&throwmiss=1100` — второй бросает в падающую (промах), `?scene=1&item=mug&flyers=1&shooter=1&still=1` — днём,
  `?finale=5&item=mug&worms=1&wshot=900&still=1` — в проклятом мире.
  Предметы и летуны для проверки: `?item=<id>` выдаёт этот предмет во всех сценах (и в баре), `?kind=<id>` — вид летунов
  `?flyers=1` (в закате своих нет); в проклятом мире летают червяки, мыши и светлячки, `?fireflies=1` — три светлячка
  сразу (`?fshot=ms` сбивает ближнего). В баре летают мухи (как `FlyerFactory::fly`: 2–3 посадки на столешницы —
  `cy − ry/2`, x в `cx ± rx/2` — и верх стойки, **запланировано** — и места посадки `perches`, подряд не на одну поверхность, сидит 900–1600 мс, перелёт 900 мс,
  вход и выход наполовину из-за боковой стены); `?flies=N` — N мух сразу, по зерну (кадры `?freeze` повторяются),
  `?flyshot=ms` — первая фигурка сбивает первую муху: `?flies=3&freeze=500` — петли, `1400` — сидят,
  `?flies=3&walkers=3&flyshot=1000&freeze=1300` — клякса.
  Выстрел по клику: событие `click` несёт кликнувшего, как на сервере, — свой клик по элементу идёт от своей фигурки
  (если она на поле), «клик», «авто» и `?auto=1` — от случайного бота или, в доле `?anon=0..1` (0,25), анонимно;
  `?still=1` — боты стоят на месте и не бродят: `?scene=1&auto=1&still=1&walkers=8` — толпа стреляет по тыквам.
  HUD и пульт по контексту (бриф 23, бриф 22 п. 3–4): `?conn=ok|reconnect|down` — лампочка связи зелёная, жёлтая
  мигающая, красная; подпись аптайма — с `?finale=3` и в баре с `?roadrunner=1`; пульт `?mod=1` в любой сцене и шаге —
  `?mod=1&scene=1`, `?mod=1&scene=1&players=12`, `?mod=1&finale=1&dice=1`, `?mod=1&finale=5`, `?mod=1&finale=6&boss=60,100`, `?mod=1&finale=7`.
  Инструменты лаборатории (утка, клик, авто, выстрел, стадия) — отдельной панелью
  `[data-lab-panel]`. Все параметры (`?walkers=N`, `?me=1`, `?join=1`, `?shooter=1` и прочие) — в комментарии в
  начале `lab.html`; `window.lab` — `{client, engine, scene}` для проверок из консоли. `?sound=1` — настоящий звук, как
  в `app.js` (первое нажатие разблокирует, кнопка «Звук» в HUD, `window.audio` — движок); без него лаборатория молчит.
- **Автопилот в лаборатории** (scenario.md, «Автопилот»): движок раз в 200 мс играет правила сервера из
  `public/dev/autopilot.js` (`autoTick` — ход по состоянию, `createSpeech` — счёт речи совы по `public/autopilot.json`,
  которую лаборатория читает, как сервер), ходит теми же вызовами, что пульт, и шлёт `auto`; RPC `auto` пульта
  (`?mod=1`) его включает. `?autopilot=1` — включён со старта; ускорение проверки: `?appause=ms`
  (`HELLOWIN_AUTO_PAUSE_MS`), `?apdawn=min-max` (рассвет, мс), `?apdice=ms` (бросок совы), `?apstall=ms` (`force`
  застрявшего зала), `?aptalk=0..1` (речь совы в счёте короче — пузырь при этом не меняется), `?aproom=1` — зал сам
  делает задачи (клики, бродячие зомби, удары рапирой; пиво и слово — боты). Весь вечер за ~5 минут:
  `?mod=1&autopilot=1&aproom=1&k=0.1&walkers=4&aptalk=0.1&appause=1500&apdawn=8000-12000&apdice=4000`. Таблица
  `public/autopilot.json` пересобирается из `owl.js` и `finale-timeline.js` (`speechTimes`); тест сверяет её с ними —
  правка каталога совы или таймлайна финала идёт вместе с пересборкой таблицы.
