# Фронтенд

Статус: пиксельная сцена на PixiJS, главная на снимке и сцена 0 «День: подготовка» — **реализовано** (идёт доводка
вида); «Как это работает» с вкладкой «Идемпотентный переход» — **реализовано** (страницу ведёт backend); курошлёпка — **реализовано**; экран входа, персонажи и прогулка по полю — **реализовано** на фронтенде и
проверено в лаборатории, **в работе** — ждёт backend (`look` в `register`, `move`, `walker`/`move`/`leave`,
`walkers` в снимке); пульт модератора, сова с пузырём, модель сюжета (`ready`, `finale`, `pause`, `zombies`),
новые летуны (вороны, мыши с `wobble`, призраки, ведьма), птица-бегун и зомби, временная панель разоблачения —
**реализовано** и проверено в лаборатории и на живом стеке; вид сцен 1–3 (свет по сценам, стадии тыкв 5–11, костёр,
прыжок тыкв, взрыв и пепелище) — **реализовано** и проверено в лаборатории и на живом стеке; магический круг (элемент,
рисунок по стадии, `circleStageMax`) и червяки финальной сцены — **реализовано** и проверено в лаборатории и на живом
стеке; визуал финала (FrankenPHP,
RoadRunner, экран разоблачения) и игроки на странице (лидеры, своя статистика) — **запланировано**.

## Зона и ограничения

- Файлы фронтенда: `app/views/**` (Stempler), `public/css/**`, `public/js/**`, `public/` (картинки, шрифты).
- Без сборщиков и npm-зависимостей в рантайме: обычные CSS и нативные ES-модули (`<script type="module">`). Внешние
  библиотеки — только с CDN с точной версией: `centrifuge@5.7.4` (UMD, глобальный `Centrifuge`),
  `pixi.js@8.22.0` (`dist/pixi.min.mjs`).
- Протокол и данные — [`protocol.md`](protocol.md); правила игры — [`scenario.md`](scenario.md). Если фронтенду нужно
  новое поле или событие — сначала правка `protocol.md`, затем backend.
- Скиллы: `pixijs` (роутер по `pixijs-*`), `pixel-art`, `pixel-art-sprites` — подключены в `skills.json`.

## Главная страница (`GET /`, шаблон `home`)

Переменные шаблона — поля снимка состояния из `protocol.md` (`round`, `scene`, `sceneStages`, `stageMax`,
`threshold`, `elements` со `size`/`stage`/`clicks`) и `centrifugoUrl`. Layout — `app/views/layout/base.dark.php`:
стеки `styles` и `scripts`, атрибуты состояния на `<body>`.

### Отрисовка: гибрид canvas + DOM

- **PixiJS рисует**, на весь экран, `<canvas>` под разметкой: небо, грядка, корень в центре, побеги к тыквам,
  тыквы, частицы. Пиксельный режим: `antialias: false`, текстуры `scaleMode: 'nearest'`, `roundPixels: true`,
  масштаб «арт-пикселя» — целое число экранных пикселей, подбирается от размера окна.
- **DOM держит состояние и ввод.** Тыквы — прозрачные `<button>` поверх своего спрайта: клик, фокус с клавиатуры,
  скринридер, хуки тестов. Canvas состояние не хранит — читает атрибуты DOM и слушает их изменения через API сцены.
- Спрайты — код: матрицы индексов палитры в JS, запекаются в текстуры при старте. Картинок-файлов нет.
- **Глубина — алгоритм художника.** Плоское (небо, дальний план, почва, газон) запекается в фон; всё, что стоит на земле
  (трава и сорняки, кусты, реквизит, плетень, дерево, тыквы, корень), — один контейнер, отсортированный по y опорной
  точки (низ спрайта): дальнее рисуется раньше, ближнее перекрывает его. Летуны в воздухе — вне этой сортировки.
- Без WebGL/WebGPU (или если PixiJS не загрузился) страница остаётся рабочей: кнопки видны с emoji-запасным видом.

и счёт работают на emoji-кнопках.

API сцены — единственная связь `app.js` с canvas:

```js
const scene = await createScene(rootEl, snapshot); // null, если рендер недоступен
scene.render(snapshot);              // полный перерендер (state, reset)
scene.click(id, {stage, clicks, threshold}); // эффект клика: тряска + частицы по сцене; у костра и круга — тряска и искры
scene.pumpkin(id, stage);            // переход стадии: вспышка, смена спрайта; у костра — вспышка света и искры
scene.setScene(n, stageMax);         // смена сцены: перекраска, закат, прыжок тыкв, взрыв костра 2 → 3
scene.circle(progress);              // магический круг на пепелище, 0–1 (0 — не рисуется); ведёт client.js по стадии круга
scene.setServerClock(fn);            // источник серверного времени (Date.now() + offset) для летунов и фигурок
scene.flyer(event); scene.shot(event); // летуны: запуск, падение (+ выстрел фигурки игрока из event.player)
scene.flyerAt(clientX, clientY);     // id летуна под указателем или null
scene.walker(w);                     // фигурка появилась или сменила вид/имя (Walker)
scene.move(id, walk);                // фигурка пошла (Walk)
scene.leave(id);                     // фигурка ушла
scene.setMe(id);                     // своя фигурка: имя другим цветом
scene.groundAt(clientX, clientY);    // {x, y} земли в координатах конфига (обратный spreadX) или null над небом
scene.perch();                       // {x, y, px}: точка на ветке, CSS-пиксели от #app; px — CSS-пикселей в арт-пикселе
scene.owl({ms, hoot});               // сова говорит ms: клюв и крыло; hoot — драматичная реплика, сначала нахохлится
```

| `#app` | `--hit-{w,h,x,y}-{s,m,l,bonfire,circle}`, `--float-lift`, `--px` (style) | хит-зоны и подъём парящих в CSS-пикселях — публикует сцена |

Хуки feature-тестов (`tests/Feature/Controller/HomeControllerTest.php`): `data-element`, `data-type`, `data-stage`,

Шаблон рисует кнопку по `type`: `pumpkin` — тыква, остальные — кнопка элемента со своими `data-threshold` /
`data-stage-max` (у тыкв `data-threshold` нет: их порог — на `#app`). «Готово N из M» в HUD считает только тыквы.

### Правила рендеринга

- **Только из событий.** Свой клик клиент не рисует локально: эффект появляется, когда из канала приходит `click`,
  у кликнувшего так же, как у всех. Задержка круга браузер → сервер → браузер — часть демонстрации.
- Клик по тыкве → `centrifuge.rpc('click', {element})`. Служебные ссылки (тыква с «?» на `/how-it-works`) — обычные
  `<a>` без `data-element`.

### Пульт модератора

`<aside data-debug-panel hidden>` в правом верхнем углу; содержимое строит `debug.js`. **Только модератору**: панель
видна, когда RPC `me` вернул `moderator: true`; остальным её нет вовсе (их RPC пульта сервер всё равно отклонит
`forbidden`). Секрет: `?moderator=<секрет>` → `localStorage['hellowin.moderator']` (в `try/catch`; без хранилища —
до перезагрузки), параметр убирается из адреса (`history.replaceState`), секрет уходит в `data` подключения рядом с
`playerSecret`; `?moderator=` (пусто) забывает секрет.

- **Свернуть/развернуть**: заголовок «🦉 Пульт» (`data-console-toggle`, рядом — сводка `data-console-summary`: сцена или
  шаг финала, «готова», «пауза»), клавиша «`» (не в полях ввода), `?debug=1` / `?debug=0`. Состояние запоминается в
  `localStorage['hellowin:console']`; по умолчанию развёрнут на экране шире 600 px, на телефоне свёрнут.
- **Сюжет**: «Следующая сцена» (`data-action="scene-next"`, RPC `scene.next {scene}`; при `ready` подсвечена и
  срабатывает сразу, без `ready` — двойное нажатие «Не готово. Точно?» и `force: true`; в финальной сцене скрыта);
  «Шаг финала N» (`data-action="finale-step"`, RPC `finale.step {step: текущий + 1}`; только в финальной сцене, после
  шага 5 — «Финал пройден», выключена); «Заново» (`data-action="reset"`, двойное нажатие, RPC `reset {round}`).
- **Сова**: кнопка на каждую реплику каталога с `button` (`data-owl-line="<id>"`, RPC `owl.say {line}`); «Повторить…»
  (`data-owl-repeat`) — авто-реплики без подстановок; поле своего текста (`data-owl-form`, `data-owl-input`, до 200
  символов) → `owl.say {text}`. Реплики с `{player}` с пульта не говорятся — некого подставить.
- **Нечисть**: «Ведьма», «Бегун» (`data-action="witch|roadrunner"`, RPC `flyer.special {kind}`), «Зомби: вкл/выкл» и
  «Пауза: вкл/выкл» (`data-action="zombies|pause"`, `aria-pressed`, RPC `zombies` / `pause {on}`).
- **Отладка**: «Клик по всем» (`data-action="click-all"`, RPC `click` по каждой тыкве с разносом ~30 мс).
- Ответ сервера кнопка показывает надписью на несколько секунд (`data-note`): успех действий без состояния — «✓»,
  ошибка — «Нет прав» (`forbidden`), «Не готово», «Уже финал», «Не финал», «Пустой текст», «Занято», прочее — «Не вышло».
  Состояние (подписи, подсветка, `aria-pressed`) — только из модели клиента: результат любой кнопки приходит событием
  канала, как у всех.
- На телефоне пульт — колонка шириной экрана минус поля, тело прокручивается, поверх панели разоблачения.

### Модель клиента

Клиент держит `round` и применяет события канала:

| Событие | DOM | Сцена |
|---|---|---|
| `click` | `data-clicks`, `data-ready`; `threshold` события — порог тыкв (`#app`) или, у костра и круга, их собственный | `scene.click` |
| `pumpkin` | `data-stage`, `data-clicks = 0`, снять `data-ready`, `data-done` по `stageMax`; пересчёт всех элементов — последняя тыква открывает костёр и отправляет тыквы в прыжок (`--out`), `data-float` | `scene.pumpkin`; у круга — `scene.circle(stage / stageMax)` |
| `scene` | `<body data-scene>`, `data-final`, `#app[data-stage-max]`, пересчёт `data-done`; `bonfireStageMax` — в `data-stage-max` костра, `circleStageMax` (без поля — 0) — круга | `scene.setScene`; `item` события — в руку всем фигуркам (`scene.walker`) |
| `reset` | новый `round`, всё в 0 (сцена, стадии, клики; `stageMax` костра — сцены 0, круга — 0) без RPC; фигурки остаются | `scene.render`; `item`, если есть, — как у `scene` |
| `walker` | — (модель: добавить или заменить по `walker.id`) | `scene.walker` |
| `move` | — (модель: `walk` фигурки `player.id`; неизвестную — пропустить) | `scene.move` |
| `leave` | — (модель: убрать фигурку) | `scene.leave` |
| `flyer`, `shot` | — | `scene.flyer`, `scene.shot` |
| `ready` | модель: `ready = true`, если `scene` события — текущая; `<body data-ready>`, `data-hud-ready` | — |
| `finale` | модель: `finale = {step, reveal?}`; `<body data-finale-step>`, панель разоблачения; замок круга (кликабелен на шаге 0) | — |
| `owl` | — | пузырь (`owl.say`) и `scene.owl`; в снимок не входит, пересинхронизация реплику не повторяет |
| `pause`, `zombies` | модель: `paused` / `zombies = on`; `<body data-paused|data-zombies>` | — |

`scene` снимает `ready`, вне финальной сцены — и `finale` (в финальную `finale {step: 0}` приходит следом). `reset`
снимает `ready`, `finale` и `zombies`, `paused` оставляет (пауза про зал, а не про сюжет). Пульт перерисовывается
после каждого применённого события и снимка (`onChange` клиента).

Кто «я»: `player.id` из ответа RPC `me` (после каждого подключения) или `register` → `client.setMe(id)`. Ходить
(`client.canWalk()`) может браузер, чья фигурка (`walkers[].id == me`) есть на поле.

- **Пересинхронизация.** После переподключения (кроме первого) и при любом событии, кроме `reset`, с `round`,
  отличным от текущего, — RPC `state` и `scene.render` из снимка. События, пришедшие до ответа, отбрасываются.
- Ошибки RPC (`busy`, `unknown element`, сеть) — в `console.warn`, на экране не показываются.

### Сцена 0 «День: подготовка»

- **Фон.** Камера низко, взгляд вдоль земли: горизонт на 37% высоты, над ним небо с солнцем и облаками, у горизонта
  дальние холмы и кромка леса (дымка — дизеринг с цветом неба). Грядка — сильно сплющенный эллипс (полуоси ~47% ширины
  и до 25% высоты), борозды сходятся к горизонту, вдали всё мельче и реже. В центре
  корень, от него к хвостику каждой тыквы идёт изогнутый побег с густой листвой (лопастные тыквенные листья
  2–3 размеров, усы). Вокруг грядки — сорняки и высокая трава, гуще к краям экрана.
- **Плотная грядка.** Грядка небольшая (полуось ~33% ширины), тыквы крупные (l 44×38, m 34×30, s 26×23 арт-px) и стоят
  тесно: спрайты ближних перекрывают дальние. Хит-зона кнопки — ядро тела (~72% спрайта, без хвостика), ядра не
  перекрываются, `z-index` кнопки растёт с `y`. Кнопки позиционирует CSS через `--x`/`--y` и `--spread`
  (`spreadX(width)` из `public/js/layout.js`, общий для DOM и сцены вместе с центром корня): на узких экранах раскладка
  растягивается по x от центра. Побеги извилистые, с боковыми отростками; толщина 4 → 2 арт-px.
- **Раскладка тыкв** — `elements` в `app/config/hellowin.php` (правит фронтенд): ~18 тыкв неровным кольцом-эллипсом
  вокруг корня (50%/63%, `ROOT` в `scene.js`), ближе-дальше от центра вразнобой; дальние (выше на экране) чаще мельче.
- **Дерево** — слева, дальше грядки (за ней по глубине), ветка тянется к середине экрана. На ветке есть точка
  `perch` (спрайт `DECOR.tree`) — туда в будущей сцене прилетит сова; сцена держит её экранные координаты.
- **Тыквы** трёх размеров (`s`/`m`/`l` — разная пиксельная сетка, не растяжение), с хвостиком; ограниченная палитра
  с hue-shift (тени к красно-коричневому, блики к жёлтому), выборочный контур, без сглаживания. Стадии — по таблице
  в `scenario.md`: 0 целая → 1 глаз → 2 два глаза → 3 рот, верхушка срезана, видна мякоть → 4 пустая (тёмное нутро).
- **Вариативность.** Вид тыквы детерминирован от `seedOf(id)` (CRC32 id): какой глаз вырезается первым, форма глаз
  (треугольник, круг, полумесяц, косые), форма рта (зигзаг, улыбка, «О», один зуб…), число долек, оттенок, хвостик.
  Одна и та же тыква выглядит одинаково у всех и после перезагрузки.
- **Слои.** Тыква — стопка слоёв, а не один спрайт: `back` (задняя стенка и нутро, видно сквозь вырезы), `body`
  (кожура с вырезанными отверстиями), `rim` (кромка мякоти по краям вырезов), `stem` (хвостик), `glow` (маска
  отверстий и среза — в ночной сцене туда кладётся свечение изнутри). Днём `glow` скрыт.
- **Клик** (событие `click`): короткая тряска/сплющивание тыквы (2–3 кадра) и частицы по стадии:
  стадии 0–2 — оранжевые куски `chunk` разлетаются от места выреза, падают с гравитацией и исчезают;
  стадия 3 — семечки `seed` и волокна мякоти `pulp` фонтаном из верхушки; стадия 4 (`data-done`) — сгоревший клик:
  пара серых искр, без частиц тыквы.
- **Переход** (событие `pumpkin`): белая вспышка-силуэт на 1 кадр, смена спрайта, «отскок».
- Готовность: тыква с `data-ready` мерцает контуром; с `data-done` — лёгкое покачивание.
- HUD: статус соединения, раунд, сцена, «готово N из M» (`data-done`). Пиксельный шрифт — системный моно
  или bitmap через `BitmapText`.
- `prefers-reduced-motion`: без тряски и частиц, переходы — мгновенная смена спрайта.
- От 390 px по ширине: позиции в процентах, масштаб арт-пикселя меньше, HUD в две строки.

### Летуны

Механика — [`scenario.md`](scenario.md), события `flyer` / `shot` и RPC `shoot` — [`protocol.md`](protocol.md).

- Полёт клиент считает сам по серверному времени: прогресс `(Date.now() + offset − launchedAt) / duration`, где
  `offset = now − Date.now()` из снимка страницы или RPC `state` (после возврата во вкладку — свежий `state`);
  летун при `Date.now() + offset >= expiresAt` не рисуется и убирается. Путь — прямая `from → to` или квадратичная
  кривая через `via`. Глубина `depth` задаёт масштаб (дальние мельче), слой (дальние позади дерева, ближние перед
  грядкой) и скорость взмахов. Утка из куста: куст шуршит, утка взлетает из его точки.
- Летуны движутся каждый кадр, поэтому попадание проверяет **canvas** (PixiJS hit-test по спрайту с запасом), а не DOM:
  клик по утке → `centrifuge.rpc(shoot, {flyer})`. Клик мимо — без RPC. Как и с тыквами, по своему выстрелу
  ничего не рисуется: падение — только по событию `shot` (перья, утка кувыркается вниз, всплывают очки).
- Кусты (`#app[data-bushes]`, JSON) и траектории летунов — в процентах экрана **без** `spreadX`, как на сервере.
- Перехват: `bindShooting` (`public/js/client.js`) слушает `pointerdown` на `#app` в фазе захвата, `scene.flyerAt(x, y)`
  проверяет летунов от ближних к дальним по хит-боксу тела (~60% спрайта, без крыльев и хвоста — сбить должно быть
  непросто); при попадании клик гасится и до кнопки тыквы не доходит.
- Слои: летун никогда не позади дальнего плана (холмы — за километры). `depth` 0 — перед холмами, за деревом, плетнём
  и наземными объектами, с лёгкой дымкой к цвету неба; `depth` 1 и 2 — над наземными объектами. Полный рендер (resync, `reset`) убирает летунов.
- Спрайты — `public/js/pixel/flyers.js`, живой пример — `public/dev/flyers.html`.

### Экран входа и персонажи

**Фронтенд — реализовано** (проверено в лаборатории), **в работе** — ждёт backend. Правила — [`players.md`](players.md)
(«Персонаж», «На поле»), протокол — `register {name, look}`, `move`, события `walker` / `move` / `leave`, `walkers` в
снимке.

- **Секрет игрока** — `localStorage['hellowin.secret']` (UUID, при первом визите), уходит только в `data` подключения
  (`{playerSecret}`). Без `localStorage` секрет живёт до перезагрузки страницы.
- **Экран входа** — `<dialog data-join>` поверх главной (`public/js/join.js`, разметка в `home.dark.php`): при первом
  визите (в `localStorage` нет `hellowin.look`) и по кнопке «Персонаж» в HUD. Поле имени `data-join-name`; по каждой
  части `look` — строка «‹ название ›» (`data-part="body|cloak|face|eyes|hat"`, у глаз — квадратик цвета); «Случайно»;
  превью — персонаж крупно, поворачивается спереди → сбоку → сзади → другим боком и шагает на месте (при
  `prefers-reduced-motion` — стоит лицом); «На поле» → `register {name, look}`, при успехе `hellowin.name`/`hellowin.look`
  запоминаются в `localStorage` для следующего входа; ошибку показывает под полем (`invalid name` — правило имени,
  `invalid look`, `anonymous`, прочее — «Не вышло»). «Просто смотреть» и Esc закрывают экран без регистрации —
  зритель не ходит, а при следующем визите экран покажется снова. Превью рисуется обычным 2D-canvas
  (`image-rendering: pixelated`), без PixiJS. Доступ к `localStorage` — в `try/catch`.
- **Персонажи — сборные спрайты** (`pixel/characters.js`). Каталог частей с подписями (`CATALOG`), части по
  умолчанию, `randomLook()`, сборка кадра из слоёв: накидка сзади → тело → лицо (цвет глаз — замена пикселей
  палитры) → шапка → накидка спереди → рука с предметом. Тело задаёт по кадру смещение головы и точку кисти;
  шапки, лица и предметы рисуются один раз на направление и ставятся по этим точкам — так частей много, а кадров мало.
  Неизвестный id части — часть по умолчанию.
- **Направления** — спереди, сзади, сбоку (влево — зеркало). **Позы**: стойка (дыхание), переминание, ходьба
  (4 кадра), стойка с согнутой в локте рукой, держащей предмет (`item`: пиво, метла, пистоль…), выстрел (отдача).
- **Ходьба.** Фигурки — в `groundLayer`, сортируются по y ступней вместе с тыквами и реквизитом. Позиция — по `walk` и
  серверным часам (то же смещение, что у летунов): постоянная скорость вдоль ломаной, длина — в единицах конфига, как
  `HELLOWIN_WALK_SPEED` на сервере; направление — по экранному наклону текущего отрезка (сбоку, если |dx| ≥ 0,8·|dy|,
  влево — зеркало). Координаты `walk` → экран тем же преобразованием, что тыквы (`spreadX`); на узком экране
  лужайка шире экрана, и фигурка за его краем рисуется прижатой к краю (10 арт-px), а не пропадает. Клик по земле (не
  по тыкве, не по летуну, не по HUD и панелям) у игрока с фигуркой на поле → `move {x, y}` в координатах конфига
  (`scene.groundAt`: обратный `spreadX`, 0,1 %; над горизонтом — `null`, без RPC). Свою фигурку клиент локально не
  двигает: она пойдёт, когда придёт `move`, — как и всё остальное, только из событий.
- **Имя** — PixiJS `Text` отдельным слоем поверх увеличенной арт-текстуры, в экранном разрешении (моно-шрифт HUD,
  12 px, кремовый с тёмной обводкой; своё имя — золотое), над верхним непрозрачным рядом кадра. Текст внутри
  арт-текстуры размылся бы при целочисленном увеличении, а свой пиксельный шрифт не покрыл бы кириллицу; DOM-подписи
  пришлось бы двигать каждый кадр. У края экрана подпись не обрезается.
- **Живость** — детерминированно, одинаково у всех: время делится на слоты `3500 + crc32(id) % 2000` мс со сдвигом
  `crc32(id)`; хеш `(crc32(id), номер слота)` даёт сторону (чаще лицом) и в трети слотов — переминание в начале слота.
  До первого слота после прибытия фигурка смотрит туда, куда шла. На `shot` с `player` стоящей фигурки (идущая не
  останавливается) — поворот к летуну (сбоку, если он заметно левее/правее, иначе спиной — птицы над дальним
  планом), поза `shoot` с пистолем на 2 цикла кадров (не меньше 600 мс), затем возврат к своему предмету.

API сцены для фигурок: `scene.walker(w)` (появилась или сменила вид), `scene.move(id, walk)`, `scene.leave(id)`,
`scene.setMe(id)`, `scene.groundAt(clientX, clientY)` → `{x, y}` в координатах конфига или `null`;
`scene.render(snapshot)` заменяет фигурки списком `walkers` из снимка (без поля — оставляет свои). Перехват кликов по
земле — `bindWalking(root, scene, canWalk, move)` в `client.js`.

### Сюжет: сова, сцены, финал

Пульт, сова, модель сюжета, новые летуны и временное разоблачение — **реализовано**; вид сцен и финала —
**запланировано**. Правила — [`scenario.md`](scenario.md) («Модератор и сова», «Сцены 1–3», «Финал», «Проклятый мир»),
протокол — [`protocol.md`](protocol.md) («Модератор», события `owl`, `ready`, `finale`, `pause`, `zombies`).

- **Пульт модератора** — см. «Пульт модератора» выше.
- **Сова** — спрайт `OWL` в `groundLayer` сразу перед деревом (zIndex дерева + 1), якорь (когти) — на `perch`. Покой
  — по серверным часам, одинаково у всех: слоты по 5 с, хеш `(константа, номер слота)` даёт момент моргания и в 4 из 9
  слотов поворот головы (в одну сторону; изредка — затылком к зрителю), между ними — дыхание `idle`. Пока показан
  пузырь — `talk` (клюв через 160 мс, иногда крыло); драматичная реплика (`hoot` в каталоге: начало, сцены, финал,
  зомби, костёр) — сначала 0,9 с `hoot`. С ночи (сцена ≥ 2) — `glowing()`. `prefers-reduced-motion`: стоит и
  говорит одним кадром.
- **Пузырь** — DOM `[data-owl-bubble]` над canvas (чёткая кириллица): вверх-вправо от совы по `scene.perch()`, хвост
  ступеньками к голове; если над совой не хватает неба — под ней, хвостом вверх; прижат к краям экрана, ширина до
  320 px; без canvas — сверху по центру. Время показа — `2000 + 70 мс × символ`, от 3,5 до 12 с. Новая реплика
  сменяет текущую, когда та провисела 2,5 с; до этого ждёт в одном слоте (последняя побеждает) — так пара
  `last-pumpkin` → `scene-ready` читается целиком, а пачка реплик не копится. Свободный текст — `textContent`, не HTML.
- **Каталог** (`public/js/owl.js`, `LINES`): id → `{text, scenes?, hoot?, button?, auto?}`; `scenes` — текст в
  конкретной сцене (`scene-ready` в сцене 2); `{player}` — `params.player.name`, без имени — «кто-то»; неизвестный id
  пропускается. Кроме id из [`scenario.md`](scenario.md) у пульта свои кнопочные реплики: `rules`, `hurry`,
  `flyers`, `outro` (сервер проверяет только формат id).
- **Разоблачение** (временно, до вида финала): при `finale.step >= 4` и `reveal` — пиксельная панель по центру
  (`reveal.js`) с числами (с согласованием «клик/клика/кликов»), кто добил последнюю тыкву, ссылка на «Как это
  работает»; «×» прячет её до следующего шага.
- **Сцены** — см. «Сцены 1–3» ниже. Предмет в руке фигурок приходит с сервера (`walker.item`, `item` в `scene` /
  `reset`) и рисуется по `ITEM_DEFS` (`characters.js`); id без рисунка — пустая рука.
- **Летуны** (**реализовано**): `crow`, `bat`, `ghost`, `witch` — наборы `FLYERS` как у уток (перья — свои, у
  дальних — одноцветные пиксели своего цвета); `wobble` (мыши) — смещение поперёк базового пути
  `amp · sin(2π · waves · t)` в процентах экрана. `roadrunner` бежит по горизонту на глубине 0 (якорь — ступни, шаг
  70 мс), за деревом и плетнём: `x` — с сервера, `y` сервера (`horizon` конфига, 38 %) сцена не берёт — ступни на
  своей линии горизонта (37 % высоты арта) минус 1 арт-px, у подножия холмов; дальний спрайт — 7×4 с дымкой; сбить нельзя (сервер всегда отвечает промахом), но клик по нему уходит в `shoot` как
  обычно. `zombie` — наземная цель в `groundLayer`: путь — в координатах конфига, как у фигурок (`spreadX`, прижат к
  краю экрана), сортировка по ступням вместе с фигурками и тыквами, шаг 150 мс; хит-бокс — тело над ступнями (50 %
  ширины, 85 % высоты); сбитый — `hit`, затем кадры `fall` (на колени, навзничь) на месте, мигает и исчезает к 2 с.
  `worm` (сцена 3) — тоже наземная цель в `groundLayer` на координатах фигурок, сортировка по точке на земле. Спрайт
  16×9 на всех глубинах, якорь — на земле под серединой, голова вправо (влево — зеркало по `to.x < from.x`); спина,
  седло и глаз светятся фиолетовым (`EMISSIVE`: под кровавой луной обычный цвет тонет в бордовом газоне), брюшко — в
  свете сцены. Кадры: `emerge` ×3 по 130 мс — выползает из холмика в точке `from`, ползёт (`fly`, 4 кадра гусеницы по
  150 мс) весь путь за оставшееся время, `burrow` ×2 по 150 мс — ныряет в землю в точке `to`. Путь — прямая с `wobble`
  поперёк в процентах конфига (поэтому петляет). Хит-бокс — непрозрачные границы кадра (`box`) плюс 2 арт-px; сбитый
  на месте корчится — `hit`, мечется из стороны в сторону каждые 90 мс до 450 мс, затем `fall` (петля над холмиком,
  холмик с искрой) и мигает до 1,7 с; перья — комья земли и фиолетовая искра.
### Сцены 1–3

**Реализовано** (лаборатория и живой стек). Сюжет — [`scenario.md`](scenario.md) («Сцены 1–3», «Костёр»), арт —
`night.js`, `bonfire.js`, стадии 5–11 в `sprites.js`, целевой вид — макеты `public/dev/night.html`.

- **Свет по сцене**: 0 — день, 1 — закат, 2 — ночь, финальная — кровавая луна (`lightingOf` в `scene.js`). Смена
  освещения — полная пересборка сцены (`rebuild`) в новом свете: небо `paintSky` (закатное солнце наполовину за холмами,
  луна с ореолом, мерцающие звёзды-кресты ночью, облака перекрашены), фон и побеги — `relightCanvas` запечённых
  дневных canvas, всё стоящее на земле (трава, реквизит, дерево, кусты, сова, фигурки, зомби, червяки и их комья) — `bakeLit` /
  `relightCanvas` с кэшем по (спрайт, свет). Светящееся не перекрашивается: `glow`/`fire`/`aura` тыкв, огонь костра,
  взрыв, угли, круг, ореолы. Летуны в небе — как нарисованы. Бабочки — только днём.
- **Два источника ночью**: в сцене 2, пока костёр горит (стадия со светом, `BONFIRE.light`), вокруг центра — эллипс
  тёплого `firelight` (полуоси 1,45 × 1,65 грядки, центр чуть ближе к зрителю), снаружи — холодная луна. Фон —
  с дизерингом края (`nearLight`), спрайт — целиком по своей опорной точке (резкий порог на середине края).
- **Переход**: кадр старого света замораживается в текстуру и гаснет поверх нового за 4 с (день → закат; ступенчатая
  прозрачность, 10 шагов), за то же время садится солнце; остальные смены — 3 с. Перезагрузка, ресинк и сброс
  показывают сцену сразу, без перехода. Пересборка — ~80 мс на 1600×900 (canvas фона и неба — CPU,
  `willReadFrequently`, иначе `getImageData` ждёт GPU); покадровой цены у света нет.
- **Тыквы, стадии 5–11**: слои `aura` → `back` → `glow` → `body` → `rim` → `stem` (колпак со стадии 8) → `fire`;
  `glow`/`fire`/`aura` — без перекраски, кадры по 120/110/160 мс со сдвигом фазы на тыкву; `glow` виден со стадии 5
  и не днём. Со стадии 7 спрайт шире и выше (поля под огонь), якорь и хит-зона — по телу, как у стадии 0. Со стадии 6
  после заката — ореол на земле (`halo`: закат — тёплый, ночь — зелёный, кровавая луна — фиолетовый). Под кровавой
  луной магия стадий 9+ — фиолетовая (`tone: 'violet'`).
- **Частицы клика — по сцене**: 0 — куски / семечки и мякоть по стадии, 1 — `ember` и `cinder`, 2 — `magic`,
  финальная — `hex`; сгоревший клик (тыква готова) — серые искры.
- **Прыжок**: когда в сцене 1 все тыквы на `stageMax` (и в любой сцене после) — `jumpedOut` в `layout.js`, по
  состоянию, перезагрузка показывает то же, — раскладка тыкв растягивается от корня в `jumpOut(width)` раз (1,18 на
  широком экране, на телефоне, где раскладку уже растянул `spreadX`, — ~1,04). Тыквы прыгают туда дугой (0,6 с,
  вразнобой до 250 мс), кнопки едут CSS-переходом `left`/`top` по `--out`. Дальше в сценах 1–2 тыквы пружинят
  (прыжок 3 арт-px раз в 1,1 с, растяжение в воздухе, сплющивание при приземлении). Парящие (стадия 11+, вся финальная
  сцена) висят на 5 арт-px и покачиваются ±2, в финальной — медленнее и с наклоном, как поплавки; на земле — тень
  `PUMPKIN_SHADOW` по высоте. Побеги остаются на месте — тыквы от них отпрыгнули.
- **Костёр** (`<button class="bonfire">`): в сцене 0 его нет (корень и ворох листьев), со сцены 1 он вместо корня и
  вороха: стадия 0 — сухая куча, 1–7 — анимация `BONFIRE.stages` (4 кадра по 110 мс), основание — в свете сцены,
  огонь — без перекраски, свет на земле `BONFIRE.light` (аддитивно, дыхание 0,55/0,48, вспышка на новой стадии).
  Клик — тряска и искры, переход — вспышка света и сноп искр. Хит-зона — `BONFIRE.hit`. Замок — `data-locked`
  (клиент считает сам: `bonfireOpen`).
- **Взрыв 2 → 3**: на событие `scene` в финальную сцену при горящем костре — вспышка бело-зелёным, тряска экрана
  0,7 с (целые арт-пиксели), 8 кадров `EXPLOSION` над уже готовым пепелищем; угли пепелища (`ASH.embers`) мерцают
  и гаснут за 9 с. Загрузка сразу в финальную сцену — холодное пепелище без углей.
- **Магический круг** (`<button class="circle">`, **реализовано**): красный круг `magicCircle` на
  пепелище рисуется до `stage / stageMax` круга (`scene.circle`), до финальной сцены его нет; клик — тряска
  пепелища и искры `hex`. Элемент есть в снимке всегда, в точке костра; последнюю стадию новой сцены приносит
  `scene.circleStageMax`. Из пары костёр/круг рисуется и кликается только элемент своей сцены (см. DOM-хуки).
- **Фигурки**: в закат и ночь у фигурки со свечой — тёплый круг `NIGHT.candleLight` у ног, с книгой после заката —
  слабый зелёный; кадры перекрашены по свету точки, где стоят.

- **Финал** (**запланировано**; шаги — **на пересмотре** в [`scenario.md`](scenario.md)) — вид шагов по `finale.step`:
  FrankenPHP поднимается из земли (узнаваемо по логотипу FrankenPHP, в нашем пиксель-арте); выбегает RoadRunner (по
  логотипу RoadRunner); экран разоблачения с числами `reveal` и ссылкой на «Как это работает» вместо временной панели;
  финальная фраза. Снимок восстанавливает шаг без анимации перехода. Кнопка пульта пока общая — «Шаг финала N».
- **Проклятый мир** — вечная ночь, FrankenPHP в центре, зомби-«воркеры» бредут с грядки, сбиваются как летуны.

## Страница «Как это работает» (`GET /how-it-works`)

- Вводный блок + вкладки (WAI-ARIA Tabs, `public/js/how-it-works.js`, вкладка в `location.hash`, без JS — все
  разделы подряд). Новая вкладка = ссылка `role="tab"` в `tabs__list` + `<section role="tabpanel">`; JS и тест не
  трогать.
- Схемы — inline SVG; цвета через CSS-переменные, подписи без обводки, ширина до 1360px. Схемы показывают реальный
  механизм: имена классов, каналов, ключей и портов берутся из кода, не из памяти.
- Вкладка «Идемпотентный переход» (`#idempotency`): клик → очередь `transitions` с дублями → `#[Idempotent]` с ключом
  `{round}:{pumpkinId}:{toStage}` → одна публикация `pumpkin`. Тесты страницы — `HowItWorksPageTest`.

## Проверка

- Песочница без backend: `public/dev/lab.html` поднимает сцену на фиктивном снимке и генерирует события `click` /
  `pumpkin` локально (кнопки «клик», «авто»). Только для разработки, ссылок на неё со страниц нет. Фиктивный движок
  играет и сторону сервера для фигурок: `register` с проверкой имени → `walker`, `move` → путь, приведённый в зону
  `walk` (копия из `app/config/hellowin.php`) и огибающий грядку по краю с короткой стороны, 12 %/с; боты бродят;
  кнопка «выстрел» — птица, которую сбивает фигурка. Сюжет — тоже: `?mod=1` — лаборатория играет модератора (пульт
  виден; без него RPC пульта отвечают `forbidden`), сцена готова, когда все тыквы готовы (`ready`, реплики
  `last-pumpkin` и `scene-ready`), дальше — только `scene.next`; шаги финала с фиктивным `reveal` (счётчики
  лаборатории); реплики совы (авто и с пульта); особые летуны; зомби бредут только на шаге 5 при включённых зомби и без
  паузы; пауза останавливает запуски; летуны и предметы — по сценам. Параметры старта: `?scene=N`, `?ready=1`,
  `?finale=N`, `?paused=1`, `?zombies=1`, `?owl=<id>`, `?say=<текст>`, `?specials=1` (ведьма, бегун и зомби
  сразу; `?zshot=ms` сбивает зомби). Костёр — как на сервере: заперт, пока тыквы сцены не готовы (клик по нему тогда не
  уходит), свой порог `?bclicks=N` (20) и стадии `0,4,7` по сценам, реплики `last-pumpkin` → `bonfire-open`, затем
  `ready` → `bonfire-done` → `scene-ready`; `?bonfire=N` — стартовая стадия костра. Магический круг — кликабелен в
  финальной сцене на шаге 0, порог `?cclicks=N` (10), 4 стадии, замкнут → `ready`, `circle-done`, `scene-ready`;
  `?circle=N` — стартовая стадия, `?nocircle=1` — без круга. Летуны финальной сцены — червяки (путь по лужайке
  12–25 %, вне грядки, `wobble` 0,8–2 × 3–6); `?worms=1` — три червяка сразу в любой сцене (`?wshot=ms` сбивает первого). `?next=ms` с `?freeze` жмёт
  «Следующая сцена» (`force`) в этот момент: с `?scene=0` — закат, с `?scene=2` — взрыв. `?stage=N` — до 11.
  `?scene=N` ставит тыквы и костёр на последние стадии сцены перед ней, `?ready=1` — на стадии своей сцены.
  Инструменты лаборатории (утка, клик, авто, выстрел, стадия) — отдельной панелью
