# Фронтенд

Статус: пиксельная сцена на PixiJS, главная на снимке и сцена 0 «День: подготовка» — **реализовано** (идёт доводка
вида); «Как это работает» с вкладкой «Идемпотентный переход» — **реализовано** (страницу ведёт backend); курошлёпка — **реализовано**; экран входа, персонажи и прогулка по полю — **реализовано** на фронтенде и
проверено в лаборатории, **в работе** — ждёт backend (`look` в `register`, `move`, `walker`/`move`/`leave`,
`walkers` в снимке); игроки на странице (лидеры, своя статистика) и сцены после 0 — **запланировано**.

## Зона и ограничения

- Файлы фронтенда: `app/views/**` (Stempler), `public/css/**`, `public/js/**`, `public/` (картинки, шрифты).
- Без сборщиков и npm-зависимостей в рантайме: обычные CSS и нативные ES-модули (`<script type="module">`). Внешние
  библиотеки — только с CDN с точной версией: `centrifuge@5.7.4` (UMD, глобальный `Centrifuge`),
  `pixi.js@8.22.0` (`dist/pixi.min.mjs`).
- Протокол и данные — [`protocol.md`](protocol.md); правила игры — [`scenario.md`](scenario.md). Если фронтенду нужно
  новое поле или событие — сначала правка `protocol.md`, затем backend.
- Скиллы: `pixijs` (роутер по `pixijs-*`), `pixel-art`, `pixel-art-sprites` — подключены в `skills.json`.

## Главная страница (`GET /`, шаблон `home`)

Переменные шаблона — поля снимка состояния из `protocol.md` (`round`, `scene`, `sceneStages`, `stageMax`,
`threshold`, `elements` со `size`/`stage`/`clicks`) и `centrifugoUrl`. Layout — `app/views/layout/base.dark.php`:
стеки `styles` и `scripts`, атрибуты состояния на `<body>`.

### Отрисовка: гибрид canvas + DOM

- **PixiJS рисует**, на весь экран, `<canvas>` под разметкой: небо, грядка, корень в центре, побеги к тыквам,
  тыквы, частицы. Пиксельный режим: `antialias: false`, текстуры `scaleMode: 'nearest'`, `roundPixels: true`,
  масштаб «арт-пикселя» — целое число экранных пикселей, подбирается от размера окна.
- **DOM держит состояние и ввод.** Тыквы — прозрачные `<button>` поверх своего спрайта: клик, фокус с клавиатуры,
  скринридер, хуки тестов. Canvas состояние не хранит — читает атрибуты DOM и слушает их изменения через API сцены.
- Спрайты — код: матрицы индексов палитры в JS, запекаются в текстуры при старте. Картинок-файлов нет.
- **Глубина — алгоритм художника.** Плоское (небо, дальний план, почва, газон) запекается в фон; всё, что стоит на земле
  (трава и сорняки, кусты, реквизит, плетень, дерево, тыквы, корень), — один контейнер, отсортированный по y опорной
  точки (низ спрайта): дальнее рисуется раньше, ближнее перекрывает его. Летуны в воздухе — вне этой сортировки.
- Без WebGL/WebGPU (или если PixiJS не загрузился) страница остаётся рабочей: кнопки видны с emoji-запасным видом.

`scene.js` и `join.js` (оба тянут `characters.js`) `app.js` грузит динамически: если они не загрузились, тыквы
и счёт работают на emoji-кнопках.

API сцены — единственная связь `app.js` с canvas:

```js
const scene = await createScene(rootEl, snapshot); // null, если рендер недоступен
scene.render(snapshot);              // полный перерендер (state, reset)
scene.click(id, {stage, clicks, threshold}); // эффект клика: тряска + частицы по стадии
scene.pumpkin(id, stage);            // переход стадии: вспышка, смена спрайта
scene.setScene(n, stageMax);         // смена сцены
scene.setServerClock(fn);            // источник серверного времени (Date.now() + offset) для летунов и фигурок
scene.flyer(event); scene.shot(event); // летуны: запуск, падение (+ выстрел фигурки игрока из event.player)
scene.flyerAt(clientX, clientY);     // id летуна под указателем или null
scene.walker(w);                     // фигурка появилась или сменила вид/имя (Walker)
scene.move(id, walk);                // фигурка пошла (Walk)
scene.leave(id);                     // фигурка ушла
scene.setMe(id);                     // своя фигурка: имя другим цветом
scene.groundAt(clientX, clientY);    // {x, y} земли в координатах конфига (обратный spreadX) или null над небом
scene.perch();                       // {x, y} точки на ветке дерева, CSS-пиксели от #app
```

### Правила рендеринга

- **Только из событий.** Свой клик клиент не рисует локально: эффект появляется, когда из канала приходит `click`,
  у кликнувшего так же, как у всех. Задержка круга браузер → сервер → браузер — часть демонстрации.
- Клик по тыкве → `centrifuge.rpc('click', {element})`. Служебные ссылки (тыква с «?» на `/how-it-works`) — обычные
  `<a>` без `data-element`.

### Дебаг-панель

`<aside data-debug-panel hidden>` в правом верхнем углу; показывается при `?debug=1` (запоминается в `localStorage`,
`?debug=0` выключает) и клавишей «`». Кнопки: «Заново» (`data-action="reset"`, двойное подтверждение, RPC `reset {round}`; отказ сервера — надпись на кнопке на несколько секунд: «Сброс выключен» при
`reset disabled`, иначе «Не вышло»)
и «Клик по всем» (`data-action="click-all"`, RPC `click` по каждой тыкве с разносом ~30 мс). Эффекты обеих — только
по событиям канала.

### Модель клиента

Клиент держит `round` и применяет события канала:

| Событие | DOM | Сцена |
|---|---|---|
| `click` | `data-clicks`, `data-ready` | `scene.click` |
| `pumpkin` | `data-stage`, `data-clicks = 0`, снять `data-ready`, `data-done` по `stageMax` | `scene.pumpkin` |
| `scene` | `<body data-scene>`, `data-final`, `#app[data-stage-max]`, пересчёт `data-done` | `scene.setScene`; `item` события — в руку всем фигуркам (`scene.walker`) |
| `reset` | новый `round`, всё в 0 (сцена, стадии, клики) без RPC; фигурки остаются | `scene.render`; `item`, если есть, — как у `scene` |
| `walker` | — (модель: добавить или заменить по `walker.id`) | `scene.walker` |
| `move` | — (модель: `walk` фигурки `player.id`; неизвестную — пропустить) | `scene.move` |
| `leave` | — (модель: убрать фигурку) | `scene.leave` |
| `flyer`, `shot` | — | `scene.flyer`, `scene.shot` |

Кто «я»: `player.id` из ответа RPC `me` (после каждого подключения) или `register` → `client.setMe(id)`. Ходить
(`client.canWalk()`) может браузер, чья фигурка (`walkers[].id == me`) есть на поле.

- **Пересинхронизация.** После переподключения (кроме первого) и при любом событии, кроме `reset`, с `round`,
  отличным от текущего, — RPC `state` и `scene.render` из снимка. События, пришедшие до ответа, отбрасываются.
- Ошибки RPC (`busy`, `unknown element`, сеть) — в `console.warn`, на экране не показываются.

### Сцена 0 «День: подготовка»

- **Фон.** Камера низко, взгляд вдоль земли: горизонт на 37% высоты, над ним небо с солнцем и облаками, у горизонта
  дальние холмы и кромка леса (дымка — дизеринг с цветом неба). Грядка — сильно сплющенный эллипс (полуоси ~47% ширины
  и до 25% высоты), борозды сходятся к горизонту, вдали всё мельче и реже. В центре
  корень, от него к хвостику каждой тыквы идёт изогнутый побег с густой листвой (лопастные тыквенные листья
  2–3 размеров, усы). Вокруг грядки — сорняки и высокая трава, гуще к краям экрана.
- **Плотная грядка.** Грядка небольшая (полуось ~33% ширины), тыквы крупные (l 44×38, m 34×30, s 26×23 арт-px) и стоят
  тесно: спрайты ближних перекрывают дальние. Хит-зона кнопки — ядро тела (~72% спрайта, без хвостика), ядра не
  перекрываются, `z-index` кнопки растёт с `y`. Кнопки позиционирует CSS через `--x`/`--y` и `--spread`
  (`spreadX(width)` из `public/js/layout.js`, общий для DOM и сцены вместе с центром корня): на узких экранах раскладка
  растягивается по x от центра. Побеги извилистые, с боковыми отростками; толщина 4 → 2 арт-px.
- **Раскладка тыкв** — `elements` в `app/config/hellowin.php` (правит фронтенд): ~18 тыкв неровным кольцом-эллипсом
  вокруг корня (50%/63%, `ROOT` в `scene.js`), ближе-дальше от центра вразнобой; дальние (выше на экране) чаще мельче.
- **Дерево** — слева, дальше грядки (за ней по глубине), ветка тянется к середине экрана. На ветке есть точка
  `perch` (спрайт `DECOR.tree`) — туда в будущей сцене прилетит сова; сцена держит её экранные координаты.
- **Тыквы** трёх размеров (`s`/`m`/`l` — разная пиксельная сетка, не растяжение), с хвостиком; ограниченная палитра
  с hue-shift (тени к красно-коричневому, блики к жёлтому), выборочный контур, без сглаживания. Стадии — по таблице
  в `scenario.md`: 0 целая → 1 глаз → 2 два глаза → 3 рот, верхушка срезана, видна мякоть → 4 пустая (тёмное нутро).
- **Вариативность.** Вид тыквы детерминирован от `seedOf(id)` (CRC32 id): какой глаз вырезается первым, форма глаз
  (треугольник, круг, полумесяц, косые), форма рта (зигзаг, улыбка, «О», один зуб…), число долек, оттенок, хвостик.
  Одна и та же тыква выглядит одинаково у всех и после перезагрузки.
- **Слои.** Тыква — стопка слоёв, а не один спрайт: `back` (задняя стенка и нутро, видно сквозь вырезы), `body`
  (кожура с вырезанными отверстиями), `rim` (кромка мякоти по краям вырезов), `stem` (хвостик), `glow` (маска
  отверстий и среза — в ночной сцене туда кладётся свечение изнутри). Днём `glow` скрыт.
- **Клик** (событие `click`): короткая тряска/сплющивание тыквы (2–3 кадра) и частицы по стадии:
  стадии 0–2 — оранжевые куски `chunk` разлетаются от места выреза, падают с гравитацией и исчезают;
  стадия 3 — семечки `seed` и волокна мякоти `pulp` фонтаном из верхушки; стадия 4 (`data-done`) — сгоревший клик:
  пара серых искр, без частиц тыквы.
- **Переход** (событие `pumpkin`): белая вспышка-силуэт на 1 кадр, смена спрайта, «отскок».
- Готовность: тыква с `data-ready` мерцает контуром; с `data-done` — лёгкое покачивание.
- HUD: статус соединения, раунд, сцена, «готово N из M» (`data-done`). Пиксельный шрифт — системный моно
  или bitmap через `BitmapText`.
- `prefers-reduced-motion`: без тряски и частиц, переходы — мгновенная смена спрайта.
- От 390 px по ширине: позиции в процентах, масштаб арт-пикселя меньше, HUD в две строки.

### Летуны

Механика — [`scenario.md`](scenario.md), события `flyer` / `shot` и RPC `shoot` — [`protocol.md`](protocol.md).

- Полёт клиент считает сам по серверному времени: прогресс `(Date.now() + offset − launchedAt) / duration`, где
  `offset = now − Date.now()` из снимка страницы или RPC `state` (после возврата во вкладку — свежий `state`);
  летун при `Date.now() + offset >= expiresAt` не рисуется и убирается. Путь — прямая `from → to` или квадратичная
  кривая через `via`. Глубина `depth` задаёт масштаб (дальние мельче), слой (дальние позади дерева, ближние перед
  грядкой) и скорость взмахов. Утка из куста: куст шуршит, утка взлетает из его точки.
- Летуны движутся каждый кадр, поэтому попадание проверяет **canvas** (PixiJS hit-test по спрайту с запасом), а не DOM:
  клик по утке → `centrifuge.rpc(shoot, {flyer})`. Клик мимо — без RPC. Как и с тыквами, по своему выстрелу
  ничего не рисуется: падение — только по событию `shot` (перья, утка кувыркается вниз, всплывают очки).
- Кусты (`#app[data-bushes]`, JSON) и траектории летунов — в процентах экрана **без** `spreadX`, как на сервере.
- Перехват: `bindShooting` (`public/js/client.js`) слушает `pointerdown` на `#app` в фазе захвата, `scene.flyerAt(x, y)`
  проверяет летунов от ближних к дальним по хит-боксу тела (~60% спрайта, без крыльев и хвоста — сбить должно быть
  непросто); при попадании клик гасится и до кнопки тыквы не доходит.
- Слои: летун никогда не позади дальнего плана (холмы — за километры). `depth` 0 — перед холмами, за деревом, плетнём
  и наземными объектами, с лёгкой дымкой к цвету неба; `depth` 1 и 2 — над наземными объектами. Полный рендер (resync, `reset`) убирает летунов.
- Спрайты — `public/js/pixel/flyers.js`, живой пример — `public/dev/flyers.html`.

### Экран входа и персонажи

**Фронтенд — реализовано** (проверено в лаборатории), **в работе** — ждёт backend. Правила — [`players.md`](players.md)
(«Персонаж», «На поле»), протокол — `register {name, look}`, `move`, события `walker` / `move` / `leave`, `walkers` в
снимке.

- **Секрет игрока** — `localStorage['hellowin.secret']` (UUID, при первом визите), уходит только в `data` подключения
  (`{playerSecret}`). Без `localStorage` секрет живёт до перезагрузки страницы.
- **Экран входа** — `<dialog data-join>` поверх главной (`public/js/join.js`, разметка в `home.dark.php`): при первом
  визите (в `localStorage` нет `hellowin.look`) и по кнопке «Персонаж» в HUD. Поле имени `data-join-name`; по каждой
  части `look` — строка «‹ название ›» (`data-part="body|cloak|face|eyes|hat"`, у глаз — квадратик цвета); «Случайно»;
  превью — персонаж крупно, поворачивается спереди → сбоку → сзади → другим боком и шагает на месте (при
  `prefers-reduced-motion` — стоит лицом); «На поле» → `register {name, look}`, при успехе `hellowin.name`/`hellowin.look`
  запоминаются в `localStorage` для следующего входа; ошибку показывает под полем (`invalid name` — правило имени,
  `invalid look`, `anonymous`, прочее — «Не вышло»). «Просто смотреть» и Esc закрывают экран без регистрации —
  зритель не ходит, а при следующем визите экран покажется снова. Превью рисуется обычным 2D-canvas
  (`image-rendering: pixelated`), без PixiJS. Доступ к `localStorage` — в `try/catch`.
- **Персонажи — сборные спрайты** (`pixel/characters.js`). Каталог частей с подписями (`CATALOG`), части по
  умолчанию, `randomLook()`, сборка кадра из слоёв: накидка сзади → тело → лицо (цвет глаз — замена пикселей
  палитры) → шапка → накидка спереди → рука с предметом. Тело задаёт по кадру смещение головы и точку кисти;
  шапки, лица и предметы рисуются один раз на направление и ставятся по этим точкам — так частей много, а кадров мало.
  Неизвестный id части — часть по умолчанию.
- **Направления** — спереди, сзади, сбоку (влево — зеркало). **Позы**: стойка (дыхание), переминание, ходьба
  (4 кадра), стойка с согнутой в локте рукой, держащей предмет (`item`: пиво, метла, пистоль…), выстрел (отдача).
- **Ходьба.** Фигурки — в `groundLayer`, сортируются по y ступней вместе с тыквами и реквизитом. Позиция — по `walk` и
  серверным часам (то же смещение, что у летунов): постоянная скорость вдоль ломаной, длина — в единицах конфига, как
  `HELLOWIN_WALK_SPEED` на сервере; направление — по экранному наклону текущего отрезка (сбоку, если |dx| ≥ 0,8·|dy|,
  влево — зеркало). Координаты `walk` → экран тем же преобразованием, что тыквы (`spreadX`); на узком экране
  лужайка шире экрана, и фигурка за его краем рисуется прижатой к краю (10 арт-px), а не пропадает. Клик по земле (не
  по тыкве, не по летуну, не по HUD и панелям) у игрока с фигуркой на поле → `move {x, y}` в координатах конфига
  (`scene.groundAt`: обратный `spreadX`, 0,1 %; над горизонтом — `null`, без RPC). Свою фигурку клиент локально не
  двигает: она пойдёт, когда придёт `move`, — как и всё остальное, только из событий.
- **Имя** — PixiJS `Text` отдельным слоем поверх увеличенной арт-текстуры, в экранном разрешении (моно-шрифт HUD,
  12 px, кремовый с тёмной обводкой; своё имя — золотое), над верхним непрозрачным рядом кадра. Текст внутри
  арт-текстуры размылся бы при целочисленном увеличении, а свой пиксельный шрифт не покрыл бы кириллицу; DOM-подписи
  пришлось бы двигать каждый кадр. У края экрана подпись не обрезается.
- **Живость** — детерминированно, одинаково у всех: время делится на слоты `3500 + crc32(id) % 2000` мс со сдвигом
  `crc32(id)`; хеш `(crc32(id), номер слота)` даёт сторону (чаще лицом) и в трети слотов — переминание в начале слота.
  До первого слота после прибытия фигурка смотрит туда, куда шла. На `shot` с `player` стоящей фигурки (идущая не
  останавливается) — поворот к летуну (сбоку, если он заметно левее/правее, иначе спиной — птицы над дальним
  планом), поза `shoot` с пистолем на 2 цикла кадров (не меньше 600 мс), затем возврат к своему предмету.

API сцены для фигурок: `scene.walker(w)` (появилась или сменила вид), `scene.move(id, walk)`, `scene.leave(id)`,
`scene.setMe(id)`, `scene.groundAt(clientX, clientY)` → `{x, y}` в координатах конфига или `null`;
`scene.render(snapshot)` заменяет фигурки списком `walkers` из снимка (без поля — оставляет свои). Перехват кликов по
земле — `bindWalking(root, scene, canWalk, move)` в `client.js`.

### Сюжет: сова, сцены, финал

**Запланировано.** Правила — [`scenario.md`](scenario.md) («Модератор и сова», «Сцены 1–3», «Финал», «Проклятый мир»),
протокол — [`protocol.md`](protocol.md) («Модератор», события `owl`, `ready`, `finale`, `pause`, `zombies`).

- **Пульт модератора** — дебаг-панель: у модератора (`me.moderator`) в ней кнопки пульта — реплики совы из каталога,
  поле своего текста, «Следующая сцена» (активна при `ready`, с подтверждением для `force`), шаги финала, особые
  летуны, зомби, пауза, «Заново». У остальных кнопок пульта нет. Секрет — из `?moderator=` в `localStorage`.
- **Сова** (`pixel/owl.js` спрайты, `owl.js` каталог текстов) — на ветке дерева (`perch`), моргает и вертит головой;
  на `owl` — пузырь с текстом над ней, время показа — по длине текста; подстановки (`{player}`) — из `params`.
- **Сцены** — палитра и свет: закат (тёплое небо, длинные тени, свечи в тыквах, слой `glow`), ночь (тёмное небо, луна,
  гроза с молниями, провода и болты к тыквам, разряды по побегам к корню, корень в швах). Новые летуны: `crow`, `bat`,
  `ghost`, `witch`, `roadrunner` (бежит по горизонту), `zombie` (на земле, в `groundLayer`). Предметы фигурок:
  `torch`, `pitchfork`.
- **Финал** — шаги по `finale.step`: молния и раскол корня; FrankenPHP поднимается из земли (узнаваемо по логотипу
  FrankenPHP, перерисованному в нашем пиксель-арте); выбегает RoadRunner (по логотипу RoadRunner); экран разоблачения
  с числами `reveal` и ссылкой на «Как это работает»; финальная фраза. Снимок восстанавливает шаг без анимации
  перехода.
- **Проклятый мир** — вечная ночь, FrankenPHP в центре, зомби-«воркеры» бредут с грядки, сбиваются как летуны.

## Страница «Как это работает» (`GET /how-it-works`)

- Вводный блок + вкладки (WAI-ARIA Tabs, `public/js/how-it-works.js`, вкладка в `location.hash`, без JS — все
  разделы подряд). Новая вкладка = ссылка `role="tab"` в `tabs__list` + `<section role="tabpanel">`; JS и тест не
  трогать.
- Схемы — inline SVG; цвета через CSS-переменные, подписи без обводки, ширина до 1360px. Схемы показывают реальный
  механизм: имена классов, каналов, ключей и портов берутся из кода, не из памяти.
- Вкладка «Идемпотентный переход» (`#idempotency`): клик → очередь `transitions` с дублями → `#[Idempotent]` с ключом
  `{round}:{pumpkinId}:{toStage}` → одна публикация `pumpkin`. Тесты страницы — `HowItWorksPageTest`.
