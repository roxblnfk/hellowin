# Игроки и статистика

Статус: **запланировано**, к реализации после движка сцены и тыкв ([`engine.md`](engine.md)).

## Идентификация

- При первом визите браузер генерирует секрет (UUID) и хранит его в `localStorage`. Секрет знает только этот браузер —
  по сути это пароль игрока. Наружу (в события, разметку, логи, метрики) он не уходит.
- Секрет передаётся только в `data` подключения к Centrifugo. `ConnectService` вычисляет `publicId = hash(secret)`
  и отвечает `user: publicId`; дальше Centrifugo сам подставляет пользователя в каждый RPC — клиент не шлёт ID
  в запросах и не может выдать себя за другого.
- Имя: RPC `register {name}`; проверка длины и допустимых символов, ошибка `invalid name`. Без имени игрок играет
  анонимно (`name` — `null`), статистика всё равно копится.

## Статистика

По игроку: клики (всего и по сценам), «добитые» тыквы, участие в раундах. «Добил тыкву» — тот, чья задача
`TransitionPumpkin` реально выполнилась: задача несёт `playerId` поставившего её клика, а из k+n дублей выполняется
одна — так идемпотентность честно выбирает победителя.

## Хранение

Всё — RR KV-плагин на Valkey (драйвер `redis`), без SQL:

- запись игрока `player:{publicId}` — JSON `{id, name, clicks, finished, …}`, изменяется под RR-локом
  `player:{publicId}` (конкуренции за него почти нет);
- индекс игроков — один ключ, обновляется только при регистрации, под своим локом;
- таблица лидеров — фоновая задача раз в N секунд читает игроков, считает топ, пишет ключ `leaderboard` и публикует
  событие `leaderboard` в канал.

RR KV не умеет атомарный инкремент, сортированные множества и обход ключей — отсюда локи, индекс и агрегирующая
задача. Это осознанный выбор: демо показывает связку KV + локи + очередь RoadRunner, а не нативные структуры Valkey.
